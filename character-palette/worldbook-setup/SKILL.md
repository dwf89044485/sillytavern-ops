# 世界书配置 — 让你写好的内容真正被 AI 读到

## R — 原文 (Reading)

> "很多人写了很好的角色设定，结果 AI 根本没读到。为什么？因为世界书的配置搞错了——条目没触发、位置放反了、递归没关、关键词写错了。内容再好，AI 收不到也是白搭。"
> — 《性格调色盘》0章 三、世界书配置

> "单角色卡，所有条目全蓝灯。这是铁律。不要因为条目多就改绿灯。缺了任何一个条目，角色就不完整，AI 就开始乱来。"
> — 《性格调色盘》0章 3.6 单角色卡和多角色卡

---

## I — 方法论骨架 (Interpretation)

世界书（World Info）是 SillyTavern 的条目化上下文系统：一堆条目，每条是一段文字，但不是全部一股脑发给 AI——它们有自己的触发规则、放置位置、前后顺序。

配置的核心逻辑一句话：**必须始终存在的内容常驻（蓝灯），按需加载的内容触发（绿灯）**。围绕它有几个固定决策：

1. **先判断单/多角色卡**（数核心角色数，不是条目数）——这是配置的第一步，搞错整张卡全错。
2. **触发策略**：蓝灯（常驻，总纲/背景/角色速览）+ 绿灯（关键词触发，NPC/场景/详情）。
3. **位置**：大世界观放角色定义前，小世界观放角色定义后；D0 只放直接指导（二次解释），D1 及以上一律不碰。
4. **顺序**：同一位置内按重要性排（总纲 1 → 速览 2-4 → 场景 50-98 → 核心角色 99 → NPC/EJS 100）。
5. **递归全勾**：每个条目都勾"不可递归 + 防止进一步递归"，否则绿灯连锁触发、token 爆炸。
6. **关键词**：英文逗号分隔，覆盖所有称呼（全名/昵称/外号/职务）。

## A1 — 书中的应用 (Past Application)

### 案例 1: 单角色卡林小雨（五条目全蓝灯）
- **问题**: 林小雨的人设拆成五个条目（基础/外貌/性格/背景/NSFW），作者纠结要不要把一些改成绿灯省 token。
- **方法论**: 判断是单角色卡（五个条目都是同一个人）→ 全部蓝灯常驻，无论拆成多少条。
- **结论**: 单角色卡全蓝灯是铁律。拆开的条目描述同一角色，AI 必须同时知道全部才能正确扮演。
- **结果**: 改成绿灯的后果——聊天里没提到触发词时 AI 读不到性格，靠猜，猜的结果就是八股。

### 案例 2: 多角色卡林小雨 × 赵明月
- **问题**: 两个核心角色 + 世界观 + 场景 + NPC，怎么配才不会互相干扰、不浪费 token？
- **方法论**: 角色速览蓝灯（AI 始终知道有谁）；各角色详细信息绿灯（关键词=角色名/昵称/外号，提到谁加载谁）；场景/NPC 绿灯按需。
- **结论**: AI 先看速览知道有林小雨和赵明月，聊到"小雨"时加载小雨详情，聊到"明月"时加载明月详情，没提到的角色不占 token。
- **结果**: 配置正确时各角色资料精准命中，不互相污染。

### 案例 3: 大世界分层（修仙世界）
- **问题**: 原创修仙大世界，多区域/多势力/多 NPC，全部常驻会 token 爆炸。
- **方法论**: 四层结构——世界总纲（常驻，目录）+ 区域速览（常驻，只列名字和一句话定位）+ 势力/场景详情（绿灯按需）+ NPC 详情（绿灯按需）。
- **结论**: 上层只放目录不展开，详情只在需要时加载。角色在南疆活动时，北原魔土的几十个条目不占 token。
- **结果**: "总纲和速览是常驻的目录，详情按需出现"——大世界跑得动。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 把写好的角色设定粘进世界书，但 AI 游玩时"不知道"这些设定。
2. 绿灯条目死活不触发（关键词配错/逗号用错/覆盖不全）。
3. 要配多角色卡（两个以上核心角色），不确定各自怎么触发。
4. 大世界设定太多，担心 token 爆炸，想分层。
5. 二次解释/纠正指令放哪里影响力最大（D0）。

### 语言信号 (用户的话里出现这些就应激活)

- "AI 没读到我的设定" / "AI 不知道这个设定"
- "绿灯不触发" / "关键词不生效"
- "多角色卡怎么配" / "世界书怎么配置"
- "配置" / "world info" / "世界书"

### 与相邻 skill 的区分

- 与 `card-diagnosis`：诊断是"内容写得不好"；本 skill 是"内容写好了但 AI 没读到"（工程配置）。如果用户说"角色 OOC/很 AI"→ 诊断；说"角色不知道这个设定"→ 本 skill。
- 与 `character-card-master`：写卡大师产出人设**内容**；本 skill 把内容**部署**进世界书。写完卡需要配置时，从写卡大师引导过来。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行：

1. **判断单/多角色卡**
   - 数核心角色数（同一角色的拆分条目不算"不同角色"）。1 个 → 单角色卡；≥2 → 多角色卡。
   - 完成标准: 明确说出来"这是单角色卡/多角色卡，因为核心角色有 N 个"。

2. **配触发策略（蓝灯/绿灯）**
   - 单角色卡：该角色所有条目全部蓝灯常驻（铁律，别因条目多改绿灯）。
   - 多角色卡：角色速览蓝灯 + 各角色详细信息绿灯（关键词=角色名/昵称/外号）。
   - 世界观/背景/总纲 → 蓝灯。NPC/场景/事件/详情 → 绿灯。
   - 完成标准: 每条目明确"蓝灯 or 绿灯 + 关键词"。

3. **配位置与顺序**
   - 大世界观 → 角色定义前（World Info before）；小世界观/角色详情/NPC/场景 → 角色定义后（after）。
   - 二次解释/直接指导 → D0（role 选 system）。**D1 及以上一律不碰。**
   - 顺序: 总纲 1 → 速览 2-4 → 场景 50-98 → 核心角色 99 → NPC/EJS 100。
   - 完成标准: 每条目有明确的位置 + 顺序数字。

4. **全勾递归 + 检查关键词**
   - 所有条目勾选"不可递归 + 防止进一步递归"。
   - 关键词用英文逗号分隔（不能中文逗号/空格/分号），覆盖所有称呼：角色全名/昵称/外号，NPC 加职务，场景加区域名/别称/相关动作。
   - 完成标准: 扫一遍所有条目，无遗漏递归勾选、无中文逗号、无漏掉的称呼。

5. **回读验证**
   - 模拟一次游玩：如果聊天里提到"小雨"，AI 是否能读到林小雨详情？提到没提到的角色时，是否不占 token？
   - 判停: 若发现是内容问题（人设本身写得差）而非配置问题，转 card-diagnosis；若需要写新内容，转 character-card-master。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 角色卡内容本身写得不好/标签化 → `card-diagnosis`。
- 从零写人设内容 → `character-card-master`。
- 用户用的是非世界书平台（纯提示词/其他工具）→ 触发/位置/递归概念不完全适用，只提取通用原则（常驻 vs 按需）。

### 作者在书中警告的失败模式

- **绿灯关键词用中文逗号/空格**：十有八九的"绿灯不触发"是这个原因。必须英文逗号，逗号后不能有空格。
- **关键词覆盖不全**：NPC 叫"林小雨"但大家都叫"小雨/班长"，只设"林小雨"则永不触发。要覆盖所有称呼。
- **绿灯遗漏/过度触发**：核心角色用绿灯会漏（用代称"她"时）或过度（名字每轮出现）。重要的内容用蓝灯。
- **D1/D2 放条目**：破坏聊天记录完整性，AI 分不清是设定还是剧情。D0 以外一律不碰。
- **递归不勾**：绿灯条目互相连锁触发，token 爆炸，AI 崩溃。所有条目全勾。
- **单角色卡改绿灯**：缺一条角色就不完整，AI 靠猜，演出八股。
- **EJS 加载的条目手动开启**：多阶段内容同时进入上下文，角色行为直接乱。

### 作者的盲点 / 时代局限

- 具体术语（世界书/蓝灯/绿灯/扫描深度/D0/EJS）是 **SillyTavern 生态专用**，其他平台用户需要对译。
- "扫描深度推荐 2""顺序数字参考"等是工具默认值建议，随版本可能变化。
- 绿灯的两个已知问题（遗漏/过度）作者建议进阶卡用 MVU+EJS 变量系统——那是更高门槛的技术路线，本 skill 默认走"蓝灯总览+绿灯详情"的经典路径。

### 容易混淆的邻近方法论

- "蓝灯" vs "绿灯"：蓝灯=常驻必须始终存在；绿灯=关键词触发按需加载。把重要内容做绿灯、按需内容做蓝灯都是常见错误。
- "D0" vs "D1"：D0 在聊天记录最底部、是 AI 最后读到的位置（影响力最大）；D1 在倒数消息之间（会破坏聊天记录）。不是数字大就重要，恰恰相反。
