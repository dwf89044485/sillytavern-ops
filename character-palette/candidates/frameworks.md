- id: f01
  title: 联想词原理（AI 是联想词机器）
  type: framework
  source_chapter: 11.另一种写法（第 1 章）+ 1.入门（第 2 部分）
  source_quote: |
    "你给的上下文越具体、越独特，AI选出来的词就越不一样。你给的上下文越空、越泛，AI就会选那些最常见的、最安全的词。"
  summary: |
    底层认知模型：AI 是"输入法联想"，根据上下文逐个预测下一个词。你写的每个字都在替 AI 选联想词。
    推理路径：从"想让 AI 输出什么"反推"该写什么"——写具体画面而非标签，AI 就找不到数据库里的现成模板，被迫走一条新路。
    判断标准：你写的内容，AI 数据库里有没有现成的常见搭配？有就等于没写。
  tags: [framework, ai-principle, character-design]

- id: f02
  title: 手写 / 半手写 / AI 直出 三分类判断
  type: framework
  source_chapter: 1.入门（第 2 部分）
  source_quote: |
    "纯手写：ai只负责修改错别字、整理格式……半手写：你有足够的内容、设定，但是输出完整内容的是Ai……AI直出：只提供一些想法，剩下的全部由AI产出创作"
  summary: |
    决策框架：确定自己属于哪类创作者，再决定写作方式。AI 输出必然把内容改成它数据库里"正确"的样子，等于给角色加上 AI 的缺点。
    所以想摆脱 AI 味就用纯手写；AI 只当工具不当助手。判断：写出来的内容是不是 AI 数据库里能找到的"正确"表达。
  tags: [framework, writing-method, ai-principle]

- id: f03
  title: 特征差异化原则（外貌只写偏离默认值的特征）
  type: framework
  source_chapter: 0.写"正确"的卡（1.3 外貌）
  source_quote: |
    "AI有自己的数据库。你只需要写偏离数据库默认认知的部分。"
  summary: |
    可迁移的取舍框架：AI 数据库里已有的默认认知不用写（中国女生默认黑发黑眼、18岁默认年轻皮肤好），只写偏离默认的部分。
    判断标准：把外貌遮住名字，能否只靠特征认出是谁？能=写得好，不能=废话。
    可迁移到世界观、背景、用户信息——一切喂给 AI 的内容都只写"AI 不知道的"。
  tags: [framework, character-design, differentiation]

- id: f04
  title: 调色盘写法（底色/主色调/点缀 + 衍生）
  type: framework
  source_chapter: 1.入门（第 3 部分）+ 02_调色盘篇
  source_quote: |
    "人的性格就像调色盘，叛逆是底色，热情与不拘一格是主色调，由多种性格衍生组合而成才是活生生的人"
  summary: |
    核心写作框架：把性格从"标签"变成"颜色"——底色（一直隐在下面）+ 主色调（日常最常见）+ 点缀（平时看不到）+ 每种颜色 2-5 条衍生。
    AI 读到的不是七个独立标签（会轮流切换），而是"需要融合的颜色"（会同时运行、互相影响）。
    写作流程：先定三层颜色 → 每种颜色写衍生 → 衍生必须写 AI 数据库里不存在的具体组合。
  tags: [framework, character-design, palette]

- id: f05
  title: 性格对冲 / 性格锚点（主+副+对冲）
  type: framework
  source_chapter: 1.入门（第 1 部分）
  source_quote: |
    "一个温柔的女角色接受了你的告白……如果在这个场景加入相反的性格会如何呢？比如我加入歇斯底里。结果场景是她哭的很狼狈，还轻锤了user几下。一个完全预料之外的场景出现了"
  summary: |
    思维模型：主性格 + 副性格 + 对冲性格（最少三个），让 AI 融合所有性格演绎，产生无法预料的行为（惊喜感/未知性）。
    优点：对 AI 直出的标签化角色修正效果明显；缺点：对手写卡反而成为限制（debuff）。
    是调色盘的前身，理解了它才能理解调色盘为什么有效。适用判断：角色是不是 AI 直出的标签化产物？
  tags: [framework, character-design, fusion]

- id: f06
  title: 衍生压缩包原理（3000 token 超越 4w token）
  type: framework
  source_chapter: 1.入门（第 3 部分 5/7）+ 02_调色盘篇
  source_quote: |
    "衍生就是一个超级压缩包，它压缩了很多东西，而ai是可以解开这个压缩包并使用的，这也是为什么我只需要写3000token就能轻松超越曾经4wtoken的角色卡"
  summary: |
    写作方法+推理路径：一条衍生 = 把抽象特质展开成具体场景/行为 + 背后原因的"超级压缩包"，AI 能解开并复用。
    核心要求：衍生必须是 AI 数据库里不存在的组合——把毫无逻辑关联的两个性格拼在一起（如"社恐"+"社交达人面具"），只有人类作者能产出。
    判断：AI 能不能自己想到这个组合？能 → 你没写，等于喂给 AI 它自己的常见联想。
  tags: [framework, character-design, compression]

- id: f07
  title: 三面性判断与拆面流程
  type: framework
  source_chapter: 2.三面性（第 3、5 部分）+ 03_三面性篇
  source_quote: |
    "这个角色在不同场景下，行为模式是否有根本性的切换？……如果你找不出两个以上'压力性质截然不同'的场景，就不需要三面性。"
  summary: |
    决策框架：先判断"行为模式是否有根本性切换"（不是语气变了，是整套行为逻辑换了），再看能否找出两个以上"压力性质截然不同"的场景。
    拆面三步骤：摊开调色盘衍生找行为差异巨大的场景 → 判断压力性质是否截然不同（不是场景不同，是压力性质不同）→ 每面装五部件。
    面数由角色决定不由名字决定（二/三/四面都行），硬拆有害。
  tags: [framework, character-design, decision-gate]

- id: f08
  title: 三面性的五部件结构 + 过渡 + 渗透
  type: framework
  source_chapter: 2.三面性（第 5、6、8 部分）
  source_quote: |
    "每一张面不是一个标签，是一个完整的行为系统。五个部件：1.触发条件 2.能量状态 3.语料 4.身体行为模式 5.功能"
  summary: |
    写作结构框架：每张面 = 完整行为系统（触发条件/能量状态/语料/身体行为模式/功能），缺一个 AI 理解就有漏洞。
    三面间写"过渡"（渐变不是开关，至少写最常见+最剧烈两条切换路径）和"渗透"（一面运行时其他面元素的泄漏——角色最真实的瞬间）。
    语料跟着三面性走（混在调色盘里 AI 分不清）；三面性只写"怎么运作"，不写"为什么"。
  tags: [framework, character-design, three-faces]

- id: f09
  title: 混色写作法（颜色在同一笔里跑）
  type: framework
  source_chapter: 4.混色教程 + 04_混色篇
  source_quote: |
    "混色就是在同一个画面、同一个动作、同一句话里，让两种以上的情绪同时出现。……是笑本身就含着哭。"
  summary: |
    进阶写作框架：调色盘把颜色分开摆好（照片里的夜空），混色让颜色在同一笔里一起跑（梵高的星空）。
    流程：摊开衍生 → 找会"撞在一起"的颜色组合 → 写成画面（只写动作/台词/物理事实）→ 不解释。
    判断标准：角色同一个瞬间会有两种以上东西在跑吗？会 → 适合混色。混色是点睛之笔不是底色，到处混色=没反差。
  tags: [framework, character-design, mixing]

- id: f10
  title: 物理事实反差（混色的核心技巧）
  type: framework
  source_chapter: 4.混色教程（第 4 步）+ 04_混色篇
  source_quote: |
    "她说'我没事'。她的手在抖。"
  summary: |
    可复用的写作技巧：把两个不带感情的客观事实摆在一起，反差自动制造混色，AI 不需要"演"复杂情绪，只需"重现"画面。
    例子："她说'不用了'。说完眼睛看了那碗汤很久。"——"不用了"和"看了很久"两个事实放一起，中间不需要解释。
    约束：不能用"但/然而"转折句（会变八股），不能点名情绪，不能解释。
  tags: [framework, writing-technique, mixing]

- id: f11
  title: 核心人格层七件套（决策发动机）
  type: framework
  source_chapter: 7.核心人格层 + 05_核心人格层篇
  source_quote: |
    "核心人格层更接近于角色的决策发动机。它回答的是：这个人以为自己想要什么？……也就是七个部分：表层欲望、深层缺失、核心恐惧、防御机制、核心矛盾、道德底线、自我认知。"
  summary: |
    决策层框架：解决"角色为什么做这个选择"（三面性只解决"场景下怎么演"）。让角色获得叙事主动权，也避免 AI 靠阴谋/第三者制造冲突。
    触发逻辑：事件触碰表层欲望→主动追求；触碰深层缺失→不自觉靠近；触碰核心恐惧→启动防御机制；防御与缺失冲突→拉扯。
    适用判断：角色有没有明确的剧情驱动、防御机制、道德底线与弧光可能？纯甜饼角色不需要。
  tags: [framework, character-design, decision-layer]

- id: f12
  title: 核心人格层反推法（从原人设长出，不推翻）
  type: framework
  source_chapter: 7.核心人格层（第 7 部分、第 10 部分）
  source_quote: |
    "第一步：看调色盘里的主色调……第二步：反推深层缺失……第三步：从背景里找核心恐惧……第四步：把防御机制写成行为"
  summary: |
    推理方法：不推翻原人设，从已有素材提炼核心人格层。主色调→表层欲望；表层欲望反向→深层缺失；背景经历→核心恐惧；防御机制必须落到具体行为（能演）；核心矛盾一句话说清；自我认知写"可能性"不写死结局。
    从旧三面性迁移：每面"功能"≈防御机制，"压力性质"反推核心恐惧，"过渡"暴露防御机制何时失效。
  tags: [framework, character-design, reverse-inference]

- id: f13
  title: 二次解释（防误读说明书/反向护栏）
  type: framework
  source_chapter: 06_二次解释篇 + 1.入门（第 4 部分）
  source_quote: |
    "二次解释就是你作为创作者，直接告诉AI：'我写的这个角色是这个意思。你不要自己脑补别的。'"
  summary: |
    防误读框架：拦住 AI 的自动补全（把"安静"读成"冷漠"、把"不接受帮助"读成"傲娇"）。
    写法核心：直接叙述你想要的样子，不要写"不是……"（AI 越听"不是冷漠"越往冷漠想）。
    位置：放所有人设内容最后（AI 最后读到的记忆残留最强；世界书里放 D0）。判断何时多写：特质易被误读、有反直觉组合、初始关系特殊。
  tags: [framework, character-design, anti-misread]

- id: f14
  title: 意象（总调性锚）
  type: framework
  source_chapter: 07_意象篇 + 11.另一种写法（第 6 章）
  source_quote: |
    "意象来自角色的核心矛盾和存在状态。你问自己三个问题：她像什么？……意象像一个锚。把整个角色锚在一个感觉上。"
  summary: |
    收束层框架：用总比喻浓缩角色所有颜色，给 AI 一个"总调性"，让正文质感自动往意象方向靠。
    找法：问"她存在的方式像什么"（不是外貌），从核心状态自然长出。原则：能承载与 {{user}} 的关系动态、要短、不解释自己、放人设最后（记忆残留最强）。
    例：风铃/一小格阳光/落尘的月亮。
  tags: [framework, character-design, imagery]

- id: f15
  title: 用户信息行为归因校准（行为翻译手册）
  type: framework
  source_chapter: 9.用户信息教程（第 6 部分）
  source_quote: |
    "AI在处理你的输入时，有一个隐藏的步骤：行为归因。……没有用户信息的时候，AI的归因来源只有一个：资料库里这个动作最常见的动机。"
  summary: |
    认知模型：AI 会对用户每个动作先做"行为归因"，默认取数据库最常见（往往最戏剧化/冲突化）的动机，导致角色反应跑偏。
    解法：用户信息给 AI 第二个归因来源，把行为从"刻板印象版本"翻译成"真实版本"（"我揉脸颊=宠溺"不是占有）。
    判断：你输入的动作，AI 会不会往最刺激的方向补全？会 → 需要写翻译手册。用户信息本质是"用户版二次解释"。
  tags: [framework, user-info, attribution]

- id: f16
  title: 抢话党 / 不抢话党 两套用户信息判断
  type: framework
  source_chapter: 9.用户信息教程（第 3、4、5 部分）
  source_quote: |
    "抢话党需要AI演好你。不抢话党需要AI读懂你。演好你，和读懂你，是两件事。"
  summary: |
    决策框架：先判断玩家玩法再决定用户信息写法。抢话党（AI 演你）→ 写简化版角色卡：基础信息 + 调色盘 + 禁止部分 + 边界提示词；不抢话党（AI 只演角色并读懂你）→ 写行为翻译手册：肢体接触含义/语气真实含义/情绪表达方式/互动模式。
    关键约束：不抢话党不写调色盘（AI 会用标签预判你的行为，偶尔热情反而被读成反差）。
  tags: [framework, user-info, player-types]

- id: f17
  title: 世界观 A/B/C 分类写法
  type: framework
  source_chapter: 0.写"正确"的卡（第 2 部分）
  source_quote: |
    "先搞清楚这个问题，再动笔。因为不同类型的世界，写法完全不同，token量差几十倍。"
  summary: |
    决策框架：先判断你的世界属于哪类——A 真实背景（AI 已知，只写虚构/自定义部分，一个条目）；B 小世界（写与 AI 已知套路的差异，1-3 条目）；C 大世界（拆分条目分层加载）。
    统一判断标准：删掉这句话 AI 还会不会演错？不会就删。
    可迁移原则：世界观是常驻提示词（每轮吃 token），不是小说设定集。
  tags: [framework, worldbuilding, decision-gate]

- id: f18
  title: 大世界分层加载（总纲/速览/详情）
  type: framework
  source_chapter: 0.写"正确"的卡（2.5 C 类）
  source_quote: |
    "思路很简单：分层。上层常驻，下层按需加载。第一层：世界总纲（常驻）……第二层：区域速览（常驻）……第三层：势力/场景详情（按需加载）……第四层：NPC详情（按需加载）"
  summary: |
    大世界的工程化写法：四层结构——世界总纲常驻（目录）、区域速览常驻（只列名字和一句话定位）、势力/场景详情绿灯按需加载、NPC 详情绿灯按需加载。
    规则：上层只放目录不展开（细节泄漏到上层=常驻吃 token）；角色在东边时西边设定不占位。
    关键词覆盖所有称呼（全名/昵称/外号/职务）。
  tags: [framework, worldbuilding, layering]

- id: f19
  title: 世界书单/多角色卡配置判断
  type: framework
  source_chapter: 0.写"正确"的卡（3.6）
  source_quote: |
    "在配置任何条目之前，你必须先判断一件事：你的世界书里有几个核心角色？……单角色卡，所有条目全蓝灯。这是铁律。"
  summary: |
    配置决策框架：数核心角色数（同一角色的拆分条目不算"不同角色"）。单角色卡 → 该角色所有条目全部蓝灯常驻（铁律，别因条目多改绿灯，缺一条角色就不完整）；多角色卡 → 角色速览蓝灯 + 各角色详细信息绿灯（提到谁加载谁）。
    所有条目必须勾"不可递归+防止进一步递归"（防多米诺连锁触发）。
  tags: [framework, worldbook, configuration]

- id: f20
  title: 蓝灯/绿灯触发策略决策
  type: framework
  source_chapter: 0.写"正确"的卡（3.2、3.7）
  source_quote: |
    "蓝灯的意思是：只要世界书开着……这段内容就一直发给AI……绿灯的意思是：只在最近的聊天记录中出现了你设定的'关键词'时，这段内容才发给AI。"
  summary: |
    触发策略决策框架：必须始终存在的内容（世界观总纲、背景、角色速览）→ 蓝灯常驻；按需加载的内容（NPC、场景、多角色详细、二次解释）→ 绿灯关键词触发。
    绿灯两个已知问题：遗漏触发（没提关键词就读不到）与过度触发（一直挂着），进阶卡改用变量系统。
    关键词格式：英文逗号分隔，覆盖所有称呼。二次解释放 D0（最后读到影响力最大）。
  tags: [framework, worldbook, trigger-strategy]

- id: f21
  title: 开场白三写法（目的 + 三种路径）
  type: framework
  source_chapter: 5.如何写出合适的开场白
  source_quote: |
    "开场白是一张角色卡的首楼（0楼）……它能够让user有一个行动目标，让玩家知道接下来要怎么玩；固定文风表现，延缓文风劣化"
  summary: |
    决策框架：开场白三个目的——给引子让用户有行动目标、固定文风（模型吃首楼文风，首楼规避 llm 八股句式可延缓文风劣化）、交代背景关系。
    三种写法：完全手写（最不八股，用自己话重写 AI 的草稿也行）；半手写（AI 写 + 人为去八股词，劣化更快）；大纲开场白（只给情节大纲，不能固定文风，仅语料多的模型可用）。
  tags: [framework, opener, writing-method]

- id: f22
  title: 从零设计一张卡的流程（驱动力→骨架→……→打动自己）
  type: framework
  source_chapter: 6.纯文字角色卡实战
  source_quote: |

- id: f25
  title: 长期性设计：变化 + 不变量
  type: framework
  source_chapter: 6.纯文字角色卡实战（第 8 部分）
  source_quote: |

- id: f27
  title: 存疑机制（打断 AI 惯性思考）
  type: framework
  source_chapter: 3.台词先行人设（第 5 部分）
  source_quote: |
    "存疑干的事情就是：不给结论。打断AI的惯性思考。"
  summary: |
    防锁死机制：AI 读三句傲娇台词就会下结论锁死角色。存疑 = 在解释里给两种以上说得通的可能性，不替 AI 选，迫使它每次生成时重新根据上下文判断。

  source_quote: |

  title: 世界观压缩与完整性验证
  type: framework
  source_chapter: 0.写"正确"的卡（2.2）

  summary: |
