# 性格调色盘 → Skill 蒸馏 — 设计决策记录

> 本文档记录从教程到 skill 的全部分岔路口：在每个节点我们面临什么选择、为什么选了这条路、放弃了什么。
> 阅读对象：后续接手此工作的 AI（或未来的自己）。

---

## 决策 0：教程的"原子"到底是什么

### 背景

cangjie-skill 的不变量第一条："一个 skill 只做一个方法论单元，不能大而全。"

《穷查理宝典》拆出来是 10 个独立 skill——多元思维模型、逆向思维、能力圈……各自独立，可以在不同场景下被分别调用。它们之间是**并列选择**关系（contrasts-with）。

但性格调色盘教程的性质不同。它的所有方法——调色盘→多面性→混色→核心人格层——不是并列的独立工具箱，而是**同一个追问路径的不同深度**。它们之间是**深度递进**关系（depends-on）。

### 决策

**追问引擎是一个原子。** 不拆开调色盘/多面性/混色/核心人格层为独立 skill。

### 依据

1. **用户触发场景检验**：多面性、混色、核心人格层在真实对话中几乎永远不会作为初始入口出现。用户不会说"帮我激活多面性模式"——是追问过程中发现了不同场景行为差异巨大，追问引擎才自然进入这个方向。
2. **如果拆开会怎样**：每个 skill 的 E 段第一步都会是"确保你已经有调色盘"——等于在说"你不应该直接调用我，你应该先去另一个 skill"。这是过度原子化的信号。cangjie-skill 的 `05-stage3-zettelkasten.md` 节制原则：一本书拆出 10 个 skill，关系数 8-15 条正常，高于 25 条说明在硬凑关系。如果拆成 6 个独立 skill，仅调色盘/多面性/混色/核心人格层之间的关系就超过 10 条依赖。
3. **类比**：就像"如何诊断病人"不能拆成"如何测体温""如何听心跳""如何问病史"然后让病人自己选先调用哪个。诊断是一个不可分割的判断循环。

## 决策 1：拆分维度 — 教程章节 vs 用户触发场景

### 背景

教程有 11 个编号章节 + 7 章大总结。自然的想法是按内容分类拆：基础信息 skill、调色盘 skill、多面性 skill、混色 skill、核心人格层 skill、世界书 skill、用户信息 skill。

### 决策

**按用户触发场景拆分，不按教程章节拆分。**

### 依据

1. **教程编号是讲述顺序，不是构建顺序。** 同一个作者用三种完全不同的顺序构建了三个角色：姜糖从画面开始→最后才写基础信息；陈乖乖从基础信息开始→逐层深入；三明月完全跳过调色盘体系→用小传和采访。教程章节编号只反映作者认为"这样讲读者最容易理解"，不反映"角色应该这样构建"。
2. **按章节拆分的 A2 段会互相抢 trigger。** 用户说"怎么写性格"同时触发调色盘 skill 和构建引导 skill。两个 skill 的 description 都会试图包含这个场景。cangjie-skill 的 `04-stage2-ria-plus.md` 警告：A2 太宽 → trigger 不准 → 永不调用或乱调用。
3. **按触发场景拆分 → trigger 天然互斥。** "帮我创建一个角色"≠"世界书怎么配置"≠"AI 为什么误解我的行为"。三个入口的语言信号截然不同，B 段互相指向形成路由。

### 放弃的方案

放弃了"一个全能 skill"（A2 无法精确描述、B 段不存在）和"6 个按章节拆分的 skill"（多面性/混色/核心人格层 trigger 虚设）。

## 决策 2：最终 skill 数量和边界

### 决策

**3 个 skill：**

| #   | slug                    | 一句话                    | 触发信号                           |
| --- | ----------------------- | ---------------------- | ------------------------------ |
| 1   | `char-build-guide`      | 晴空妈妈追问引擎，通过追问让用户自己看见角色 | "帮我写角色""不知道怎么下手""角色很平面"        |
| 2   | `worldbook-config`      | 世界书配置：内容放哪里、什么时候触发     | "世界书怎么配置""绿灯不触发""关键词怎么写"       |
| 3   | `user-info-calibration` | 用户信息校准：AI 别再误解我的行为     | "AI 老误解我""抓手腕总被理解成强制""怎么写用户信息" |

### 关键变化

从最初的 5→6→3。变化过程中：

- **多面性**：从独立 skill → 合并到调色盘 → 最终作为 char-build-guide 的内部模式。每次变化都是因为发现它没有独立的用户触发场景。
- **混色**：同上。
- **核心人格层**：同上。
- **用户信息**：从"降级为附录"→ 在 V2 预测力测试中证明了自己（可诊断"AI 为什么总误解抓手腕"），V3 独特性通过（"行为翻译手册"是独创概念），trigger 独立。恢复为独立 skill。
- **世界书配置**：一直保持独立。技术问题的 trigger 和创作引导的 trigger 天然分开。

### 依据

三重验证（V1 跨域 / V2 预测力 / V3 独特性）+ A2 trigger 独立性和互斥性检验。详见 `verified.md`。

## 决策 3：char-build-guide 的设计范式 — 知识手册 vs 追问引擎

### 背景

最自然的 skill 设计是"角色卡写法指南"——把调色盘/多面性/混色/核心人格层的定义、格式、示例都写进去，用户问什么就输出什么。教程本身就可以被压缩成一份这样的指南。

### 决策

**char-build-guide 是一个追问引擎，不是知识手册。** 它通过提问让用户自己发现角色，而不是输出方法论知识给用户。

### 依据

1. **教程自身的成功不是靠"写得好"，是靠"问得好"。** 晴空妈妈从来不跟柚子说"现在我们来写底色"。她说的是"你问问自己，这七个标签里哪个是无论如何都在那里的"。教程最核心的教学法不是七层工具本身，而是**让柚子自己说出答案的追问路径**。
2. **如果 skill 输出知识而不是追问，它就变成了另一份教程。** 用户需要的是"帮我写角色"，不是"给我上一课"。她不需要知道什么是调色盘——她只需要被问到"你觉得她骨子里是什么"然后回答。
3. **追问让产出属于用户。** 晴空妈妈最后一章说"谢你自己。是你把她从七个标签里救出来的"——这句话不是煽情，是教程核心哲学：角色必须从作者自己脑子里长出来。skill 追问出来的角色属于用户，skill 输出模板填出来的角色属于 skill。

### 放弃的方案

放弃了"知识手册式 skill"（用户被动接收方法论，填表式交互）。它更简单、更容易写，但它让用户变成了"教程的读者"而不是"角色的作者"。

## 决策 4：内部模式不暴露给用户

### 背景

char-build-guide 内部有 7 种模式：基础信息、调色盘、多面性、混色、核心人格层、二次解释、意象。另加两条路径：快速路径和小传/采访路径。

用户可以主动说"我要写调色盘"吗？skill 应该告诉她"你现在进入了调色盘模式"吗？

### 决策

**不暴露。** 模式切换由追问引擎根据用户回答内容自动判断。用户不需要听到"调色盘""多面性""混色"这些术语（除非她自己用）。

### 依据

晴空妈妈从来没有跟柚子说过"我们现在进入调色盘模式"或"接下来我们写多面性"。她只是继续问下一个问题。"调色盘""多面性""核心人格层"这些是**教学元语言**——它们是教程作者和读者之间的术语，不是晴空妈妈和柚子之间的对话语言。skill 应该用教学元语言来组织自己的内部逻辑，但不应该把这些术语泄漏到和用户的对话中。

唯一的例外：如果用户自己使用了这些术语（如"我已经写了调色盘"），skill 当然可以接住——这说明用户已经读过教程，skill 不需要装傻。

## 决策 5：命名 "三面性" → "多面性"

### 决策

教程中的"三面性"改称"多面性"。

### 依据

"三面性"是教程作者给这种写法起的名字，但教程原文明确说："本质上这是'多面性'。可以是两面、三面、四面，甚至更多。叫它'三面性'，是因为大多数角色拆到最后，三张面刚好是一个常见的数量——但这不是固定规则。面的数量由角色本身决定，不由这个名字决定。"

以"三"命名容易误导 AI 和用户认为必须拆三张面。改为"多面性"消除这种误导。

## 决策 6：Skill 需要"判断规则"而非"原理阐述"

### 背景

教程花了大量篇幅解释底层原理——"AI 是输入法联想""反直觉组合只有人类能创造""解释了就是标签"。这些原理对于说服人类作者放弃"写标签就够了"的直觉是必要的。

### 决策

**Skill 传递给 AI 的核心内容是判断规则（判停标准、硬约束、切换规则、措辞模式），不是原理阐述。**

### 依据

1. **原理是写给人类的。** 人类需要被说服"为什么不能只写温柔"。AI 没有这个错觉——AI 不需要被说服。
2. **AI 需要的不是"为什么追问有效"，而是"什么时候该追问、什么时候该停"。** 如果 skill 只给了 6 种追问措辞但没有判停标准，AI 会变成一台追问机器——不管用户说什么都继续问，直到用户关掉对话。
3. **一个浓缩版"方向锚点"仍然需要，但目的不同。** 不是让 AI "理解教程思想"——是让 AI 在遇到规则没覆盖的边缘情况时，知道该往哪个方向偏。就像司机不需要理解内燃机原理，但需要知道踩油门是加速的方向感。

### 方向锚点（5 条，附在对应判断规则后面，每条 ≤1 句）

| 锚点                                           | 对应什么判断  |
| -------------------------------------------- | ------- |
| 越具体的画面 → AI 越难套模板。追问到"只有她才这样"就停。             | 追问判停标准  |
| AI 生成的内容 = AI 数据库里最常见的东西。所以用户说不知道的时候不许替她生成。  | 硬约束     |
| 角色之间的区别不在于颜色多，在于有没有 AI 数据库里不存在的颜色组合。         | 矛盾/混色检测 |
| 问"她做了什么"比问"她感受到了什么"有效 10 倍。                  | 追问措辞方向  |
| AI 会偷懒下结论然后锁死。永远只整理用户说了什么，不替用户总结"所以她是什么样的人"。 | 收束规则    |

## 决策 7：多入口路由

### 背景

教程中不同的角色案例走了完全不同的构建路径。姜糖从画面开始，陈乖乖从标签开始，三明月完全不用调色盘。

### 决策

**Skill 不预设一条固定路径。** 收到用户第一句话后，先判断入口类型，然后从那里开始追问：

| 用户说了什么    | 入口      | 追问起点                          |
| --------- | ------- | ----------------------------- |
| 一个具体画面/场景 | A: 画面入口 | "那个画面里她在做什么？"→ 从画面反推颜色        |
| 一堆标签/形容词  | B: 标签入口 | "挑一个最核心的。具体在什么场景下能看到？"→ 标签→衍生 |
| 背景故事/经历   | C: 背景入口 | "这段经历把她变成了什么样的人？"→ 经历→人格      |
| "不知道/帮我想" | D: 空白入口 | 24 问第一题，一次一问                  |
| "帮我看看这段"  | E: 校验入口 | 不启动引导，单点诊断                    |

所有入口最终汇入同一个追问引擎。追问引擎是通用的——不管从哪个门进来，追问方向（标签→行为→矛盾→为什么→绝对内核）是一样的。

### 依据

教程作者用这三种路径分别构建了成功的角色。路径不该由 skill 替用户选，应该由用户的初始状态决定。

## 未决事项

以下问题尚未讨论或尚未达成结论，留给下一阶段：

1. **快速路径的触发条件**：用户说"不用那么复杂，简单点"→ 切快速路径。但用户没明说的时候，skill 怎么判断她需要快速路径而不是完整追问？是在追问 3 轮用户仍只给简短回答后自动切换？还是主动问"你想深入一点还是快速一点"？——**待定。**

2. **追问循环的节奏控制**：连续追问几轮后暂停让用户整理？追问引擎是否有自我节制的机制？——**待定。** 这个在最新讨论中已有初步方向（连续两轮"不知道"切换入口，5 轮后暂停整理），但尚未固化为明确规则。

3. **收束后输出格式**：追问收束后，输出调色盘格式（底色/主色调/点缀+衍生）还是自然语言总结？取决于用户的下一步需求（"写下来给 AI 用"vs"我就是想理解她"），但这个判断 skill 怎么做出？主动问还是自动判断？——**待定。**

4. **worldbook-config 和 user-info-calibration 的详细设计**：目前只确定了它们的边界和触发场景，内部 RIA++ 六段尚未写。——**待阶段 2 处理。**

5. **三面性→多面性改名后，教程原文引用怎么处理**：教程原文写的是"三面性"，skill 内部用"多面性"，但引用原文时是否保留原词加注？——**待定。**
