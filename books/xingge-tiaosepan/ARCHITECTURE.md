> cangjie-skill 阶段 1.5 产出 · 待用户确认后进入阶段 2

## 一、核心设计原则

### 1.1 拆分维度：用户触发场景，不是教程章节

| 按教程章节拆（错误）                                     | 按触发场景拆（正确）                 |
| ---------------------------------------------- | -------------------------- |
| 调色盘 skill / 多面性 skill / 混色 skill / 核心人格层 skill | "帮我写角色"是一个场景，"配置世界书"是另一个场景 |
| 每个 skill 的 trigger 高度重叠，互相抢调用                  | trigger 天然互斥，B 段边界清晰       |
| 多面性和核心人格层几乎不会作为用户初始问题出现                        | 每个 skill 都对应一种用户实际会说的话     |

### 1.2 教程讲述顺序 ≠ 角色构建顺序

| 教程编号（讲述顺序）  | 在实际构建中的位置                    |
| ----------- | ---------------------------- |
| 0号：基础信息+世界观 | 可以在最前面（陈乖乖路径），也可以在最后面（姜糖路径）  |
| 1号：调色盘      | 不是第一步——调色盘是从追问中"长出来"的，不是用户填的 |
| 2号：多面性      | 追问过程中发现的，不是用户主动选的            |
| 4号：混色       | 追问到"颜色打架"时自然激活，不是独立步骤        |
| 7号：核心人格层    | 追问到"为什么选这条路"时激活，不是独立步骤       |
| 11号：小传/采访   | 可以完全替代调色盘体系——另一条路，同样的终点      |

### 1.3 方法论的"原子"在这里是什么

性格调色盘不是一本"多个并列方法论"的书。它的所有方法——调色盘→多面性→混色→核心人格层——是**同一个追问路径的不同深度**，不是可独立调用的工具箱。它们之间的关系是**深度递进**（depends-on），不是**并列选择**（contrasts-with）。

因此，cangjie-skill 的"原子性"原则在这里的适用方式是：**追问引擎是一个原子。** 拆开追问引擎，就像把"如何诊断一个病人"拆成"如何测体温""如何听心跳""如何问病史"——每个独立步骤离开了诊断上下文就没有意义。

## 三、内部模式激活条件（char-build-guide 追问引擎）

这些模式**不暴露给用户选择**，由追问引擎根据用户回答自动判断是否需要激活：

| 模式        | 激活条件（追问引擎的判断逻辑）                | 来自教程的哪个方法论          |
| --------- | ------------------------------ | ------------------- |
| **基础信息**  | 追问发现用户还说不清"她是谁"→ 优先确定身份        | 0号 / 11号第二章         |
| **调色盘**   | 用户已经有一堆标签/描述，需要翻译成行为画面         | 1号 / 大总结02          |
| **多面性**   | 追问发现 ≥2 个压力性质截然不同的场景下行为模式根本性切换 | 2号 / 大总结03          |
| **混色**    | 追问发现两种以上颜色在同一类场景中频繁"打架"        | 4号 / 大总结04          |
| **核心人格层** | 追问到了"为什么选这条路"但用户说不清底层逻辑        | 7号 / 大总结05          |
| **二次解释**  | 以上任一模式产出后，检查 AI 最容易误读的点        | 1号第四章 / 大总结06       |
| **意象**    | 追问接近尾声，用户需要一个总画面收束全部           | 6号 / 11号第六章 / 大总结07 |

**模式之间不是线性的。** 追问引擎可能在调色盘模式中发现多面性激活条件→跳到多面性模式→发现混色激活条件→跳到混色模式→回到调色盘继续追问→最后进入意象模式。这是**对话驱动的跳转**，不是**向导驱动的下一步**。

## 四、多入口路由逻辑

```
用户第一句话
    │
    ├── "我有一个画面/场景/瞬间"
    │   → 追问："描述那个画面。她在做什么？周围是什么？"
    │   → 从画面反推：这个画面里有什么颜色在跑？→ 调色盘模式
    │   → 参考路径：姜糖
    │
    ├── "她很温柔/自卑/傲娇/..."（标签）
    │   → 追问："你说的温柔，具体做什么的时候你能看出来？"
    │   → 从标签追问到衍生 → 调色盘模式
    │   → 参考路径：陈乖乖
    │
    ├── "她家里很穷/小时候被抛弃/..."（背景）
    │   → 追问："这段经历让她变成了什么样的人？"
    │   → 从经历追问到人格 → 调色盘模式
    │   → 参考路径：（教程中隐含路径）
    │
    ├── "我想写一个像xxx的角色"（参考）
    │   → 追问："那个角色让你印象最深的一个瞬间是什么？"
    │   → 从参考画面切入 → 追问"你的角色和那个角色的区别在哪？"
    │
    ├── "我不知道，帮我"（空白）
    │   → 24问急救模式
    │   → "先不管格式。闭上眼，有没有一个画面让你想写她？"
    │   → 如果仍然没有 → 从基础信息填表开始
    │
    └── "帮我看看这段写得对不对"（校验）
       → 校验模式，不启动完整引导流程
```

## 五、与其他两个 skill 的路由关系

```
char-build-guide 追问过程中：

    "世界观怎么写？"
    → 判断：真实背景？小世界？大世界？
    → 如果是简单 AB 类 → char-build-guide 内部处理
    → 如果是复杂 C 类（多区域多势力多NPC）→ 路由到 worldbook-config

    "写好了，怎么配置世界书？"
    → 路由到 worldbook-config

    "AI老是误解我的行为"
    → 路由到 user-info-calibration
    （这个可能在构建角色阶段出现，也可能在测试角色阶段出现）
```

## 六、为什么是 3 个而不是 6 个或 1 个

| 数量      | 会出现什么问题                                                                                                                       |
| ------- | ----------------------------------------------------------------------------------------------------------------------------- |
| **1 个** | A2 trigger 太宽，description 无法精确描述何时调用。B 段不存在（因为"什么都在范围内"）。违反 cangjie-skill 的 A2/B 质量红线。                                        |
| **6 个** | 多面性、混色、核心人格层的 trigger 在真实对话中几乎不会作为初始入口出现。用户不会说"帮我激活多面性模式"。过度原子化导致虚假链接（关系数 >25）。                                               |
| **3 个** | 每个 skill 有独立且互斥的 trigger。char-build-guide 的"大"是合理的——因为追问引擎本质上是一个不可分割的诊断系统。worldbook-config 和 user-info-calibration 的独立触发场景清晰。 |

## 七、命名的关键修正

| 旧称  | 新称      | 原因                                    |
| --- | ------- | ------------------------------------- |
| 三面性 | **多面性** | 面的数量由角色决定，两面、三面、四面皆可。旧称容易误导为"必须拆三张面"。 |
| —   | —       | 其余命名保持不变                              |

## 八、质量红线自检

- [ ] 每个 skill 的 trigger 是否都有**独立的、互斥的**用户语言信号？→ ✅
- [ ] 每个 skill 的 B 段是否天然互斥、形成路由？→ ✅（char-build-guide 不负责技术配置；worldbook-config 不负责写内容；user-info-calibration 不负责写角色）
- [ ] 是否存在"用户永远不会主动说"的 trigger？→ ✅ 已消除（多面性/混色/核心人格层不再作为独立 skill）
- [ ] 是否过度原子化导致虚假链接？→ ✅ 3 个 skill，关系数 <8，符合 cangjie-skill 的节制原则
- [ ] 原子性能否经受"同一本书拆出独立的单元"检验？→ ✅ 追问引擎是一个不可分割的诊断单元；世界书配置和用户信息校准是两个独立的工具
