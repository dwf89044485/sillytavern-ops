## 二、各 Agent 完整产出

### Agent 1（全盘设计）

#### 触发场景（5 个）

1. **从零创建角色**：想写角色卡但不知道从哪里下手
2. **标签型角色不立体**：已写一堆性格标签，但 AI 演出来拧巴——频道切换不融合
3. **角色行为不一致/OOC**：AI 演出来的和脑子里想的不一样，说不清哪里出问题
4. **画面/场景碎片待成型**：脑子里有一个具体画面，不知道怎么扩展成完整角色卡
5. **角色卡校验**：已经写好了一段角色卡，想让人帮忙看看写得对不对

#### 语言信号清单（15 条，覆盖 5 个入口）

**从零创建 / 空白入口：**
- "帮我写角色" / "帮我创建角色" / "我想写一个角色但不知道怎么下手"
- "帮我想想这个角色应该是什么样"
- "create a character" / "I want to make a character card but don't know where to start"

**标签不立体 / 标签入口：**
- "角色很平面" / "角色不够立体" / "角色太标签化了"
- "标签写了很多但 AI 演出来很拧巴"
- "character feels flat" / "character tags not working"

**OOC / 校验入口：**
- "角色总是 OOC" / "AI 演出来的和我想要的不一样" / "帮我看看这段角色卡写得对不对"
- "角色行为没有逻辑" / "她在不同场景下表现太割裂了"
- "my character keeps going OOC" / "can you check my character card"

**画面入口：**
- "我脑子里有个画面/场景，但不知道怎么变成角色"
- "我能想到她在一个具体场景里的样子，但说不清她是什么人"
- "I have a scene in mind but don't know how to turn it into a character"

**深化已有角色：**
- "怎么让角色更真实/更活" / "角色已经有了但想再深入一点"
- "how to make my character feel more alive"

#### 与相邻 skill 的区分

| 用户说的话 | 路由到 | 原因 |
|---|---|---|
| "世界书怎么配置""绿灯不触发""关键词怎么写" | worldbook-config | 技术配置问题，不是角色性格怎么写 |
| "AI 老误解我的行为""抓手腕被理解成强制" | user-info-calibration | AI 对**用户**行为的解读，不是对**角色**的演绎 |
| "模型很克制""台词写出来生硬" | dialogue-persona | 需要调色盘的**平级替代方案**，不是体系内部深化 |

三个关键边界判断规则：
- **char-build-guide vs worldbook-config**：内容创作 vs 技术配置
- **char-build-guide vs user-info-calibration**：AI 把**角色**演错了 vs AI 把**用户**理解错了
- **char-build-guide vs dialogue-persona**：最难切的边界。用户是否表达了"调色盘体系不适合我的情况"

#### Description 草稿

```
用户想创建或深化 AI 角色扮演的角色卡时激活——通过追问让用户自己发现角色，不输出模板。触发信号："帮我写角色""角色很平面/不够立体""标签写了很多但AI演出来拧巴""角色总是OOC""我有个画面但不知道怎么变成角色""帮我看看这段角色卡""create a character""character feels flat"。不适用于：世界书技术配置（蓝灯/绿灯/关键词→worldbook-config）、用户行为被AI误解（→user-info-calibration）、克制型模型需台词人设替代方案（→dialogue-persona）、纯信息查询。核心：苏格拉底式追问引擎，不替用户生成角色内容，通过提问让用户自己看见角色。
```
（约 270 字）

#### 设计理由（摘要）

- "追问引擎"必须在 description 中明示——这是与所有"角色卡写作助手"的根本区别
- 5 个入口的语言信号必须全覆盖——DESIGN_DECISIONS.md 只列了 3 个，漏了画面入口和校验入口
- "拧巴"是教程原文中柚子亲口说的词，精准指向标签不融合这个 char-build-guide 独有问题域
- 三个"不适用于"边界必须写进 description，否则用户说"世界书不触发"也会激活 char-build-guide
- 中英双写覆盖国际化社区
- 用户说"能让我 AI 帮我写吗"应触发 char-build-guide——教程里晴空妈妈接住并追问了

#### 质疑已有文档

> DESIGN_DECISIONS.md 决策 2 中的 trigger 信号（"帮我写角色""不知道怎么下手""角色很平面"）方向正确但不够完整。它只覆盖了空白入口和标签入口，漏掉了画面入口（"我有个画面"）、校验入口（"帮我看看这段"）和深化入口（"角色已经有了但想再深入"）。原决策是阶段 1.5 做的粗粒度验证，阶段 2 需要更细粒度。

### Agent 2（边界视角）

#### 不应触发的情况（文档未充分讨论的）

**灰色地带 1："AI 演得不对""角色不像"**
根因可能有四种——描述太平面（✓ char-build-guide）、世界书配置有问题（✗ worldbook-config）、AI 误解用户行为（✗ user-info-calibration）、台词风格不对（✗ dialogue-persona）。不应收录为裸 trigger，或极度窄化。

**灰色地带 2：用户问技术配置**
"这段放世界书还是放角色定义""token 太多了"——技术配置问题，不是角色构建。但措辞很像。

**灰色地带 3：用户在学习而非构建**
"什么是调色盘""多面性怎么理解"——知识查询。char-build-guide 不是知识手册。

**灰色地带 4：用户要求 AI 直接生成**
"帮我生成一个温柔的角色""给我写三个人设"——要输出，不是追问。与 char-build-guide "让用户自己发现" 定位冲突。

#### 容易误触发的热点

**热点 1："怎么写性格"**
意图可能三种：问方法、问配置、或真的需要引导构建。A2 不能收裸短语，只能收带上下文的措辞（"怎么写性格，不知道从哪下手"）。

**热点 2：char-creator 已存在**
char-creator 的 description 已覆盖 "create a character, design a persona, build a character card"。char-build-guide 必须在措辞上区分——char-creator 强调 "collaborator / build"，char-build-guide 应强调 "追问 / 碎片到完整 / 用户自己发现"。

**热点 3："角色"一词本身**
在 SillyTavern 语境下含义极广。A2 不能依赖"角色"作为信号锚点，必须搭配"不知道怎么下手""只有碎片""太平面"等状态词。

**热点 4："帮我看看"**
万能句式。校验入口的信号应窄化为"这段角色描述哪里不够""为什么她太纸片"——指向描述质量诊断。

#### A2 措辞建议

**强调：**
- "碎片"和"拼不出"的状态——char-build-guide 独有的触发空间
- "不知道怎么下手"的无力感——用户有意图但无方法
- "追问让用户自己发现"的机制——同时告诉 AI 工作方式和排除"直接生成"
- "平面/纸片"的质量诊断信号——不太可能与兄弟 skill 重叠

**避免：**
- "创建角色""设计人设""写角色卡"——char-creator 已占位
- "帮用户理解角色"——太模糊，会误触发知识查询
- "角色不像/演得不对"——根因不明确
- 裸"帮我看看"——万能句式
- 方法论术语（调色盘/多面性等）——决策 4 已明确不暴露

#### Description 草稿

```
用户想构建角色但不知道怎么下手时。她可能有碎片——一个画面、一堆标签、一段背景、或只有一个模糊感觉——但拼不出完整人物。典型信号："帮我写角色""不知道她该是什么样的人""角色太平面了""我只有一个画面/感觉""帮我把她变成活的角色""这段设定哪里不够"。通过追问让用户自己发现角色，不替用户生成、不输出方法论。不适用于：世界书配置、AI误解用户行为、给已有角色写台词/开场白、纯知识查询、要求直接生成角色设定。En: "build character from scratch" "character feels flat" "flesh out this character".
```
（约 260 字）

#### 与 Agent 1 的关键差异

Agent 2 的措辞**完全避开了 char-creator 已占位的短语**："帮我写角色" 保留了但通过 "不替用户生成" 区分；"创建角色""设计人设""写角色卡" 全部不出现。

### Agent 3（教程原文视角）

#### 从教程原文提取的 4 种真实触发模式

**模式 1：标签轰炸（柚子，01篇开头）**
> "晴空妈妈！我想写一个角色！我有好多想法！她特别可怜，特别善良，特别自卑……"

特征：一串 "特别XX""极度XX" + 背景脱口而出 + 直接表达"想写角色"。这是最典型的 char-build-guide 触发场景——用户有碎片但全是标签。

**模式 2：画面起点（姜糖作者，06篇）**
> "我脑子里最开始只有一个画面：一个丧尸老婆……她站在你面前，嘴张开了，本能在叫她咬，但她咧嘴笑了。"

特征：一句话描述一个完整场景。用户不是从标签开始，是从一个瞬间开始。这个入口在之前的设计文档中被忽略了。

**模式 3：背景脱口而出（柚子也有）**
> "她家里特别穷，妈妈生病了需要筹钱，然后她的同桌是个很烦人的富二代——"

特征：用户先想到的是故事/情境，而不是性格。这些背景需要被追问成"这段经历把她变成了什么样的人"。

**模式 4：空白迷茫（柚子，被晴空追问后）**
> "那我应该从哪里开始？"

特征：用户已经意识到自己之前的方法不对，但不知道正确的入口在哪。这通常是标签轰炸被追问后的自然结果。

**额外发现：三明月（11篇）路径完全不同**
> 作者从对角色的感性理解出发，用小传和采访替代调色盘。这是 char-build-guide 内部快速路径的触发原型——用户可能完全不需要调色盘术语。

#### Description 草稿

```
用户想创作或改进角色卡、但不知道怎么把模糊想法变成活生生的人时使用。典型场景：(1)带着一堆性格标签如"特别自卑、特别善良"不知如何深入；(2)脑子里有一个画面或场景但不知怎么展开成完整角色；(3)有背景故事但不知怎么转化为性格；(4)完全不知道从哪开始；(5)觉得已有角色"太标签""很假""不像活人"。触发词：写角色、创建角色卡、角色太平面、不知道怎么下手、怎么写性格、标签化、角色不够立体、create character、character card。不适用于：世界书/关键词配置（→worldbook-config）；AI误解用户自身行为（→user-info-calibration）；纯知识查询如"调色盘是什么"。
```
（约 240 字）

#### 语言信号清单（14 条）

**意图表达类：**
1. "我想写一个角色" / "帮我写个角色卡" / "我想创建一个角色"
2. "I want to create a character" / "help me write a character card"

**标签轰炸类（柚子模式）：**
3. "她特别可怜，特别善良，特别自卑" — 一串"特别XX"/"极度XX"
4. `性格: ["自卑", "善良", "坚韧"]` — 直接贴出标签数组
5. "我已经写了一些标签，怎么往下深入"

**画面起点类（姜糖模式）：**
6. "我脑子里有一个画面：她……" — 描述具体场景或动作
7. "我想到一个场景，她在做XX" — 从一个瞬间切入

**背景故事类：**
8. "她家里很穷，妈妈生病了" — 背景经历脱口而出
9. "我有她的背景故事，但不知道怎么变成性格"

**空白/迷茫类（柚子"那我该从哪里开始"）：**
10. "不知道从哪里开始" / "不知道怎么下手"
11. "我有好多想法但不知道怎么组织" / "想法很乱"

**质量诊断/校验类：**
12. "为什么我的角色很假/很平面/不像活人" / "角色不够立体"
13. "AI演出来的角色和我想要的不一样" / "感觉太标签化了"
14. "帮我看看这段角色设定写得怎么样"

#### 关于"帮我生成/扩写"的不同立场

> "帮我生成/扩写"这类信号不应被排除在 A2 之外，而应被拦截并转为追问。柚子在 02 篇问"那我能让 AI 帮我写衍生吗？"时，晴空妈妈的回答不是"好的我帮你写"，而是解释了为什么必须用户自己想，然后继续追问。这意味着这恰恰是 char-build-guide 应该接住的场景。
