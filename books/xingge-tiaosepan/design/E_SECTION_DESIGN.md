> 本文档基于两轮共 7 个独立审查 agent 的分析 + 主流程的多轮讨论，沉淀 E 段的最终设计及全部决策理由。

## 一、E 段的核心矛盾

char-build-guide 是一个**追问引擎**，不是线性方法论。但 cangjie-skill 的 E 段模板要求 1-2-3 步骤 + 每步可判断的完成标准。

这个矛盾不能靠硬塞解决，也不能靠放弃模板解决。解法在 cangjie-skill 模板**自身的灵活性**里。

---

## 二、决策 1：E 段按"职责"切三步，不按追问深度或时间阶段

### 结论

```
步骤 1 — 入口与素材初始化
步骤 2 — 追问引擎循环
步骤 3 — 条件深化与收束组装
```

### 为什么不是其他维度

| 候选维度                 | 为什么不用                               |
| -------------------- | ----------------------------------- |
| 按时间阶段（开始→中间→结束）      | "中间"没有可判断的完成标准                      |
| 按追问深度（浅层→中层→深层）      | 追问是跳转的，不是单向下钻。用户可能从画面直接跳到矛盾再回到标签    |
| 按教程七层（调色盘→多面性→混色→……） | 教程编号是讲述顺序不是构建顺序。多面性和混色可能在调色盘完成前就被发现 |

### 为什么是职责

三步的职责天然互斥，完成标准锚定在不同类型的产出上：

- 步骤 1 完成 = 素材区有东西了（文档状态可检查）
- 步骤 2 完成 = 调色盘写定了（文档状态可检查） + 用户确认了
- 步骤 3 完成 = 全部文档组装验证通过（文档状态可检查）

三个步骤的"什么时候算做完"可以锚定在文档产物上，不需要判断用户的心理状态。

### 依据

- Agent A（方法论合规）："真正红线是动作性和可判断性，不是线性性"
- Agent C（第一轮）："步骤划分维度应该是职责——步骤 1 接住用户收素材，步骤 2 追问到底推演到行为，步骤 3 组装验证交付文档"
- Agent C（第二轮，轨迹 2 漏洞）：步骤 1 和步骤 2 在"用户只给标签"时会边界模糊，需要显式写清

## 决策 2：步骤 2 是循环步骤，内部用每轮决策表描述，不拆成编号子步骤

### 结论

步骤 2 的结构为：

```
2. **追问引擎循环**
   - 完成标准: [见决策 4]
   - 判停条件: 用户说"够了/先到这里" → 跳到步骤 3

   每轮操作（AI 内部执行，不输出给用户）:

   A. 读取用户最新回答，判断回答类型 → 匹配追问动作
   B. 检查模式切换条件（镜子→脚手架→推演）
   C. 检查退出条件（调色盘是否已写定）
   D. 将本轮确认的产出写入文档
```

### 为什么不用编号子步骤

Agent B（第一轮，格式约束）明确警告：

> 编号子步骤 (2a, 2b, 2c) 产生歧义——"2a 完成算步骤 2 完成吗？2b 和 2c 是顺序还是并行？"这是在步骤内部造了第二套控制流。

每轮决策表的本质是**查表**——"用户说了标签 → 查表 → 追问行为"——不是"先判断类型再选动作再追问"的线性序列。追问循环内部不存在顺序推进，只存在**每轮一次判断**。

### cangjie-skill 合规性

Agent A（方法论合规）确认：

> 步骤内部可以有子结构（决策表、检查清单、轮次描述）。模板约束的是步骤的粒度（必须有编号 + 完成标准），不是步骤内部的展开方式。

## 决策 3：步骤 1 的入口检测是"素材类型识别"而非"入口类型分类"

### 结论

```
步骤 1 动作：
  1. 听用户说完，不打断，不引导方向
  2. 识别用户给了哪些类型的素材（可多选）：
     - 行为切片（有场景+有动作）
     - 经历事件（背景、关键经历）
     - 标签（纯性格形容词）→ 暂存不入素材区，标记为待追问
     - 画面（场景描述但缺上下文）
     - 已有角色卡/设定 → 解析映射到素材区，标记标签化点
  3. 将所有非标签素材写入素材区
  4. 从信息密度最高的素材开始追问

完成标准：素材区有 ≥1 条非标签化记录
```

### 为什么不是"判断用户属于哪个入口类型"

Agent C（第二轮，轨迹 1）发现了关键漏洞：

> 步骤 1 的入口检测是分类逻辑而非并行处理逻辑。混合入口时 AI 可能纠结"到底从画面还是标签切入"。实际答案是：画面和标签都记，但从信息密度更高的素材开始追问。

用户经常同时带来画面和标签（"她站在天台上，是很累的那种人"），或者同时带来背景和标签。把入口做成互斥分类会让 AI 在混合输入时犹豫。

### 步骤 1 完成标准未满足时的处理

Agent C（第二轮，轨迹 2）：用户只给标签时，素材区为空。需要显式写清：

> 步骤 1 完成标准未满足 → 在步骤 1 内继续追问（使用步骤 2 的追问动作集），直到拿到第一条非标签化记录后再进入步骤 2。

## 决策 4：完成标准锚定文档产物，不锚定用户心理

### 结论

| 步骤   | 完成标准                                                                | 为什么可判断            |
| ---- | ------------------------------------------------------------------- | ----------------- |
| 步骤 1 | 素材区有 ≥1 条非标签化记录（行为切片或经历事件，包含具体场景+具体动作）                              | 检查文档内容。要么有，要么没有   |
| 步骤 2 | 底色+主色调+点缀已命名且用户给出确认信号（见下）；每色 ≥3 条衍生，每条通过合格标准检查（显式包含场景+动作，无形容词，无解释词） | 数条数+查格式+用户确认信号可观察 |
| 步骤 3 | 文档已组装 + 一致性验证通过（性格不打架/衍生不矛盾/语料不混用/防御机制落到行为）+ 意象已探索或跳过               | 全是对文档内容的结构检查      |

### 用户确认信号的严格定义

Agent B（第二轮）给出了可直接采纳的定义：

| 类型        | 可观察特征                     | 示例                   | 算确认      |
| --------- | ------------------------- | -------------------- | -------- |
| **正面认可**  | 用户用肯定词回应，且回应指向 AI 展示的具体内容 | "对，就是这种""嗯没错"        | ✅        |
| **补充确认**  | 认可基础上追加细节，细节不推翻核心         | "对，而且她还会 XX"         | ✅        |
| **修正确认**  | 否定部分但确认主体，给出修正方向          | "大体对，但她不会 XX，她更像 YY" | ✅（修正后写入） |
| **沉默不反对** | 用户没有认可也没有反对，继续往下说         |                      | ❌ 不算     |
| **模糊敷衍**  | "行吧""嗯""随便""你看着办"         |                      | ❌ 不算     |
| **诱导性确认** | AI 问"她是不是有点 XX？"用户说"对"    |                      | ❌ 不算     |

防作弊规则：

- 确认前必须展示具体的行为级内容（不是抽象总结）
- 禁止诱导性提问（"她是不是缺乏安全感？"）
- 敷衍信号触发追问："我拿不准——是'对了'还是'还行'？哪里偏了吗？"

### "用户说够了就停"优先于"框架说完整"

Agent C（第一轮）明确提出并被所有审查接受：

> 角色创作的主权在用户。用户在任何节点说"够了/先这样/我想看看效果"→ 立即收束当前层。不替用户决定"你应该再深挖"。

## 决策 5：MVC 决策点——追问循环的节奏控制器

### 结论

调色盘 + 第一轮二次解释完成后，触发 MVC 决策点：

```
MVC 决策点触发条件：
  1. 三色命名已确认
  2. 每色 ≥3 条衍生通过合格标准
  3. 第一轮二次解释已生成

MVC 决策点告知内容：
  "调色盘 + 基本防误读已经够了——角色现在就能跑起来。
   接下来可以继续深化：多面性（如果她在不同场景像两个人）、
   混色（如果有些瞬间说不清是哪种情绪）、核心人格层（挖掘她为什么做这些选择）。
   你想继续深化，还是先这样？"

→ 用户选继续 → 检查多面性/混色/核心人格层触发条件，逐一激活
→ 用户选停止 → 跳到步骤 3 收束
```

### 为什么需要 MVC

Agent A（第一轮，结构分析）首次提出："追问循环每完成一层，主动向用户汇报'现在到哪了、接下来能做什么、你想继续还是停'"。

Agent B（第二轮）指出 MVC 标准在候选列表中缺失，补全了触发条件。

MVC 的核心价值：**让追问有节奏。** 不是闷头狂问直到用户累了，而是每个里程碑暂停，让用户决定下一步。

### MVC 的双重触发（补充）

除上述文档状态检查外，**用户可能在 AI 展示调色盘之前就自然说出"我觉得她就是这样的人了""我好像知道了"等信号。** 此时应优先响应用户信号：

```
用户自然表达"我知道了/差不多清楚了" →
  追问确认："你是觉得已经清楚了，还是想继续往下挖？"
  → 用户确认已清楚 → 直接进入收束（跳过文档状态检查，不强行走 MVC 展示流程）
  → 用户说"继续"   → 继续追问，不做 MVC 暂停
```

原则：用户自己觉得够了 > 框架说够了。文档状态检查是兜底（用户没有主动喊停时的安全网），不是前置。

## 决策 6：降级链条——镜子→脚手架→推演→溯源→降级路径

### 结论

步骤 2 内部的模式切换条件（从 Agent C 第二轮轨迹 2 的漏洞分析中修正）：

```
镜子模式（默认）：
  "你觉得是为什么？"——追问，不提示方向
  切换条件：最近 3 轮追问没有产出新的行为场景或关系细节
  → 进入脚手架模式

脚手架模式：
  "让我换个方式——我猜一个方向你看对不对"
  从已确认素材推演 1 个候选方向，让用户判断
  切换条件：2 次试探被否，且用户给不出方向词
  → 进入推演模式

推演模式：
  从 ≥2 个独立视角各推 1 条候选，标注行为场景 + 依据，用户裁决
  切换条件：用户全部否决
  → 溯源："哪里偏了？一个词就行"
  → 如果用户说不出偏在哪 → 暴露理解："我现在的理解是……是这里出了偏差吗？"
  → 如果仍然无法推进 → 降级

降级：
  跳过当前维度，标记为留空
  如果多个维度连续降级 → 切换到快速路径（基础信息→小传→采访→情绪阈值→意象）
  不挖核心人格层、不拆多面性
```

### 为什么不是固定轮数

Agent C 第二轮轨迹 2 的漏洞：

> 降级触发条件应该是"产出质量下降"而非仅"用户说不知道"。用户从没说不知道，一直在回答，只是回答越来越薄。用固定轮数会错过这种情况。

旧方案只写了"不知道→脚手架"，覆盖不了"用户在回答但没产出"的场景。

## 决策 6.1：降级链条的根因诊断——按用户认知阶段区分卡住类型

### 结论

决策 6 的降级链条解决的是"追问工具升级"（用什么方式追问），但缺少对"卡住根因"的诊断。用户在不同认知阶段卡住，需要的处理完全不同：

| 用户所处阶段 | 卡住的本质 | 处理方式 |
|------------|-----------|---------|
| **物化阶段**（还没有画面） | "我没有素材"——脑子里有东西但说不出来，或真的还没有角色 | 场景引导激发：给具体钩子（"闭上眼第一秒看到什么"），不是追问。≥3 轮场景引导无产出 → 诚实告知局限 |
| **展开阶段**（画面不够多） | "我有素材但挖不动了"——在同一个方向被反复追问，回答越来越薄 | 换切面：正面→反面→侧面→关系面。不是升级追问工具，是换追问方向 |
| **收敛阶段**（看不出规律） | "素材够了但看不出共性"——行为之间模式不明显 | 帮用户回看已有素材，逐条念出，问"这里面有没有什么感觉是共通的"。不是继续追问而是回看整理 |
| **穿透阶段**（说不出为什么） | "说不清动机"——好奇心到了但认知没到 | 追问 1-2 次。仍说不出 → 正常降级，不是失败。"她为什么这样做你可能还没想清楚——角色现在跑起来已经够了" |

### 与决策 6 的关系

决策 6 的降级链条是**通用追问工具升级**（适用所有阶段的追问卡壳），决策 6.1 是**根因诊断**（判断用户在哪个阶段、卡住的本质是什么）。两者配合使用：

- 先诊断阶段 → 决定处理策略（场景引导 / 换切面 / 回看整理 / 正常降级）
- 在处理策略内卡壳 → 使用决策 6 的链条（镜子→脚手架→推演→降级）

## 决策 7：方向变更处理——允许回到步骤 1

### 结论

用户可能中途推翻整体方向（"不对，她不是病娇，她是表面冷但其实关心人"）。E 段需要显式处理：

```
用户推翻整体方向：
  1. 确认旧素材是否保留（"你之前说的跟踪、偷看手机——她还是会做这些事吗？"）
  2. 清除旧方向的构建区内容（颜色候选、衍生、二次解释）
  3. 保留用户确认仍属于角色的素材
  4. 回到步骤 1 重新初始化

用户推翻的不只是单条追问而是整体方向时：
  不适用脚手架/推演降级——这是方向变更，不是卡壳
```

### 为什么需要

Agent C 第二轮轨迹 4：3 步结构是线性的（1→2→3），没有迭代环。用户改主意时，skill 不知道能不能回到步骤 1。

## 决策 8：矛盾路由区分——跨场景矛盾 vs 同瞬间矛盾

### 结论

步骤 2 发现矛盾时，先追问画面，再判断类型：

```
矛盾追问 → 拿到具体画面 → 判断类型：

跨场景矛盾（对 A 温柔，对 B 凶）：
  → 标记为"多面性线索"
  → 继续当前追问方向
  → 步骤 3 统一激活多面性

同瞬间矛盾（骂的同时后悔）：
  → 当场追问混色画面："那个瞬间她具体做了什么？"
  → 如果用户给不出 → 标记为"混色线索"，步骤 3 处理
```

### 为什么需要

Agent C 第二轮轨迹 3：3 步结构把所有矛盾都路由到"混色追问"，但"对谁都好 vs 对妹妹凶"是跨场景的，应该路由到多面性。"骂完又后悔"才是同瞬间的，应该路由到混色。

## 决策 9：步骤 2 每一步判停与方向切换的第二层判断

除了三步的完成标准，追问循环内部还需要**每轮的方向判断**：

### 追问判停（单条追问够了）

```
当前追问方向判停：
  用户给出了一个画面/行为描述
  AND
  这个画面能回答"她在什么场景下做了什么"（有场景 + 有动作）
  AND
  和已有素材不重复（换措辞不算新）
→ 这条追问结束，换下一个方向
```

### 方向枯竭判断

```
当前追问方向枯竭：
  最近 2-3 轮追问用户没有产出新的行为场景或关系细节
  （用户可能一直在用不同措辞说同一件事）
→ 换切面：从正面转反面 / 从反面转侧面 / 从侧面转关系面
  不在同一枯竭方向继续挖
```

## 决策 9.1：三层判停框架——性质不同，不能混淆

### 结论

E 段的判停点分布在三个层级，性质完全不同：

| 层级 | 作用域 | 判的是什么 | 回跳方向 | 对应决策 |
|------|--------|-----------|---------|---------|
| **步骤级判停** | 步骤间大跳转 | 整体方向对不对 | 方向错→回步骤 1；用户喊停→跳步骤 3 | 决策 7 |
| **轮次级判停** | 步骤 2 循环内每轮微调 | 这条方向够不够了 | 够→换方向；枯竭→换切面；卡住→升级模式 | 决策 6、决策 9 |
| **里程碑判停** | MVC 暂停 | 此时该不该问用户 | 达到里程碑→暂停展示进度，让用户选择 | 决策 5 |

三层判停互不干扰：轮次级在步骤 2 内部持续运行（每轮一次），满足 MVC 条件后走里程碑判停，用户推翻方向时走步骤级判停。AI 在追问中先走轮次级，依次检查更高级别，不会同时触发多个层级。

## 决策 10：E 段变形边界——哪些可以变，哪些绝对不能变

### 可以变的

| 维度     | 怎么变                                    | cangjie 依据                           |
| ------ | -------------------------------------- | ------------------------------------ |
| 步骤内部结构 | 每步内部展开决策表、检查清单、每轮操作描述                  | 模板未禁止子结构                             |

## 三、E 段最终设计骨架

```markdown
## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行:

### 1. 入口与素材初始化

**动作**:
- 听用户说完，不打断，不引导方向
- 识别用户给了哪些类型的素材（可多选）：
  行为切片 / 经历事件 / 标签 / 画面 / 已有角色卡
- 将非标签素材写入素材区对应位置
- 标签暂存不入素材区，标记为待追问
- 如果用户有现成角色卡 → 解析全部内容，映射到素材区，标记标签化点
- 从信息密度最高的素材开始第一轮追问

**完成标准**: 素材区有 ≥1 条非标签化记录
（行为切片或经历事件，格式：包含具体场景 + 具体动作）

**标准未满足时**: 在步骤 1 内继续追问（使用步骤 2 的追问动作集），
直到拿到第一条非标签化记录后再进入步骤 2

### 2. 追问引擎循环

**完成标准**:
- 底色 + 主色调 + 点缀色的命名已展示给用户
- 用户给出了确认信号（见 §用户确认信号定义）
- 每色 ≥3 条衍生，每条通过合格标准检查：
  显式包含场景 + 动作，无纯形容词，无解释词
- 第一轮二次解释已生成

**判停条件**: 用户在任何时候说"够了/先到这里/我想看看效果"
→ 跳到步骤 3 收束

**每轮操作**（AI 内部执行）:

A. 读取用户最新回答，判断类型 → 匹配追问动作:

| 用户说了什么 | 追问动作 | 目标 |
|------------|---------|------|
| 标签/抽象描述 | 追问具体画面："在什么场景下能看到？她当时在做什么？" | 标签 → 行为 |
| 行为但不够独特 | 追问只有她才有的细节："有没有只有她才会这样做的地方？" | 通用行为 → 独有画面 |
| 两个以上一致描述 | 追问反面："有没有哪个时刻她表现得完全相反？" | 找矛盾 |
| 发现了矛盾 | 先追问画面，再判断类型：跨场景矛盾 → 标记多面性线索；同瞬间矛盾 → 当场追问混色画面 | 区分矛盾类型 |
| "不知道"/答不上来 | 换一个更具体的角度追问；连续 2 轮 → 启动脚手架 | 不逼问，换路走 |
| 已回答了足够画面 | 追问底层常量："这些里面，哪个是无论什么场景都在的？" | 提取底色 |

B. 检查模式切换:
- 镜子模式（默认）：追问但不提示方向
  切换条件：最近 3 轮无新行为场景或关系细节 → 脚手架
- 脚手架模式：从已确认素材推演 1 个候选方向，用户判断
  切换条件：2 次试探被否，用户给不出方向词 → 推演
- 推演模式：从 ≥2 个视角各推 1 条候选，用户裁决
  切换条件：用户全部否决 → 溯源；仍无法推进 → 降级（留空，切换维度）

C. 检查退出条件:
- 底色+主色+点缀能从素材中提取且有用户确认
- 每色有 ≥3 条行为级衍生 → 触发 MVC 决策点
- MVC 后用户选继续 → 检查多面性/混色/核心人格层触发条件（步骤 3）

D. 将本轮确认的产出写入文档对应位置

### 3. 条件深化与收束组装

**动作**:
- MVC 决策点：告知"到哪了/能干嘛/下一步"，用户决定继续或收束
- 用户选继续 → 依次检查触发条件：
  - 多面性：素材指向 ≥2 个压力性质截然不同的场景下行为模式根本性切换 → 拆面
  - 混色：两种以上颜色在同一场景频繁碰撞 → 写画面
  - 核心人格层：有剧情驱动 + 内部矛盾 + 能追问到"为什么选这条路" → 挖七层
- 每层完成后追加对应二次解释
- 快速路径（降级时）：跳过条件深化，走 基础信息→小传→采访→情绪阈值→意象
- 方向变更处理：用户推翻整体方向 → 确认旧素材保留 → 清除构建区 → 回到步骤 1
- 组装收束：一致性验证 + 意象探索 + 最终二次解释

**完成标准**:
- 文档已按呈现顺序组装
- 一致性验证通过：性格不打架 / 衍生不矛盾 / 语料不混用 / 防御机制落到行为
- 意象已探索（找到或用户跳过均有记录）
- 第二轮二次解释已追加

**判停条件**: 用户在任何节点说"够了/先这样/我想看看效果"
→ 立即跳到收束组装，不替用户决定是否继续深化
```

## 四、用户确认信号定义（E 段 § 参考）

确认信号 = 用户对 AI 展示的具体行为级内容，给出以下任一回应：

- **正面认可** ✅：用户用肯定词回应具体内容（"对""没错""就是这样"）
- **补充确认** ✅：认可基础上追加细节，细节不推翻核心
- **修正确认** ✅：否定部分但确认主体，给出修正方向
- **沉默不反对** ❌ 不算
- **模糊敷衍** ❌ 不算（"行吧""嗯""随便"）
- **诱导性确认** ❌ 不算（AI 问"她是不是有点 XX？"用户说"对"）

防作弊规则：

1. 确认前必须展示具体的行为级内容
2. 禁止诱导性提问
3. 敷衍信号 → 追问"是'对了'还是'还行'？哪里偏了吗？"

## 五、设计原则总结

1. **1-2-3 是骨架，不是牢笼。** 每一步是"职责阶段"，有独立的完成标准和退出条件。阶段内部可以是循环、决策表、多层子结构。

2. **完成标准锚定在 AI 能检查的东西上。** 文档里有没有记录、有几条、格式对不对。不锚定在"用户想清楚了没""角色立体了没"。

3. **循环不是无序。** 追问有方向（标签→行为→矛盾→为什么→不变内核），每次只追一个方向。方向枯竭→换切面。深度不够→升级模式。深度够了→MVC 暂停。

4. **用户主权不可侵犯。** 确认信号严格定义（敷衍不算）。用户说停就停。用户改方向就回头。推演永远提案，用户永远裁决。

5. **降级不是失败。** 用户答不出→脚手架→推演→溯源→降级留空→快速路径收束。一个没有核心人格层的角色，靠调色盘+二次解释+意象，依然远比七个标签强。
