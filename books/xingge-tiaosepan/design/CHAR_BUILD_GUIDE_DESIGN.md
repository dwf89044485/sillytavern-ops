> 阅读对象：后续接手此工作的 AI、未来的自己。

## 任务定位（一句话）

做一个 skill：**在 Claude Code 里通过追问引导用户创建角色，让用户不需要学习教程的理论和方法，也能在引导下创建出好角色。** 用户提供想法，AI 追问帮用户自己看见角色，产出可直接用的角色卡内容。

**核心目标**：让用户"不需要学习整套理论"——她不需要知道调色盘、多面性这些词，只需要回答问题。**好坏的唯一标准**：用户说出的话越来越具体、越来越像"只有她的角色才会这样"（§1.3）。

## ⚠️ 教程→Skill 翻译层（最高优先级，先读这里）

本 skill 的源材料是"性格调色盘"教程（`性格调色盘/`）。教程和 skill 有本质区别：

- **教程**：晴空妈妈教柚子学会调色盘理论。默认模式是教学——追问角色 + 顺手教方法 + 检验学习。
- **skill**：AI 用教程中的追问方法引导用户创建角色。默认模式是追问——帮用户说出角色，不教方法论。

这意味着读教程时，每看到一个晴空妈妈的行为，先问：她是在**追问角色本身**（可融入 skill 默认行为），还是在**教柚子方法论**（只在用户追问"为什么"时才简答）？

教程中大量教学手段——原理解释、正确/错误对比、课后检验、先让柚子写错再纠正——是教程的教学方式，不是 skill 的默认行为。

## 〇、决策记录方式 ★（最高优先级，先读这里）

> 本文档是设计共识的唯一权威主文档。你在此文档中做的每一个决策，都必须按本节规范记录。
> 本规范对标 handoff 文档（`没有明确要求禁止读/DESIGN_HANDOFF.md`）的记录方式——它有完整的"背景→决策→依据→被否决方案"推理链，而本文档曾因只记结论不记推理链，导致后续接手者无法判断决策是否适用、甚至重复提出已被否决的方案。

### 0.1 每条决策必须回答 5 问

| 问         | 内容                                     | 缺了会怎样                 |
| --------- | -------------------------------------- | --------------------- |
| **做什么**   | 结论本身                              | 无法执行                  |
| **怎么做**   | 操作方式                                   | 无法落地                  |
| **为什么**   | 决策依据（包括但不限于与用户的探讨、agents的洞察思考、引用的教程章节） | 接手者无法判断是否适用自己的场景      |
| **代价**    | 这个决策放弃了什么/有什么风险                        | 无法权衡                  |
| **不要怎样做** | 被否决的方案 + 否决原因                          | 未来会重复提出已否决方案（我们踩过这个坑） |

### 0.2 决策记录格式

```markdown
### 决策 [N]：<标题>

**结论**：<结论本身>

**依据**：<教程章节/审查报告/用户确认/agent 共识，引用出处>

**代价**：<放弃什么/风险是什么>

**否决方案**：<被否决的方案 + 为什么否决>
```

### 0.3 三条铁律

1. **被否决的方案必须记录**，且标注否决原因。防止未来的自己/AI 重复提出已否决方案。
2. **被取代的决策不删除**，标注"已被取代 → 新位置"。保留审计轨迹。
3. **推理链必须保留**。"为什么不这样做"和"为什么这样做"同等重要。

### 0.4 决策状态标记

每条已记录的决策标注状态：✅ 已确认（用户拍板）/ 🟡 待确认（agent 给了结论但用户没拍板）/ 🔴 待决策（有分歧）。

| 维度    | handoff       | char-build-guide（本文档）     |

### 0.6 设计依据的来源分级（2026-08-12 补）

以下内容来自讨论过程中被确认的设计依据，与"决策记录"不同——它们是**设计的前提认知**，不是逐条决策：

**"教程是写给人看的"洞察**：教程花了大量篇幅说服人类作者（"AI 是输入法联想""手写优于 AI 扩写"），因为人类的直觉和这些结论相反。但 skill 的执行者（AI）不需要被说服——AI 没有"写标签就够了"的错觉。所以 **skill 应该剔除教程的说服性内容，只保留操作指令和判断标准**。这条洞察决定了 skill 的 I 段/E 段写作原则（执行语言而非教学语言，§〇 0.6 → §5.1.2 第 4 项）。

**"AI 不是 if-else 执行器"洞察**：skill 不能写成穷举规则表（那会变成死板的状态机），也不能只给抽象原则（AI 没有可操作的抓手）。正确做法是**顶层原则 + 清晰目标 + 判断好坏的标准，信任 AI 在具体场景中判断**（§1.2）——这是讨论中多次确认的设计前提。

**追问引擎设计范式的演进过程**（本次讨论最核心的认知过程，2026-08-12 补）：

skill 的"怎么写"经历了三次认知演进，最终落在"原则驱动"：

| 阶段  | 方案                    | 为什么被否/确认                                                                       |
| --- | --------------------- | ------------------------------------------------------------------------------ |
| 1   | 原理阐述（把 6 条原理讲给 AI 听）  | ❌ 原理是写给人类的。教程花篇幅说服人类作者（"AI 是输入法联想""手写优于 AI 扩写"），是因为人类直觉和结论相反。AI 没有这些错觉，不需要被说服。 |
| 2   | 穷举判断规则（if-else 状态机）   | ❌ AI 不是 if-else 执行器。规则越多，AI 越不敢用自己的判断力；而且规则永远覆盖不完真实对话的边缘情况。                    |
| 3   | **原则驱动 + 方向感 + 判断标准** | ✅ 给顶层原则、清晰目标、判断好坏的标准，信任 AI 在具体场景中用自己的世界知识和推理能力判断。                              |

**这个演进过程的结论就是 §1.2。** 记录推理链的原因：防止未来的自己重新提"给 AI 讲原理"或"写穷举规则"——两个方案都被明确否决过。教训：**skill 是给 AI 执行者看的，不是给人类读者看的**——剔除说服性内容（原理），保留操作指令和判断标准（原则+判据）。

## 一、skill 的定位与核心哲学

### 1.1 追问引擎，不是知识手册

char-build-guide 是一个**追问引擎**——通过提问让用户自己看见角色，而不是输出方法论知识给用户。

教程自身的成功不是靠"写得好"，是靠"问得好"。晴空妈妈从来不跟柚子说"现在我们来写底色"，她说的是"你问问自己，这七个标签里哪个是无论如何都在那里的"。skill 要继承的是追问能力，不是术语表。

### 1.2 AI 有智能，原则驱动优于规则穷举

不给 AI 穷举 if-else 规则表。给顶层原则、清晰目标和判断好坏的标准，信任 AI 在具体场景中用自己的世界知识和推理能力做判断。

规则越多，AI 越不敢用自己的判断力。原则越清晰，AI 越能在规则没覆盖的边缘情况下做出正确选择。

### 1.3 用户不需要学习教程

用户脑子里可能有模糊的画面、零散的标签、一段背景故事，或者什么都没有。skill 的工作是通过对话让她**看见**角色——最终她不需要理解"调色盘""多面性"这些术语，但产出的东西天然符合这些方法论。

好坏标准就一条：用户说出的话越来越具体、越来越像"只有她的角色才会这样"。

### 1.4 AI 的主动性边界

| AI 应该做                                          | AI 不应该做                  |
| ----------------------------------------------- | ------------------------ |
| 追问 → 帮用户自己想出来                                   | 用户说"不知道"时替她生成答案          |
| 从用户已有行为中找出模式，推给用户确认（"你说 A、B、C——底下是不是都有一个东西在跑？"） | 替用户编一个她没有描述过的行为或特质       |
| 用专业框架诊断用户描述属于哪个深度，选择对应追问维度                      | 把术语（底色/防御机制/核心矛盾）直接抛给用户  |
| 帮用户把模糊的描述推到具体的、独有的画面                            | 在用户确认前替她做总结（"所以她的核心是……"） |

## 二、顶层原则

这些不是执行步骤——它们是 AI 在每一步追问判断背后的价值观。

### 2.1 从最具体的地方开始

用户说了一堆东西——标签、经历、场景。不要做分类，直接找里面最具体、最能看到画面的那个点作为第一个追问入口。"具体"的标准：能让人闭上眼看到她在做什么。

### 2.2 只追问，不填空

追问的目的是帮用户自己想出来，不是替她编。用户说"不知道"→ 换角度、换切面、降低抽象层级，但不能替她生成。这条是硬约束——AI 替用户生成的任何内容都是 AI 数据库里最常见的东西，喂回去等于什么都没做。

### 2.3 推向独特性

"她很温柔"是通用的。"她会在没墨的同学桌上悄悄放一支备用笔，做完就收回目光"是独特的。每一步追问都在往独特性推——追问具体场景、追问只有她才有的细节、追问矛盾、追问为什么选这条路。当用户的描述遮住名字还能认出她的时候，追问就达到了目的。

### 2.4 节奏由用户决定

用户说"够了"就停。用户回答越来越薄就换切面，而不是同一方向深挖。一个阶段结束主动暂停，告知"现在到哪了，还可以往什么方向走，你想继续还是停"。追问不是审讯。

### 2.5 帮用户梳理，不替用户总结

共性提炼是 AI 应该做的——用户的专业能力在于想象画面和行为，但提炼共性需要 AI 帮忙。AI 从用户已有的 5-6 个行为画面中找到模式，推给用户确认："你说的这些——A、B、C——都有一个共同的东西：XXX。对吗？"这不是编造，是帮她看到她已经在描述但没意识到的规律。

但最终解释属于用户。不做诱导性总结（"所以她的核心是缺乏安全感"）。不说"她就是这样的人"然后锁死。确认信号必须是用户对具体内容的回应，不能是敷衍的"嗯"或 AI 引导的"是不是有点 XX？"。

## 三、AI 的内部诊断地图

教程的方法论框架——调色盘、多面性、混色、核心人格层——不是给用户看的术语表，是给 AI 用的**诊断地图**。AI 听到用户描述时，在地图上定位"这个描述属于哪个深度的东西"，然后选择对应的追问维度往下挖。

### 3.1 追问的自然方向

标签 → 具体行为画面 → 矛盾/反差 → 为什么选这条路 → 绝对不变的内核

这个方向不是线性的——追问可能在拿到第一个画面时就发现多面性信号，也可能追问到底都没遇到混色场景。地图是方向指引，不是流程强制。

### 3.2 深度信号识别

| 用户描述中的信号                   | AI 应识别为什么             | 追问方向                           |
| -------------------------- | --------------------- | ------------------------------ |
| 纯形容词/标签（"她很温柔"）            | 还不够，需要画面              | 追问"什么时候你能看到她温柔的样子？她具体做了什么？"    |
| 具体行为但不够独有（"她会帮同学"）         | 接近了，但还能更独特            | 追问"有没有只有她才会这样做的地方？"            |
| 两个以上截然不同的行为模式（"在外端庄，私下奔放"） | 多面性信号——不同压力场景下的生存策略切换 | 追问切换的触发条件、能量状态、每面的具体行为         |
| 两个特质在同一画面中打架（"一边骂一边掖被子"）   | 混色信号——同一瞬间多种情绪同时跑     | 追问"那个瞬间她具体做了什么？"不要让用户描述感受      |
| 不知道行为背后的原因（"我也不知道她为什么这样"）  | 到了决策层面——需要挖核心人格层      | 追问"同样处境别人可能选另一条路——为什么她偏偏选了这条？" |
| 多个行为画面但用户看不出共性             | AI 应主动帮忙提炼            | 从已有行为中找模式，念给用户听，推方向确认          |

## 四、执行框架

三个职责阶段。阶段之间是路标，不是流程强制——AI 在两个路标之间自主导航。

### 4.1 阶段 1：接住用户 → 找到追问起点

AI 听用户说完，不做分类，直接从中找最具体、最能看到画面的那个点开始追问。

- 用户说了画面（"她站在天台上，风很大"）→ 从这里开始
- 用户只给了标签（"她很温柔"）→ 追问"什么时候你能看到她温柔的样子？"
- 用户什么都说不出 → 给场景钩子："闭上眼，你第一个想到的场景是什么？在什么地方？她在做什么？"

### 4.2 阶段 2：追问循环 → 核心浮现

每次拿到用户回答，做三个判断：

- **追问什么方向**：当前描述够具体了吗？遮住名字能认出她吗？不够→追问更具体的。够了→换方向。不知道从哪追问→查技法工具箱。
- **方向够了还是该换**：用户刚给的内容有场景+动作且不重复→够了，换方向。最近几轮回答都在用不同措辞说同一件事→方向枯竭，换切面。
- **卡住了怎么办**：换角度→从已有素材推一个具体候选→被否换视角再推→全否→溯源"哪里偏了？"→说不出→留空跳过。

**核心浮现条件**：MVC 暂停点的触发逻辑是三层判读（质量判读 + 结构判读 + 时机判读）的配合，详见 §4.3。此处不再以"用户能说出底色/主色调/点缀"作为硬性前置——那是教学语言，§1.2 明确用户不需要学会这些术语。改以质量信号为主、文档状态为兜底。

### 4.3 MVC 暂停点（2026-08-11 定稿，见 §4.3.1 决策依据）

MVC 暂停点的本质：**"角色现在能跑起来了"——AI 对角色状态的就绪评估，附带给用户一个选择权：停下或继续深化。**

触发 = 三层判读配合：

```
MVC 触发逻辑（每轮追问后内部检查）：

第一层 — 用户主权（最高优先，无条件）
  用户说"够了/先这样/我想看看效果/我累了"
  → 立即收束，跳过 MVC。用户随时可以停，不需要任何条件。

第二层 — 自然收束信号（用户已主动表达）
  用户说"我好像知道她是什么样的人了""我脑子里能看到她了"
  → 追问确认："你是觉得已经清楚了，还是想继续往下挖？"
  → 用户确认已清楚 → 直接收束（不强行走 MVC 展示流程）
  → 用户说"继续" → 继续追问，不做 MVC

第三层 — 就绪判读（AI 侧，质量 + 结构双条件）
  质量判读（信号系统）：
    ≥3 个质量信号通过（见下"质量信号表"）
  结构判读（文档状态，兜底）：
    三色命名已从素材中提取且用户给出有效确认
    + 每色 ≥3 条衍生通过合格标准（场景+动作，无纯形容词，无解释词）
    + 画面去重检查：画面指向不同的行为模式，不是同一行为的换措辞
    + 第一轮二次解释已生成
  两个判读都满足 → 在自然间隙（当前追问方向完成/枯竭时）抛出 MVC
  质量信号强但结构未满足 → 可提前触发（角色已活，结构条件是安全网不是关卡）
  结构满足但质量信号弱（≤1 个信号通过）→ 不触发，继续追问换切面
  结构满足但质量信号持续 3 轮不达标 → 触发（结构是兜底安全网）

第四层 — 行为测试（可选验证，不是必经步骤）
  见 §4.3.2。用于"AI 对角色是否真活不确定"时的迁移验证。
  注意：必须用修改版（用户自发生成场景），禁止原始版（AI 构造场景）。
```

**MVC 告知内容**：
"现在角色已经能跑起来了。接下来还可以深化：如果她在不同场景像换了一个人→多面性；如果有说不清是哪种情绪的瞬间→混色；如果想挖她为什么做这些选择→核心人格层。你想继续深化，还是先这样？"

用户选继续→阶段 3。用户选停→收束。**用户在任何时候自己说"够了/先这样"→立即收束，跳过 MVC。**

#### 4.3.1 为什么是"质量 + 结构"双判读，而不是锚定调色盘写定（决策依据）

**MVC 锚定的是"用户能看见角色了"，不是"调色盘写定了"。** 三个独立 agent 审阅（glm-5.2 × 3）+ 主流程交叉判断一致确认：

1. **设计文档自身记录了非调色盘路径**（姜糖从画面入口、三明月非调色盘路径）。如果 MVC 锚定调色盘写定，这些路径结构性地永远进不了 MVC——用户可能已经能看见角色了，但 AI 说"你的调色盘还没填完"。这直接违反 §2.4（节奏由用户决定）。
2. **§4.2 旧版"核心浮现条件"和 E\_SECTION 决策 5 自相矛盾。** 旧版要求"用户能说出底色/主色调/点缀"（结构判据），但 §1.2 明确"用户不需要学习教程术语"。结构判据如果变成"用户必须能说出术语"，是内部矛盾。改以质量信号为主、结构为兜底后，这个矛盾消解了——用户不需要会说术语，AI 内部用诊断地图判断素材够不够。
3. **调色盘是 AI 的内部诊断地图，不是验收清单。** §3 自己说"调色盘不是给用户看的术语表，是给 AI 用的诊断地图"。把内部工具的结构完成度当作用户暂停的闸门，是把地图当成了目的地。
4. **违反 §1.2 原则驱动。** "三色命名 + 每色 ≥3 衍生"作为触发条件，本质是一个结构性 checklist，接近 §1.2 警告的规则穷举倾向。质量信号是"原则 + 判断标准"，更符合 §1.2。

**为什么"用户主权 > 质量 > 结构"这个优先级：**

- 用户主权最高：创作主权在用户（E\_SECTION 决策 5："用户自己觉得够了 > 框架说够了"）。用户说停就停，不需要任何条件。
- 质量信号高于结构：质量信号反映的是"角色在用户脑中活没活"，结构反映的是"素材文档齐没齐"。前者是 MVC 的本质（§1.3 的好坏标准），后者只是兜底。
- 质量可以解锁结构（提前触发），但质量弱时结构不能强行触发（那会逼用户在角色还没活的时候停）。

#### 4.3.2 质量信号表（每轮追问后内部检查）

> 这些信号全部可从对话文本中判断。AI 看不到用户表情/打字速度，所以信号必须锚定在用户说出来的话上。

| 层               | 信号            | 检查什么                                 | 通过样例                                            |
| --------------- | ------------- | ------------------------------------ | ----------------------------------------------- |
| 单轮信号（每轮必查）      | **A. 行为级密度**  | 本轮回答是否包含"场景+动作"单元（何时何地 + 她具体做了什么）    | "她在食堂排队时会把最后一份红烧肉让给后面的人，然后自己去打别的菜"              |
|                 | **B. 独有性**    | 遮住角色名，这段描述放在同类型角色身上还成立吗？不成立 → 亮      | "她会在没墨的同学桌上悄悄放一支备用笔，放完就收回目光"                    |
|                 | **C. 新增性**    | 本轮是否带来新场景/新行为/新关系细节（不是换措辞说同一件事）      | —                                               |
| 跨轮信号（每 3-4 轮查）  | **D. 模式可见性**  | 多个行为画面底下是否有一个一致的东西在跑，且用户确认了这个模式      | AI 提炼"这些行为底下都是'不出声就不会出错'"→ 用户确认                 |
|                 | **E. 修正精度**   | 用户对 AI 推测的否定是模糊的还是精确的（精确 = 给出具体行为替代） | AI:"她是不是当面说出来的人？" 用户:"不对，她会沉默几秒然后岔开话题，过两天再找机会提" |
| 自主信号（出现即亮，权重最高） | **F. 自发延伸**   | 用户是否在 AI 问题之外主动补充新画面/连接多个画面          | 用户没被问到妈妈，自己延伸"其实她对她妈也这样"                        |
|                 | **G. 自然收束意愿** | 用户是否说"我好像知道她了""我脑子里能看到她了"            | "原来她是这样的"                                       |

**组合规则**：

- 单轮信号 A/B/C 持续为亮（每色衍生通过合格标准）→ 结构判读的"每色 ≥3 衍生"被支撑
- ≥3 个质量信号通过（其中至少 D/E/F/G 中的 1 个）→ 质量判读通过
- **最强的信号是 E（修正精度）和 F（自发延伸）**——它们证明用户脑中有一个比 AI 追问更详细的角色模型。模糊的角色只能产生模糊的接受/拒绝（"嗯……不太对"），精确纠偏需要清晰的内部参照。

**明确排除的假信号**：

- 回答变长 ≠ 能看见角色（可能在编故事）
- 用了术语 ≠ 能看见角色（可能在模仿 AI 的语言）
- 说"我知道了" ≠ 能看见角色（可能敷衍，需要二次确认，见第二层）
- 情绪激动 ≠ 能看见角色（可能是被自己的故事感动，但角色还不清晰）

#### 4.3.3 行为测试：为什么禁止原始版，只用修改版 ★

**行为测试的初衷**：当质量信号显示角色基本成型但 AI 不确定时，想验证"用户能否把角色迁移到一个没提过的场景"——能，说明角色真的活了。

**原始版（禁止）**：AI 主动构造一个新场景让用户判断（"如果她最好的朋友背叛了她，她会怎么做？"）。

为什么禁止——这是设计文档 §1.1 追问引擎的本质冲突：

1. **方向反了。** 晴空妈妈的追问永远指向用户已经拥有的东西（"你问问自己，这七个标签里哪个是无论如何都在那里的"）。她从不在用户脑子里放一个外部场景让用户反应。行为测试原始版是"往用户脑子里放一个场景然后让她反应"——这是设局，不是追问。
2. **场景会嵌入角色假设。** AI 构造的场景（"朋友背叛""保护朋友说谎"）本身来自 AI 数据库，且常常隐含角色特质（"重视友情"）。这踩到 §1.4"替用户编一个她没有描述过的行为或特质"的红线。
3. **交互姿态变成考官。** "我给你一个场景，你来判断"是测试姿态，不是追问姿态。§2.4 说"追问不是审讯"。
4. **用户答不出时是挫败不是卡壳。** 用户面对新场景说"她也说不清"——这在追问中是自然的"换角度"，在测试中是"考试没考过"。体验完全不同。

**修改版（允许，可选）**——场景由用户自发生成，AI 不构造：

> "你现在脑子里她的画面，放到一个你没提过的场景里——她还成立吗？你想想，有没有什么情况是你还没说过但她一定会遇到的？"

- 用户自己生成场景 + 给出具体独有行为 → 迁移成功 → 角色活了，可触发 MVC
- 用户想不出场景 → AI 提供**中性脚手架场景**（不嵌入角色假设，遵循 E 段决策 6 的脚手架规则）作为兜底
- 用户在脚手架场景里说"她不会这样，她会那样" → 修正确认 → 角色活了
- 用户在脚手架场景里说"她也说不清" → 迁移失败 → 角色还没活 → 继续追问（换切面）

**关键差异**：场景来源是用户的脑子，不是 AI 的数据库。这和晴空妈妈的追问方向一致。AI 只在用户卡住时提供中性脚手架，机制与 E 段决策 6 的脚手架模式完全相同（AI 提案 → 用户裁决）。

**定位**：可选增强层，不是必经步骤。当质量信号收敛度刚过线、AI 不确定时才用。用户自主信号（F/G）已很强时，角色明显已活，不需要迁移验证。

### 4.4 阶段 3：深化（可选）+ 收束

深化：按用户选的方向追问，追问到用户说停或深度极限。
收束：将全部确认内容整理为清晰的结构化记录。不做解读式总结。最后问"你觉得还有什么地方没被写到的？"留空白入口。

#### 5.1.1 分界原则

**body 管每一轮都要用到的方向感，references 管阶段性才需要的操作手册。**

分界测试：如果把这条从 body 拿掉，AI 是在**每一轮都可能犯同一个错**，还是**只在某个阶段可能犯某个错**？前者必须在 body，后者可以放 references。

## 六、与其他 3 个 skill 的边界

### 6.1 路由总图

```
用户入口
├─ 想写角色卡内容
│   ├─ 新手/快速上手/简单角色 → dialogue-persona
│   │   └─ 角色变复杂需要进阶 → 转 char-build-guide
│   └─ 深入构建/复杂角色/需要进阶 → char-build-guide
│       └─ 发现更喜欢台词/小传方式 → 转 dialogue-persona
├─ 角色内容已写好，需配置世界书 → worldbook-config
├─ 需要写用户信息 → user-info-calibration
│   └─ 如角色卡本身没写好 → 先去 char-build-guide / dialogue-persona
└─ 需要测试和迭代 → 当前无 skill 覆盖（B 段诚实标注缺口）
```

### 6.2 与 dialogue-persona 的路由规则 ★

**二选一，不混用。双方 B 段互相指向。**

| 判断维度   | char-build-guide | dialogue-persona |
| ------ | ---------------- | ---------------- |
| 角色表达媒介 | 叙事/描写驱动          | 对话驱动             |
| 用户擅长方式 | 分析性格结构           | 写台词/对话           |
| 需要的深度层 | 可能需要多面性/混色/核心人格层 | 不需要这些层           |
| 角色复杂度  | 中高               | 中低               |

**路由时机**：入口检测阶段判断。如果用户在初始对话中关心的核心问题是"模型台词生硬""角色说话像 AI"→ 路由到 dialogue-persona。如果用户在意的核心问题是"角色不立体""不知道她是什么样的人"→ char-build-guide。

**中途切换**：如果 char-build-guide 追问过程中用户反复表示"我就是想让她的对话更像活人""别的无所谓"，AI 可以提议切换到 dialogue-persona。反之亦然。

**重要**：用户说"帮我生成/帮我扩写"→ 不应被排除，而应被拦截并转为追问。教程里晴空妈妈对柚子"那我能让 AI 帮我写衍生吗？"的回答不是拒绝，而是解释了原因然后**继续追问**。

### 6.3 与其他 skill 的边界

| Skill                   | 触发场景                  | 与 char-build-guide 的关系                                                                     |
| ----------------------- | --------------------- | ------------------------------------------------------------------------------------------ |
| `worldbook-config`      | 世界书怎么配置、绿灯不触发、关键词怎么写  | **独立技术 skill**。内容 vs 配置的判断：把所有条目改蓝灯→问题消失=配置问题→worldbook-config。问题还在=内容问题→char-build-guide。 |

## 七、未决事项（已更新，2026-08-11）

### 已解决（来自 design/ 审查文档）

- [x] ~~AI 需要多深的方法论理解~~（原 #2）→ **I 段不出现术语。** I\_SECTION\_REVIEW 三方一致：调色盘/多面性/混色/核心人格层术语不出现在 I 段。I 段只用追问深度轴（标签→行为→矛盾→为什么→内核），不用产出结构图。I 段必须用**执行语言**（"追问用户哪个特质是一直在的"），不用**教学语言**（"底色是无论什么场景都隐隐存在的东西"）。术语放在 E 段作为 AI 的内部标签使用。
- [x] ~~和 dialogue-persona 的路由时机~~（原 #7）→ **入口检测阶段判断。** 见 §六边界。双方 B 段互相指向。判断维度：角色表达媒介 / 用户擅长方式 / 需要深度层 / 角色复杂度。

### 新增共识（来自 design/ 审查文档，需并入 skill 写作）

以下不是未决事项，而是审查文档中的高质量结论，已确认采纳：

- **I 段是 E 段的 fallback。** E 段覆盖不到时，AI 靠 I 段的方向感判断。没有 I 段，执行 E 段会变成机械走步骤。（来自 I\_SECTION\_REVIEW Agent 3）
- **A1 必须展示追问的对话过程，不能只展示方法论产物。** 保留 2-3 个追问回合的原始对话片段。A1 是 case study，不是 testimonial。（来自 A1\_REVIEW\_REPORT 三方一致）
- **硬边界和软边界必须显式区分。** 硬边界 = "做了会坏"（用必须/不可/禁止），软边界 = "不做更好但做了不至于崩"（用建议/通常）。B 段审查给出了 8 条硬边界 + 5 条软边界的完整清单。（来自 B\_SEGMENT\_AGENT\_INSIGHTS）
- **教程与 skill 之间存在"翻译层"。** "手写优于 AI 扩写"这条对人说的原则，在 AI 自己就是执行者的场景下需要重新表述：推演候选供用户裁决 ≠ AI 替用户生成。"衍生不适合 AI 直出"同理。（来自 B\_SEGMENT\_AGENT\_INSIGHTS 发现 1 + I\_SECTION\_REVIEW 交叉验证）
- **"进阶不是必选"在教程中无效，但 skill 可以让它生效。** 作者口头说"不是必选"但写了三万字教程——内容体量在暗示"你应该学"。Skill 主动判断是否激活进阶模式，不暴露给用户选。（来自 B\_SEGMENT\_AGENT\_INSIGHTS 发现 4）
- **追问引擎预设了"理想用户"，需要优雅退出路径。** B 段应诚实标注：对"有画面但说不出来"的用户最有效；对"完全没有角色概念"的用户效果有限。连续 N 轮追问无有效产出 → 收束 → 诚实告知 → 切换 24 问急救或给参考案例。（来自 B\_SEGMENT\_AGENT\_INSIGHTS 发现 6）

### 11.5 多会话续接（2026-08-12 补，来自 handoff §2.4 对比发现）

char-build-guide 的追问循环预设了单次连续会话，但角色构建往往跨天跨周。handoff 用"最近更新的特征点旁做标记（⏸/日期）"续接，char-build-guide 缺失此机制。

**结论**：追问过程中，AI 在每次写人物文档时，在最近更新的特征点旁标注日期/⏸。新会话读文档 → 找最近更新标记 → 从标记处继续追问。

**依据**：handoff §2.4（"下次新会话读到标记就知道上次在构建哪个特征点，从那里继续。这比'下一步'字段精准——字段是抽象指令，标记是具体位置。"）+ 用户确认"运行在 Claude Code 里面"（有文件系统，可落盘）。

**代价**：无。轻量标注，不增加认知负担。

**否决方案**：单独维护"下一步"字段。否决原因：抽象指令不如具体位置精准；且"阶段/下一步"概念已被取消（handoff §2.4 决策 4）——构建是特征驱动的迭代环，不是线性流程。

## 十二、运行时承载机制（2026-08-12 补）

> 本节回答"追问过程中收集的素材和已确认的构件，怎么承载"。由 3 个独立 agent（glm-5.2 × 3，S1/S2/S3）+ 主流程独立判断 + handoff 对照后定稿。

### 12.1 部署环境

**结论**：char-build-guide 运行在 **Claude Code** 里（用户确认），有文件系统。可以落盘，不依赖对话上下文承载。

**依据**：用户明确确认"运行在 claudecode 里面"。

### 12.2 承载方案：单文件人物文档

**结论**：每角色一个目录 `workspace/角色名/`，一个文件 `人物文档.md`，内含素材区 + 构建区。

```
workspace/角色名/
└── 人物文档.md
    ├─ 素材区（她经历过什么）——用户原话/经历/行为切片/关系动态，含否决揭示的角色特征
    └─ 构建区（她是什么样的人）——已确认的性格构件，最近更新点旁有标记（⏸/日期）
```

**依据**：

- 3 个 agent（S1/S2/S3）一致推荐单文件（最低更新成本 + 跨维度检索够用 + 跨会话延续最简单）
- handoff §2.2/2.3 同一结论（"素材区和构建区是同一个人的一部分，拆开反而要跨文件引用"）
- 教程产物形态一致（一份完整角色卡）

**代价**：文件随会话推进变长，可能成为上下文负担。对策：素材区只保留有信息量的原话（含场景+动作、精确否定、自发延伸），不保留寒暄/敷衍/重复（对齐 §4.3.2 假信号排除表）。

**否决方案**：

- **多文件（按维度分）**：否决。跨维度操作（推演多面性时回看调色盘素材）天然需要素材和结构在同一视野内；为可能用不到的维度预设文件是过度工程化——"char-build-guide 是 skill，不是角色管理应用"（S1）。
- **纯上下文承载**：否决。长对话压缩会丢失素材（"草稿纸正反面算了无数遍"→被压成"她学习很努力"）；跨会话/换会话全丢；方向枯竭判断/模式提炼需要回看素材，纯上下文检索不可靠（S1/S2/S3 一致）。
- **素材区/构建区分两个文件**：否决。紧耦合（每条衍生引用素材区原始描述），分开增加交叉引用复杂度（S2）。

### 12.3 记录粒度：事件驱动

**结论**：事件驱动记录——特征闭环即记录，每轮不自动写。

**依据**：handoff §2.12（"只有内容变化时才写入文档，避免噪音"）+ E\_SECTION 决策 4（闭环判据：能落成一句行为描述且用户认可）。

**具体规则**：

- 用户提供新素材（含场景+动作的画面、精确否定、自发延伸）→ 追加素材区
- 结构化状态变化（颜色确认/衍生通过/元素被否定）→ 更新构建区
- MVC 暂停点/方向切换 → 强制同步
- 用户只回"嗯""对" → 不记录

### 12.4 协作层否决：不记录到角色档案 ★

**结论**：协作层信息（"别往这个方向挖了""这个推演不对"）**不记录到 `人物文档.md`**——那是角色档案，只放角色内容。协作层否决属于 AI 的会话内部记忆，在对话上下文中维护即可，不落盘。

**依据**：用户明确确认（"协作信息肯定不记录到角色档案里面"）。角色相关的否决（"她不是那种在意场合的人"）揭示角色特征，**进素材区**（handoff §2.4）；纯协作否决（"别往这方向挖"）是会话内的即时指令，不存档（handoff §2.4）。

**代价**：纯协作否决不落盘，跨会话可能丢失"用户否过这个方向"的记忆。可接受——用户新会话中如果还记得，会再说；不记得说明不重要。

### 12.5 素材区记录标准：推演价值判据

**结论**：素材区不是"人物数据库"，是"推演的原料库"。记录标准只有一条：**这条素材能不能成为推演的起点？能不能问出"她为什么这样"或"这暗示了她是什么样的人"？**

**记什么（四类有推演价值）**：

- 经历事件（改变了这个人）："爸爸10岁去世"
- 行为切片（能问出"她为什么这样"）："在家穿衣大胆，网上活跃线下沉默"
- 标志性偏好/习惯（定义辨识度或暗示心理）："只穿高领无袖"
- 关系动态（有具体互动画面）："他把零食放她桌上，她用书本推到桌角"

**不记什么（三类无推演价值）**：

- 纯审美标签（放在谁身上都行）："喜欢听音乐"
- 无辨识度的默认值（AI 已知）："黑头发"
- 与推演无关的一次性事件（删掉人物没变化）："有一次下雨没带伞"

**依据**：handoff §2.3c（被 H1/H2 评为"被忽视的好东西"，可直接转化为追问引擎的"什么值得追问"判据）+ 教程 11 号验证（三明月"接电话前深吸一口气"是行为切片有推演价值；"她喜欢音乐"是纯审美标签无价值）。

### 12.6 素材区与构建区的关系：状态升级而非跨区复制

**结论**：同一条记录从素材状态变成构建区构件时，是**状态标记改变**（如 "📌线索" → "✅确认"），不是跨区域复制。追溯链不丢。

**依据**：主流程独立判断（"爸爸去世"从素材状态变成"底色：不甘心"的衍生时，内容还在原位，只是状态变了）——素材区保留做追溯，写卡只拿构建区（handoff §2.3）。

**代价**：无。这是记录格式的约定，不是功能差异。

### 12.7 审阅过程与对照（2026-08-12，两轮独立审阅）

> 本节记录承载机制结论的审阅过程，作为 §12.1-12.6 的决策依据。
> 对早期设计决策记录（`DESIGN_HANDOFF.md`，即 `character-palette-collab` 项目）中**与承载机制相关**的部分做了两轮独立审阅。
> 第一轮：3 个批判 agent（glm-5.2，H1/H2/H3）+ 主流程独立判断。
> 第二轮：3 个辩护 agent（glm-5.2，D1/D2/D3），为 handoff 辩护、挑战共识。
> **范围说明**：仅审阅承载机制（素材/状态怎么承载）。handoff 中 MVC 时机、构建顺序、意象位置、产物名、多框架推演等非承载机制内容，不在本次审查范围——那些问题以后讨论时再单独审。
> **方法论教训**：第一轮共识受 prompt 立场影响（"早期设计"暗示过时）；辩护轮发现单轮共识不可靠。最终结论以两轮对照为准。

**两轮对照表**：

| handoff 决策       | 批判轮共识              | 辩护轮发现                                   | 最终判断               |
| ---------------- | ------------------ | --------------------------------------- | ------------------ |
| 单文件人物文档（素材区+构建区） | 采纳                 | 强辩护：固定结构提供可追溯可验证（一致性验证需要知道内容归属）         | **采纳**（§12.2）      |

| 取消过程记录           | 采纳                 | 强辩护：handoff 的区分是精确的（角色相关否决进素材区，纯协作否决不记） | **采纳**（§12.4，用户确认） |

**辩护轮发现、与承载机制相关的补充**：

## 十三、快速路径设计与引导机制（2026-08-12 定稿）

> 本节记录 Todo 1.3（快速路径切换判断标准）讨论中产生的全部决策，以及由此引出的引导机制体系。
> 来源：主流程与用户的逐项讨论 + 3 个独立 agent（glm-5.2）对快速路径流程的审阅 + 3 个独立 agent（glm-5.2）对教程引导机制的提取。三方 agent 结论高度交叉验证。
> 决策记录格式遵守 §〇。

### 决策 [G1]：快速路径的本质——能力问题，不是意愿问题

**结论**：使用 char-build-guide 的用户不存在"抗拒追问"问题——会来用这个 skill 的人有意愿，只有能力高低。快速路径是**同一套追问引擎，换了一套更轻的追问语言**（不引入调色盘/多面性/混色术语），不是"抗拒用户的降级方案"，也不是另一个独立 skill——它是 char-build-guide 内部的分叉路径。

**依据**：
- 用户明确纠正（2026-08-12）："没意愿的就不会用这个 skill，用这个 skill 的都是有意愿的，只有能力高低的问题，能力低的就想办法引导啊。"
- 教程 11 号定位："面向完全不知道怎么下手的人""如果你还没看过那些，或者看了但觉得太复杂不知道怎么开始，这篇就是给你的。"
- 3 个 agent 独立确认：快速路径是"用'看'代替'拆'，用'变成她'代替'分析她'"——另一套引导逻辑，不是简化版深入模式。

**代价**：放弃"抗拒检测"的复杂信号体系（信号 1/2/3 分层、元对话分析等——这些是上一版过设计的产物）。接受的风险：用户可能疲劳但不表达——由 §2.4（节奏由用户决定）和 MVC 暂停点的时机判读兜底，不单独设检测机制。

**否决方案**：
- ~~"抗拒信号检测体系"（回答变薄/元对话/主动性下降三层信号分类）~~：否决。把"能力弱"误诊为"抗拒"，且引入大量不可观察的心理状态判断。用户一句话点破：不存在抗拒问题。
- ~~快速路径作为独立 skill~~：否决。trigger 与 char-build-guide 重叠，且快速路径和深入模式共用追问引擎、共用基础信息步骤、共用意象收束——拆出去等于把引擎拆两半。

### 决策 [G2]：快速路径切换条件——连续卡住即切，不追问原因

**结论**：切换条件只有一种——**深入模式中连续卡住**（换了 ≥2 个切面 + 脚手架推演 ≥2 次被否）→ 不追问"为什么卡住"，直接切。切换语："我们换个方式——闭上眼，你第一个想到的关于她的画面是什么？"

**依据**：
- E_SECTION_DESIGN 决策 6（降级链条：镜子→脚手架→推演→溯源→降级）+ 用户确认（"搞这么复杂干什么"——砍掉多信号检测）
- 教程 11 号本身就是为"调色盘拆不动"的用户准备的降维路径。

**代价**：可能在用户只是暂时卡住时就切换。可接受——快速路径和深入模式双向可转（决策 [G4]），切错了可以回来。

**否决方案**：
- ~~"用户显式表达'简单点'才切换"~~：否决。能力弱的用户往往不会表达需求，等显式信号等于不救。
- ~~"连续 N 轮敷衍才切换"~~：否决。敷衍信号本身不可靠（E_SECTION 决策 4 已定义敷衍不算确认），用它做切换依据更不可靠。

### 决策 [G3]：快速路径五步流程——每步的追问动作与完成标准

**结论**：五步流程为 **基础信息 → 小传 → 采访 → 情绪阈值 → 意象**。每步的追问动作（A 类，吸收）和完成标准（AI 从文本可观察）如下：

| 步骤 | 追问动作 | 完成标准 |
|------|---------|---------|
| 基础信息 | 遮名测试 / 删行测试（"这条删了角色会变吗"）/ 画面替换（"写他们具体做了什么"）/ 性格标签混入时截断 | 外貌遮名后能唯一锁定；背景每条删了角色会变；关系是具体动作不是形容词；无性格标签混入 |
| 小传 | "闭上眼看一段她的生活，写下来" / 录像带规则（只写五官能感受到的）/ 删词检查（删掉"她觉得/因为/其实/内心"后画面还完整吗）/ "日常最好，越小的瞬间越能看清她" / 数量引导（三四段最少，六七段舒服） | ≥3 段；每段删词后画面仍完整（动作/表情/对话/环境至少两样）；场景覆盖不同侧面 |
| 采访 | 暴露型问题（"你怕什么""你觉得自己值不值得被喜欢"，不问"喜欢什么颜色"）/ 完全代入（用她的语气，不是你的）/ 说谎处理（动作细节露馅 或 直接标注"她在说谎"） | 3-5 段；问题是暴露型；回答有角色独有语言习惯；谎话有处理 |
| 情绪阈值 | 每种情绪三问：什么触发（具体场景）/ 过程（变化轨迹不是静止画面）/ 怎么结束（出来以后落到哪）。五种：喜怒哀惧衰 | 五种各有三要素；触发是具体场景；过程是曲线；"衰"的触发是"不需要触发，其他情绪结束后的落点" |
| 意象 | "她存在的方式像什么"（不是外貌不是性格）/ 从角色本身长出来（截断外部套用："不要从'她代表什么'出发，问'她像什么'"）/ 承载主要矛盾 / 写短 / 不解释 / 放最后 | 有具体象征物；承载核心矛盾；篇幅短；无解释性语言 |

**依据**：
- 教程 11 号全文（三明月案例）+ 教程 0 号基础信息部分
- 3 个 agent 对教程 11/0 的独立提取，三方对每步的追问动作和完成标准交叉一致
- A/B 类划分：每步的核心追问动作均为 A 类；"为什么只写特征不写美感""小传和衍生效果差不多"等原理解释为 B 类，用户问时才简答

**代价**：五步流程比深入模式（直接从素材进调色盘）多了"采访"和"情绪阈值"两个独立结构。接受——快速路径用户没有调色盘结构来约束角色语言和情绪表现，采访和情绪阈值是补位的等价物。

**否决方案**：
- ~~快速路径只用"小传+意象"两步~~：否决。教程 11 明确五步各有不可替代功能（身份→行为→语言→情绪→象征），砍步会导致 AI 拿到的信息维度缺失。
- ~~把深入模式的追问语言简化版直接搬过来~~：否决。Agent 2 明确："快速路径不是简化版的深入模式，是另一套引导逻辑。"快速路径的追问基于"看"和"变成她"，深入模式基于"拆"和"分析她"。

### 决策 [G4]：快速路径的 MVC 锚点、入口与双向性

**结论**（三个子项，3 个 agent 独立得出同一答案）：

1. **MVC 锚点**：快速路径没有调色盘三层结构，MVC 锚定在**情绪阈值完成之后、意象之前**。前四步（身份+行为画面+说话方式+情绪曲线）已等价于调色盘给 AI 的东西，意象是收束抛光不是承重结构。MVC 触发前做**一致性检查**：小传里的她、采访里的她、情绪阈值里的她是不是同一个人，矛盾则先追问解决。
2. **入口**：可以一上来就选。三个入口信号——用户自述"不知道怎么写/太复杂"；用户带来的素材是感性画面（"我看到她在做X"）而非结构化分析（"她的底色是焦虑"）；深入模式中连续卡住。默认仍走深入模式（教程 11 自己说"如果看过调色盘教程，这篇对你太基础"）。
3. **双向性**：快速路径完成后可回深入模式。教程 11 结尾："想进一步提升，去看调色盘教程。调色盘会教你把你已经写出来的这些画面，拆解成更系统的结构。"快速路径产出（小传/采访/情绪阈值）是深入模式反向拆解的素材。

**依据**：3 个 agent 独立审阅教程 11 后三方一致 + 教程 11 原文。快速路径和深入模式的产出质量差别是**精度不同不是高低**——已覆盖场景两者差不多；边缘场景深入模式更稳（结构允许外推），快速路径需补新画面（教程 11 自称"平替"）。

**代价**：允许自选入口意味着部分用户会跳过深入模式直接走快速路径，产出的角色在边缘场景可外推性较弱。接受——教程 11 的定位本来就是"入门替代"，且双向切换保证了升级通道存在。

**否决方案**：
- ~~快速路径只能作为深入模式的降级出口~~：否决。教程 11 开篇明确面向"完全不知道怎么下手的人"，是独立入口不是降级通道。
- ~~快速路径单向，完成后不能回深入模式~~：否决。教程 11 结尾明确给出升级路径，堵死它等于砍掉用户的成长通道。

### 决策 [G5]：标签优先——标签是低分辨率的种子，不是错误

**结论**：对能力最弱的用户，**先收标签，不纠正**——"先别管具体，用几个词说说你脑子里对她的印象。"然后三步深化：①标签阶段先扫矛盾（"你说了'极度自卑'，也说了'成绩年级前列'——一个极度自卑的人是怎么做到年级前列的？"标签分辨率下矛盾最显眼）；②每个标签用四问转化（做什么/什么时候/为什么/伤到谁）直至产出 ≥1 个行为画面；③标签退场——产出文档里没有标签，只有画面。标签是脚手架，盖完楼拆掉。

**依据**：
- 教程 02 调色盘篇的实际做法：柚子从七个标签起步，晴空顺着标签往下挖，结尾"没有一个标签消失了。它们只是从空洞的形容词变成了可以被 AI 演出来的画面"
- 24 问工作流追问规则（四问转化器）
- Agent 3 发现"命名滞后于感觉"："不甘心"诞生之前柚子已经感觉到了它，晴空只是在她的感觉上贴标签——标签是起点不是终点
- 用户提问引导（2026-08-12）："虽然最终不能用标签，但是可以先让用户说说标签化印象，然后从标签入手去深化"

**代价**：标签会锚定用户（说了"温柔"就只在温柔框架里想）。对冲：矛盾扫描在标签阶段执行，用行为矛盾击碎锚定。另有风险：用户给的标签可能是错的——转化过程中画面和标签矛盾时，AI 问"你说她温柔，但你刚说的画面里她在算计——哪个才是她？"标签可以被画面推翻。

**否决方案**：
- ~~"看到标签就立刻追问画面"（标签过敏）~~：否决。对能力最低的用户，标签是唯一入口——拒绝标签等于拒绝她的唯一把手。且标签阶段的矛盾扫描最锋利（低分辨率反而让矛盾显眼）。
- ~~"禁止用户使用标签描述角色"~~：否决。教程从未禁止标签，只是不停留在标签。

### 决策 [G6]：引导机制升级阶梯——从最轻干预开始，前一级失效才升级

**结论**：用户卡住时按四级阶梯升级，永远从最轻的开始：

```
第一级：钻探链（最轻）——"为什么""再往下一层"，不给任何信息只施加压力
第二级：回链+行为锚定（中等）——抽象追问 stall 时，列出用户已写的具体行为，
        "她为什么把牛奶推开？她为什么说'我会还的'？"从行为端反推
第三级：多选行为引导（较重）——"她的温柔是哪种？记住别人的话/过度照顾/回避冲突？"
第四级：假设场景/闭上眼指令（最重）——"如果她走投无路需要借钱呢？"
        "闭上眼，看一段她的生活"
```

越往上越接近"替用户想"，所以越轻越好。核心原则：先诊断卡住类型（标签卡/表面卡/八股卡/空白卡/碎片卡/深度卡/拆分卡），再匹配机制，不做无差别"再具体一点"。

**依据**：3 个 agent 从教程提取的 15-18 个引导机制，三方独立收敛出高度一致的卡住类型分类和升级逻辑。教程原文证据链：05 篇核心恐惧挖三层（钻探链）→ stall 后列"推开牛奶/说我会还的"（行为锚定）→ 24 问工作流的选项追问（多选引导）→ 03 篇"走投无路借钱"（假设场景）。

**代价**：四级阶梯是 agent 提取的框架，不是教程明写的流程——存在把教程的"灵性"过度结构化的风险。缓解：按 §1.2（原则驱动）落地，阶梯是方向感不是穷举规则。

**否决方案**：
- ~~"无差别追问"（不管卡住类型一律"再具体一点"）~~：否决。Agent 1 明确：如果只给追问措辞不给卡住类型诊断，AI 会变成追问机器。
- ~~"优先用重的干预"（直接给场景投掷）~~：否决。越重越接近替用户想，违背 §2.2 硬铁律。

### 决策 [G7]：示范边界——三条硬约束

**结论**：示范（AI 给例子让用户仿写）**允许**，但必须遵守三条硬约束：

1. **不写用户的角色**。示范用通用例子或教程案例库里的其他角色，不碰用户正在创建的角色。
2. **只示范一条**。一条够校准"具体到什么程度"的标尺，多了就是代写。示范后明确交还："这是示范的写法。现在你来写你的角色的。"
3. **"找到"型任务不示范**（意象、底色这类需要用户自己"找到"的），只用排除引导+方向暗示。示范只用于"写法校准"型任务（"什么叫有画面的衍生"）。

**依据**：
- 教程证据链：晴空示范"算题时的较劲"只写一条后说"继续"（02 篇）；混色示范用通用技巧例子不用陈乖乖（04 篇）；意象刻意不示范（"妈妈不告诉你答案"，07 篇）
- 3 个 agent 独立得出几乎相同的边界划分
- 与 §2.2 硬铁律的调和：示范通用行为类型 ≠ 替用户生成她的角色内容

**代价**：允许示范意味着接受"示范质量影响用户产出方向"的风险——示范错了方向用户会跟着偏。对冲：示范用教程案例库的真实高质量内容（陈乖乖/三明月的画面），不用 AI 即兴生成；示范后立刻切回追问交还产出权。

**否决方案**：
- ~~完全禁止示范~~：否决。纯追问解决不了"用户不知道具体到什么程度算够"——晴空示范后柚子明显进步（"悄悄把备用笔放在没墨的同学桌角"是柚子自己写的），没有示范就没有这个标尺。
- ~~示范用户的角色内容~~：否决。替用户写她的衍生等于代写，违背 §2.2。

### 决策 [G8]：追问节奏与动态引导强度

**结论**（两个机制）：

1. **肯定+追问成对出现**。引导是"接受→推深→接受→推深"的螺旋，不是直线下挖。只追问不肯定→用户挫败；只肯定不追问→用户停在第一层。肯定的是"方向对了"，推深的是"但还不够"。
2. **引导强度动态调整**。追踪已建立的素材量：对话初期用户几乎没有素材→重引导（多选、场景投掷、闭上眼）；素材积累后→轻引导（"再往下一层"就够）。教程证据：02 篇柚子高度依赖晴空（晴空写全部示范）→ 05 篇柚子自己答出核心矛盾。

**依据**：Agent 1（肯定+追问螺旋）+ Agent 3（动态引导强度，追踪柚子全程产出能力变化）。

**代价**：动态强度要求 AI 持续跟踪素材量——增加 AI 的认知负担。缓解：素材量本就由 §12 人物文档承载，AI 查文档即可知。

**否决方案**：
- ~~只肯定不追问~~：否决。用户会停在第一层答案，角色停在标签深度。
- ~~固定引导强度~~：否决。前期重引导后期还重=干扰有能力用户；前期轻引导后期还轻=救不了能力弱用户。

### 决策 [G9]：情绪串的追问——防御性纠偏，不是主动追问

**结论**：情绪串（同一瞬间多种情绪同时跑）**不主动追问**。教程 11 的立场是"串会自然发生，你不用管它；如果它出现在你写的文字里，用矛盾动作承载，不要用解释句点名"。skill 的行为只有防御性纠偏：用户写出"她同时感到快乐和焦虑"这种解释句时，才追问"别解释。写一个看起来矛盾的动作就行。"追问动作里没有"有没有另一种情绪"这一问。

**依据**：教程 11 原文："这种'串'不需要你刻意去写'她同时感到快乐和焦虑'这种解释。你只需要写过程里那些看起来矛盾的动作，AI 自己会理解。"——教程从未要求作者主动识别"另一种情绪"，主动追问会把用户推向情绪标签库。

**代价**：放弃"主动帮用户发现情绪混色"的机会。接受——混色是深入模式的进阶能力，快速路径的任务是让角色跑起来，不是追求梵高星空。

**否决方案**：
- ~~主动追问"这种情绪里有没有同时跑着另一种情绪"~~：否决。用户去标签库里翻"喜悦/愤怒/悲伤"→混色变成标签拼盘，和教程核心思想背道而驰。此方案曾出现在 agent 转述中并被主流程错误采信，用户指出后修正。
