# B 段设计 — 3 个 Knot Agent 独立审阅综合报告

> 来源：2026-08-11 使用 knot-cli 并行启动 3 个 glm-5.2 agent，各自独立阅读全套教程后产出。
> 用途：为后续阶段 2 编写 4 个 skill 的 SKILL.md（B 段）提供参考输入。
> 4 个 skill：char-build-guide / dialogue-persona / worldbook-config / user-info-calibration

## 一、三个 Agent 的角色分工

| Agent | 角度 | 核心关注 |
|-------|------|---------|
| 1 | **执行风险分析** | 教程方法论被 AI 机械执行会出什么问题？作者自己踩过什么坑？从"人读的教程"到"AI 执行的 skill"翻译层有什么风险？ |
| 2 | **路由与边界冲突** | 4 个 skill 之间的责任边界图。最容易互相抢触发的冲突对。灰色地带。硬边界 vs 软边界。 |
| 3 | **深层矛盾与不应被 skill 化** | 教程自相矛盾之处。不能被普通人复现的方法。如果蒸馏成 skill 反而有害的内容。 |

## 二、跨 Agent 共识：最重要的 8 个发现

### 发现 1：教程与 skill 之间存在"翻译层"，三条核心矛盾必须处理

三个 agent 独立发现了同一组矛盾——教程中反复强调的原则，在执行者就是 AI 的 skill 场景下会产生悖论：

| 教程原文（对人说的） | Skill 场景下的悖论 | 翻译层处理方式 |
|---------------------|-------------------|---------------|
| "手写优于 AI 扩写" | skill 的推演阶段就是 AI 在生成内容 | 明确区分"推演候选"和"最终写入"。推演候选供用户裁决（用户选择=手写的独特性），不是直接写入角色卡 |
| "衍生不适合 AI 直出" | skill 的多框架推演就是在生成行为场景（=衍生） | 推演不是 AI 直出衍生，是 AI 从多视角生成候选，用户选择和修改后成为衍生。用户的选择本身就是那个"反直觉组合"的动作 |
| "二次解释预判 AI 的误读" | 执行预判的就是 AI 自己 | 弱模型可能生成泛泛之谈。B 段应标注：二次解释的精准度取决于模型对自身误读模式的反思能力 |

**来源：Agent 1 §3.4, Agent 3 §矛盾一**

### 发现 2：4 个 skill 的 B 段整体正交无矛盾，但有两个冲突对需要统一路由规则

**Agent 2 的核心结论**：4 个 skill 不存在两个 skill 声称对同一问题负责的矛盾。但有两对需要注意：

**冲突对 1：char-build-guide ↔ dialogue-persona（最核心的二选一关系）**

两个 skill 的 B 段需要写入同一条路由规则：

> 用户是新手/想快速上手/角色复杂度低 → dialogue-persona。
> 用户想深入构建/角色复杂度高/需要进阶工具（多面性/混色/核心人格层）→ char-build-guide。
> 教程铁律：两者不混用。一旦选定一条路径，不要在中途混入另一条的方法论元素。

**冲突对 2：配置问题 vs 内容问题的判断**

用户说"AI 总是忘记她的性格"——可能是配置问题，也可能是内容问题。B 段需要给出可操作的判断标准：

> 把所有世界书条目改成蓝灯（全常驻）。
> 问题消失 → 配置问题（worldbook-config）。
> 问题还在 → 内容问题（char-build-guide）。

**来源：Agent 2 §三**

### 发现 3：硬边界 vs 软边界必须显式区分

三个 agent 都强调了区分硬软边界的重要性。以下是跨 agent 汇总的清单：

**硬边界（违反会导致明确的功能失败，B 段用"必须/不可/禁止"）：**

| 边界 | 所属 skill | 违反后果 |
|------|-----------|---------|
| 调色盘体系与台词人设体系不混用 | char-build-guide ↔ dialogue-persona | 方法论混乱，AI 收到矛盾信号 |
| 不抢话党不能写调色盘 | user-info-calibration | AI 用标签预判用户行为，抢占用户话语权 |
| 抢话党必须写禁止部分 | user-info-calibration | AI 过度代写用户行为 |
| 单角色卡全蓝灯 | worldbook-config | 角色信息时有时无，角色漂移 |
| 用户信息 token ≤ 角色卡 1/4 | user-info-calibration | 角色卡信息被挤出上下文窗口 |
| D1+ 绝不放任何东西 | worldbook-config | 对话历史完整性被破坏 |
| 递归全勾（不可递归+防止进一步递归） | worldbook-config | 条目连锁触发，token 爆炸 |
| 核心人格层不为轻松角色硬加 | char-build-guide | 日常场景触发核心恐惧，角色沉重化 |

**软边界（违反不会立即失败但会降低效果，B 段用"建议/通常/优先考虑"）：**

| 边界 | 所属 skill | 违反后果 |
|------|-----------|---------|
| 进阶工具不是必选 | char-build-guide | token 浪费 + 角色过度复杂 |
| 台词人设在复杂角色上有天花板 | dialogue-persona | 角色深度不足但不会出错 |
| 用户信息在长对话中衰减 | user-info-calibration | 后期对话中用户信息作用自然减弱 |
| 多角色卡配置复杂度被低估 | worldbook-config | 多角色场景下配置不够精细 |
| 抢话/不抢话二分法是简化 | user-info-calibration | 中间状态用户需要自行调整 |

**区分原则：硬边界 = "做了会坏"，软边界 = "不做更好但做了也不至于崩"。**

**来源：Agent 2 §四, Agent 3 §问题三**

### 发现 4："进阶不是必选"这个警告在教程中无效，但 skill 可以让它生效

**Agent 3 发现的深层矛盾**：作者口头反复说"不是必选"，但给三面性写了一整篇教程+大总结一篇、混色一整篇+大总结一篇、核心人格层一整篇+大总结一篇。**内容体量本身就在暗示"这些很重要，你应该学"。** 这不是作者的恶意，而是知识传播的结构性问题——你不可能写 3 万字讲一个东西然后说"你其实不需要用"。

**Skill 有机会修正这个问题**：追问引擎可以在内部判断"这个角色不需要多面性"，直接跳过，不暴露给用户。教程做不到的"主动不教"，skill 可以做到。

**来源：Agent 3 §矛盾二**

### 发现 5：覆盖盲区 — 4 个 skill 都覆盖不到的场景

三个 agent 独立识别了以下盲区，需在 skill 体系的 B 段中诚实标注：

| 盲区 | 说明 | 处理建议 |
|------|------|---------|
| **同人角色构建** | 原著一致性检查、OOC 风险防范、原著信息到调色盘的转化 | 标注"不覆盖"，建议用户自行参考原著 |
| **多角色卡/多角色交互** | 教程聚焦单角色。角色间化学反应在卡层面如何表达未涉及 | 标注"本体系聚焦单角色构建" |
| **角色卡测试与迭代** | 写完角色卡后怎么测试好不好用，教程几乎没有讨论 | 标注"当前无 skill 覆盖测试迭代环节" |
| **群聊场景** | 多 AI 角色的互动、用户信息的多角色适配 | 标注"群聊场景需额外考虑，本体系未覆盖" |
| **NSFW 深度内容** | 1 号教程提到 NSFW 调色盘但不展开 | 标注"性格构建方法论一致，但 NSFW 具体内容生成不在覆盖范围" |
| **跨平台格式迁移** | 从 RisuAI/Chub 等平台迁移已有角色卡到 ST | 标注"本体系假设从零构建，不负责跨平台迁移" |
| **token 预算的系统性管理** | 教程从未讨论 token 预算 | 标注"在方法论执行中，agent 应有 token 成本意识" |

**来源：Agent 1 §2.2, Agent 2 §七, Agent 3 §问题二**

### 发现 6：追问引擎预设了"理想用户"，需要优雅退出路径

**Agent 3 的核心发现**：晴空妈妈→柚子妹妹的对话体教学中，柚子妹妹是"理想用户"——她虽然笨拙但总能给出有效回答、她有角色画面只是说不出来。真实用户中存在：

- 完全没有角色画面的用户（"我就是想写个角色但我脑子里什么都没有"）
- 不愿意被追问的用户（"直接给我模板就行"）
- 回答质量极低导致引擎无法判断的用户

**B 段应承认**：本 skill 对"心里有画面但需要方法整理"的用户最有效。对"从零开始连角色概念都没有"的用户效果有限。如果连续 N 轮追问无有效产出，不应继续追问——收束已有内容，诚实告知用户可能需要先积累对角色的感受，然后切换到 24 问急救模式或给出参考案例激发灵感。

**来源：Agent 3 §矛盾六**

### 发现 7：AI 机械执行教程方法论的 6 个具体风险

**Agent 1 的专项分析**。即使 B 段写好了，AI 在执行时仍可能出现以下偏差：

| 风险 | 表现 | 对冲方式 |
|------|------|---------|
| **标签放大** | AI 拿到"她很安静"→每段输出都强调安静→角色变成"安静"的复读机 | 推演硬规则：禁止出形容词，只许出行为场景。加自检：推演结果里有没有伪装成行为描述的标签？ |
| **频道切换** | 多面性被理解成"切换场景时换一个人格"，面与面之间无过渡无渗透 | 多面性设计要求写过渡和渗透，AI 执行时不可跳过 |
| **情绪点名** | 每个场景都塞两种情绪，把"混色是点睛之笔"理解成"每笔都要混色" | 给出明确的不适用案例（参考教程 4 号原文错误示范） |
| **戏剧化升级** | 核心恐惧每次触发都崩溃，忽略教程说的"日常只泄漏一点点" | 二次解释中加入"关于她的日常状态"防误读条目 |
| **过度追问** | 追问引擎无退出条件，用户被无限追问 | 设计退出机制：N 轮无有效产出 → 收束 / 换入口 / 诚实告知 |
| **框架滥用** | 推演变成"先用依恋理论推一条，再用防御机制推一条"的机械套框架 | 推演主引擎是"从用户素材里抓重复出现的模式"，框架是后备而非首选 |

**来源：Agent 1 §3.1**

### 发现 8：教程中有 12 个作者明确警告的失败模式，应全部收入 B 段

**跨三个 agent 汇总**，教程中作者用"不要""错误""危害"等词明确标记的失败模式：

| # | 失败模式 | 来源教程 | 严重级 |
|---|---------|---------|--------|
| 1 | AI 扩写污染角色内容（AI 的"正确"=数据库高频关联） | 1 号 | 致命 |
| 2 | 衍生给 AI 写（AI 无法做反直觉组合） | 1 号 | 致命 |
| 3 | 不需要多面性的角色强行拆面→AI 切频道式扮演 | 2 号 | 致命 |
| 4 | 调色盘与台词人设混用 | 11 号 | 致命 |
| 5 | 单角色卡不全蓝灯→角色信息时有时无 | 0 号 | 致命 |
| 6 | D1+ 放东西→对话历史被污染 | 0 号 | 致命 |
| 7 | 不抢话党写调色盘→AI 预判用户行为 | 9 号 | 严重 |
| 8 | 抢话党没写禁止部分→AI 越界代写 | 9 号 | 严重 |
| 9 | 把二次解释写进三面性（"为什么"和"怎么运作"混淆） | 2 号 | 严重 |
| 10 | 每个画面都混色→角色情绪不稳定 | 4 号 | 严重 |
| 11 | 核心人格层写成心理词清单 | 7 号 | 严重 |
| 12 | 外貌写成文学描写/比喻/意象堆砌 | 0 号 | 中等 |

**来源：Agent 1 §3.2, Agent 2 §一, Agent 3 §失败模式**

## 三、对 4 个 Skill B 段的逐项建议

### char-build-guide（追问引擎）

**何时不用：**
- 用户只需要写用户信息（→ user-info-calibration）
- 用户只需要配置世界书（→ worldbook-config）
- 用户明确想用台词/小传/采访方式写角色（→ dialogue-persona）
- 用户已有完整的角色卡，只想做微调或格式检查（→ 校验模式，不启动完整引导流程）

**关键硬边界：**
- 与 dialogue-persona 二选一，不混用
- 进阶工具（多面性/混色/核心人格层）不是必选项，引擎主动判断是否需要
- 追问引擎不可无限追问——N 轮无产出 → 换入口或诚实告知局限

**与相邻 skill 区分：**
- vs dialogue-persona：统一路由规则（见发现 2）
- vs worldbook-config：角色卡内容 vs 世界书技术配置。所有条目改蓝灯→问题消失=配置问题
- vs user-info-calibration：角色侧 vs 用户侧。描述对象是 AI 演的角色还是 AI 读的用户

**来源：Agent 2 §一, Agent 2 §三, Agent 3 §矛盾六**

### dialogue-persona（台词人设）

**何时不用：**
- 用户需要完整心理深度（多面性/核心人格层）→ char-build-guide
- 角色核心魅力在行为模式而非台词表现力 → char-build-guide
- 用户已选择调色盘体系

**二选一判断标准（教程未给出，需 skill 自行定义）：**

| 判断维度 | 调色盘法（char-build-guide） | 台词法（dialogue-persona） |
|---------|---------------------------|-------------------------|
| 角色表达媒介 | 叙事/描写驱动 | 对话驱动 |
| 用户擅长方式 | 分析性格结构 | 写台词/对话 |
| 需要的深度层 | 可能需要多面性/混色/核心人格层 | 不需要这些层 |
| 角色复杂度 | 中高 | 中低 |

**关键局限（需诚实标注）：**
- 教程内容体量不对称（调色盘 10 篇 vs 台词人设 1 篇），台词人设在复杂角色场景下不是调色盘的等效替代
- 3 号教程的原始版本已被标记"废止"，本 skill 基于 11 号教程的改良版方法
- 台词人设 token 消耗大（教程经验值约四百句），需提醒用户 token 成本

**来源：Agent 2 §一（dialogue-persona 部分）, Agent 3 §矛盾三**

### worldbook-config（世界书配置）

**何时不用：**
- 角色卡内容本身还没写好（先走 char-build-guide 或 dialogue-persona）
- 用户不在 SillyTavern 环境（配置概念可能不适用）
- 用户的世界观是纯真实背景且无架空元素（A 类世界，几乎不需配置）

**关键硬边界：**
- 只负责"怎么配置"，不负责"世界观内容是什么"
- 角色卡内容属 char-build-guide/dialogue-persona
- 强绑 ST 平台，B 段应标注"基于 SillyTavern 世界书系统，不保证适用于其他前端或 ST 未来版本"

**配置 vs 内容的判断标准**（来自 Agent 2）：
> 把所有条目改成蓝灯。问题消失=配置问题。问题还在=内容问题 → 路由到 char-build-guide。

**来源：Agent 1 §（worldbook-config 部分）, Agent 2 §一**

### user-info-calibration（用户信息校准）

**何时不用：**
- 角色卡本身没写好（先走 char-build-guide）
- 用户不需要 AI 扮演用户（纯第三人称交互）
- 用户把用户信息当人设在写（→ 这是反场景，路由到 char-build-guide）

**关键硬边界：**
- 不抢话党不能写调色盘（违反会导致 AI 用标签预判用户行为）
- 抢话党必须写禁止部分（违反会导致 AI 过度代写）
- 用户信息 token ≤ 角色卡 1/4（违反会导致角色卡信息被挤出上下文）
- 写"我是什么"不写"我不是什么"（否定句式反而强化 AI 对否定词的关注）

**与相邻 skill 区分：**
- vs char-build-guide：用户侧 vs 角色侧
- vs worldbook-config：用户信息的内容写法归本 skill，用户信息条目的世界书配置归 worldbook-config

**关键局限（需诚实标注）：**
- 抢话/不抢话二分法过于简化，真实存在中间状态
- 用户信息在长对话中自然衰减（AI 从对话历史中积累了对用户的理解，用户信息作用递减）
- "token ≤ 角色卡 1/4"是作者经验值而非科学标准，需根据实际模型上下文窗口调整

**来源：Agent 2 §一（user-info-calibration 部分）, Agent 3 §B3**

## 四、跨 Skill 路由网络

Agent 2 绘制的路由关系：

```
用户入口
├─ 想写角色卡内容
│   ├─ 新手/快速上手/简单角色 → dialogue-persona
│   │   └─ 角色变复杂需要进阶 → 转 char-build-guide
│   └─ 深入构建/复杂角色/需要进阶 → char-build-guide
│       └─ 发现更喜欢台词/小传方式 → 转 dialogue-persona
├─ 角色内容已写好，需配置世界书 → worldbook-config
├─ 需要写用户信息 → user-info-calibration
│   └─ 如角色卡本身没写好 → 先去 char-build-guide / dialogue-persona
└─ 需要测试和迭代 → 当前无 skill 覆盖（B 段诚实标注缺口）
```

**路由关系类型：**
- CBG ↔ DPM：硬路由（二选一，不可混用，双方 B 段互相指向）
- CBG → WBC：顺序路由（角色卡完成后 → 配置世界书）
- CBG ↔ UIC：工具共享路由（抢话党用户信息借用调色盘方法）
- WBC ↔ UIC：配置协作路由（用户信息条目的配置归 WBC，内容归 UIC）

**来源：Agent 2 §二, §六**

## 五、教程深层矛盾清单（独立审阅视角）

Agent 3 识别了 6 个结构性问题，这些不是"写错了"而是"教程作为人类知识产品的固有局限"：

| # | 矛盾 | 对 skill 设计的启示 |
|---|------|-------------------|
| 1 | "AI 做不到"与"AI skill 做引导"的张力 | char-build-guide 的定位是"AI 引导你思考"，不是"AI 帮你写角色"。B 段必须明确这个定位 |
| 2 | "进阶不是必选"与教程体量的结构性矛盾 | Skill 主动判断是否激活进阶模式，不暴露给用户选 |
| 3 | "平替"的不对称（调色盘 10 篇 vs 台词人设 1 篇） | B 段诚实标注：台词人设在简单场景下是平替，复杂场景下不是等效替代 |
| 4 | token 预算的集体沉默（全部教程 0 讨论） | 所有 skill 的 B 段应有 token 成本意识 |
| 5 | SillyTavern 环境深度绑定 | worldbook-config 的 B 段标注平台依赖 |
| 6 | 追问模式预设"理想用户" | B 段标注适用条件：对"有画面但说不出来"的用户最有效；对"完全没有角色概念"的用户效果有限 |

**来源：Agent 3 §六**

## 六、B 段写作指南（跨 agent 共识提炼）

如果你要开始写正式的 SKILL.md，以下是关于 B 段的 6 条写作原则：

1. **B 段不是教程摘要，是路由器和防误触机制。** AI 读 B 段是为了判断"该不该触发"和"触发了不该做什么"。不要把教程的论证搬进来。

2. **硬边界用判断标准，不用模糊描述。** "角色卡 vs 用户信息"不是"看情况"，是"描述对象是 AI 演的角色还是 AI 读的用户"。

3. **失败模式分类呈现。** 致命级（毁掉角色）→ 严重级（降低质量）→ 中等级（影响细节）。AI 优先防致命级。

4. **翻译层矛盾显式处理。** "手写优于 AI 扩写"与 skill 是 AI 驱动、"衍生不适合 AI 直出"与推演是 AI 生成——这些矛盾不能回避，必须在 B 段中标注并给出处理方式。

5. **软边界标注组合可能性。** char-build-guide 和 dialogue-persona 不是绝对的互斥（用户可能在中间切换）。不要假装硬隔离。

6. **盲区诚实标注。** 同人角色、多角色交互、测试迭代、token 预算——这些覆盖不到的场景，B 段要让 AI 知道自己不该假装能处理。
