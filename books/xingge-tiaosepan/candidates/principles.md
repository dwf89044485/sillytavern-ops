# 原则 / 清单 / 规则 / 格言 候选提取结果

## 提取说明

从"性格调色盘"全部教程文本（原始11篇 + 大总结教程7章 + 问题库 + 工作流）中提取：
- **原则 (principle)**: 作者明确提出的"应该如何/不应该如何"的断言
- **清单 (checklist)**: 结构化的项目列表
- **规则 (rule)**: 可直接套用的强制判断规则
- **格言 (maxim)**: 作者反复强调的短句

以下按出现顺序组织，每条标注来源教程。

## 一、原则 (principles)

### 教程0：写"正确"的卡

- id: p01
  title: 基础信息与性格分开放
  type: principle
  source_chapter: 教程0/1.1
  source_quote: "性格不在这里写。性格有自己的条目。这里只写'这个人是谁'，不写'这个人是什么样的人'。"
  summary: 角色基础信息（姓名、外貌、背景、关系）必须与性格条目分离。混在一起会导致AI提前定型，后续性格内容与前面的标签打架。
  tags: [基础信息, 结构分离, 防标签化]

- id: p02
  title: 外貌只写特征不写美感
  type: principle
  source_chapter: 教程0/1.3
  source_quote: "外貌写的不是'美'，是'特征'。特征的意思是：只有这个角色才有的东西。"
  summary: 外貌描写应只写偏离AI数据库默认认知的、仅属于该角色的可辨识特征。禁止"精致""白皙""好看"等万能美人词汇。
  tags: [外貌, 特征差异化, 白描]

- id: p03
  title: 特征差异化原则
  type: principle
  source_chapter: 教程0/1.3
  source_quote: "AI有自己的数据库。你只需要写偏离数据库默认认知的部分。"
  summary: 角色外观中与种族/国籍/年龄的默认设定一致的内容不需要写。只写偏离默认值的特征，如异色瞳、特殊发色、疤痕等。
  tags: [外貌, 特征差异化, 默认值]

- id: p04
  title: 遮名辨认测试
  type: principle
  source_chapter: 教程0/1.3
  source_quote: "如果你把外貌描写遮住名字，能不能只靠这些特征认出是谁？能→写得好。不能→删掉，那是废话。"
  summary: 外貌描写的唯一检验标准：遮住名字后是否仍能辨认出角色。任何放在别的角色身上也成立的描写都是无效信息。
  tags: [外貌, 检验标准, 白描]

- id: p05
  title: 外貌不写比喻和意象
  type: principle
  source_chapter: 教程0/1.3
  source_quote: "外貌只写特征，不写美感描述。不写意象，不写比喻，不写'感觉'。白描、零度、干干净净。"
  summary: 外貌条目中禁止出现文学比喻（如"朝霞橙金"）、意象（如"晨光般暖白"）、感觉描述。只保留可验证的客观特征。
  tags: [外貌, 白描, 禁止项]

- id: p06
  title: 背景只写改变角色的事
  type: principle
  source_chapter: 教程0/1.4
  source_quote: "如果你发现自己写了十几条背景但删掉任何一条角色都没变化，那这条就是废的，删。"
  summary: 背景设定只保留对角色产生了实际影响、改变了角色状态的关键事件。与当前角色状态无关的童年琐事一律不写。
  tags: [背景, 精简, 因果]

- id: p07
  title: 关系写具体画面不写抽象形容
  type: principle
  source_chapter: 教程0/1.5
  source_quote: "不要写'他们之间有着深厚的感情'，写他们具体做了什么。"
  summary: 关系设定必须落到具体行为画面上，禁止抽象形容词。"收发作业时递本子"优于"没有私人交集"。
  tags: [关系, 具体化, 行为描写]

- id: p08
  title: 世界观是提示词不是小说设定集
  type: principle
  source_chapter: 教程0/2
  source_quote: "世界观不是小说设定集。世界观是提示词。用最少的字说清所有设定。不删核心要素，但也不留任何一个无用的词。"
  summary: 世界观是常驻提示词，每一轮对话都吃token。必须以极致压缩的数据库格式书写，每个多余的字都在浪费AI的记忆力和创作力。
  tags: [世界观, token精简, 提示词意识]

- id: p09
  title: 删了AI不会演错就删
  type: principle
  source_chapter: 教程0/2.1
  source_quote: "判断标准：删掉这句话，AI是否还能正确表现？能删就删。"
  summary: 世界观中每一句话的检验标准：删除后AI是否会演错。不会出错的内容就是废话，无论看起来多漂亮都要删除。
  tags: [世界观, 检验标准, 精简]

- id: p10
  title: 压缩不等于删除核心信息
  type: principle
  source_chapter: 教程0/2.2
  source_quote: "压缩是把'修炼者需要通过不断的修炼来提升自己的境界，境界从炼气期开始……'压缩成清晰的列表。删除是把'金丹期可御剑飞行，元婴期可神识外放'压缩成'修炼提升境界'——信息丢失了，这不可接受。"
  summary: 世界观的精简是信息压缩而非信息删除。检验标准：另一AI只看这份条目能否完整还原世界设定。能压缩到三个字的十个字信息要压缩，但不能把十个信息点压缩成三个。
  tags: [世界观, 压缩, 信息密度]

- id: p11
  title: 世界观语言零度白描
  type: principle
  source_chapter: 教程0/2.6
  source_quote: "世界观的语言要求比角色基础更严格。不写主观评价、不写比喻和意象、不写废话、能用列表就用列表。"
  summary: 世界观条目禁止主观评价（"强大的帝国"）、比喻（"如同天堑的裂谷"）、废话（"充满机遇与挑战的世界"）。格式应像数据库而非小说。
  tags: [世界观, 语言规范, 白描]

- id: p12
  title: 世界书名称禁用emoji
  type: principle
  source_chapter: 教程0/3.1
  source_quote: "世界书名字不要带emoji。太老版本的Node处理不了，会导致整个世界书消失。"
  summary: 世界书条目标题中禁止使用emoji，旧版Node不兼容会导致整本书数据丢失。
  tags: [世界书, 配置, 技术规范]

- id: p13
  title: 关键词必须用英文逗号分隔
  type: principle
  source_chapter: 教程0/3.2
  source_quote: "关键词的格式：必须用英文逗号隔开。不能用中文逗号，不能用空格，不能用分号。"
  summary: 世界书绿灯条目的关键词分隔符必须是英文半角逗号","。中文逗号"、"和空格均会导致关键词不触发。逗号后不要有空格。
  tags: [世界书, 关键词, 格式规范]

- id: p14
  title: D0放指导D1及以上不碰
  type: principle
  source_chapter: 教程0/3.3
  source_quote: "D0以外的深度，什么都不要放。D1就是倒数第一条消息和倒数第二条消息之间。你在那个位置插一段世界观设定，AI看来就是对话到一半突然冒出来一大段说明书。这会严重干扰AI对剧情的理解。"
  summary: 世界书条目只允许放在D0深度。D1及以上深度会插入到聊天记录的对话之间，破坏AI对剧情的理解，输出质量明显下降。
  tags: [世界书, D0, 配置规则]

- id: p15
  title: 所有条目强制勾选递归防护
  type: principle
  source_chapter: 教程0/3.5
  source_quote: "所有世界书条目，都必须同时勾选'不可递归'和'防止进一步递归'。无论蓝灯还是绿灯，无论什么位置，无论什么顺序，这两个勾必须打上。"
  summary: 世界书每个条目必须同时启用不可递归和防止进一步递归。不勾选的后果是绿灯条目间连锁触发导致token爆炸。
  tags: [世界书, 递归, 硬性规则]

- id: p16
  title: 单角色卡所有条目全蓝灯铁律
  type: principle
  source_chapter: 教程0/3.6
  source_quote: "单角色卡，所有条目全蓝灯。这是铁律。同一个角色拆成十个条目也还是一个角色。缺了任何一个条目，角色就不完整，AI就开始乱来。"
  summary: 只要世界书里只有一个核心角色（无论其设定拆成多少个条目），该角色的所有条目必须全部设为蓝灯常驻。不可因条目多而改绿灯省token。
  tags: [世界书, 单角色卡, 蓝灯, 铁律]

- id: p17
  title: EJS被控条目必须禁用
  type: principle
  source_chapter: 教程0/3.7
  source_quote: "这些条目是被EJS控制器通过代码动态加载的。它们自己不能开启。如果你手动开启了，所有阶段的内容会同时出现在AI的上下文里。让EJS控制器来管它们，你不要碰它们的开关。"
  summary: 由EJS控制器动态管理的条目必须将其enabled设为false。手动开启会导致多个阶段的内容同时暴露给AI，造成角色行为混乱。
  tags: [世界书, EJS, 配置规则]

- id: p18
  title: 关键词覆盖所有可能的称呼
  type: principle
  source_chapter: 教程0/3.8
  source_quote: "核心原则：覆盖所有可能被提到的称呼。角色条目的关键词：全名、昵称、外号。NPC条目的关键词：全名、昵称、外号、职务。"
  summary: 绿灯条目的关键词必须穷举该角色/场景/势力在对话中可能出现的所有称呼方式。漏任何一个称呼都可能导致应触发时未触发。
  tags: [世界书, 关键词, 完整性]

### 教程1：入门，性格调色盘

- id: p19
  title: 性格对冲去标签化原理
  type: principle
  source_chapter: 教程1/一
  source_quote: "如果在这个场景加入相反的性格会如何呢？比如我加入歇斯底里。结果场景是她哭的很狼狈，还轻锤了user几下。一个完全预料之外的场景出现了，AI会融合现有的所有的性格演绎。"
  summary: 给角色设置主性格+副性格+对冲性格（最少三个），利用AI的性格融合机制，产生不可预测的行为模式，从而去除标签化。手写卡不需要对冲，AI直出卡效果最明显。
  tags: [性格对冲, 去标签化, 惊喜感]

- id: p20
  title: AI参与创作的角色劣化最严重
  type: principle
  source_chapter: 教程1/二
  source_quote: "ai输出就意味它帮你把一些内容改成它资料库里认为'正确'的内容。我们在想法设法的摆脱ai的缺点，你让ai输出角色这不就是本末倒置，把你的内容加上Ai缺点了？"
  summary: 让AI扩写/生成角色设定等于让AI用其数据库中的刻板印象覆盖你的创意。严格区分三类创作模式：纯手写（AI仅改错字）、半手写（AI辅助输出）、AI直出（效果最差）。
  tags: [手写, AI扩写, 创作模式]

- id: p21
  title: 不通顺和重复可能是角色"活"的关键
  type: principle
  source_chapter: 教程1/二
  source_quote: "不通顺的句子，Ai需要重新思考这句话的真正含义，就会展开资料库查询。重复的话会存在'二次强调'的作用。你在创作时出现重复的内容，说明你的创作潜意识中，这部分是重要的。"
  summary: 作者手写的不通顺句子会迫使AI重新思考，打破其惯性输出。重复的内容蕴含作者的潜意识强调。不要删除这些"不完美"，它们反而让角色更鲜活。
  tags: [手写, 潜意识, 非完美性]

- id: p22
  title: 衍生是超级压缩包
  type: principle
  source_chapter: 教程1/三/7
  source_quote: "衍生就是一个超级压缩包，它压缩了很多东西，而ai是可以解开这个压缩包并使用的，这也是为什么我只需要写3000token就能轻松超越曾经4wtoken的角色卡。"
  summary: 性格衍生以极少token完成过去大量条目的效果。AI能自行"解压"衍生中编码的行为模式。这是调色盘体系高效的核心原因。
  tags: [衍生, token效率, 压缩]

- id: p23
  title: AI无法做到毫无关联的性格组合
  type: principle
  source_chapter: 教程1/三/5
  source_quote: "这是ai目前和未来一段时间做不到的、只有人类才能做的事：把毫无逻辑、毫无关联的两个性格组合在一起。"
  summary: 衍生中最有价值的内容是AI数据库里不存在关联的性格组合（如"社恐"衍生出"社交达人面具"）。AI只会沿数据库的常规路径展开，人类作者才能写出反直觉的独特组合。
  tags: [衍生, 人类优势, 反直觉]

- id: p24
  title: 二次解释填补演绎指导的缺陷
  type: principle
  source_chapter: 教程1/四
  source_quote: "二次解释完美填补了'演绎指导'的缺点，那就是'演绎指导'是Ai觉得这个角色应该这么演，直接把你的角色变成了Ai输出的内容了。"
  summary: 传统演绎指导是让AI替作者决定角色如何表现，二次解释则是由作者直接定义角色的表现方式。本质上是把角色写成了"预设"结构，让AI进行标签召回和二次思考。
  tags: [二次解释, 演绎指导, 作者主权]

- id: p25
  title: 写自己作为第一个角色
  type: principle
  source_chapter: 教程1/六
  source_quote: "如果你不知道怎么开始写第一个角色，就写自己！如果你发现你写的自己和本人很像！那就成功了。"
  summary: 初学者写第一个角色时不应凭空想象，应从写自己开始。能写像自己是入门标志。
  tags: [入门, 自写, 实战]

### 教程2：三面性

- id: p26
  title: 三面性本质是生存策略不是三种性格
  type: principle
  source_chapter: 教程2/一
  source_quote: "三面性的本质是：一个人在不同压力环境下，启动了不同的生存策略。关键词是'生存策略'。不是她想怎么表现，而是她的经历和本能替她做的选择。"
  summary: 三面性的每一面不是独立性格标签，而是同一台发动机在不同压力路况下的不同档位。先有调色盘（发动机），再有三面性（档位切换）。
  tags: [三面性, 生存策略, 压力场景]

- id: p27
  title: 面的数量由角色决定不由名字决定
  type: principle
  source_chapter: 教程2/二
  source_quote: "你的角色如果只有两种截然不同的行为模式，那就写两面。如果有四种，那就写四面。不要为了凑'三'硬拆，也不要为了省事把该拆的合并。"
  summary: "三面性"只是写法的名字，不代表必须有三张面。可两面、四面甚至更多。面的数量由角色在不同场景下的实际行为差异决定。
  tags: [三面性, 灵活性, 角色驱动]

- id: p28
  title: 不是所有角色都需要三面性
  type: principle
  source_chapter: 教程2/三
  source_quote: "当调色盘的衍生不足以描述角色在不同场景下的行为差异时，就需要三面性。行为差异不大的角色用调色盘衍生就能覆盖。"
  summary: 三面性是工具而非必选项。只有当角色在不同场景下存在"根本性的行为模式切换"时才需要。找不出两种以上压力性质截然不同的场景，就不需要三面性。
  tags: [三面性, 可选, 判断标准]

- id: p29
  title: 先有调色盘再有三面性
  type: principle
  source_chapter: 教程2/四
  source_quote: "先有调色盘，再有三面性。没有调色盘的三面性是空壳。调色盘回答的问题是：这个人是什么做的？三面性回答的问题是：同样这些材料，在不同房间里怎么组合？"
  summary: 写作顺序必须是调色盘先于三面性。三面性只是同一盘颜料在不同场景下按不同比例混合。没有调色盘的三面性会变成三个独立人格的拼接。
  tags: [三面性, 写作顺序, 调色盘]

- id: p30
  title: 三面性每面必须有五个部件
  type: principle
  source_chapter: 教程2/五
  source_quote: "每一张面不是一个标签，是一个完整的行为系统。五个部件：触发条件、能量状态、语料、身体行为模式、功能。缺一个都不完整。"
  summary: 三面性的每张面必须完整包含五个部件。缺任何一个，AI对该面的理解就会出现漏洞。
  tags: [三面性, 五部件, 完整性]

- id: p31
  title: 有三面性则语料从调色盘移出
  type: principle
  source_chapter: 教程2/八
  source_quote: "有三面性的角色→语料从调色盘里剔除，放到三面性的每一张面里。没有三面性的角色→语料留在调色盘里。"
  summary: 如果角色写了三面性，所有具体台词必须从调色盘移除，分别放入对应面的语料区。因为不同面的说话方式完全不同，混在调色盘里AI分不清什么时候用哪套。
  tags: [三面性, 语料分流, 写作顺序]

- id: p32
  title: 面与面之间必须写过渡
  type: principle
  source_chapter: 教程2/六
  source_quote: "最少写两组过渡：最常见的切换路径和最剧烈的切换路径。"
  summary: 三张面不是硬切换，是渐变。至少写两组过渡场景描述，展示角色如何在面之间平滑转换。
  tags: [三面性, 过渡, 完整性]

- id: p33
  title: 必须写渗透——一面运行时其他面的泄漏
  type: principle
  source_chapter: 教程2/六
  source_quote: "一张面运行中，其他面的元素会不会泄漏出来？这些泄漏是角色最真实的瞬间。"
  summary: 在每张面的描述之外，必须补充"渗透"部分：A面运行时B面的元素偶尔泄漏的瞬间。这些渗透是角色真实感的来源。
  tags: [三面性, 渗透, 真实感]

- id: p34
  title: 三面性只写"怎么运作"不写"为什么"
  type: principle
  source_chapter: 教程2/九/错误一
  source_quote: "如果你写的内容里出现了'因为''本质上''其实''内心'这些词，大概率你在写二次解释，不是三面性。三面性不管'为什么'。三面性只管'怎么运作'。"
  summary: 三面性内容中禁止出现解释性词汇。为什么角色在某面如此表现，交给二次解释负责。三面性只描述客观运行参数。
  tags: [三面性, 边界, 二次解释]

### 教程3：台词先行

- id: p35
  title: 调色盘是主方案台词人设是特化方案
  type: principle
  source_chapter: 教程3/二
  source_quote: "调色盘是主方案。万用型，什么模型什么角色都能跑。台词人设是特化方案。两者不冲突，但也不混用。一个角色要么用调色盘写，要么用台词人设写。"
  summary: 调色盘和台词人设是两种独立的写作方案，不可混用。大部分角色用调色盘，仅当模型表现生硬、台词像AI时才切换为台词人设。
  tags: [台词人设, 方案选择, 互斥]

- id: p36
  title: 台词人设只写台词和第三人称解释
  type: principle
  source_chapter: 教程3/三
  source_quote: "不写性格标签，不写衍生，不写二次解释，不写背景故事。就是她说的话，加上一个旁观者对这句话的分析。"
  summary: 台词人设只包含两个元素：角色台词+第三人称旁观者分析。其余一切设定（性格、衍生、背景）全部省略。
  tags: [台词人设, 极简, 格式]

- id: p37
  title: 第三人称解释是观察不是代入
  type: principle
  source_chapter: 教程3/四
  source_quote: "你不是她。你是在看她。你不知道她心里在想什么，你只能根据她说的话、说话时的状态，去猜测、去分析。但你的猜测不是结论。"
  summary: 第三人称解释的写作立场必须是"外部观察者"而非"角色内心代言人"。只能描述听见了什么、看见了什么、做出推测但不下结论。
  tags: [台词人设, 观察视角, 第三人称]

- id: p38
  title: 存疑打断AI惯性
  type: principle
  source_chapter: 教程3/五
  source_quote: "存疑干的事情就是：不给结论。打断AI的惯性思考。AI被迫在每次生成时重新根据当前上下文判断。每句话都要重新想。角色就活了。"
  summary: 台词解释中始终保留"不确定""是否真的XX存疑"的判断，不给AI下结论的空间。这迫使AI每次都要重新判断角色说话的真实含义，防止角色僵化。
  tags: [台词人设, 存疑, 防僵化]

- id: p39
  title: 台词不要分类写
  type: principle
  source_chapter: 教程3/六
  source_quote: "不要写'对外人的台词''对{{user}}日常的台词'。一旦你分了类，你就在告诉AI'她在这种场景下应该这样说话'。这和写标签有什么区别？"
  summary: 台词人设中所有台词打散混合写出，不按场景/对象分类。让AI自己从几百句话里提取说话模式，而不是按作者预设的标签分类演绎。
  tags: [台词人设, 不分类, AI自主学习]

### 教程4：混色

- id: p40
  title: 混色不是转折也不是伪装
  type: principle
  source_chapter: 教程4/二
  source_quote: "不是'先笑后哭'，那是转折。不是'表面在笑内心在哭'，那是伪装。是笑本身就含着哭。同一个动作里，温柔和自私住在一起。"
  summary: 混色的本质是同一个瞬间同一个动作中同时存在多种情绪。区别于先后出现的"转折"和内外不一致的"伪装"。情绪在同一个动作里共存而非分离。
  tags: [混色, 定义, 同步性]

- id: p41
  title: 先有调色盘再有混色
  type: principle
  source_chapter: 教程4/三
  source_quote: "先有调色盘，再有混色。没有调色盘的混色是一团糨糊。调色盘回答这个人身上有哪些颜色，混色回答这些颜色在同一笔里怎么搅。"
  summary: 混色的前提是已经通过调色盘明确了角色有哪些颜色。直接写混色而不先构建调色盘，AI会读成角色情绪不稳定。
  tags: [混色, 写作顺序, 调色盘]

- id: p42
  title: 混色不解释只写动作
  type: principle
  source_chapter: 教程4/四
  source_quote: "不要写'她同时感到温柔和悲伤'。这是解释，不是画面。写动作。写她做了什么，说了什么，身体怎么动的。让情绪从动作里长出来。"
  summary: 混色画面中绝对禁止情绪解释（"她感到XX和XX交织"）。只写角色做了什么、说了什么、身体如何反应。情绪通过画面自然溢出。
  tags: [混色, 动作描写, 不解释]

- id: p43
  title: 物理事实反差技巧
  type: principle
  source_chapter: 教程4/四
  source_quote: "'她说'就是有点热'。那天是阴天，不算热。'前半句是她说的话，后半句是物理事实。两句话放在一起，不需要解释'她在撒谎'或者'她在隐瞒身体不适'，读的人自己就看出来了。"
  summary: 混色最好用的技巧：将角色的台词/行为与一个客观物理事实并置，两者的反差自动产生情绪层次。不解释，只摆事实。
  tags: [混色, 物理事实, 反差]

- id: p44
  title: 混色是点睛之笔不是底色
  type: principle
  source_chapter: 教程4/五/错误二
  source_quote: "不是每个瞬间都需要多种颜色在跑。如果你的角色每一秒都在体验复杂情绪，AI会读成'她情绪不稳定'。混色的画面是点睛之笔，不是底色。"
  summary: 大部分时间角色情绪可以相对单一。混色只出现在颜色撞到一起的特定关键瞬间。全篇混色等于没有混色，反而让角色显得情绪不稳定。
  tags: [混色, 频率控制, 点睛]

- id: p45
  title: 混色禁用转折句标记
  type: principle
  source_chapter: 教程4/五/错误四
  source_quote: "'她笑了——但那个笑里藏着说不出的苦涩。'这是在用文学手法强行告诉读者'注意这里有反差'。AI读了以后会模仿这种'——但'的句式，出来的效果是八股味的。"
  summary: 混色画面禁止使用"但""然而""——"等转折标记来提示反差。让两种颜色的事实直接并置，无需任何标记，读者自己完成混合。
  tags: [混色, 八股防护, 语言规范]

### 教程5：开场白

- id: p46
  title: 开场白必须制造事件给引子
  type: principle
  source_chapter: 教程5/2.1
  source_quote: "如果开场白十分简单，没有制造任何矛盾，没有创造任何目标让角色去行动。那么这样一个角色卡，玩家拿到手上会不知所措，不知道该玩什么。"
  summary: 开场白必须主动制造一个事件/矛盾/目标，让玩家拿到卡就知道要做什么。没有引子的开场白等于没有起点。
  tags: [开场白, 引子, 目标]

- id: p47
  title: 开场白固定文风延缓劣化
  type: principle
  source_chapter: 教程5/2.2
  source_quote: "如果开场白主动规避llm爱用的八股句式，后续生成时会很大程度延缓文风劣化的速度。反过来说，如果开场白就包含大量的投石，指节泛白。玩的时候就会很容易出现这些八股。"
  summary: 开场白是后续文风的模板。首楼规避八股句式，后续AI也会更少输出八股。首楼就用八股，后续八股泛滥。
  tags: [开场白, 文风, 八股防护]

- id: p48
  title: 完全手写开场白效果最好
  type: principle
  source_chapter: 教程5/3.1
  source_quote: "自己写是最好的，也最不容易八股。你写的只要做到没有llm的八股，就比llm写的强了。放手去写就好了，大白话也没关系的。"
  summary: 手写开场白（哪怕是大白话）天然优于AI生成的开场白，因为不含AI的八股句式。不知道怎么写可以先让AI写然后用自己的话重写。
  tags: [开场白, 手写, 八股防护]

### 教程6：纯文字卡实战

- id: p49
  title: 写卡第一步想清楚核心驱动力
  type: principle
  source_chapter: 教程6/一
  source_quote: "写卡的第一步，想清楚三件事：这个角色的核心驱动力是什么？用户会怎么玩？这张卡能玩多久？"
  summary: 在写任何设定之前，必须先回答三个设计问题：角色为什么"活着"、用户玩什么、能玩多少轮。骨架清楚了再写人设。
  tags: [设计先于写作, 核心驱动力, 长期性]

- id: p50
  title: 每个角色身上有"绝对的内核"必须一开始定死
  type: principle
  source_chapter: 教程6/三
  source_quote: "每个角色身上都有一个'绝对的东西'，一个不管发生什么都不会改变的内核。你要在一开始就把它定死，后面所有的设计都围着它转。"
  summary: 在写任何衍生和画面之前，必须先确定角色"绝对不变的内核"。所有后续设计——画面、衍生、两面性、进化规则——都围绕这个内核展开。不在一开始定死会中途摇摆。
  tags: [内核, 设计先于写作, 不变量]

- id: p51
  title: 角色经历变故后原调色盘要做转换
  type: principle
  source_chapter: 教程6/二
  source_quote: "如果角色经历了重大变故，你需要想清楚'原来的调色盘里哪些颜色还在，哪些没了，哪些变形了'。"
  summary: 当角色经历过丧尸化、失忆、时间跳跃等重大变故时，必须对原调色盘逐一做"转换分析"：哪些颜色消失、哪些保留、哪些变形。不是直接扔掉旧的写新的。
  tags: [调色盘, 角色变化, 转换]

- id: p52
  title: 作者自己必须先被角色打动
  type: principle
  source_chapter: 教程6/十
  source_quote: "写卡最重要的一件事，整个流程里最核心的一步：你自己得先被你的角色打动。如果这个画面没有打动我，写出来的东西也打动不了任何人。"
  summary: 无法被自己角色打动的人，写出的东西也无法打动任何人。那个最打动你的画面是整张卡的驱动力来源。
  tags: [创作动机, 内驱力, 设计]

- id: p53
  title: 变化给新鲜感不变给安全感
  type: principle
  source_chapter: 教程6/八
  source_quote: "变化的东西给用户新鲜感，不变的东西给用户安全感。两个加在一起，用户就能玩很久。"
  summary: 角色卡长期可玩性的底层逻辑：给角色设计可变化的维度（进化、分支），同时锚定一个永不改变的内核。两者缺一不可。
  tags: [长期性, 变化与不变, 设计]

### 教程7：核心人格层

- id: p54
  title: 核心人格层是决策发动机
  type: principle
  source_chapter: 教程7/二
  source_quote: "核心人格层更接近于角色的决策发动机。它回答的是：这个人以为自己想要什么、真正缺什么、最怕什么、怎么保护自己、这种保护为什么会伤到自己和别人。"
  summary: 核心人格层不描述性格质地（那是调色盘的工作），而是定义角色在压力下的决策逻辑。七个组成部分构成角色的判断系统。
  tags: [核心人格层, 决策, 七部分]

- id: p55
  title: 核心人格层和混色一样是进阶选择
  type: principle
  source_chapter: 教程7/六
  source_quote: "进阶不是必选。进阶是当角色真的需要时，你有更强的工具。纯日常小甜饼、没有明显内部矛盾的角色不需要核心人格层。"
  summary: 核心人格层不是所有角色都需要的。适合有明确剧情驱动、内部矛盾、防御机制的复杂角色。纯甜饼角色硬写反而会让AI在日常乱开高潮戏。
  tags: [核心人格层, 可选, 进阶]

- id: p56
  title: 核心人格层从原人设里提炼不推翻原人设
  type: principle
  source_chapter: 教程7/七
  source_quote: "不要推翻原人设。不要拿一套新理论把原角色重写成另一个人。你要做的是从原人设里提炼。"
  summary: 核心人格层不是替换调色盘，而是从已有调色盘中向下深挖一层。从主色调反推表层欲望，从被压住的颜色反推深层缺失，从背景找核心恐惧。
  tags: [核心人格层, 提炼, 兼容]

- id: p57
  title: 防御机制必须落到具体行为
  type: principle
  source_chapter: 教程7/七
  source_quote: "防御机制必须能落到行动上。'逃避'太空了。要写'她一旦察觉自己开始依赖{{user}}，就会故意把话说轻，说成玩笑，或者主动消失一段时间，让关系重新退回安全距离。'"
  summary: 核心人格层的防御机制不能只写一个词（"逃避""嘴硬"），必须展开为具体可被执行的行为描述。AI只能演行为，不能演标签。
  tags: [核心人格层, 防御机制, 行为化]

- id: p58
  title: 核心矛盾必须一句话说清
  type: principle
  source_chapter: 教程7/七
  source_quote: "核心矛盾最好一句话说完。一句话能说清，AI就能抓住。"
  summary: 核心矛盾必须浓缩为一句话。能一句话说清的矛盾AI才能准确理解和执行。例如"她渴望亲密，却把每一次靠近都理解成危险"。
  tags: [核心人格层, 核心矛盾, 一句话]

- id: p59
  title: 自我认知写可能性不写固定结局
  type: principle
  source_chapter: 教程7/七
  source_quote: "自我认知不是剧情结局。AIRP不是剧本。更好的写法：她可能意识到……注意可能。角色可以完成弧光。也可以失败。失败同样有张力。"
  summary: 自我认知必须写为"可能性"而非"结尾"。角色可以成长也可以退回去，可以在这次前进下次又后退。写成确定结局等于替玩家写好了剧本。
  tags: [核心人格层, 自我认知, 开放性]

- id: p60
  title: 日常不要频繁触发核心恐惧
  type: principle
  source_chapter: 教程7/十五/错误二
  source_quote: "核心恐惧不是每次都要爆。{{user}}晚回一句消息，不等于角色立刻崩溃。日常里可以泄漏一点。但不要每次都进入高潮戏。核心人格层是底层逻辑，不是天天按下去的核按钮。"
  summary: 核心恐惧只在被真正触碰时触发。日常互动中最多轻微泄漏（多看一眼手机、话变少一点），不应每次都爆发出极端反应。否则角色显得过度敏感。
  tags: [核心人格层, 频率控制, 日常]

- id: p61
  title: 核心矛盾不应只围着{{user}}
  type: principle
  source_chapter: 教程7/十五/错误五
  source_quote: "角色可以爱{{user}}，但她的人格不能只为{{user}}存在。更好的写法是：她本来就害怕依赖，{{user}}只是第一个让她不得不面对这件事的人。"
  summary: 核心人格层的矛盾应是角色性格中固有的，而非"为了和{{user}}谈恋爱而临时长出来的"。{{user}}是触发者而非矛盾的全部原因。
  tags: [核心人格层, 独立性, {{user}}关系]

- id: p62
  title: 写得准比写得惨重要
  type: principle
  source_chapter: 教程7/十五/错误四
  source_quote: "不是所有核心人格层都必须来自极端创伤。有些人的核心恐惧来自长期被忽视、来自一直被比较、来自从来不被认真听。写得准比写得惨重要。"
  summary: 核心恐惧和深层缺失不必来自极端童年创伤。来自日常积累的细微心理伤害（长期被忽视、每次表达需求都被嫌麻烦）同样有效，关键在于写得准而非写得戏剧化。
  tags: [核心人格层, 准确性, 反套路]

### 教程9：用户信息

- id: p63
  title: 用户信息是给AI读的不是给AI演的
  type: principle
  source_chapter: 教程9/一
  source_quote: "角色卡是给AI演的。用户信息是给AI读的。它的作用是：补充用户输入内容，让AI扮演的角色做出正确的反应。"
  summary: 用户信息与角色卡的定位根本不同。角色卡是让AI变成角色，用户信息是让AI理解用户。用户信息本质是提示词，校准AI对用户行为的解读。
  tags: [用户信息, 定位, 提示词]

- id: p64
  title: 不抢话党不写调色盘
  type: principle
  source_chapter: 教程9/五
  source_quote: "不抢话党的AI不扮演你。AI只扮演角色。所以你不需要写调色盘。调色盘是给AI演的你更需要写的是：我做这些事的时候，是什么意思。"
  summary: 不抢话党（只写自己行为等AI回复的玩家）的用户信息不应包含调色盘/性格衍生。应写"行为翻译手册"——肢体接触含义、语气真实含义、情绪表达方式。
  tags: [用户信息, 不抢话党, 行为翻译]

- id: p65
  title: 抢话党必须写禁止部分
  type: principle
  source_chapter: 教程9/四
  source_quote: "特征后面必须跟禁止说明。白色短发（禁止频繁描写，仅初次见面的角色时可适当插入）。因为AI一旦知道你'白发'，它就会在每一段描写里都提你的白发。"
  summary: 抢话党用户信息中每个外貌特征后必须跟"禁止频繁描写/仅在XX情况可提"的限定说明，防止AI在每句回复中都反复提及同一特征。
  tags: [用户信息, 抢话党, 禁止部分]

- id: p66
  title: 不写"我不是什么"只写"我是什么"
  type: principle
  source_chapter: 教程9/八/错误四
  source_quote: "这种写法有一个致命问题：AI读到'不是冷漠'，它脑子里第一个蹦出来的词就是冷漠。正确写法是直接写是什么。"
  summary: 用户信息中禁止用否定句式定义行为（"{{user}}不是冷漠的人"）。直接写正面定义（"{{user}}表达关心的方式是行动而非语言"），避免AI被否定句中的关键词触发。
  tags: [用户信息, 否定句式, 避免]

- id: p67
  title: 用户信息token不超角色卡四分之一
  type: principle
  source_chapter: 教程9/八/错误五
  source_quote: "用户信息不是主角。角色才是主角。用户信息的token量应该控制在角色卡的四分之一以下。写多了，AI的注意力会被你的用户信息抢走。"
  summary: 用户信息的体积必须严格控制。超过角色卡四分之一的token量会导致AI注意力从角色身上偏移。
  tags: [用户信息, token控制, 比例]

### 大总结教程

- id: p68
  title: 基础信息中不写性格
  type: principle
  source_chapter: 大总结/01/二
  source_quote: "如果你在基础信息里就写了'极度自卑、沉默寡言、极致善良'，AI还没读到你后面精心写的调色盘和衍生，就已经对这个角色定型了。它会用最刻板的方式去演绎。"
  summary: 基础信息条目中绝对不能出现性格标签。AI读到基础信息中的性格词会直接定型，后续调色盘写的再精细也打不过前面先入为主的标签。
  tags: [基础信息, 性格分离, 防标签化]

- id: p69
  title: AI读到形容词输出形容词AI读到行为输出行为
  type: principle
  source_chapter: 大总结/01/六
  source_quote: "AI读到形容词会输出形容词。AI读到行为会输出行为。你希望你的角色被AI演成一个会观察细节的人，就给AI具体的观察细节。"
  summary: 关系设定和背景描写中必须用具体行为替代抽象形容词。AI的输出质量直接取决于输入的质量类型——输入画面输出画面，输入总结输出复述。
  tags: [关系, 行为描写, AI特性]

- id: p70
  title: 标签导致频道切换衍生导致颜色融合
  type: principle
  source_chapter: 大总结/02/开头
  source_quote: "七个标签堆在一起，AI不会融合它们。它会轮流切换，像在换频道。这一段演'自卑'，下一段演'善良'，再下一段演'坚韧'。"
  summary: 性格标签列表的最大问题是AI无法融合——它只会按频道轮流切换表演。调色盘+衍生的写法让AI理解颜色如何同时运行、互相渗透。
  tags: [调色盘, 标签化, 融合]

- id: p71
  title: 不要在标签前加极端放大器
  type: principle
  source_chapter: 大总结/02/二
  source_quote: "绝对不要在前面加'极度''极致'这种放大器。AI会把一切往最极端的方向拉，角色就失去了弹性。"
  summary: 性格描述中禁止使用"极度""极致""非常"等程度副词。AI读到这些放大器会机械地推向极端，角色失去所有层次和弹性。
  tags: [调色盘, 语言规范, 弹性]

- id: p72
  title: 衍生是只有人类能写的反直觉组合
  type: principle
  source_chapter: 大总结/02/二
  source_quote: "AI不会把'自卑'和'话多'联系在一起，因为它的数据库告诉它这两样东西不常共存。这些反直觉的组合，只有你自己才能想到。"
  summary: 衍生中真正有价值的是AI数据库里不存在关联的性格组合。AI只会沿常规路径展开（"自卑→不敢看人"），人类作者才能写出"自卑的人反而话特别多"这种独特性。
  tags: [衍生, 人类优势, 反直觉]

- id: p73
  title: 二次解释放最后面效果最强
  type: principle
  source_chapter: 大总结/06/五
  source_quote: "你把二次解释放在最后，AI最后读到的东西会在它开始写正文时有更强的'记忆残留'。最后读到的备注，效果最强。"
  summary: 完整的写作顺序：基础信息→调色盘→三面性→混色画面→核心人格层→二次解释→意象。二次解释因是AI在生成正文前最后读到的内容，纠正效果最强。
  tags: [二次解释, 位置, 写作顺序]

- id: p74
  title: 意象从角色本身长出来不从外部套用
  type: principle
  source_chapter: 大总结/07/四
  source_quote: "不要去网上搜'好看的比喻'然后往角色身上套。意象要从你对角色的理解里自然生长。你想她像什么，这个'像'必须能承载她的核心状态。"
  summary: 意象必须从角色自身的核心矛盾和存在状态中生长出来，不能从外部搬一个好看的比喻套上去。珞蒹葭的风铃从"随缘""被动"中长出，不是搜来的。
  tags: [意象, 内生, 核心状态]

- id: p75
  title: 意象要短且不解释自己
  type: principle
  source_chapter: 大总结/07/四
  source_quote: "意象不是小作文。几段话就够了。它的力量在于浓缩。和混色画面一样——写完放在那里。不要在意象后面加一段'这个意象的含义是……'。让它自己发光。"
  summary: 意象应控制在几段话以内，写完即止不加任何解释注解。其力量在浓缩而非详尽展开。
  tags: [意象, 长度控制, 不解释]

### 教程11：另一种写法

- id: p76
  title: 你写的每个字都在替AI选联想词
  type: principle
  source_chapter: 教程11/一
  source_quote: "你写的每一个字，都在替AI选联想词。你写得越像你自己的话、越具体、越有画面，AI接出来的内容就越像一个活人。你写得越像AI会写的东西，AI接出来的就越像AI。"
  summary: AIRP的底层机制就是AI的联想词预测。角色卡中写的所有字都在修改AI下一个词的选择概率。越具体独特的内容越产生非模板化输出。
  tags: [底层原理, 联想词, 独特性]

- id: p77
  title: 手写效果优于AI扩写的根本原因
  type: principle
  source_chapter: 教程11/一
  source_quote: "你让AI扩写'温柔'，AI写出来的就是它数据库里'温柔'最常见的那套。你再把这套东西喂回给AI去扮演，等于你用AI最常见的联想词告诉AI'你应该联想这些'。那它当然还是联想到一模一样的东西。等于什么都没改。"
  summary: AI扩写的性格内容等于把数据库中最常见的模板喂回给AI。手写的独特内容因为没有和标签绑定过，能迫使AI走一条新路径。
  tags: [手写, AI扩写, 联想词]

- id: p78
  title: 小传只写五官能感受到的
  type: principle
  source_chapter: 教程11/三
  source_quote: "小传里只写：她做了什么、她说了什么、她的表情变化、她的身体动作、环境里发生了什么。不写'她觉得'。不写'她心想'。不写'因为'。不写'其实'。"
  summary: 小传（替代调色盘衍生的入门写法）严格限制为感官可验证的内容——画面、声音、动作。禁止一切内心活动、因果解释和结论性描述。
  tags: [小传, 感官描写, 零度]

- id: p79
  title: 喜怒哀乐衰写的是阈值不是样子
  type: principle
  source_chapter: 教程11/五
  source_quote: "这一章写的不是情绪的样子。写的是情绪的阈值。什么让她从正常状态变成开心。什么让她从开心停下来。什么让她从正常状态变成愤怒。什么让她从愤怒冷却。"
  summary: 情绪描写的重点不是"开心时她笑"的外观，而是触发条件（什么让她进入这种情绪）、变化轨迹（从弱到强的曲线）、结束方式（怎么从情绪中出来）。这给AI的是一套情绪运行规则。
  tags: [情绪, 阈值, 轨迹]

- id: p80
  title: 基础信息严格分离性格
  type: principle
  source_chapter: 教程11/二
  source_quote: "性格不在这里写。性格有自己的地方。因为你在基础信息里写了'极度自卑、沉默寡言'，AI还没读到你后面精心写的小传和采访，就已经拿着这两个标签开始联想了。"
  summary: 即使在入门写法中，基础信息与性格也必须严格分离。AI读到基础信息中的性格标签会先入为主地定型。
  tags: [基础信息, 性格分离, 入门]

### 问题库

- id: p81
  title: 24问答不出就不要碰高级工具
  type: principle
  source_chapter: 问题/24问
  source_quote: "如果用户连24问都答不出来，就不要急着让她写调色盘、混色、三面性、核心人格层。因为那时候的问题不是写法不够高级，而是角色还没有在作者脑子里站起来。"
  summary: 在角色核心（一句话定义、颜色、欲望恐惧）都没想清楚之前，不应跳级去写调色盘或更高级的写作工具。先用入门24问把角色轮廓立起来。
  tags: [入门, 阶段, 24问]

- id: p82
  title: 回答标签要继续追问行为
  type: principle
  source_chapter: 问题/24问
  source_quote: "如果答案只有标签，要继续问：它具体会做什么？它什么时候出现？它为什么会出现？它会不会伤到别人？"
  summary: 任何仅以标签形式（"她很温柔""她很傲娇"）给出的回答都不合格。必须追问到行为层面：具体做什么、何时出现、原因、后果。
  tags: [问答, 追问, 行为化]

- id: p83
  title: 200问是抽题卡住时用不是一次答完
  type: principle
  source_chapter: 问题/200问
  source_quote: "它适合当用户卡住时抽题，不适合一上来压给新手。如果用户一上来就被要求回答200问，大概率会从创作变成考试。"
  summary: 200问题库不是必答列表，而是卡住时按需抽题的参考工具。分24问（入门）、80问（正式）、200问（补题）三个梯度递进使用。
  tags: [问答, 梯度, 工具化]

- id: p84
  title: AI问答工作流只提问不替用户写人设
  type: principle
  source_chapter: 问题/工作流
  source_quote: "你的任务不是替用户写人设，不是扩写角色卡，不是生成完整设定。你的任务是根据用户选择的模式，通过循环问答帮助用户整理角色思路。"
  summary: AI辅助问答工作流的定位是"思路整理助手"而非"人设生成器"。AI只负责提问、追问、记录、归纳，绝不替用户决定未知设定。
  tags: [工作流, AI辅助, 边界]

  type: checklist
  source_chapter: 大总结/03/九
  source_quote: "如果回答以下问题都是'否'，就不需要三面性：她在不同场景下的说话方式差异大到像两个人吗？她在不同场景下的身体状态差异大到可以明确区分吗？她的行为模式切换是因为面对的压力性质截然不同吗？"
  summary: 判断角色不需要三面性的三项否定检查。全部否定的角色用调色盘衍生即可覆盖。
  tags: [三面性, 不需要, 判断]


## 三、规则 (rules)

- id: r01
  title: 世界书递归双勾铁律
  type: rule
  source_chapter: 教程0/3.5
  source_quote: "所有世界书条目，都必须同时勾选'不可递归'和'防止进一步递归'。无论蓝灯还是绿灯，无论什么位置，无论什么顺序，这两个勾必须打上。"
  summary: 绝对规则：每个世界书条目无条件勾选不可递归+防止进一步递归。不勾选导致连锁触发token爆炸。
  tags: [世界书, 递归, 无条件]

- id: r02
  title: 单角色卡全蓝灯铁律
  type: rule
  source_chapter: 教程0/3.6
  source_quote: "单角色卡，所有条目全蓝灯。这是铁律。不要因为条目多就改绿灯。缺了任何一个条目，角色就不完整，AI就开始乱来。"
  summary: 绝对规则：只要世界书只有一个核心角色，该角色所有条目必须全蓝灯常驻。禁止为了省token而改绿灯。
  tags: [世界书, 单角色卡, 无条件]

- id: r03
  title: D1及以上绝对不碰
  type: rule
  source_chapter: 教程0/3.3
  source_quote: "D1、D2、D3……不要放任何东西。D0以外的深度，什么都不要放。"
  summary: 绝对规则：世界书条目只允许使用D0深度。D1及以上任何深度都不放内容。
  tags: [世界书, D0, 无条件]

- id: r04
  title: 关键词英文逗号格式
  type: rule
  source_chapter: 教程0/3.2 + 教程0/3.8
  source_quote: "必须用英文逗号隔开。正确：林小雨,小雨,班长。错误：林小雨，小雨，班长（中文逗号）。错误：林小雨 小雨 班长（空格）。错误：林小雨, 小雨, 班长（逗号后空格）。"
  summary: 绝对规则：世界书绿灯条目关键词必须用英文半角逗号分隔，逗号后不加空格。中文逗号、空格、分号均导致触发失效。
  tags: [世界书, 关键词, 格式]

- id: r05
  title: 世界书名称禁止emoji
  type: rule
  source_chapter: 教程0/3.1
  source_quote: "世界书名字不要带emoji。太老版本的Node处理不了，会导致整个世界书消失。"
  summary: 绝对规则：世界书条目/书名中不得包含任何emoji字符。版本兼容性问题可导致数据丢失。
  tags: [世界书, 技术规范, 禁止]

- id: r06
  title: EJS被控条目必须禁用
  type: rule
  source_chapter: 教程0/3.7
  source_quote: "状态：禁用（enabled设为false）。这些条目是被EJS控制器通过代码动态加载的。它们自己不能开启。"
  summary: 绝对规则：所有由EJS控制器动态管理的条目必须将enable设为false。手动开启导致多阶段内容同时暴露。
  tags: [世界书, EJS, 禁止手动开启]

- id: r07
  title: D0的role必须选system
  type: rule
  source_chapter: 教程0/3.3
  source_quote: "注意：D齿轮的role要选system。"
  summary: 绝对规则：D0深度的世界书条目role必须设为system。
  tags: [世界书, D0, role]

- id: r08
  title: AI绝不参与创作
  type: rule
  source_chapter: 教程1/二 + 教程1/五
  source_quote: "绝不能让Ai代替你成为创作者！Ai一旦参与创作，在ai扮演中劣化最严重的！"
  summary: 绝对规则：创作阶段AI只可做格式整理和错别字修正，不可对内容进行任何扩写、生成、修改。让AI写角色等于把AI的缺点注入你的角色。
  tags: [手写, AI辅助, 边界]

- id: r09
  title: 调色盘和台词人设不混用
  type: rule
  source_chapter: 教程3/二
  source_quote: "两者不冲突，但也不混用。一个角色要么用调色盘写，要么用台词人设写。别把调色盘的衍生和台词人设的台词塞到一起，AI会困惑。"
  summary: 绝对规则：同一角色不可同时使用调色盘写法和台词人设写法。二选一，混用会导致AI困惑。
  tags: [台词人设, 方案选择, 互斥]

- id: r10
  title: 有三面性则语料从调色盘移除
  type: rule
  source_chapter: 教程2/八 + 大总结/03/七
  source_quote: "有三面性的角色→语料从调色盘里剔除，放到三面性的每一张面里。没有三面性的角色→语料留在调色盘里。"
  summary: 绝对规则：一旦写了三面性，调色盘中所有具体台词必须移除，分别放入对应面的语料区域。衍生描述规律，语料展示实例。
  tags: [三面性, 语料, 无条件]

- id: r11
  title: 三面性出现"因为""本质上"说明写错了
  type: rule
  source_chapter: 教程2/九/错误一
  source_quote: "如果你写的内容里出现了'因为''本质上''其实''内心'这些词，大概率你在写二次解释，不是三面性。"
  summary: 判定规则：三面性条目中出现"因为""本质上""其实""内心"等解释性词语，说明内容混入了二次解释，应移动到二次解释条目中。
  tags: [三面性, 边界判定, 二次解释]

- id: r12
  title: 核心矛盾必须一句话说清否则AI抓不住
  type: rule
  source_chapter: 教程7/七 + 大总结/05/五
  source_quote: "核心矛盾最好一句话说完。一句话能说清，AI就能抓住。说不清，AI也抓不住。"
  summary: 判定规则：核心矛盾如果不能用一句话（约30字以内）完整概括，说明提炼不到位，AI无法有效抓住并执行。
  tags: [核心人格层, 核心矛盾, 一句话]

- id: r13
  title: 防御机制不能只写一个词
  type: rule
  source_chapter: 教程7/二 + 大总结/05/三
  source_quote: "不要写'防御机制: 逃避'。太空了。要写她具体会做什么。"
  summary: 判定规则：防御机制如果只写一个词（"逃避""控制""冷处理"），等于没写。必须展开为具体可执行的行为描述。
  tags: [核心人格层, 防御机制, 行为化]

- id: r14
  title: 24问答不出则禁止跳级写高级工具
  type: rule
  source_chapter: 问题/24问 + 问题/工作流
  source_quote: "如果用户连24问都答不出来，就不要急着让她写调色盘、混色、三面性、核心人格层。"
  summary: 强制规则：24问（角色一句话、底色、主色调、点缀、表层欲望、深层缺失、核心恐惧）中有大量"不知道"的，禁止进入调色盘及更高级工具的写作。先补三块：底色、缺失、被触发后的反应。
  tags: [入门, 前置条件, 24问]

- id: r15
  title: 回答只有标签则必须追问四层
  type: rule
  source_chapter: 问题/24问 + 问题/80问
  source_quote: "如果答案只有标签，就继续往下问一层：它具体会做什么？它什么时候出现？它为什么会出现？它会不会伤到别人？"
  summary: 强制规则：任何以标签形式（如"她很温柔"）给出的回答，必须追问到行为层的四个问题后才可接受。
  tags: [问答, 追问, 行为化]
