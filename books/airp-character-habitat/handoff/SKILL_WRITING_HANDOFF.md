# Skill 写作 Handoff

> 本会话用真实失败换来的教训。接手任何 skill 写作任务前先读这份文档。

## 一、最高宗旨

**教程是教人学会理论、自己塑造角色；skill 是把教程内化之后，AI 直接带着用户塑造角色。**

由此推出 skill 的三层本质：

1. **skill 不是给人读的教程**——教程的使命是"让人理解方法"；skill 的使命是"让 AI 按方法工作"。
2. **skill 不是给 agent 执行的程序**——程序假设确定性规则链（if-then），skill 的执行依赖 agent 的理解与判断。skill 是给 agent 的**工作方式配置**：改变它的默认行为倾向，给判断依据与约束，让它在规则没覆盖的地方按原则推广，而不是机械套用或自由发挥。
3. **skill 写给 AI，但 AI 不是执行者而是引导者**——交互式 skill 里，AI 是懂方法的人，用户是懂角色的人。所有创作决定由用户拍板；AI 提供证据、建议和提问。

## 二、蒸馏取舍：什么进、什么不进

**判定标准只有一个：这条内容会不会改变 agent 在决策点的默认选择？会 → 进；不会 → 不进。**

注意：**不要用"agent 知不知道"作标准。** Agent 知道"健谈的人也会沉默"——训练数据里全是。但**知道 ≠ 会执行**：它生成角色卡时，默认倾向恰恰是把角色写扁、写满固定状态，它不会主动调用这个常识来对抗自己。所以：

| 内容类型 | 进不进 | 理由 |
|---|---|---|
| 纯科普（Transformer 原理、人格心理学引用） | 不进 | 不改变任何决策点的选择 |
| **有倾向的选择**（题材通识，但方法论做出明确方向选择："空白不是缺陷""写倾向不写状态""用删减完成角色"） | **必须进** | 它与 agent 的默认倾向**相反**——不写进去，agent 会在决策点做出相反选择 |
| 独创方法、个人实践经验 | 必须进 | skill 的核心价值，天然对抗默认倾向 |

形态：有倾向的选择写成"原则 + 为什么这条原则重要"——这个 why 不是给人类的科普，是让 agent 在规则覆盖不到的地方能正确推广的依据。

## 三、Skill 的知识结构：宗旨 → 原则 → 规则

**三层都要有，缺一层就残废：**

- **宗旨**：这个 skill 要达成什么效果（一句到三句）。
- **原则**：几个全局取向，解释所有规则为什么指向这个方向。
- **规则**：具体判据、步骤、检查项——是原则在具体场景的推导。

- 没有宗旨的规则清单 = 规则执行器（agent 遇到规则没覆盖的情况就乱套）。
- 没有规则的宗旨 = 退回教程（agent 知道方向但不知道怎么落地）。
- 宗旨和原则是 skill 的**主干**，不是装饰。SKILL.md 里必须读得出"规则是从原则推导的"。

**本会话的反面教材**：v2 重写 SKILL.md 时，把教程的核心思想（"不为角色预写答案，而是用尽可能少、彼此分工明确的内容，建立足以让角色在陌生情境中继续生活的生成条件"）删掉了——规则还在，思想没了。

## 四、写作形式

1. **以 agent 的执行为目的**。区分"教程体 vs 指令体"不靠文体（祈使句还是陈述句），靠内容：这句话是让 agent 做判断用，还是给人类读者看？服务于"让 agent 在覆盖不到处正确推广"的 why 段落要写，它不是教程残余。
2. **示例会反噬——对 skill 自身同样适用。** 写进 skill 的每个例子都会被 agent 当模板学走：具体句子被照抄，分类列表变成"隐藏菜单"（用户说"温柔"，AI 自行匹配四型之一代填）。对策：
   - 正反例用抽象结构表达：`[身体部位]+[动作]` 证明 `[标签]`。
   - 不可避免的具体例子加【示范·勿抄】标记 + "看结构，不套句式"。
   - 给**用户**选的选项可以具体（用户选=合法）；给 **AI** 当参考的分类必须标记（AI 代选=病根）。同一个四型列表，放访谈问题里给用户是工具，放规则文件里给 AI 是菜单。
3. **按读取时机组织文件，不按内容来源。** 同一时刻要读的内容放同一个文件；跨文件指针必然断裂漂移（本会话实例：分册指着问题库里不存在的内容）。重复 15 行 << 指针断裂的代价。skill 自包含优先。
4. **提醒无效，机制才有效。**
   - ✗ "请注意区分事实与推断"——无效。
   - ✓ "起草时标注每条来源；推断交用户确认；推断不得作为二次推断的依据"——可执行。
   - 检查优先设计成机械可查（词表扫描），其次才是逐项自查清单。
5. **约束少而硬。** 约束越多，agent 注意力越分散。每加一条规则问一句：**不加它，agent 会不会犯方向性错误？** 会 → 留；只会"不够好" → 删。留下的规则解释为什么重要，不要大写 MUST 堆砌。
6. **压缩 ≠ 蒸发。** 改形式（教程体→指令体）可以，丢内容不行。丰富内容（问法变体、答不出处理、负面结果处理）要**完整迁移**，不能只留一个指针指向准备删除的文件。
7. **视角转换要彻底。** 教程里的"你"是作者（他知道角色的答案）；搬进 skill 后"你"变成 AI（他不知道）。"供你认识人物"这类自省问题搬进 skill = 让 AI 自己编答案填空，直接制造教程最警惕的错误。每个"思考方向"必须转成"问用户的话术"。

## 五、避免清单（本会话实际犯过的）

1. 教程体（讲概念、讲道理给人类读者）。
2. 自省问题原样搬进 skill 让 AI 代答——v1 的病根。
3. 具体例句无标记——agent 照抄句式。
4. 分类列表无标记——隐藏菜单，AI 替用户选型。
5. 跨文件指针——断裂、漂移。
6. "请注意区分"式无效提醒。
7. 约束堆叠（红线越加越多，注意力稀释）。
8. 压缩时蒸发内容——指针指向不存在的文件。
9. 把"思想/原则"当装饰删掉，只剩规则——规则执行器化。
10. 用"agent 知不知道"判断通识去留——知道 ≠ 会执行，标准应该是"改不改变默认选择"。
11. 不验证就交差——没跑过一次测试的稿子当成品。
12. 审计结果全盘采信——agent 会误报（把教程 4.13 的内容说成编造）也会漏报（主控自查漏掉的两条由另一路 agent 补出）。

## 六、验证方式（skill 写完 ≠ 完成）

1. **五维独立审计**，每维一路 agent，并行：
   - 覆盖：源材料每节的可操作方法有没有落点（注意：覆盖审计不看深度，全绿 ≠ 合格）。
   - 视角：每条内容是"AI 可执行判据 / 问用户的话术 / AI 建议用户拍板 / 给人看的"，B 类内容以 A 类形态存在 = 病根残留。
   - 转化忠实：访谈问题的选项是否忠实于源材料自己给的选项集，有没有编造或漏掉方向。
   - 判据正确：源材料的谨慎限定（"可能""没有普遍出现"）有没有被读成绝对断言。
   - 反向压力：假设 agent 只拿 skill 文件执行，源材料警告的失败模式哪类会被突破——这条能发现自查发现不了的问题（如"提炼模板自相矛盾"）。
   - 另查一项：**顶层思想有没有在**——skill 里能否辨认出"宗旨 → 原则 → 规则"结构；把原则抽掉后，规则是否失去方向。
2. **主控逐条复核**每个 agent 的发现（对照源材料原文），误报剔除、漏报补充。多路交叉核对有真实增量。
3. **对照测试**：真实用户话术，with-skill / without-skill 并行跑，输出给用户评审，按反馈迭代。

## 七、与用户同步 agent 结果的方式

**前提：不预设用户看过任何东西。** 用户的上下文里没有 agent 的原始输出、没有文件结构、没有术语表。每条同步自带上下文。

五层协议：

| 层 | 内容 |
|---|---|
| 1 背景一句 | 这轮派了几个 agent、各审什么、对照什么材料 |
| 2 各 agent 发现了什么 | 每条发现一行：`[哪路] 在 [源材料节号] 发现 [什么问题] → 判定 [漏提/失真]`。保留出处，可追溯 |
| 3 主控逐条复核 | 每条标：采纳 / 驳回 / 修正。驳回和修正必须给理由（对照源材料原文） |
| 4 综合修正方案 | 基于采纳项，打算怎么改（改哪个文件、怎么改）。决策层与证据层分开呈现 |
| 5 落盘 | 完整版（原始表格+逐条复核+清单）写进审计文档；对话里给压缩版 |

三条铁律：
1. **引用码必须带内容**——不说"F7"，说"F7——起草后自查步骤在压缩时丢了"。码是文档索引用的，不是给人脑用的。
2. **结论永远跟在证据后面**——先 agent 说，再主控说。不跳过证据直接抛结论。
3. **术语首次出现给一句定义**——SKILL.md、references、判断门这类词，第一次提就解释，不默认用户知道。

用户偏好记录：曾两次要求"把 agent 的原始结果列出来给我"——用户要看原始材料，不是预消化过的结论。

同步合格的判据：同步结束后，用户应能回答三问——① 每个 agent 分别发现了什么？② 哪些被采纳、哪些被驳回、为什么？③ 接下来要改什么、怎么改？能回答 = 用户可以独立拍板；答不上 = 同步失败。
