# AIRP 人物生境写法 · Skill 架构决策

> 依据：`AIRP人物生境教程整理.md`（约 1.8 万字）
> 方法：cangjie-skill 流水线的阶段 0–1.5（整书理解 → 多角度提取 → 三重验证）
> 论证：12 路 GLM-5.2 独立实例（knot-cli），分三轮：6 路开放设计 → 4 路定向裁决 → 2 路对抗攻击
> 日期：2026-08-16

---

## 一、结论摘要

**2 个 skill + 各自的 references/**

| skill | 输入 | 产物 | 触发信号 |
|---|---|---|---|
| `airp-habitat-build` | 原始资料（无卡） | 新角色卡 | "帮我把这些设定整理成角色卡""按生境写法写人设" |
| `airp-habitat-revise` | 已有卡（±输出样本） | 修改后的卡 + 修改说明 | "她演得像复读机""这张卡太长了""基础信息和性情写重了" |

**分界线是「输入物是否已有卡」**，不是「症状 vs 结构」，也不是教程的四层内容结构。

## 二、被否决的方案及理由

### 方案 A：按教程四层切 4 个 skill（基础信息 / 生活结构 / 人物性情 / 场景表达）

**全票否决。** 这是最直觉但最错的切法，与教程自身论述正面冲突：

- 教程 3.5：生活结构"可以很短，也可以**直接并入基础信息**"
- 教程 6.2：场景表达"已经能够成立时便可以**省略**"
- 教程 6.1 第 5 步："从头重读，把在不同部分重复说明的同一个意思**合并**"
- 教程 6.4 标题即"**用删减完成角色**"

一个独立 skill 被触发就意味着"该产出这一层了"，它无法表达"我这一层应该被删掉"的语义。切成 4 个的后果：
1. agent 被迫每层填满，把教程的减法哲学逆转成加法流水线
2. 没有任何一个 skill 拥有全局视野去执行跨层合并
3. 用户说"帮我写角色卡"时，可能只触发其中一个，产出残缺

### 方案 B：按教程最独特的判断切（示例意识 / 层次分工 / 性情写作 / 人物独立性）

**否决，理由是「触发饥饿」。** skill 由 agent 根据 description 自动挑选，所以切分维度必须与**用户实际会说的话**对齐，而不是与内容审计出的概念结构对齐。

用户永远不会说"帮我做示例意识检查"或"帮我做人物独立性设计"。这些 skill 的 description 只能写成"当用户需要检查示例的三重示范效应时使用"，与任何真实用户输入都没有语义重叠，会成为死代码。

**但方案 B 有一个洞察被完整吸收**（见第四节）：只有独特判断才值得占 skill 篇幅，常识不该占位置。

### 方案 C：按作者工序切 5 个（整理 / 归位 / 返修 / 删减 / 验收）

**部分否决。** 归位判断和删减不是独立工序，而是贯穿主流程的判断动作——教程 6.1 的整理步骤本身就在做归位，第 5 步本身就是删减。抽成独立 skill 等于把一道菜的"切菜/调味/装盘"拆成三个餐厅，但顾客永远一起点。

"验收"（2.3 六项观察指标）内容不足以独立：教程只给了"看什么"，没给"怎么设计测试场景、测多少轮、边界结果如何判定、多模型矛盾如何归因"。降级为两个 skill 内的检查步骤。

### 方案 D：3 个 skill（构建 / 诊断 / 精简归位）

**这是最接近的竞争方案，最终被否决。** 决胜的核对是：**诊断与精简用的是不是同一套判据？**

逐条映射结果——是同一套：

| 诊断"复读机"的根因 | ↔ | 精简的删除检查判据 |
|---|---|---|
| 示例动作过多被当固定写法（2.1/4.10） | ↔ | 跨场景句子能否替代多个固定动作；某例子是否过于醒目会变固定镜头（6.4/4.10） |
| 材料不足走向公共路径（3.1） | ↔ | 删除后是否在多种场景失去判断依据（6.4，反向） |
| 层间混写重复占用上下文（3.4） | ↔ | 是否换说法重复已写过的性情；重复同一意思→合并（6.4/4.10） |
| 写了唯一答案而非倾向（4.6） | ↔ | 只是提前交付一次回答，还是让模型更了解这个人（4.10） |
| 性情过完整变内心独白（4.11） | ↔ | 是否换说法重复已写过的性情（同一意思的变体复读） |
| 意义写成固定反应公式（4.13） | ↔ | 是否只能复现一幕而非迁移到别处（6.4） |
| 表达写成表演说明书（5.7） | ↔ | 只能复现一幕 + 跨场景句子能否替代固定动作（6.4） |

七条根因每一条都精确映射到删除检查清单中的对应判据。**诊断"为什么会复读"和精简"什么该删"用的是同一把尺子，只是拿尺子的方向不同**：诊断从输出症状逆向找到卡里哪段触发了红线，精简从卡面结构正向量每段内容。

而且诊断完根因（如"示例动作过多"）之后，修复动作就是"用删除检查清单找出哪些该删、哪些能合并成一个跨场景句子"——和精简做的事完全一样。诊断多出的只是"症状→根因"这一步薄映射。

拆成 3 个的代价：同一套判据要么复制两份（必然漂移），要么跨 skill 引用（不可靠）；换不来真正的触发可靠性提升。

**另一个理由**：教程本身说明"症状"与"结构"边界不稳定——3.4 说层间混写会导致模型"复述作者的心理分析"（结构问题，症状表现），4.13 说把意义写成固定反应会产生新公式（同上）。用户报"复读机"时根因常常是结构性的；报"太长了"时太长本身也可能正在制造复读机。按这两个入口切会在触发时制造歧义。

## 三、构建 skill 的内部流程设计

### 核心风险

agent 拿到列出四层的 skill，**天然倾向是四层都写满**——它看到结构就会填充结构。单纯写"可以省略"是无效的提醒。这是整个架构的头号失败风险。

### 防填满机制（三层嵌套 + 攻击后的修正）

**第一层：默认状态逆转。** 四层不是一律对待——基础信息与人物性情默认写，生活结构与场景表达**默认不写**。流程骨架是"写两层 + 两次判断门"，不是"写四层（其中两层可短）"。

**第二层：判断门内联为准入条件。**

原设计是"输出结构化判定声明"。对抗审查（rz2）指出了致命缺陷：**agent 既是裁判又是选手**——判定声明是同一个 agent 在同一次生成中为同一个写作任务产出的自我辩护，"仍需临时发明的材料"门槛极低，agent 填满模板的能力远超它拒绝写作的能力。

**采纳的修正**：不要独立的声明步骤，把判断门内联为该层的准入条件，并加**硬字数预算**。预算约束比自我审查可靠——如果 agent 真需要写，它必须在这个空间里完成；如果不需要，它会发现自己写不满。

未采纳"结构性禁止"（构建产物只允许两层，补充层只能由返修追加）：过于激进，教程 3.7 明确说贺明珠这类"只有抽象身份与性情、缺少承载行动的现实"的人物，生活结构确有价值；把它整个移出构建流程会让这类角色的首次产出就是残缺的。

**第三层：回溯校验。** 收尾时回查判断门的判定与最终产出是否一致。

### 判断门 A — 生活结构

核心判据（可直接测试）：把人物放进日常/冲突/独处三种情境，基于已有的基础信息与性情，模型是否需要**临时发明**行动材料（一项责任、一个场所、一种能力、一个限制）？

**准入（满足任一才写）**
- 身份标签没有展开成日常生活：写了"她是销售负责人"，但没写这份工作在她日常中实际意味着什么——长期面对什么结果、对谁负责、出问题会影响什么。
  - 实证依据（3.7）：贺明珠加入生活结构前只会回到团队谦让"合同是我签的，但拿下来靠的是全组人连着跑了三周"；把销售负责人长期面对的个人结果与团队责任同时放回她的生活后，才写出"签名是我，但季度末的报表是小组一起熬出来的……但我这一杯先敬自己"。
- 性情有明确指向但缺少可供发生的现实：写了"珍惜责任"，但人物没有一个长期经手的现实责任。（3.1：只有"珍惜责任"，模型仍要临时发明一项责任）

**否决（满足任一则省略或并入基础信息）**
- 基础信息已提供具体活动场域。实证依据（3.7）：夏燃已有攀岩、运动康复、旧伤、比赛构成的活动场域，加入生活结构后多数输出仍走向相近选择，**新增价值很小**。
- 内容只是换说法重复基础信息或性情（3.4：已在基础信息说清的，不需在生活结构扩写成散文）
- 只能贡献固定物件或固定动作（3.5：上下文价值很低）

### 判断门 B — 场景表达

核心判据：基于前三层，把人物放进一个需要她**开口说话或采取行动**的场景，她的表达是否会被压缩成同一种语气、同一套小动作或被动回应？

**准入（满足任一才写）**
- 前三层只产生心理旁白，没有产生发言和行动。实证依据（5.9）：唐酥只有性情时能感到安排带来的窒息，却把整轮用来解释这种感觉——"指腹摩挲着一张边缘卷曲的旧车票，心里关于'离开'的念头又一次冒出来"；加入场景表达后开始使用车站、天气、购票工具处理事务——"这些酒店和车票，如果还没扣手续费，你能先退掉吗？"
- 表达方式有不能从性情直接推导的独立特点。实证依据（5.9）：程雾"安静的人在自己的责任领域内会变得完整而主动"——先把信纸归位、压好镇纸，再说明工作进度，最后把没动过的菜和干净筷子推到对方手边。这一点无法从"他不习惯被照顾"直接推出。
- 别人不替她推动剧情时，她不知道做什么（5.5）

**否决（满足任一则省略或删短）**
- 前三层已能使人物自然发言和行动。实证依据（5.9）：夏燃加入场景表达后多份输出仍走向相近动作，说明前一层已足够，**场景表达可以删短**。
- 只是重复性情层已说清的价值与原因（5.8 的三级归属判定）
- 变成表演说明书（5.7："愤怒时提高音量，悲伤时沉默，紧张时摸头发"）

### 收尾删减（攻击后修正）

原设计"逐段裁定表 + 5 项检查逐项是/否 + 若全部保留必须额外说明理由"。对抗审查指出了**凑数删除**风险：

- "全保留需额外说明理由"把"全保留"变成需要辩护的异常状态，把"删掉点东西"变成默认的正确行为
- LLM 有"满足过程要求"的本能，会倾向让裁定表看起来有成果，至少删一两个东西证明自己认真做了
- 裁定表对四层一视同仁，但教程说人物性情**往往是人设的核心**——为凑数砍性情，后果比不删更糟

**采纳的修正**
1. **删掉"全保留需额外说明理由"这条规则**——全保留是正常状态
2. **只输出删除项**，不输出保留项。没有可删的就输出"无需删除"，消除格式压力
3. **加删除难度梯度**：基础信息与人物性情是核心层，删除需 5 项检查中至少 4 项判为可删；生活结构与场景表达是补充层，3 项即可
4. **删除建议交用户确认**，不由 agent 自动执行

### 流程步骤（砍到 5 步）

对抗审查指出 9 步 + 2 声明 + 1 裁定表**严重过重**：①注意力衰减，靠后步骤执行变浅（教程自己引用的 Lost in the Middle 效应）；②过程完成感替代结果质量，得到格式完整内容空洞的卡；③步骤 5（跨层合并）与步骤 6（删减）逻辑上是同一个操作，拆成两步只增加疲劳。

**最终流程**
1. 写基础信息（含静态/动态分离、删除检验；材料三分类降级为引导语，不单独输出）
2. 写人物性情（写完强制检查"解释停在根部"；事实/解释/空白三层分离）
3. 检查是否需要补充层（判断门 A 与 B 内联为准入条件 + 硬字数预算）
4. 全文清理（合并重复 + 删减，一次遍历，只输出删除项）
5. {{user}} 拿走终检 → 清洗过程信息 → 输出（无内容的层连标签一起删）

### 写作顺序 vs 输出顺序

**先全部草拟，再统一清洗输出。** 不边写边输出最终文本，理由：
- 后层的判断门依赖前层的完整草稿（判断门 A 要列举基础信息已提供的行动材料）
- 跨层合并需要同时看到所有层——若基础信息已"交付"，后来发现性情层有重复，要么改已输出的文本，要么保留重复
- 删减可能需要把内容从一层移到另一层

## 四、独特判断如何吸收（方案 B 的洞察）

**原则：skill 正文的空间分配应与内容的犯错成本成正比，而不是与概念篇幅成正比。**

高独特度判断提升为**全局红线**放在 SKILL.md 显眼处；常识性内容压缩或删除。

### 独特性审计结果

| 判断 | 独特度 | 落点 |
|---|---|---|
| 示例同时是内容示范+语言示范+镜头示范 | 9/10 | 全局红线（见下方修正） |
| 让解释停在人物根部，防心理旁白复读 | 8/10 | 全局红线 + 性情层强制检查 |
| 把 {{user}} 拿走的独立性测试 | 7.5/10 | 构建终检 + 返修诊断项 |
| 标签只提供方向，同一标签落在完全不同的人身上 | 7/10 | 性情层写法 |
| 生活结构 vs 性情的"事实连接 vs 意义解释"分界 | 7/10 | 判断门 A + 归位判据 |
| 写倾向不写唯一答案（往往/除非 vs 永远/绝不） | 6.5/10 | 全局红线（可机械检查） |
| 事实/解释/空白三层划分，空白不是缺陷 | 6.5/10 | 性情层步骤 |
| 静态人设 vs 动态事实分离 | 6/10 | 基础信息层硬规则 |

被判定为**常识、不值得占篇幅**：基础信息追求确定性而非文采、姓名年龄用一行固定、角色可以成长、不强求反差、沉默可以是拒绝/观察/保护、情绪有来路也有经过、测试要面对没写过的场景、Transformer/few-shot/长上下文原理。

### 「示例三重示范」的机制修正

对抗审查指出这是**最不现实的约束**：它要求 agent 在写下每个例子前，预测该例子会被下游模型如何学习，从三个维度同时评估——一个三阶元认知任务。生成时 agent 的注意力在"表达内容"，不在"预测下游学习行为"；且"什么算变成了镜头示范"本身模糊、无可操作检验标准；红线在 SKILL.md 开头，距实际写例子处可能隔几千 token，被位置效应稀释。

**采纳的修正——把自我审查换成机械规则**：
- 不禁止所有具体内容，而是禁止"可重复的物理动作"作为性格证明。"她紧张时会攥住衣角"禁止；"她能够承认自己技不如人"是倾向描述，保留。
- 硬规则：人物性情与场景表达正文中，不得出现"主语 + 具体动词 + 具体身体部位/物件"构成的独立动作句。
- 初稿完成后跑一次**动作扫描**：搜索身体部位名词 + 动词组合，任何组合出现超过一次就 flag。把自我审查变成机械检查。

同理，"写倾向不写唯一答案"提供可机械检查的版本：扫描"永远/绝不/总会/每次都"等绝对化词语。

### SKILL.md 中 ✗/✓ 对照的陷阱

对抗审查发现一个自指问题：**SKILL.md 里用来防止"示例变成固定模式"的 ✗/✓ 对照，自己就是示例。** 如果 ✓ 写的是"她总觉得自己的难处可以再忍一忍"，agent 产出的卡里就会出现这个句式——不是因为理解了原则，而是因为学习了模板。

**修正**：✗/✓ 对照用**抽象结构**而非具体句子表达。
- ✗ 用 `[身体部位]+[动作]` 证明 `[性格标签]`
- ✓ 用 `[情境]+[倾向性词语]+[多场景适用范围]` 表达 `[理解方向]`

## 五、返修 skill 的设计

### 内部薄分岔

- **症状驱动**：多一步"症状 → 根因映射"，映射完成后进入与结构驱动完全相同的修改流程
- **结构驱动**：跳过映射，直接进入逐段检查与修改

这不是两个平行工作流，而是一个工作流带一个可选前导步骤——用 if-else 比用两个 skill 更自然。

### 防失控（攻击采纳）

对抗审查指出教程有近 10 种失败模式，一个 skill 同时处理"症状诊断"与"结构精简"有失控风险，且两者认知模式不同（诊断需要输出样本对照，精简只需审查卡本身）。

**采纳的修正**
1. **一次只修一两个问题**，不试图在一次返修中处理所有失败模式
2. **核心方法改为差异检测**，而不是枚举失败模式清单：把卡中每条内容与输出样本中的实际行为对照，找出"卡里没写但输出里出现了"（= 补造事实）与"卡里写了但输出里没体现"（= 失效）。这种差异检测比枚举清单更适合 LLM 执行。
3. 无输出样本时降级为纯结构审查（归位 + 合并 + 删减）

### 失败模式清单（返修的诊断词典）

1. 小动作复读（2.1 / 4.10 / 5.6 / 5.9）
2. 心理旁白替代表达（4.11 / 4.15 / 5.9）
3. 补造往事与事实（3.7 / 4.12）
4. 标签化固定表演（4.2 / 4.13）
5. 关系依附，人物围绕 {{user}} 转（1.5 / 4.9）
6. 公共模板覆盖（职场谦让、温暖内向镜头）（3.7 / 5.9）
7. 情绪即时特效，不经过时间（5.3）
8. 表达体量单一（5.2）
9. 静态事实过期，状态复位（1.3）
10. 跨层内容重复（3.4 / 6.4）

**关键校准（来自教程实证的诚实记录）**：有些问题不是写法错了，而是模型本身的倾向——即使正确写作，模型仍会补造旧信年代/任职年限/家庭成员（Claude 甚至为只有"优秀兄长"这一事实的贺明珠新增了弟弟）；小动作不会因为原因写得更深就消失（唐酥仍触碰耳钉车票包带，程雾仍摘眼镜）；贺明珠的职场谦让不会被一段新增内容稳定压过。这影响诊断结论与返修预期——**遇到这种结果不应立刻堆叠更多命令**。

## 六、文件组织

### SKILL.md 的取舍判据

**一条内容是否留在 SKILL.md，取决于：如果 agent 没读 references/ 就开工，省掉这条会导致它犯教程明确警告的错误吗？** 会 → 留下；只是导致产出"不够好"而非"方向错误"→ 下沉。

设计目标不是"让 agent 不读 references 也能写出好卡"，而是**"让 agent 不读 references 也不犯方向性错误"**。好与差交给 references/，对与错的分界线必须留在 SKILL.md。

**留下**：四层职责 + 每层一条最高频错误的抽象结构 ✗/✓ 对照、整理顺序、判断门准入判据与字数预算、静态/动态测试、三条全局红线（含可机械检查的版本）、精简版删除清单、references 指针。

**绝对不放**：Transformer / 上下文学习 / 人格心理学的理论论证、Google 与 Anthropic 的提示建议、74 份对照的方法论说明、原始对话引用、给作者看的思考辅助问题（"她怎样解释失败？"这类）。

### 反向压力测试结论

只读 SKILL.md 就开工的 agent 会产出**结构正确但每层内部有方向性错误**的卡，具体会犯：静态/动态混淆（不知道年龄/学籍/职业属于中间地带）、性情写成规定性表述、标签直接进正文、生活结构写成日程表物品栏、场景表达写成表演说明书、性情变心理独白、不做跨场景价值检查。

补上每层的抽象结构 ✗/✓ 对照后（约 +300 字），前 5 个最严重的错误可被避免；剩余 2 个（生活结构边界、跨场景价值判断）仍需 references/，但严重性较低。

### 共享内容处理

**各自复制一份，按用途重新表述**，不跨目录引用。

Claude Skill 是自包含目录，跨目录引用（`../shared/xxx.md`）的路径解析不可靠，且返修 skill 可能在构建 skill 未安装的环境中运行。

同一份底层知识在两个 skill 中以不同表述出现——**表述差异本身就是价值**：

| 共享内容 | 构建中的表述 | 返修中的表述 |
|---|---|---|
| 四层定义 | 每层写什么、怎么写 | 每层检查什么、什么算不合格 |
| 失败模式 | 避免这些错误 | 识别这些症状 |
| 删除清单 | 完成后这样删减 | 检查是否该删而未删 |

**已知代价**（对抗审查提出，接受但缓解）：两份副本会随时间漂移。缓解方式——把真正共享的部分压缩到极小（四层职责定义 + 3 条红线，10 行以内），小到复制也不易出问题；并在两个 SKILL.md 中注明知识源自本教程，维护时知道去哪里对齐。

### 实证部分（3.7 / 4.15 / 5.9）的处理

拆成三类，分别处理：

1. **可操作结论 → 提取进对应的 layer rules 作为判断门判据来源**。如"生活结构在缺少现实材料的角色上可能有用，在已有场域的角色上新增价值很小"直接决定是否写这一层。
2. **持续存在的失败模式 → 提取进 `empirical-limits.md`**。这些告诉 agent"有些问题不是你的写法错了，而是模型本身的倾向"，影响诊断结论与返修预期。
3. **原始对话引用与逐句模型对比 → 不进入任何 skill 文件**。这是给人看的证据，agent 不需要看到程雾的具体台词就能应用结论。

## 七、触发边界设计

### 两个 skill 的划界

| | 构建 | 返修 |
|---|---|---|
| 输入 | 原始人物资料（采访、小传、设定碎片、参考图） | 已完成的角色卡（± 输出样本） |
| 关键动词 | 整理、构建、建立、写 | 修、删、合并、归位、诊断、精简 |
| 产物 | 新的角色卡 | 修改后的卡 + 修改说明 |

核心区分句：构建用"**从原始资料**构建角色卡"，返修用"**对已有角色卡**执行诊断与修改"。输入物的性质不同，用户几乎总是知道自己手里有没有卡，触发不会模糊。

### 诱饵（不应触发）

| 请求 | 为何不触发 |
|---|---|
| "你演这个修古籍的角色，我演来拜访的客人" | 执行角色扮演本身，不是写卡 |
| "帮我想个剧情大纲，主角是个修古籍的" | 目标产物是剧情，不是卡 |
| "帮我写个产品文案，要有人物感" | 营销文案；"人物感"是文风要求 |
| "讲讲注意力机制和上下文学习怎么工作的" | 抽象 LLM 科普，不是把原理用在写卡上 |
| "这个角色在我小说里该怎么成长、什么时候觉醒" | 小说角色弧光设计，不是为 LLM 写提示词 |

共同防误触发机制：**用产物类型锚定**——这两个 skill 的产物始终是"一份角色卡或对角色卡的修改"，上述五条的产物分别是对话、剧情大纲、文案、科普、小说大纲。

### 兄弟混淆测试

最易互相误触发：**"AI 演得像复读机，帮我改改这张卡"**——前半是症状，后半是修复动作。

在 2-skill 架构下这个混淆消失了：两者都归返修。真正需要划界的是构建与返修，而"这张卡"三个字已经明确输入物是已有卡。

残余风险：用户贴了一大段原始资料并说"我这个角色写得不好"——资料是原料还是卡？处理方式：在返修 SKILL.md 中写明"若用户提供的是未成卡的原始资料，转交构建流程"。
