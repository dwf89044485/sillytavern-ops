> 本 skill 的 SKILL.md **没有**按六段排版。这份文件记录：六段的实质分别落在哪里，以及为什么重新安置。

## 判断：RIA++ 是推导脚手架，不是交付格式

RIA++ 面向**思维框架型 skill**——从一本书里抽出一个心智动作（如"逆向思维"），价值在于让 agent 理解这个动作，所以需要原文、案例、解释来建立理解。

人物生境要做的是**生产流程型 skill**：输入原始资料 → 走五步 → 输出角色卡。agent 不需要"理解"，需要"执行"。

六段照搬会产生三个具体损害：

1. **R 段与红线一直接冲突。** 教程本身论证"写进提示词的每个例子都同时是内容示范、语言示范和镜头示范"。把教程原句（含程雾的台词、唐酥的车票）贴进 SKILL.md，agent 会照抄句式——这正是本 skill 要防止的错误。教程是第三方作者所写，本 skill 的目标是把它的方法内化成 AI 的执行能力，不是保存这份文档的原貌。
2. **B 段的位置会被稀释。** 教程自己引用 Lost in the Middle 效应。红线放在文末 B 段，agent 写到第三层时已隔数千 token。失败模式必须内联到对应步骤旁。
3. **E 段被压缩成六分之一。** 对生产流程型 skill，E 就是整个 skill，该占 70% 篇幅。

**结论**：用 RIA++ 保证内容不漏，按 agent 的执行顺序排版。红线第 2 条的意图是"不许漏"，不是"必须长成这个形状"。

## 三重验证记录

单元：AIRP 人物生境写法（整体作为一个生产流程型 skill）

### V1 跨域佐证 ✓

四层分工不是单点主张，在教程中有独立佐证：

- 3.4 从"市图书馆纸张修复人员"一例正面划出三层分界。
- 5.8 从场景表达一侧给出三级归属判定（为什么在意 → 性情；这一幕说了什么 → 具体场景；通常怎样转化 → 场景表达）。
- 6.1–6.2 从整理顺序与篇幅分配再次确认同一套分工。
- 3.7 / 4.15 / 5.9 用实测输出反向验证：分层错位时模型的具体退化形态（公共模板、心理旁白、表演说明书）。

### V2 预测力 ✓

用它回答教程没明说的新问题：

> 一个角色的资料里写着"她收藏了三百张不同城市的车票"，这条该放哪一层？

推导：先过基础信息的删除检验——删掉它，模型会认错她的身份或长期生活吗？不会 → 不属于基础信息。再过生活结构的三条排除线——是物品栏，除非它持续改变她的选择、能力或关系。再过 3.4 的爱好条款——"不是每一种爱好都必须被提升为人物象征"，强行解释会制造新的固定意象。最后过红线一——若写成"她摩挲车票"就是禁止的动作组合。

结论：**默认哪一层都不进**。只有当它确实连接了长期活动（比如她靠这个在某个圈子里有位置）时，才作为该长期活动的一部分进入生活结构。教程没有讨论过"收藏"这个具体案例，方法本身足以推出答案。

### V3 独特性 ✓

不是任何聪明人都会说的常识。三条判据：

- **"处理过期信息的办法不是在人设里追加『不要回到过去』，而是不把会过期的状态写进静态人设"**——常识路径恰恰是加禁止句。这条反直觉。
- **"空白不是人设缺陷，保留未完成能减少模型补造往事"**——常识路径是"写得越完整越好"。这条反直觉。
- **"解释停在人物根部"**——常识路径是"把动机写清楚、写深"。教程指出写得过深会变成内心旁白复读。这条反直觉。

反面对照：被判定为常识、因此**未占用 SKILL.md 篇幅**的内容——基础信息追求确定性而非文采、角色可以成长、不强求反差、沉默可以是拒绝或观察、情绪有来路也有经过、测试要面对没写过的场景。这些下沉到 references 或省略。

## 对抗轮采纳的四处修正

这些是 12 路 GLM-5.2 分析中对抗攻击轮（rz2）推翻原设计的部分，已落进 SKILL.md：

### 1. 「示例三重示范」红线 → 机械规则

**原问题**：要求 agent 在写下每个例子前预测该例子会被下游模型如何学习——三阶元认知任务，生成时 agent 的注意力在"表达内容"，且"什么算变成了镜头示范"无可操作检验标准。

**修正**：禁止的不是所有具体内容，而是"可重复的物理动作作为性格证明"。硬规则：性情与场景表达正文中不出现「主语+具体动词+具体身体部位/物件」的独立动作句。步骤 4b 跑机械扫描（列出了具体的身体部位与物件词表），把自我审查换成搜索。

同理，红线二给出可扫描版本（绝对化词表）。

### 2. 判定声明 → 内联准入 + 硬预算

**原问题**：判定声明是同一个 agent 在同一次生成中为同一个写作任务产出的自我辩护。agent 既是裁判又是选手，"仍需临时发明的材料"门槛极低，它填满模板的能力远超拒绝写作的能力。

**修正**：不设独立声明步骤，把判断门内联为该层的准入条件，加硬字数预算（生活结构 ≤120 字，场景表达 ≤100 字），并写明"预算即二次校验：写完超预算说明写进去的多半是日程、偏好或同义解释，回到否决条件重判，不要靠拆句压字数"。

**未采纳「结构性禁止」**（构建产物只允许两层，补充层只能由返修追加）：过于激进。教程 3.7 明确说只有抽象身份与性情、缺少承载行动现实的角色，生活结构确有价值；把它整个移出构建流程会让这类角色的首次产出就是残缺的。

### 3. 删减裁定表 → 只输出删除项

**原问题**："若全部保留必须额外说明理由"把全保留变成需要辩护的异常状态，把删掉点东西变成默认的正确行为。LLM 有"满足过程要求"的本能，会为了让裁定表看起来有成果而至少删一两处。而人物性情往往是人设的核心，凑数砍性情比不删更糟。

**修正**：删掉该规则；只输出删除项，无可删就写"无需删除"；加删除难度梯度（核心层 4/5，补充层 3/5）；删除清单交用户确认。

### 4. 9 步 → 5 步

**原问题**：注意力衰减（教程自己引用的 Lost in the Middle），且过程完成感会替代结果质量——得到格式完整、内容空洞的卡。原步骤 5（跨层合并）与步骤 6（删减）逻辑上是同一个操作。

**修正**：合并为步骤 4「全文清理」一次遍历；判断门内联；材料三分类降级为步骤 2 内的检查项，不单独成步。

### 5. ✗/✓ 对照本身是示例

**原问题**：SKILL.md 里用来防止"示例变成固定模式"的 ✗/✓ 对照，自己就是示例。若 ✓ 写成一个具体句子，agent 会照抄句式。

**修正**：全部改用抽象结构表达。`[身体部位]+[动作]` 证明 `[性格标签]` / `[能接受什么]` 却 `[无法接受什么]`。

## 落盘后自查发现的第 6 处问题

写完后对全部文件做了与教程原文的逐段照搬率测量：

| 文件 | 照搬 ≥30 字连续片段的占比 |
|---|---|
| SKILL.md | 4% |
| assembly-and-cutting.md | 25% |
| basic-info.md | 37% |
| life-structure.md | 40% |
| disposition.md | 56% |
| scene-expression.md | 62% |

**照搬率高本身不等于错，但也不是免责理由。** 教程是第三方作者所写，本 skill 的目标是把方法内化成 AI 的执行能力，而不是保存这份文档的原貌。逐段照搬会同时带来两个问题：一是把教程「写给人类作者看」的视角一并搬了进来（详见下方视角错位问题），二是把具体人物的例句留在了 AI 正要动笔的位置。

**真问题是窄的**：修正 5 只在 SKILL.md 生效（4% 证明抽象结构起了作用），但对抗轮指出的陷阱**原封不动转移到了 references**。`disposition.md` 与 `scene-expression.md` 里保留了完整的正面例句和实证段落——它们正是最容易被 agent 当模板抄进角色卡的部分，而且它们出现的位置恰好是 agent 正在写那一层的时候。

**处理**：不删例句（删掉会让 agent 失去判断"倾向 vs 固定答案"结构差异的参照），改为加 `【示范·勿抄】` 标记 + 抽象结构标注 + 一句"看结构，不套句式"。SKILL.md 红线一末尾加了一条元规则，声明这条红线也适用于本 skill 自己的示例。

标记覆盖：SKILL.md 1 处（元规则）、disposition.md 3 处、scene-expression.md 3 处（含全部实证段落）、life-structure.md 1 处（实证段落）。`basic-info.md` 与 `assembly-and-cutting.md` 无正面人物例句，不需要标记。

**这是压力测试最该验的一项**：标记能否真的阻止抄袭，还是 agent 只会绕开标记继续套用句式。

## V2 修订：体裁修正（2026-08-16 下午）

### 用户指出的根本原则

> 教程是写给人类作者的；skill 是给 AI 运行的。skill 要把教程**内化**，用户来用时，**AI 直接带着用户塑造角色**。

V1 的体裁错误：把教程里"供作者自省的问题"（她怎样解释失败？她怎样看待自己？）搬进 skill 后，"你"从作者变成了 AI——而这些问题只有用户知道答案。实际效果是让 AI 自己揣测答案填空，直接违反教程 4.12（空白不是缺陷，代填会诱发模型补造往事）。

### 新体裁：引导式访谈 + 落笔

- AI 是访谈者，不是代笔者。所有创作决定来自用户；AI 的推断必须标注并交用户确认；用户没提到的就是空白，不代填。
- 判断门从"AI 自我裁决"改为"AI 提建议、用户裁决"——硬字数预算（120/100 字）随之废弃，那是给"AI 既是裁判又是选手"打的补丁，裁判换成用户后失效。
- 删减从"AI 输出删除清单"改为"AI 逐项给出原文 + 删后效果预览 + 理由 + 代价，用户逐项决定"。原删除难度梯度（核心层 4/5、补充层 3/5）废弃——裁判是用户，不需要数字门槛。
- 新增 `references/interview-questions.md`：访谈问题库。每条含问法（资料多/少两变体）、答不出时的处理、答案→正文的提炼动作。

### 用户拍板的三项决定

1. **引导深度：重档**。以完整塑造人物为准，轻中档以后再做减法。
2. **顺序：生活结构在性情之前**（保持教程 6.1 原顺序）。用户理由：生活结构是定义人物的前提条件，生活结构有可能决定人物性情。
3. **语言**：用新手听得懂的话，但**不设术语禁令**——约束越少，AI 注意力越分散。

### 五份 references 的视角改写要点（三路 GLM/DS 审计 + 主控审核）

- 每份文件顶部加**视角说明**：规则是 AI 的判据；"提问方向"是向用户提问的素材，不是 AI 自己回答的题目。
- `disposition.md`：三处思考方向块改为指向访谈问题库（主题一至三）；合并"写倾向"与"固定反应"两节的重叠；补入教程 4.15 的缺失内容（性情层实际改变了什么 + 写太满的风险）；修正反面例句的标记。
- `life-structure.md` / `scene-expression.md`：实证边界从人物叙事改造为四段式判定规则（提议写入条件 / 跳过条件 / 预期效果 / 负面结果处理），具体人物材料（车票、信纸、岩壁）全部清除；准入判据前置。
- `assembly-and-cutting.md`：改为协作式删减；空白清单、独立性终检保留。
- `basic-info.md`：轻度改写——三处"只有用户知道"的判据（关系实际重量、故事跨度、关系是否可能改变）标为问用户。

### V1 仍然成立的结论

2-skill 架构、否决按四层切分、三条红线、`【示范·勿抄】` 机制、SKILL.md 4% 照搬率的抽象结构写法——全部保留。
