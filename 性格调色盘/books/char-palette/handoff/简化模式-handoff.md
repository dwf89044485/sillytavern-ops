# Handoff：要不要有个"简化模式"，什么时候切进去

> 这份文件是自足的。你不需要读任何其他文件就能开始讨论。
> 读者：另一个 AI（帮我把这个问题聊清楚）。产出：一个可以带回原项目直接执行的结论。

## 一、背景：我在做什么

我在做一个 skill（给 Claude Code / Cursor 这类 AI 编程助手用的能力包），作用是：

**通过一问一答，引导用户创造出一个角色**（用于 AI 角色扮演的角色卡）。

用户提供想法——可能只有一个标签（"她很温柔"）、一个画面、一段经历，或者干脆"我不知道她是谁"——AI 通过持续追问，帮用户把脑子里模糊的感觉，变成具体、独特、AI 能演得出来的角色描述。最终产出一份角色文档。

这个 skill 是从一套中文教程《性格调色盘》里蒸馏出来的。教程的核心洞察是：**告诉 AI "她温柔"，AI 只会演数据库里的温柔模板；告诉 AI "她把削好的铅笔放在没笔的同桌桌角，做完就收回目光"，AI 才知道这个温柔长什么样。** 所以整个 skill 的任务，就是把用户嘴里的标签，翻译成具体行为画面。

### 标准流程（主路径）是什么样

AI 会带着用户走完一套完整的角色构建，按教程定义的七层推进：

```
基础信息（她是谁：外貌 / 背景 / 关系）
  ↓
调色盘（她是什么质地：底色 / 主色调 / 点缀色，每种颜色配几条具体行为画面）
  ↓
多面性（不同场景下整套行为逻辑的切换）      ← 按苗头触发，不是必经
  ↓
混色（同一瞬间两种情绪撞在一起的画面）        ← 按苗头触发
  ↓
核心人格层（她为什么是这样的，底层驱动）      ← 按苗头触发
  ↓
二次解释（补说明，防止 AI 演的时候理解歪）
  ↓
意象（用一个形象概括她的存在方式）
```

这套走完，用户会得到一份很扎实的角色文档。但**很慢**——可能要几十轮对话。

### 用户是什么人

创作者，不是工程师。**没读过教程，不懂任何方法论术语。** 他判断好坏靠直觉——"这么问我答得上来吗""这个流程我坚持得下去吗"。

## 二、要解决的问题

**标准流程对一部分用户/一部分场景太重了。要不要有一个"简化模式"？什么时候切进去？切了还能不能切回来？**

已知的几种"标准流程不合适"的情况：

- 用户就想快点搞出一个能用的角色，不想聊几十轮
- 用户在标准流程里持续卡住，问什么都答不上来，越问越挫败
- 用户对角色的感觉很整体、很直觉，但拆不成"底色/主色调/点缀色"这种结构化的东西
- 用户是来做一个次要角色（配角、NPC），不值得投入完整流程
- 用户已经有大量现成素材，只需要整理不需要挖掘

### 已有的候选方案

这个设计过程里出现过一条"快速路径"，五步：

```
基础信息 → 小传 → 采访 → 情绪阈值 → 意象
```

思路是：不做结构化的调色盘拆解，改成让用户**讲故事**（小传）和**回答角色视角的问题**（采访），AI 从这些自然叙述里自己提取出性格质地，最后确认一下角色在什么情况下会情绪失控（情绪阈值），再给个意象收尾。

有一句现成的切换话术：**"闭上眼，第一个画面是什么？"**

### 已经定了的相关规则（不要推翻）

- **深度层次不设关卡**：多面性 / 混色 / 核心人格层不是"通过检查才解锁"，而是用户露出苗头才进入，没苗头就不进。用户对此完全无感知。
- **意象总是尝试**：无论走哪条路径，最后都试着提炼一个意象，用户觉得对就留，不对就扔。
- **有一个"够用了"的暂停点**：攒到角色基本可用时，AI 会停下来给用户看一次全貌，让用户决定收工还是继续挖。（在快速路径里，这个暂停点定在"情绪阈值之后、意象之前"）
- **用户说够了就立刻停**，优先级最高。

## 三、没想清楚的地方（讨论的核心）

1. **谁决定切换？** AI 检测到情况不对自动切？还是问用户"要不要换个快一点的方式"？还是一开始就让用户选？
   - 自动切：用户无感知、体验流畅，但可能切错，而且用户会困惑"怎么突然不一样了"
   - 问用户：尊重主权，但要求用户理解两种模式的差别——而用户不懂方法论，很难判断
   - 开头选：最省事，但用户还没开始聊，不知道自己适合哪种

2. **切换的触发条件是什么？** 要能落到可判断的信号，不能是"感觉用户不行了"。
   - 连续几轮无进展？用户主动说"能不能快点"？用户回答持续简短？

3. **切了还能切回来吗？** 用户在快速路径里聊嗨了，想深入了，怎么办？反过来，标准流程走一半切到快速路径，前面攒的东西怎么衔接？

4. **要不要让用户知道自己在哪条路径上？** 告诉他会不会让他觉得"我被降级了"？不告诉他会不会让他困惑？

5. **快速路径产出的角色，质量上会差多少？** 差在哪？要不要在收尾时告诉用户"这里还可以再挖"？

6. **这两条路真的需要是"两条路"吗？** 有没有可能其实是一条路的不同颗粒度，根本不需要"模式切换"这个概念？（这个方向值得认真考虑——多一个模式就多一份复杂度和出错可能）

---

## 四、约束（必须遵守，否则结论没法用）

1. **AI 不教方法论。** 不对用户解释原理，不抛术语（不说"调色盘""底色""三面性"）。用户全程不需要知道任何理论。
2. **不能让用户感觉被降级、被放弃、被区别对待。** 切换如果让用户觉得"AI 觉得我不行"，就是失败的设计。
3. **用户主权最高。** 用户说停就停，用户说要深入就深入。
4. **这个 skill 只负责塑造角色**，不负责生成最终角色卡、不配世界书、不写开场白。
5. 产出都是同一种东西——一份角色文档，不因为走了哪条路径而改变格式。

## 五、我需要你产出什么

请和我讨论清楚，最后给我一个**可以直接照着写进 skill 的结论**，包含：

1. **到底要不要设这个简化模式**——如果你认为不该设（比如认为它其实是同一条路的不同颗粒度），请明确说，并给出替代方案。
2. 如果要设：**切换由谁决定、怎么决定**。
3. **可判断的触发条件**——落到具体信号，不能是"用户明显吃力"这种。
4. **切换时 AI 实际说的那句话**——自然口语，不带术语，不让用户觉得被降级。
5. **能不能切回来、怎么切回来**，前面攒的内容怎么衔接。
6. **简化路径每一步的完成标准**——AI 怎么知道这一步够了可以往下走。
7. 如果用户在简化路径里露出了值得深挖的苗头（比如说出"她在家和在外面完全是两个人"），**要不要临时深入一下**？

讨论时请多用具体对话样例，少用抽象描述——我靠直觉判断，看到实际对话才知道好不好。
