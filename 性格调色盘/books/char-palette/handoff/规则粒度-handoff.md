# Handoff：规则该写到多细，AI 才既守得住方法论、又发挥得出智能

> 这份文件是自足的。你不需要读任何其他文件就能开始讨论。
> 读者：另一个 AI（帮我把这个问题聊清楚）。产出：一把能逐条审查规则的尺子。

---

## 一、背景：我在做什么

我在做一个 skill（给 Claude Code / Cursor 这类 AI 编程助手用的能力包），作用是：

**通过一问一答，引导用户创造出一个角色**（用于 AI 角色扮演的角色卡）。

用户提供想法——可能只有一个标签（"她很温柔"）、一个画面、一段经历，或者干脆"我不知道她是谁"——AI 持续追问，帮用户把脑子里模糊的感觉变成具体、独特、AI 演得出来的角色描述，最终产出一份角色文档。

这个 skill 从一套中文教程《性格调色盘》蒸馏而来。教程的核心洞察：**告诉 AI "她温柔"，AI 只会演数据库里的温柔模板；告诉 AI "她把削好的铅笔放在没笔的同桌桌角，做完就收回目光"，AI 才知道这个温柔长什么样。** skill 的全部任务，是把标签翻译成行为画面。

skill 的运行形态：AI 每轮判断用户的回答缺什么（太笼统 / 前后打架 / 说的是结论不是画面 / 人物太单薄），挑最要紧的追问；用户露出特定苗头时自然往深挖一层；确认过的内容立刻写进文档；攒够了停下来给用户看全貌。用户全程不需要懂任何方法论术语。

**用户是创作者不是工程师**，没读过教程，靠直觉判断好坏。

---

## 二、要解决的问题

**这个 skill 的规则，该写到多细？**

我担心的是：写太多非常具体的规矩、要求、约束，会让执行这个 skill 的 AI 没法灵活应对真实用户——用户的情况千变万化，规则穷举不完，而且细规则会互相打架、会让 AI 变成僵硬的状态机。

但反过来，只给顶层原则不给具体判据，AI 可能理解不到位、每次表现不一致、或者干脆偏离方法论跑回它自己的默认套路。

**我要的结论是一把尺子**：拿到任何一条候选规则，能判断"这条该写成原则、还是该写成具体判据、还是干脆不写"。

---

## 三、现状实测（已经量过了，这是真实数据）

我按下面这把分级尺子量了现有全部设计材料：

- **L0 哲学/定位** — "这个 skill 是追问引擎不是知识手册"
- **L1 顶层原则** — "只追问，不替用户填空"
- **L2 判据/标准** — "遮住名字放到别的角色身上还成立吗？成立就是不够具体"（给可判断的检验方法，怎么用靠 AI）
- **L3 决策规则** — "如果用户回答里出现结论性措辞，就改问具体画面"（if-then）
- **L4 阈值/公式/枚举** — "正面特质 ≥3 且负面 =0 则触发扁平诊断"
- **L5 话术脚本** — 规定 AI 对用户说出口的具体句子

### 实测分布

| 部位 | 主导粒度 |
|---|---|
| 定位与原则 | L0–L1 |
| 诊断（判断用户回答有什么毛病） | **L4** |
| 追问动作（怎么问） | **L5** |
| 信号路由（什么苗头往哪挖） | L3 |
| 主流程与暂停点 | L4 |
| 交互协议（卡住/确认/降级） | L4 |
| 上一代已落地的成品 SKILL.md | L1–L3 |

### 最极端的几条（原文摘录）

```
形容词部分占段落总信息量的 50% 以上 → 触发
正面 ≥ 负面 + 3；≥4 且负=0；≥5 且负≤1 → 触发
真负面 = 0 且总特质 ≥ 3 → 触发
同一诊断连续 3 轮以上触发 → 降标推进
换了 ≥2 个切面 + 脚手架推演 ≥2 次被否 → 切快速路径
每色 ≥3 条衍生；≥3 个质量信号 → 可以暂停给用户看
```

追问动作那一份文件，主体是**成段的、可以直接复制念出来的话术**，不是示例。

### 已经暴露的两个问题

**问题一：哲学和产物正面打架。**

设计主文档写着：
> 不给 AI 穷举 if-else 规则表。给顶层原则、清晰目标和判断好坏的标准

诊断标准文件开篇写着：
> 10 次判断应得到 10 次一样

这两句是反的。一句在信任 AI 判断，一句在追求确定性。

**问题二：细化反而制造了不一致。**

同一个例子——"她很独立，但每天都要给男朋友打电话"——在一份诊断文件里判定为「通过」，在另一份里判定为「弱触发」。两份都是同一条线的产出，都在试图把标准写精确。**规则细到这个程度，没换来一致性，反而制造了不一致。**

**一个有价值的对照：**上一代已经写出来跑过的成品，SKILL.md 只有 127 行，主导粒度在 L1–L3，细节全推到按需加载的 references 里，而且取舍是**"细在禁止什么，粗在怎么判触发"**。这是落地过的实践判断。

## 四、我的初步判断（是假设，请质疑）

**假设一：规则密度应该正比于"AI 默认行为与期望行为的偏离度"。**
AI 本来就会做的事不用写（写了纯浪费预算，还稀释对重要规则的注意力）；AI 本来会做反的事必须硬写（不写一定出问题）。这能解释为什么上一代成品的实践是"细在禁止什么"——AI 默认就爱写形容词、爱替用户补全、爱下结论，这些是强先验，不硬压压不住；而"判断这句话够不够具体"本来就是语言模型擅长的，给个判据就够了。

**假设二：数值阈值给的是虚假的精确。**
"形容词占 50%"、"正面≥负面+3"这类，AI 没法可靠计算，只会估一下然后当作算过了。结果是既没获得确定性，又损失了灵活性。上面那个判定打架的例子就是证据。

**假设三：粒度问题有一部分是架构问题。**
SKILL.md 是常驻加载的，预算有限、每条规则都在稀释注意力，所以它只能装原则；具体判据可以住在按需加载的文件里，那里可以更细。所以"该多细"的答案一部分取决于"它住在哪个文件"。

**假设四：话术示例和话术脚本是两回事。**
给 2–3 个例句，是让 AI 理解"这类问题长什么样"（示范形状）；给出口句型，是让 AI 照着念。前者有用，后者僵硬。目前追问动作那份是后者。

## 五、约束

1. **方法论必须守得住。** 灵活不能变成放飞——这个 skill 的价值就在于它逼出具体行为画面，AI 不能退回"你觉得她是什么样的人？"这种泛泛而谈。
2. **用户不懂术语，AI 不能上课。** 任何规则都不能导致 AI 对用户解释方法论。
3. **有硬红线不能软化**：只追问不替用户填空；用户说停立刻停。这两条不参与粒度讨论，是恒定的。
4. **上下文预算是真实约束。** 常驻文件越长，AI 对每条规则的注意力越稀。
5. 判断标准最终要能被另一个 AI 执行，不能依赖"凭感觉拿捏"。
