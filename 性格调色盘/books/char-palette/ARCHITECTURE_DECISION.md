## SKILL.md 的职责：大脑

SKILL.md 只做三件事，不做其他：

### 1. 持续诊断（4 个 pattern matching，全程运行）

每轮用户说了话之后，AI 内部默默检查 4 种问题：

- **泛化检测**：用户的描写放到别的角色身上也成立吗？（"五官精致气质优雅"→泛化）
- **矛盾检测**：用户给的标签/描述互相打架吗？（"极度自卑"+"成绩前列"→打架）
- **结论检测**：用户给的是事实画面还是总结分析？（"她对他充满恐惧"→结论）
- **扁平检测**：全是正面没有反差吗？（5 个优点 0 个缺点→扁平）

这 4 个诊断是 pattern matching 规则，不是追问话术。它们告诉 AI "用户的回答有什么问题"，然后 AI 根据问题类型决定怎么追问。具体怎么追问的话术不在 SKILL.md 里——SKILL.md 只需要知道"检测到泛化→需要具象化追问"。

**为什么放在 SKILL.md 而不是 reference**：这 4 个诊断全程运行，每轮都要用。如果放 reference，等于一个"永远要加载"的 reference，那文件边界没有提供任何信息——永远要加载的东西就该放在永远加载的文件里。

### 2. 信号检测 + 路由

AI 在性格质地阶段持续监听 3 类信号，检测到信号后路由到对应的 probe 文件：

| 信号 | 症状示例 | 路由目标 |
|---|---|---|
| 场景差异信号 | "她在家和在外面完全不一样""她必须扮演大小姐" | → probe-faces.md |
| 情绪碰撞信号 | "她那时候又开心又难过"、调色盘颜色有强烈张力 | → probe-moments.md |
| 决策深度信号 | "她明明可以接受帮助但就是不要"、有明显防御模式 | → probe-core.md |

未检测到信号 → 不加载对应 probe，角色不需要那个层次。

另外还有条件触发路由：
- 用户主动提及亲密/NSFW → probe-nsfw.md
- 用户还没提世界设定 → probe-world.md

以及阶段性路由：
- 进入性格质地阶段 → probe-tag-compress.md, probe-why.md
- 进入 AI 可执行性阶段 → probe-misread.md
- 进入收束阶段 → probe-imagery.md

### 3. 流程管控

```
入口分流 → 基础身份(轻量) → 性格质地(主阶段) → AI可执行性 → 意象(总是尝试) → 整理输出
```

包括运行规则（不强制线性、基础身份轻量处理、深度分支自然过渡不是关卡、意象总是尝试等）和输出格式（区分已确认/AI推论/待用户决定）。

## references/ 的职责：操作手册

每个 probe-*.md 文件是一个独立的追问操作手册。AI 通过 SKILL.md 的信号路由决定"我需要做什么"，然后加载对应的 probe 文件知道"具体怎么做"。

每个 probe 文件的内部结构统一：
1. **AI 内部诊断**：更详细的判断标准（SKILL.md 里的是摘要，这里是完整版）
2. **AI 对用户的外部问法**：2-4 个示例问句，自然语言，不用术语
3. **质量门**：怎么判断用户的回答"够了"可以推进

**关键原则：AI 内部诊断和外部问法必须分开。** 诊断是 AI 内心的判断，用户看不到。外部问法是 AI 实际说的话，不暴露方法论、不用术语、不预设用户懂任何理论。

### 各 probe 文件的量级和使用模式

| 文件 | 预估行数 | 对话轮数 | 加载时机 | 特点 |
|---|---|---|---|---|
| probe-tag-compress.md | ~20 行 | 2-4 轮 | 性格质地阶段 | 几乎每个角色都会用 |
| probe-why.md | ~20 行 | 2-3 轮 | 性格质地阶段 | 几乎每个角色都会用 |
| probe-world.md | ~15 行 | 1-2 轮 | 入口/基础身份早期 | 一次搞定后不再需要 |
| probe-faces.md | ~50 行 | **8-15 轮** | 信号触发 | **重模式**，不是每个角色都需要 |
| probe-moments.md | ~25 行 | 3-6 轮 | 信号触发 | 中等，不是每个角色都需要 |
| probe-core.md | ~55 行 | **8-15 轮** | 信号触发 | **重模式**，不是每个角色都需要 |
| probe-nsfw.md | ~15 行 | 2-3 轮 | 用户主动提及时 | 条件触发，不主动引导 |
| probe-misread.md | ~20 行 | 2-3 轮 | AI 可执行性阶段 | 几乎每个角色都会用 |
| probe-imagery.md | ~15 行 | 1-2 轮 | 收束阶段 | 总是尝试，用户不要就不要 |

## 为什么是这个架构

### 核心比喻：医生的脑子 vs 手术操作手册

SKILL.md 是医生的脑子——诊断能力（4 个 pattern matching）、判断做什么手术（信号检测）、决定手术顺序（流程管控）。这些能力必须始终在线，不能"需要的时候再想起来"。

probe 文件是手术操作手册——具体怎么做标签压缩、怎么引导三面性构建。医生决定"这个病人需要做 X 手术"之后才翻 X 手术的操作手册。不需要把所有手术手册都背在脑子里。

### 为什么 SKILL.md 不装追问话术

之前的方案试图把"轻量追问"内联到 SKILL.md，把"重追问"放 reference。但这个区分是模糊的——什么算轻什么算重没有清晰边界。而且这样 SKILL.md 既要做判断又要装话术，职责不清晰。

现在的方案：SKILL.md 纯粹做判断，所有话术都在 reference。职责边界清晰，没有模糊地带。

### 为什么每个追问独立一个文件（而不是合并成 2-3 个大文件）

经过讨论确认：这 9 个追问动作互不交叉、不会同时进行、没有衔接依赖。它们是完全独立的"模式"——进入一个模式，做完，退出，可能进入另一个模式。

独立文件的好处：
- **信号→文件的映射是一对一的**：检测到场景差异信号→读 probe-faces.md。不需要"读某个大文件的某个章节"。
- **只加载需要的**：简单角色可能只用 probe-tag-compress + probe-why + probe-misread，完全不需要加载 faces/core/moments。
- **每个文件职责单一**：打开 probe-faces.md 就知道"这个文件只做三面性引导"，不会和别的东西混在一起。

独立文件的弊端（已评估，认为可接受）：
- **文件数量多（9 个）**：但每个文件只有 15-55 行，加载成本极低。
- **部分文件很小（15 行）**：确实很小，但它们有独立的触发时机和独立的职责。15 行的文件不是问题，空文件才是问题。

### 为什么不合并成 2-3 个大文件

之前考虑过按阶段合并（phase-personality.md / phase-depth.md / phase-output.md）。放弃的原因：

1. **按阶段拆导致跨文件引用**：信号检测在 personality 阶段进行，但触发后要读 depth 文件。检测和执行被拆到了两个文件里。
2. **阶段边界是模糊的**：实际对话中用户可能在任何时候给出触发信号，不一定严格按阶段顺序。
3. **合并后的文件里有不需要的内容**：打开 phase-depth.md 做三面性的时候，核心人格层的内容也在里面占着上下文。

现在的方案用"一对一映射"替代了"先找文件再找章节"，消除了以上三个问题。

### 为什么 4 个基础诊断放 SKILL.md 而不是 reference

4 个基础诊断全程运行，每轮都要用。如果放 reference：
- 要么"始终加载"——那和放 SKILL.md 没区别，多了一个文件边界但没有信息量
- 要么"按需加载"——但它每轮都需要，"按需"等于"每次都需"，回到第一种情况

所以直接放 SKILL.md。它们是大脑的一部分，不是操作手册。

### 为什么示例文件暂缓

skill 还没写出来，不知道"好的使用"长什么样。现在写示例只能凭想象编，不如先把 skill 跑起来，从真实对话中提取效果好的片段作为示例。计划在阶段 4（压力测试）之后补充。

## 决策过程

### 怎么得出这个决策的

1. **阶段 1**：派 3 个独立 AI agent 分析教程，提取了 13 个追问动作
2. **阶段 1.5**：三重验证筛选，确认 13 个追问动作（11 个直接通过 + 2 个用户捞回）
3. **架构讨论第一轮**：我提出按阶段拆 3 个 reference 的方案（phase-personality / phase-depth / phase-output）
4. **用户反馈**：指出"遮住名字测试"等诊断逻辑是 AI 内部用的，不能直接问用户
5. **架构讨论第二轮**：派 6 个 agent（两轮各 3 个）独立设计架构，得到方案 A（不拆）/B（3-4 个 reference）/C（9 个 reference）
6. **关键追问**：用户问"深度追问是一个长期多轮的重动作吗？" → 重新分析每个追问的实际轮数和重量
7. **最终收敛**：用户指出所有追问都不交叉、不同时进行 → SKILL.md 做信号判断，所有追问独立成文件 → 当前架构

### 被否决的方案和原因

| 方案 | 被否决原因 |
|---|---|
| 全部装进 SKILL.md（~410 行） | 170 行阶段追问在入口阶段白白占上下文；违反 progressive disclosure |
| SKILL.md 装基础诊断+轻量追问，reference 只放重追问 | "轻"和"重"的边界模糊；SKILL.md 职责不清晰（既判断又执行） |
| 按阶段拆 3 个 reference | 阶段边界模糊；信号检测在 A 文件触发后要跳到 B 文件执行 |
| 三面性+核心人格层合并为 1 个 deep-structure.md | 两者不交叉不衔接，合并没有收益，拆开加载更精准 |
| 基础诊断放 reference "但始终加载" | "始终加载"的 reference 和放 SKILL.md 没区别，多一个文件边界没有信息量 |

## 接手 AI 的行动指南

### 要做的事

1. **写 SKILL.md**（~150-180 行）：身份约束 + 流程模型 + 4 个基础诊断 + 信号检测路由表 + 对话风格 + 输出格式
2. **写 9 个 probe-*.md**：每个按统一结构（AI 内部诊断 + AI 外部问法 + 质量门）
3. **写 agents/openai.yaml**

### 必须遵守的约束

- **教程 ≠ skill**：不教方法论，不用术语（底色/主色调/三面性/混色/核心人格层这些词不对用户说）
- **标签是起点不是敌人**：接受用户给的标签，用追问下钻成具体行为
- **用户没读过教程**：不预设用户懂任何东西
- **诊断和追问分两层**：AI 内部诊断用户看不到，AI 外部追问用户看到但不暴露方法论
- **输出分三类**：已确认 / AI 推论 / 待用户决定，不把推论当事实

### 输入材料在哪

- 13 个追问动作的完整定义 → `candidates/questioning-moves.md`
- 验证通过的名单和理由 → `verified.md`
- 流程模型 → `candidates/questioning-moves.md` 第三部分
- 教程原文 → `性格调色盘/` 目录下 11 篇
- 整书理解 → `BOOK_OVERVIEW.md`
