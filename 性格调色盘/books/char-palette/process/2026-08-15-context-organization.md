## 整理方法论（本次的核心思考，回答"应该怎么整理"）

### 1. 三层文档体系（替代"散着看"）

- **入口层**：SKILL_WRITING_CONTEXT.md，通读一次（约 20 分钟）。
- **按需加载层**：8+2 份核心材料，写哪个部分读哪个（阅读地图 §9 给了精确映射）。
- **回查层**：审查报告/候选池/教程章节，只有需要细节时才读（教程只在 §7 例外边界内回查）。

这直接复用了 skill 自己的设计哲学：SKILL.md 是大脑，probe 用哪个读哪个。写 skill 的过程也按 progressive disclosure 组织。

### 2. 明确结论怎么写 → 决策日志（包 §4）

每条一句话结论 + 出处 + 状态标记，按主题分组编号（A 定位 / B 诊断 / C 追问动作 / D 架构 / E 流程 / F 快速路径 / G 交互协议 / H 承载机制 / I 边界 / J 命名）。**不复制全文，只给结论和指针**——单一事实源保持在原文档。

### 3. 冲突怎么写 → 两条路

- 新旧取代（有明确日期先后、一方明示否决另一方）→ **显式裁决"以新为准"**（包 §5 S1-S8），被取代的旧决策标"不要改回"。
- 两代平行、双方各有"已确认"依据、或融合产物单方面裁决未拍板 → **不裁决，记待办**（包 §6 Q0/Q11/Q12/Q13：背景+选项+建议+阻塞关系），用户拍板后转裁决。**这是上次融合失败教训的直接修正。**

### 4. 教程问题怎么写 → 结论 + 理由 + 例外边界（包 §7）

**结论：写 skill 的 AI 不通读教程。** 理由：蒸馏已完成且可追溯；教程是教学语言会污染 skill；20 万 token 以上成本。**例外边界必须配齐**：probe→教程章节映射 + 定点提取指针（精确到节）+ "回查必先套翻译层"。且教程精要已内化进包 §3——结论成立的代价是包必须自足。
