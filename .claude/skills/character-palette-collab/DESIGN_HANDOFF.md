# 设计 Handoff：人机协作调色盘 skill（character-palette-collab）

> 本文件是设计决策的完整交接文档。**回退后的 AI 必须完整阅读本文件，再开始设计/编写 skill。** 本文件内的决策是用户逐条确认过的，不要推翻重来；如有疑问，先读本文件，仍有疑问再问用户。

---

## 0. 任务定位（一句话）

做一个 skill：**人机协作构建角色**。不是 AI 直接写角色，而是**人提供经历素材 → AI 用心理学框架推演 → 人裁决 → 循环迭代**，最终按"性格调色盘"方法组装出完整人设。

## 1. 大原则（最高优先级，违反即错）

1. **技能用途是构建角色卡，不是运行角色卡。** 不管 SillyTavern 的实际运行顺序。人物成型后，一次性写成实际用的卡（"实际用的卡"怎么写是之后的事，现在不设计）。
2. **教程顺序 = 教学逻辑，不是构建逻辑。** 教程（调色盘/三面性/混色/核心人格层等）的章节顺序是作者的教学顺序，**不作为** skill 的设计依据。
3. **用户铁律——每句话必要性审查**：skill 里的每一句话，思考"删掉它是否影响读 skill 的 AI 的理解和执行"。删掉不影响 → 是废话，删掉。解释逻辑、原理、原则、有助于模型理解和执行质量的 → 保留。**用词精准、明确、直接。**
4. **文档顺序本身就应该就是呈现顺序。** 框架模板本身就是顺序，不要额外加"按呈现顺序排版""增量写入"这类话术——确认了什么就填到对应框架底下，这是自然发生的，不需要说明。

## 2. 已确认的设计决策（逐条，含决策逻辑）

### 2.1 技能触发方式

- 用户**主动使用**本技能（不依赖自动触发）。description 不需要做触发优化。

### 2.2 文件结构（重要：一个文件，不是两个）

- **每角色一个目录**：`workspace/角色名/`
- 目录内**一个文件**：`人物文档.md`
- 早期设计有"过程记录"文件，**已被取消**（决策逻辑见 2.4）。
- 也砍掉了"待定区"这个文件（原因：它是数据的坟墓——候选够好会当场拍板进性格，不够好进了也不会被翻出来；未决候选要么留在对话里继续磨，要么等于"下一步要做的事"）。

### 2.3 人物文档：素材区 + 构建区（同一个文件）

- **素材区 = 原始事实**：身份、外貌、背景、关系、经历事件、行为切片、画面。用户提供，AI 记录，不改动。
  - **基础信息"（姓名/年龄/外貌/背景/关系）**不单独成章**，它也是素材，归入素材区。构建时你不可能先写完基础信息再写经历——都是想到哪填到哪。
  - "背景设定"和"经历事件"不分家（"爸爸 10 岁去世"是背景还是经历？分不出来，也不该分）。
  - **素材区内部细分小节，但小节是归档位置，不是填写要求**：素材区细分五个小节（身份/外貌/背景/关系/习惯与偏好），小节标题下标注"按需记录，不要求完整"——防止 AI 或用户误解为"每节都要填、按顺序填"。每条素材确认时，AI 判断它属于哪个小节，填进去。某些小节始终为空很正常。细分的好处：AI 做推演时能按需定位（如"翻她的经历找线索"→ 直接看背景小节），不用扫描全文。

**素材区内部结构**：
```
素材区
├─ 身份（姓名/年龄/身份/世界设定）——按需记录
├─ 外貌（特征，不是美感）——按需记录
├─ 背景（改变了这个人的经历事件）——按需记录
├─ 关系（具体互动画面）——按需记录
└─ 习惯与偏好（标志性行为切片/偏好）——按需记录
```
- **构建区 = 从素材推演出的性格**：调色盘、核心人格层、多面性、混色、二次解释。AI 推演 + 用户裁决后写入。
- **素材区和构建区放同一个文件**，不拆文件。原因：它们是同一个人的一部分（"她爸爸去世了"和"她的底色是不甘心"说的是同一个人），拆开反而要跨文件引用；且拆不拆不影响"想到哪填到哪"的读写逻辑。
- 素材区是地基，构建区是地基上盖的楼。写卡只拿构建区，但素材区保留做追溯（每条推演要标注"从哪段经历推出来的"）。

### 2.3b 人物文档的定位：人物小传，不是最终卡

**人物文档 ≠ 最终放到世界书里的角色卡。** 二者是"素材"和"产品"的关系。

| | 人物文档 | 最终卡（世界书里的角色卡） |
|---|---|---|
| **用途** | 构建过程中的工作稿 + 完整人物记录 | 给 AI 运行时用的提示词 |
| **读者** | 构建者本人 + 未来写卡的 AI | 运行卡的 AI |
| **内容** | 人物的全部信息，包括推演依据（"她的底色是不甘心，因为爸爸去世后她扛起了家"） | 只写运行时需要的，不写"为什么"，极致压缩 |
| **完整性** | 追求完整可追溯——每条性格能从经历里长出来 | 追求 token 效率——删掉 AI 已知的默认值、删掉推演因果链 |
| **信息密度** | 追求"无废话"（每一条揭示人物侧面） | 追求"极致压缩"（连接词都删，用列表替代叙述） |

**人物文档的本质是人物小传**——它要回答的不只是"她是谁"，还有"她为什么是ta"。最终卡是"从人物文档里提炼出来的运行时版本"。

**最终卡怎么做**：人物成型后，从人物文档提炼最终卡。提炼规则参考教程"写正确的卡"（`性格调色盘/0.写"正确"的卡.md`）：
- 素材区里 AI 已知的默认值（如"中国人黑头发"）→ 删掉
- 构建区里的推演依据（"她为什么这样"）→ 删掉（运行时 AI 不需要）
- 性格构件 → 按调色盘/多面性框架精简写入
- 世界观 → 按教程 ABC 分类（真实背景/小世界/大世界）压缩

**教程里哪些原则适用于人物文档、哪些不适用**：

适用的（信息质量原则，与用途无关）：
- **外貌只写特征，不写美感**："精致的脸蛋、白皙的皮肤"遮住名字放谁身上都行 → 写"杏眼眼尾微垂、刘海自己剪的参差"。特征是事实、可追溯可推演，美感是判断、不能。
- **背景只写改变了这个人的事**：能推演出性格的经历才记录。"她喜欢吃草莓"如果没推演价值 → 不记。
- **关系写具体画面，不写抽象形容**："她对他充满恐惧" → "他把零食放她桌上，她用书本推到桌角"。画面是推演的原料，抽象形容不是。
- **基础信息与性格分开放**：这恰好是素材区（事实）和构建区（性格）分离的设计依据。
- **每句话过"删掉它有没有影响"的测试**：人物文档的判断标准是"删掉它，对这个人的理解会不会丢失信息"（不是 token 效率）。

不适用的（最终卡特有的 token 优化逻辑）：
- **"只写偏离默认值"**：不适用。人物文档是完整画像，不是运行时提示词。删默认值是提炼最终卡时做的事。"她长得太普通了，普通到没人记得她"在推演阶段可能是关键线索（→ 她故意让自己不起眼）。
- **极致压缩**：不适用。人物文档追求可读性和完整性，不追求 token 效率。
- **不写"为什么"**：恰好相反——人物文档的核心价值就是"为什么"。推演依据是人物文档独有的。

### 2.3c 素材区记录标准：推演价值

素材区不是"人物数据库"，而是**推演的原料库**。每条素材都是一个未解释或已解释的特征点。记录标准只有一条：

**判据：这条素材能不能成为推演的起点？能不能问出"她为什么这样"或"这暗示了她是什么样的人"？**

**记什么——四类有推演价值的素材：**

| 类型 | 判据 | 例子 |
|---|---|---|
| **经历事件** | 改变了这个人 | "爸爸10岁去世""大学被孤立" |
| **行为切片** | 能问出"她为什么这样" | "在家穿衣大胆""网上活跃线下沉默" |
| **标志性偏好/习惯** | 能定义她的辨识度或暗示心理 | "只穿高领无袖""一个人时才吃草莓""进门先洗手" |
| **关系动态** | 有具体的互动画面 | "他把零食放她桌上，她用书本推到桌角" |

**不记什么——三类没有推演价值的素材：**

| 类型 | 判据 | 例子 |
|---|---|---|
| **纯审美标签** | 放在谁身上都行的偏好 | "喜欢听音乐""喜欢看电影" |
| **无辨识度的默认值** | AI已知的、没有偏离的 | "黑头发""穿校服"（除非校服有特殊之处） |
| **与推演无关的一次性事件** | 删掉它人物没变化 | "有一次下雨她没带伞"（除非这件事有后果） |

注意"偏好"的时机判断：如果只是"她喜欢吃草莓"，价值低；但如果"她只在自己一个人的时候吃草莓"，就是一个行为切片——因为有了情境限制，就能问出"为什么"。

### 2.4 过程记录已被取消（重要决策）

\**早期设计：**过程记录只记协作过程（否决记录、待定项、下一步），判断标准是"主语是她→人物文档，主语是我们→过程记录"。

**最终决策：过程记录整个取消，并入人物文档。** 推理链：

1. **否决记录被拆解**：用户否决一条推演候选，否决的原因往往揭示了角色特征（如否决"社会学习版穿衣推演"，原因"她不是那种在意场合的人"——这本身就是一条角色事实，应进素材区）。**角色相关的否决 → 原因进素材区；纯协作信息的否决（如"必须要用英文沟通"）→ 不记录**（它是会话内的即时指令，下次会话用户需要会再说，不存档）。
2. **防重复功能被素材区天然承担**：否决原因进了素材区后，AI 下次推演读素材区时自然不会再推已被否决的方向——**不需要专门的"否决记录"字段来防重复**。
3. **待定项并入"下一步"**：未决候选本质上就是"下一步要做的事"。
4. **阶段/下一步概念被取消**（关键决策）：构建是**特征驱动的迭代环，不是线性流程**——你可能同时推进多个特征点，每个都在不同深度，不存在"我现在在第 3 阶段"这种清晰状态。所以"标记阶段"没有价值。**"下一步"也不需要单独拎出来**——改为：**最近更新的特征点旁边做标记**（如 ⏸ 或日期）。下次新会话读到标记就知道上次在构建哪个特征点，从那里继续。这比"下一步"字段精准（字段是抽象指令，标记是具体位置）。
5. **纯会话痕迹（"本轮聊了什么"）不记录**：角色内容进人物文档，会话过程零价值。

**最终文件结构：**

```
workspace/角色名/
└── 人物文档.md
    ├─ 素材区（她经历过什么）——含否决揭示的角色特征
    ├─ 构建区（她是什么样的人）——最近更新的特征点旁有标记（如 ⏸ 或日期）
    └─（无状态区、无过程记录、无阶段概念）
```

**续接机制**：新会话读文档，找最近更新标记，从标记处继续。角色相关的否决原因已在素材区，AI 不会重复推演已否决的方向。

### 2.5 呈现顺序（人物文档的物理排版顺序）

```
意象 → 素材区 → 调色盘 → 核心人格层 → 多面性 → 混色 → 二次解释
```

- **意象是呈现顺序的第一个，但它是构建顺序的最后一个。** 意象 = 用具体物件/画面把角色内核浓缩成总比喻（陈乖乖="冬天窗台上那一小格阳光"，姜糖="向日葵"，洛潮汐="潮汐"）。它需要全部素材和核心矛盾都清晰后才能凝聚出来——是构建的封顶，不是起点。
- **呈现上第一个被读到**（锚定读文档者对人物整体的感觉）；**构建上最后一个被创造**。
- 构建/写作时**不从头写到尾**：确认了什么就填进对应部分，用户想到哪部分（哪怕是核心人格层）直接写进那部分。

### 2.6 构建顺序（实际干活的顺序，与呈现顺序不同）

```
素材收集 → 调色盘 → 核心人格层 → 多面性 → 混色 → 二次解释 → 意象
```

- **意象最后凝聚**：意象需要等全部素材聊完才能长出来（"她像冬天窗台上那一小格阳光"是陈乖乖全部素材聊完之后才找到的）。
- **核心人格层在多面性之前**（与教程顺序相反——教程是先教多面性，但那是教学顺序）。原因：多面性每张面有一个"功能"部件——"这张面在保护什么、解决什么问题"——而这个"保护什么"恰恰就是核心人格层的防御机制。如果先拆多面性，"功能"只能凭感觉写，写完挖了核心人格层发现不准，要重写。先挖核心人格层，多面性的"功能"直接等于防御机制的分支，有依据，一次写准。**多面性是从人格内核长出来的，不是从场景表面拍的。**（例外：角色没有明显场景切换时不需要多面性，直接用核心人格层+调色盘，此逻辑不触发。）

### 2.7 多面性（不叫三面性）

- **名称必须是"多面性"**。"三面性"一定会引入"必须三张面"的误解。本质是多面性：两面、三面、四面都可以，面的数量由角色本身决定，不由名字决定。

### 2.8 总流程（迭代环）

```
入口探测 → 素材收集 → 动机追问 → 多框架推演 → 组装轮廓 → 用户确认 → 补全档案 → 一致性验证
   ↑                                            ↓
   └──── 否决或新素材，回到素材收集（迭代环）────┘
```

### 2.9 入口引导（所有用户都走同一套开始流程，不是空白才引导）

**原则：先开放聆听，后定向追问。引导永远是兜底，不是默认。世界设定先行——不管用户空白不空白，都要先交代基本世界设定，否则角色构建就是空中楼阁。**

- **第一步：世界设定（必走）。**
  - 题材："想写什么题材？现代都市？古风？仙侠？末世？校园？"——题材直接决定场景库
  - 世界基调：按需聊到能支撑角色构建即可（"写多少世界观取决于角色需要多少才能活"——不需要聊很细）
  - 世界设定记入素材区（作为角色的背景上下文）

- **第二步：开放式人物询问（必问，不强引导）。**

  > "这个人物你心里有没有一些构思？不管是一个画面、一个习惯、一段经历，还是一个模糊的感觉，都可以说。"

  - 用户自由说，**AI 先完整听，不打断、不引导、不提问**

- **第三步：根据用户说的内容展开。** 用户说完了，AI 总结记录，再按内容选方向追问：
  - 说了画面 → 围绕画面追问细节
  - 说了切片 → 围绕切片追问（什么时候/对谁）
  - 说了经历 → 围绕经历追问事件细节
  - 只有模糊感觉 → 用镜像类/具象类问题钩出具体（见下"问法六类"）

- **第四步：用户确实没有构思 → 才用情景引导**（收窄边界再激发）：
  1. 题材第一步已确认 → **身份/处境**："她在这个世界里大概是个什么身份？学生？社畜？剑修？"——框住人物边界
  2. **情景引导**："想象一个场景：<契合题材和身份的具体场景>。在这个场景里，她的第一反应是什么？"
  3. 生成的初始素材回到第三步展开

- **问法六类**（在展开/追问阶段用，按可答性排序）：
  1. **镜像类**（最好答）："你身边有没有认识的人，身上有你想写的那个感觉？"——用户心里有模糊影子时，最容易从现实认识的人开始
  2. **反应类**："如果她看到有人被欺负，她会怎么做？"——一个反应就是一个性格切片
  3. **具象类**："她每天放学回家，进门做的第一件事是什么？"——问具体的物，不问抽象的理
  4. **关系类**："她和谁关系最好？她和谁的关系让她最不舒服？"——关系是钩子，从关系钩出人物
  5. **反差类**（活人感入口）："她在什么情况下会和平时完全不一样？"——多面性的天然入口
  6. **决策类**（最难答，素材足够后才问）："如果她只有一次机会救一个人，她会救谁？"——能挖核心人格层，但凭空问答不上来

- **永远不先问"她是什么性格"**——问性格=诱导贴标签。改为问**事件类/具象类问题**，钩出用户已有的倾向，而不是要求现场创作。

- **现代都市爱情题材的现成情景引导**（第四步题材确认后用反应类问题最自然）：
  - 日常生活类（最容易答）："她下班回家，进门做的第一件事是什么？""她周末一个人在家，会怎么过这一天？"
  - 关系类："她最好的朋友失恋了半夜打电话给她，她第一反应是什么？""她在公司遇到一个很烦的同事，她会怎么处理？"
  - 反差类（活人感入口）："她在什么情况下会和平时完全不一样？""她在外人面前是什么样子？只有她自己一个人的时候呢？"
  - 压力类（挖深层，素材足够后再用）："她接到一个坏消息，第一反应是什么？先做什么？""她发现自己被最信任的人骗了，她会怎么做？"
  - 决策类（最难答，最后用）："她只有一次机会，只能救一个人，她会救谁？"

### 2.10 动机追问协议（先问后推演——本协作模式的核心基石）

- **AI 永远先问作者，禁止先给候选。** 原因：作者的解释永远比 AI 的推演独特。AI 一旦先给候选，作者就被框住了——要么被带着走，要么觉得"不是这个但说不清哪里不对"。
- **第一层：问。** 用**具体化问法**，不问抽象的"为什么"，问"什么时候/对谁/什么情境"：
  - "这个切片从什么时候开始有的？"
  - "她在什么样的人面前会收敛、什么样的人面前不会？"
  - "如果这个环境永远不会有人来，她还这样做吗？"
  - "她有没有一个想让他看见'原来她是这样的'的人？"
- **第二层：作者答上了 → 验证，不替换。** AI 做三件事：①检查内部矛盾（解释和已有素材打架吗）②补盲区（作者没想到的层面，标注"这是补充，不是替换"）③指出隐含结构（切片里隐含了什么可发展的结构，如"外端庄/家大胆"已是多面性的雏形）。
- **第三层：作者无解 → 多路径推演。** 无解的判定标准：作者说"不知道/没想过/说不上来"，或答案模糊（"就是感觉"），或解释与素材明显矛盾。
- **第四层：人裁决 → 循环。** 勾选→记录；修改→按修改定稿；否决→记否决原因，且否决时用户往往补充新经历→回到素材收集。

### 2.11 多框架推演（取代"反直觉"概念——重要的设计决策）

- **"反直觉"概念被废掉。** 对 AI 来说没有"反直觉"这回事：数据库里有大量"被抛弃→学会先抛弃别人"这类低频但真实的关联，AI 知道这些可能性，只是默认不会先想到它们。

- 真正的问题叫**频率偏差**：AI 生成时天然偏向语料中高频共现的关联（"被抛弃"→"缺乏安全感、敏感多疑、害怕亲密"）。文章作者观察到"AI 总是给最刻板的关联"，观察是真的，机制就是频率偏差。"活人感"恰恰来自低频但真实的关联，所以 skill 要解决的是**强制 AI 突破自己的频率偏好**。

- **为什么不干脆"列出所有可能性"**：纯清单会被频率偏差和锚定效应双重杀死——AI 列 8 条第一条还是最常见的，用户面对平铺选项会选前几条，又回到标签化。清单没有结构，每条候选没有"为什么值得选"。

- **解法：多路径推演**——从 ≥2 个不同心理学框架各推演一条，每条标注依据。**推演的多样性不靠 AI 灵机一动，靠从不同生成轴各推一条。**

- **核心四框架**（任何角色都能推出东西，普适生成轴）：

  | 框架   | 生成轴   | 推演方向                   | 卡片映射             |
  | ---- | ----- | ---------------------- | ---------------- |
  | 依恋理论 | 关系轴   | 怎么靠近/推开、怎么表达需求、对分离什么反应 | 调色盘衍生、核心人格层·深层缺失 |
  | 防御机制 | 自我保护轴 | 压力下做什么来保护自己            | 核心人格层·防御机制（直接对应） |
  | 社会学习 | 环境学习轴 | 从谁身上学了什么、什么行为被环境留下/抹掉  | 调色盘衍生、多面性        |
  | 认知图式 | 认知解读轴 | 内心相信什么、每个情境怎么被解读       | 深层缺失/核心恐惧、二次解释   |

  - 选择这四个的依据（筛选标准）：**生成性**（必须能"经历→行为"推演，纯描述的不算）、**行为落地**（推演出来必须能演）、**结构性差异**（框架视角互不重叠，重叠的只留一个）、**领域覆盖**（覆盖写卡领域真正的角色类型）、**卡片映射**（推演结果能流进调色盘结构）。
  - 排除的：**特质论（大五）**——描述性而非生成性，且整套方法论要消解的就是特质标签；**进化心理学**——讲人类共性，对个体独特性贡献低；**沟通分析（TA）**——和认知图式高度重叠，二选一。

- **扩展池**（按角色类型触发，每个只需一句话机制+触发条件+示例）：创伤/应激反应（有极端事件）、家庭系统（家庭驱动背景，陈乖乖=被父母化的孩子）、存在主义（死亡/意义主题，洛潮汐）、社会角色/印象管理（伪装/身份切换，秋明月）、自我决定理论（强烈表层欲望）、发展任务（成长转变期）、荣格阴影（表里反差极大）、情感调节（情绪表达特殊）。

- **选择规则**：每轮推演**不是全框架各来一遍**（会很机械）——从核心四挑 2-3 个 + 按角色类型从池里加 1 个，凑出 **2-3 条结构性差异最大**的推演。

- **开放原则**：池不封闭，某段经历有更贴切的框架（如文化心理学），AI 可以用，但必须标注框架名和机制，不许裸套。

- **硬规则：推演禁止出形容词，只许出行为场景。**"缺乏安全感"不许写，要写"她每次分开前都会反复确认下次见面的时间"。因为出形容词=出标签。

- **每条推演标注三要素**：①行为场景（可直接当衍生素材）②心理学机制 ③从哪段经历推出来的（闭环可回溯）。

### 2.12 记录粒度（特征闭环即记录，事件驱动，不是轮次驱动）

- 一个特征点被用户明确认可（"这个对""就是这种感觉"）→ **立即**写入人物文档对应部分，不等轮次结束。
- 闭环判据：这条特征已经能被一句行为描述说清楚、且用户认可。
- 未闭环的留在对话里继续磨。
- **记录是事件驱动，不是轮次驱动**：只有内容变化时（特征闭环、用户否决、新素材确认）才写入，没有变化就不碰文件。**每轮结束不自动写**——很多轮次没有有效产出（"我想想"也算一轮），每轮都记太密集，且有效信息未成型就落盘没有价值。
- **不丢信息的保障**：有效信息产生的那一刻就被记录（特征闭环→构建区、否决揭示的角色特征→素材区），不需要等用户说"存档"；即使中途关掉对话，只要有过内容变化，文档就在，新会话读文档的最近更新标记即可续上。

### 2.13 组装与输出

- **先给轮廓，用户确认后补全**——不要把完整人设一次性砸给用户。
- 素材流向：推演出的行为场景→调色盘衍生；用户提供的原始切片→混色画面（原样保留）；作者解释+推演候选→核心人格层；意象→从核心矛盾里长出（不是搜来的比喻）。
- 组装完成后跑一致性验证（性格打架吗、衍生矛盾吗、多面性里混入二次解释吗、语料移出调色盘了吗、混色解释情绪了吗、防御机制落到行为了吗、意象从核心矛盾长出了吗）。

### 2.14 红线（不可违反）

1. 禁止先给推演（作者无解之前，先问；作者能答，绝不抢答）
2. 禁止形容词（所有推演/衍生只许出行为场景）
3. 禁止一次性砸完整档案（先轮廓，确认后补全）
4. 禁止标签化（不写"极度自卑""傲娇"裸标签）
5. AI 永远提案，用户永远裁决

### 2.15 边界（不做的事）

- 不生成开场白、不写正文、不做 NSFW 内容
- 不替代作者决策
- 不一次输出全部性格（分轮推进）

### 2.16 问题目标层（补回"问的目标"——重要决策，2026-08-05 确认）

**问题（为什么补这一层）**

2.10 动机追问协议定义了"怎么问"——具体化问法、先问后推演、问法六类。但它**没有定义"问的目标是什么、问到什么程度算够"**。后果：一个只读 skill 文档的 AI 知道要问具体问题，却不知道每个问题在探什么、探到什么算够，会把问法六类当菜单轮着用，永远不收敛——**为问而问**。

**洞察来源（教程里已有完整答案，skill 设计当时没抄）**

| 来源文件                                   | 给出的东西                                                                                                                                                          |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `调色盘/角色理解80问教程.md`                     | 十个分组，每组开头一句"这一组解决的是：……"（角色核心 / 调色盘 / 背景来源 / 欲望缺失恐惧 / 防御决策 / 关系 / 三面性 / 混色 / 台词行为 / 底线弧光二次解释）；每题带一行"解释："（单题目标）；开头总目的："让作者从'我想写一个什么标签的角色'慢慢走到'我知道这个角色为什么会做这种选择'" |

**设计结论（skill 怎么改）**

在动机追问之上补一层"问题目标层"，三样东西：

1. **探明什么**——十组目标作为提问方向索引。不是每次问全十组，是 AI 判断当前特征点落在哪一组、就往哪一组问。
2. **终点**——核心人格层"最低限度要知道"清单：所有提问最终要到达"角色怎么做选择"。这是 2.10 第二层"指出隐含结构"和 2.11 多框架推演的前提。
3. **够不够的判据**——标签下钻五连问（只有标签=没问够）+ 2.12 闭环判据（能落成一句行为描述且用户认可=够）。

**实现位置**

- `references/03_动机追问.md`（第二批）：开头先写"本阶段目标契约"——每个问题都要能回答"我在探什么"；探明什么=十组方向；终点=核心人格层清单；够不够=下钻五连问 + 闭环判据。
- `SKILL.md` 阶段三概述：加一句"每个问题都要有目标：在探什么、探到什么算够"，把"为问而问"堵死。

**为什么不动 2.10**：2.10 的"先问后推演、具体化问法"是交互顺序和问法，仍然成立；问题目标层解决"问什么、问到什么算够"，两者互补不冲突。红线 1（作者无解之前先问）不变。
