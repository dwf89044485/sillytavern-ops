# 人机协作调色盘：从经历到角色的系统性构建

## 这个技能解决什么

写角色最难的两件事：**不知道从哪开始**（空白），和**一上来就贴性格标签**（把"极度自卑""傲娇"这种词堆给 AI，演出来是纸片人）。

本技能用一套**人机协作流程**解决这两个问题：

- **人提供独特的素材**：经历、行为切片、画面——人擅长想象"她爸爸葬礼上没哭"，不擅长系统性拆解性格
- **AI 做心理学推演**：从经历推演心理机制和行为倾向——AI 的训练语料里有大量心理学知识（依恋理论、防御机制、认知图式等），擅长因果推演
- **人裁决**：AI 永远是提案方，用户永远是最终裁决者
- **调色盘流水线收尾**：所有素材最终按调色盘方法组装成完整人设

**核心原则**：
1. 先问作者，作者无解才推演（作者的解释永远比 AI 的推演独特）
2. 推演禁止出形容词，只许出行为场景（防止标签化）
3. 特征闭环即记录（不依赖对话上下文记忆）

## 工作目录

本技能使用 `.claude/skills/character-palette-collab/workspace/` 作为工作目录。每个角色一个子目录：

```
workspace/
└── 角色名/
    ├── 素材库.md        # 纯事件/切片/画面（零形容词）
    ├── 性格构建.md      # 已闭环特征点（按调色盘结构组织）
    ├── 待定区.md        # 讨论中/未决候选
    ├── 过程记录.md      # 会话过程日志（哪轮聊了什么、怎么定的）
    └── 角色档案.md      # 组装后的最终产物（模板见 templates/角色档案模板.md）
```

找不到工作目录时先创建。**每次交互结束时，把当前状态写入过程记录.md**，保证下次会话能续上。

## 总流程

```
入口探测 → 素材收集 → 动机追问 → 多框架推演 → 组装轮廓 → 用户确认 → 补全档案 → 一致性验证
   ↑                                            ↓
   └────────── 否决或新素材，回到素材收集（迭代环）──────────┘
```

## 阶段详解

### 阶段一：入口探测

会话开始，先判断用户从哪个入口进入：

| 入口 | 用户特征 | 引导方式 |
|---|---|---|
| A. 画面入口 | "我心里有个画面" | 围绕画面追问细节 |
| B. 切片入口 | "我有一个习惯/细节"（如穿衣反差） | 围绕切片追问 |
| C. 经历入口 | "我想写一个经历过X的人" | 围绕经历追问事件 |

**永远不先问"她是什么性格"**——问性格=诱导贴标签。改为问"她小时候最怕什么""她爸爸去世那天她做了什么"这类事件问题。

如果用户完全空白（"我什么想法都没有"），用情景引导激发想象：*"想象一个下雨天，她在公交站等车，手机没电了，她第一反应是什么？"*

细节见 `references/01_入口引导.md`。

### 阶段二：素材收集

收集用户的经历、行为切片、画面。**产出纯事件清单，零形容词。**

- 用户提供的所有事件/切片/画面，逐条记录进 `素材库.md`
- 只追问事件类问题，禁止问性格
- 用户说了性格词 → 追问"这个性格在哪个场景里出现过？"把它变成事件

细节见 `references/02_素材收集.md`。

### 阶段三：动机追问

对每个关键素材，**先问作者，不给选项**：

- 用具体化问法："这个切片从什么时候开始有的？""在谁面前会这样？"
- 作者答得上 → 记录作者解释 → 验证（检查内部矛盾、补盲区、指出隐含结构）
- 作者无解 → 进入阶段四

**无解的判定标准**：作者说"不知道/没想过/说不上来"，或给的答案模糊（"就是感觉"），或解释与素材矛盾。

细节见 `references/03_动机追问.md`。

### 阶段四：多框架推演

对作者无解的关键素材，AI 用心理学框架推演：

- 从**核心四框架**（依恋理论、防御机制、社会学习、认知图式）挑 2-3 个，按角色类型从**扩展池**加 1 个，凑出 2-3 条**结构性差异最大**的推演
- **禁止出形容词，只许出行为场景**："缺乏安全感"不许写，要写"她每次分开前都会反复确认下次见面的时间"
- 每条推演标注：①行为场景 ②心理学机制 ③它从哪段经历推出来的（闭环可回溯）
- 候选之间必须有结构性差异，同义改写不算

用户勾选/修改/否决。否决时用户往往补充新经历 → 回到素材收集，形成迭代环。

细节见 `references/04_多框架推演.md`。

### 阶段五：组装轮廓

素材足够后，按调色盘流水线组装**轮廓**（不是完整档案）：

```
基础信息 → 调色盘 → 三面性 → 混色 → 核心人格层 → 二次解释 → 意象
```

**关键：先给轮廓，用户确认后再补全。** 不要把完整人设一次性砸给用户。

素材流向：
- 推演出的行为场景 → 调色盘衍生
- 用户提供的原始切片 → 混色画面（原样保留）
- 作者解释 + 推演候选 → 核心人格层
- 意象 → 从核心矛盾里长出

细节见 `references/05_组装流水线.md`。

### 阶段六：一致性验证

用户确认轮廓后，AI 跑一遍验证清单：性格打架吗？衍生矛盾吗？三面性混入二次解释吗？语料移出调色盘了吗？混色解释情绪了吗？防御机制落到行为了吗？意象从核心矛盾长出了吗？

细节见 `references/06_一致性验证.md`。

### 阶段七：补全档案

验证通过后，按 `templates/角色档案模板.md` 补全为完整人设。

## 记录协议（贯穿所有阶段）

**特征闭环即记录**——不依赖对话上下文记忆。

- 一个特征点被用户明确认可（"这个对""就是这种感觉"）→ **立即**写入 `性格构建.md` 对应章节，不等轮次结束
- 讨论中、AI 推演但未定论的候选 → 写入 `待定区.md`
- 用户否决的 → 标记否决原因（防止 AI 下一轮又推出来）
- 每轮交互结束 → 更新 `过程记录.md`

**闭环的判据**：这条特征是否已经能被一句行为描述说清楚、且用户认可。闭环了就记录，没闭环就留在对话里继续磨。

## 输出格式

- 推演候选 → `templates/推演候选模板.md`
- 过程记录 → `templates/过程记录模板.md`
- 最终人设 → `templates/角色档案模板.md`

## 红线（不可违反）

1. **禁止先给推演**：作者无解之前，先问；作者能答，绝不抢答
2. **禁止形容词**：所有推演/衍生只许出行为场景，不许出性格词
3. **禁止一次性砸完整档案**：先轮廓，用户确认后补全
4. **禁止标签化**：任何时候不往人设里写"极度自卑""傲娇"这类裸标签
5. **AI 永远提案，用户永远裁决**：所有特征点必须用户认可才闭环

## 边界（不做的事）

- 不生成开场白、不写正文、不做 NSFW 内容
- 不替代作者决策，AI 永远是提案方
- 不一次输出全部性格（分轮推进，避免用户被淹没）
- 不追求一次性完美，迭代环是核心
