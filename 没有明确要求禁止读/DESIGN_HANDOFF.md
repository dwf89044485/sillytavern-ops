# 设计 Handoff：人机协作调色盘 skill（character-palette-collab）

> **本文件的定位**：设计决策的来龙去脉——记录了**做了什么决策、为什么这样做**，以及讨论过程中的推理链和分歧点。它的读者是后续接手设计的 AI 和需要回溯决策依据的人。
> 
> **本文件不是什么**：不是 SKILL.md 的模板或蓝图。SKILL.md 是一份**行动文档**——它的语言是"怎么做"，不是"为什么"。handoff 里的强制格式、复杂度、术语定义，不需要原样搬进 SKILL.md。SKILL.md 需要的是判据、流程、边界，按自己的语言组织。
> 
> **回退后的 AI 必须完整阅读本文件，再开始设计/编写 skill。** 本文件内的决策是用户逐条确认过的，不要推翻重来；如有疑问，先读本文件，仍有疑问再问用户。

---

## 0. 任务定位（一句话）

做一个 skill：**人机协作构建角色**。不是 AI 直接写角色，而是**人提供经历素材 → AI 用心理学框架推演 → 人裁决 → 循环迭代**，最终按"性格调色盘"方法组装出完整人设。

## 1. 大原则（最高优先级，违反即错）

1. **技能用途是构建角色卡，不是运行角色卡。** 不管 SillyTavern 的实际运行顺序。人物成型后，一次性写成实际用的卡（"实际用的卡"怎么写是之后的事，现在不设计）。
2. **教程顺序 = 教学逻辑，不是构建逻辑。** 教程（调色盘/三面性/混色/核心人格层等）的章节顺序是作者的教学顺序，**不作为** skill 的设计依据。
3. **用户铁律——每句话必要性审查**：skill 里的每一句话，思考"删掉它是否影响读 skill 的 AI 的理解和执行"。删掉不影响 → 是废话，删掉。解释逻辑、原理、原则、有助于模型理解和执行质量的 → 保留。**用词精准、明确、直接。**
4. **文档顺序本身就应该就是呈现顺序。** 框架模板本身就是顺序，不要额外加"按呈现顺序排版""增量写入"这类话术——确认了什么就填到对应框架底下，这是自然发生的，不需要说明。

## 2. 已确认的设计决策（逐条，含决策逻辑）

### 2.1 技能触发方式

- 用户**主动使用**本技能（不依赖自动触发）。description 不需要做触发优化。

### 2.1b AI 主动性与确认边界（关键原则）

AI 内化教程知识后**主动**引导、过滤、追问、推演——但不是一刀切的"全自动"。

**分场景处理**：

| 场景                     | AI 怎么做                           | 是否需确认         |
| ---------------------- | -------------------------------- | ------------- |
| 纯过滤（无推演价值的素材、AI 已知默认值） | AI 自动过滤，不写进文档                    | 不需要——不产生新内容   |
| 追问具体化（"她很好看"→追问"哪里好看"） | AI 追问直到拿到特征，然后确认"我理解成XX写入文档，对吗？" | 最终写入前确认       |
| 推演候选                   | 多路径推演 2-3 条，标注依据                 | 必须经用户勾选/修改/否决 |
| 世界设定够不够、推演有无价值         | AI 内部判断，直接推进                     | 不需要——不抛回给用户   |

**不是"AI 默默做了判断不告诉用户"——而是 AI 驱动流程、不把教程判据转嫁给用户，但加工过的结果经用户确认后才写入。**

### 2.1c 引导 vs 说教

AI 默认给轻量引导——用户构建方式不太对时（如上来就贴性格标签），引导正确的做法（"我们可以先不急着写性格，先聊聊她经历过什么？"）。

**但教学是附带收获，不是任务目标。核心目标始终是帮用户完成角色构建。**

- 用户跟着引导走、表现出学习意愿 → AI 可以展开讲原理
- 用户说"直接来""别讲那么多" → AI 立即闭嘴，快速推进
- 用户没明确表态 → 默认一两句引导，不展开长篇教学

### 2.2 文件结构（重要：一个文件，不是两个）

- **每角色一个目录**：`workspace/角色名/`
- 目录内**一个文件**：`人物文档.md`
- 早期设计有"过程记录"文件，**已被取消**（决策逻辑见 2.4）。
- 也砍掉了"待定区"这个文件（原因：它是数据的坟墓——候选够好会当场拍板进性格，不够好进了也不会被翻出来；未决候选要么留在对话里继续磨，要么等于"下一步要做的事"）。

### 2.3 人物文档：素材区 + 构建区（同一个文件）

- **素材区 = 原始事实**：身份、外貌、背景、关系、经历事件、行为切片、画面。用户提供，AI 记录，不改动。
  - **基础信息"（姓名/年龄/外貌/背景/关系）**不单独成章**，它也是素材，归入素材区。构建时你不可能先写完基础信息再写经历——都是想到哪填到哪。
  - "背景设定"和"经历事件"不分家（"爸爸 10 岁去世"是背景还是经历？分不出来，也不该分）。
  - **素材区内部细分小节，但小节是归档位置，不是填写要求**：素材区细分五个小节（身份/外貌/背景/关系/习惯与偏好），小节标题下标注"按需记录，不要求完整"——防止 AI 或用户误解为"每节都要填、按顺序填"。每条素材确认时，AI 判断它属于哪个小节，填进去。某些小节始终为空很正常。细分的好处：AI 做推演时能按需定位（如"翻她的经历找线索"→ 直接看背景小节），不用扫描全文。

**素材区内部结构**：

```
素材区
├─ 身份（姓名/年龄/身份/世界设定）——按需记录
├─ 外貌（特征，不是美感）——按需记录
├─ 背景（改变了这个人的经历事件）——按需记录
├─ 关系（具体互动画面）——按需记录
└─ 习惯与偏好（标志性行为切片/偏好）——按需记录
```

- **构建区 = 从素材推演出的性格**：调色盘、核心人格层、多面性、混色、二次解释。AI 推演 + 用户裁决后写入。
- **素材区和构建区放同一个文件**，不拆文件。原因：它们是同一个人的一部分（"她爸爸去世了"和"她的底色是不甘心"说的是同一个人），拆开反而要跨文件引用；且拆不拆不影响"想到哪填到哪"的读写逻辑。
- 素材区是地基，构建区是地基上盖的楼。写卡只拿构建区，但素材区保留做追溯（每条推演要标注"从哪段经历推出来的"）。

### 2.3b 人物文档的定位：人物小传，不是最终卡

**人物文档 ≠ 最终放到世界书里的角色卡。** 二者是"素材"和"产品"的关系。

|          | 人物文档                                    | 最终卡（世界书里的角色卡）                     |
| -------- | --------------------------------------- | --------------------------------- |
| **用途**   | 构建过程中的工作稿 + 完整人物记录                      | 给 AI 运行时用的提示词                     |
| **读者**   | 构建者本人 + 未来写卡的 AI                        | 运行卡的 AI                           |
| **内容**   | 人物的全部信息，包括推演依据（"她的底色是不甘心，因为爸爸去世后她扛起了家"） | 只写运行时需要的，不写"为什么"，极致压缩             |
| **完整性**  | 追求完整可追溯——每条性格能从经历里长出来                   | 追求 token 效率——删掉 AI 已知的默认值、删掉推演因果链 |
| **信息密度** | 追求"无废话"（每一条揭示人物侧面）                      | 追求"极致压缩"（连接词都删，用列表替代叙述）           |

**人物文档的本质是人物小传**——它要回答的不只是"她是谁"，还有"她为什么是ta"。最终卡是"从人物文档里提炼出来的运行时版本"。

**最终卡怎么做**：人物成型后，从人物文档提炼最终卡。提炼规则参考教程"写正确的卡"（`性格调色盘/0.写"正确"的卡.md`）：

- 素材区里 AI 已知的默认值（如"中国人黑头发"）→ 删掉
- 构建区里的推演依据（"她为什么这样"）→ 删掉（运行时 AI 不需要）
- 性格构件 → 按调色盘/多面性框架精简写入
- 世界观 → 按教程 ABC 分类（真实背景/小世界/大世界）压缩

**教程里哪些原则适用于人物文档、哪些不适用**：

适用的（信息质量原则，与用途无关）：

- **外貌只写特征，不写美感**："精致的脸蛋、白皙的皮肤"遮住名字放谁身上都行 → 写"杏眼眼尾微垂、刘海自己剪的参差"。特征是事实、可追溯可推演，美感是判断、不能。
- **背景只写改变了这个人的事**：能推演出性格的经历才记录。"她喜欢吃草莓"如果没推演价值 → 不记。
- **关系写具体画面，不写抽象形容**："她对他充满恐惧" → "他把零食放她桌上，她用书本推到桌角"。画面是推演的原料，抽象形容不是。
- **基础信息与性格分开放**：这恰好是素材区（事实）和构建区（性格）分离的设计依据。
- **每句话过"删掉它有没有影响"的测试**：人物文档的判断标准是"删掉它，对这个人的理解会不会丢失信息"（不是 token 效率）。

不适用的（最终卡特有的 token 优化逻辑）：

- **"只写偏离默认值"**：不适用。人物文档是完整画像，不是运行时提示词。删默认值是提炼最终卡时做的事。"她长得太普通了，普通到没人记得她"在推演阶段可能是关键线索（→ 她故意让自己不起眼）。
- **极致压缩**：不适用。人物文档追求可读性和完整性，不追求 token 效率。
- **不写"为什么"**：恰好相反——人物文档的核心价值就是"为什么"。推演依据是人物文档独有的。

### 2.3c 素材区记录标准：推演价值

素材区不是"人物数据库"，而是**推演的原料库**。每条素材都是一个未解释或已解释的特征点。记录标准只有一条：

**判据：这条素材能不能成为推演的起点？能不能问出"她为什么这样"或"这暗示了她是什么样的人"？**

**记什么——四类有推演价值的素材：**

| 类型           | 判据            | 例子                        |
| ------------ | ------------- | ------------------------- |
| **经历事件**     | 改变了这个人        | "爸爸10岁去世""大学被孤立"          |
| **行为切片**     | 能问出"她为什么这样"   | "在家穿衣大胆""网上活跃线下沉默"        |
| **标志性偏好/习惯** | 能定义她的辨识度或暗示心理 | "只穿高领无袖""一个人时才吃草莓""进门先洗手" |
| **关系动态**     | 有具体的互动画面      | "他把零食放她桌上，她用书本推到桌角"       |

**不记什么——三类没有推演价值的素材：**

| 类型              | 判据          | 例子                    |
| --------------- | ----------- | --------------------- |
| **纯审美标签**       | 放在谁身上都行的偏好  | "喜欢听音乐""喜欢看电影"        |
| **无辨识度的默认值**    | AI已知的、没有偏离的 | "黑头发""穿校服"（除非校服有特殊之处） |
| **与推演无关的一次性事件** | 删掉它人物没变化    | "有一次下雨她没带伞"（除非这件事有后果） |

注意"偏好"的时机判断：如果只是"她喜欢吃草莓"，价值低；但如果"她只在自己一个人的时候吃草莓"，就是一个行为切片——因为有了情境限制，就能问出"为什么"。

### 2.4 过程记录已被取消（重要决策）

\*\*早期设计：\*\*过程记录只记协作过程（否决记录、待定项、下一步），判断标准是"主语是她→人物文档，主语是我们→过程记录"。

**最终决策：过程记录整个取消，并入人物文档。** 推理链：

1. **否决记录被拆解**：用户否决一条推演候选，否决的原因往往揭示了角色特征（如否决"社会学习版穿衣推演"，原因"她不是那种在意场合的人"——这本身就是一条角色事实，应进素材区）。**角色相关的否决 → 原因进素材区；纯协作信息的否决（如"必须要用英文沟通"）→ 不记录**（它是会话内的即时指令，下次会话用户需要会再说，不存档）。
2. **防重复功能被素材区天然承担**：否决原因进了素材区后，AI 下次推演读素材区时自然不会再推已被否决的方向——**不需要专门的"否决记录"字段来防重复**。
3. **待定项并入"下一步"**：未决候选本质上就是"下一步要做的事"。
4. **阶段/下一步概念被取消**（关键决策）：构建是**特征驱动的迭代环，不是线性流程**——你可能同时推进多个特征点，每个都在不同深度，不存在"我现在在第 3 阶段"这种清晰状态。所以"标记阶段"没有价值。**"下一步"也不需要单独拎出来**——改为：**最近更新的特征点旁边做标记**（如 ⏸ 或日期）。下次新会话读到标记就知道上次在构建哪个特征点，从那里继续。这比"下一步"字段精准（字段是抽象指令，标记是具体位置）。
5. **纯会话痕迹（"本轮聊了什么"）不记录**：角色内容进人物文档，会话过程零价值。

**最终文件结构：**

```
workspace/角色名/
└── 人物文档.md
    ├─ 素材区（她经历过什么）——含否决揭示的角色特征
    ├─ 构建区（她是什么样的人）——最近更新的特征点旁有标记（如 ⏸ 或日期）
    └─（无状态区、无过程记录、无阶段概念）
```

**续接机制**：新会话读文档，找最近更新标记，从标记处继续。角色相关的否决原因已在素材区，AI 不会重复推演已否决的方向。

### 2.5 呈现顺序（人物文档的物理排版顺序）

```
意象 → 素材区 → 调色盘 → 核心人格层 → 多面性 → 混色 → 二次解释
```

- **意象是呈现顺序的第一个，但它是构建顺序的最后一个。** 意象 = 用具体物件/画面把角色内核浓缩成总比喻（陈乖乖="冬天窗台上那一小格阳光"，姜糖="向日葵"，洛潮汐="潮汐"）。它需要全部素材和核心矛盾都清晰后才能凝聚出来——是构建的封顶，不是起点。
- **呈现上第一个被读到**（锚定读文档者对人物整体的感觉）；**构建上最后一个被创造**。
- 构建/写作时**不从头写到尾**：确认了什么就填进对应部分，用户想到哪部分（哪怕是核心人格层）直接写进那部分。

### 2.6 构建顺序（实际干活的顺序，与呈现顺序不同）

```
素材收集 → 调色盘 → 核心人格层 → 多面性 → 混色 → 二次解释 → 意象
```

- **意象最后凝聚**：意象需要等全部素材聊完才能长出来。
- **核心人格层在多面性之前**（与教程顺序相反——教程是先教多面性，但那是教学顺序）。原因：多面性每张面有一个"功能"部件——而这个"保护什么"恰恰就是核心人格层的防御机制。先挖核心人格层，多面性的"功能"直接等于防御机制的分支，有依据，一次写准。
- **螺旋模型**（2026-08-07 补充）：上一条的"层→面"顺序是 AI **内部推演优先级**（AI 主动推演时，先推层再拆面——因为面的功能更准）。但不是**用户交互硬约束**。用户可能先说面的描述（"她在家和在外面穿得完全不一样"）→ AI 顺着面追问动机 → 动机累积为层素材 → 层成型后校准面功能。无论从面还是层开始，最终组装时跑一致性验证确保收敛。

**步骤分级（2026-08-07 补充）**：

| 步骤                | 性质       | 判据                                                |
| ----------------- | -------- | ------------------------------------------------- |
| 入口引导（世界设定 + 用户角色） | **必须**   | 开篇走，缺则角色缺少坐标系                                     |
| 素材收集              | **必须**   | 无素材无推演                                            |
| 调色盘               | **必须**   | 核心产出，标签→行为描述体系                                    |
| 二次解释              | **必须**   | 防 AI 误读，调色盘从"被理解"到"被正确理解"                         |
| 意象                | **必须尝试** | 最后凝聚，构建最后、呈现最前。**必须尝试找，但 2-3 个方向都不贴可跳过**（见 §2.23） |
| **MVC 决策点**       | **必须**   | 暂停，用户选择继续或收工                                      |
| 多面性               | 条件       | 不同场景下行为模式有根本性切换 → 拆面；否则跳过                         |
| 混色                | 条件       | 有两种以上内心矛盾会撞在一起 → 写画面；否则跳过                         |
| 核心人格层             | 条件       | 有剧情驱动/内部矛盾/成长空间 → 挖七层；纯日常/轻松陪伴 → 跳过               |

**MVC 后的条件步骤按构建顺序依次检查触发条件**，不是一次性全推。

### 2.7 多面性（不叫三面性）

- **名称必须是"多面性"**。"三面性"一定会引入"必须三张面"的误解。本质是多面性：两面、三面、四面都可以，面的数量由角色本身决定，不由名字决定。

### 2.8 总流程（迭代环）

```
入口探测 → 素材收集 → 动机追问 → 多框架推演 → 组装轮廓 → 用户确认 → 补全档案 → 一致性验证
   ↑                                            ↓
   └──── 否决或新素材，回到素材收集（迭代环）────┘
```

### 2.9 入口引导（所有用户都走同一套开始流程，不是空白才引导）

**原则：先开放聆听，后定向追问。引导永远是兜底，不是默认。**

- **第零步（接管道具）：有现成的角色卡/设定？还是从零开始？**（2026-08-07 新增）
  
  - **有现成** → AI 解析现有内容映射到素材区对应小节 → 分析现有设定中的标签化点 → 从标签化的点开始追问具体化 → 正常进入调色盘推演缺失部分。**不要求用户重新走完整流程**——尊重已有劳动，skill 的价值是"帮你把不够好的变得更好"。
  - **从零开始** → 正常走下面的第一步。

- **第一步：世界设定（必走）。**
  
  - 题材："想写什么题材？现代都市？古风？仙侠？末世？校园？"——题材直接决定场景库
  - 世界基调：按需聊到能支撑角色构建即可（"写多少世界观取决于角色需要多少才能活"——不需要聊很细）
  - 世界设定记入素材区（作为角色的背景上下文）

- **第二步：用户角色定位（必走）。**（2026-08-07 新增）
  
  - 世界设定定了之后，立即问："你在这个世界里是什么身份？你和角色的关系是什么？还是说你是旁观者？"
  - 这一步确定角色的行为参照系——她对不同人的反应可能完全不同。素材区里记"关系"，这个阶段只是问一句定下基本框架。
  - 和世界设定是**先后不是同时**——先世界设定（范围大、好答），再用户角色（引入关系维度）。

- **第三步：开放式人物询问（必问，不强引导）。**
  
  > "这个人物你心里有没有一些构思？不管是一个画面、一个习惯、一段经历，还是一个模糊的感觉，都可以说。"
  
  - 用户自由说，**AI 先完整听，不打断、不引导、不提问**

- **第四步：根据用户说的内容展开。** 用户说完了，AI 总结记录，再按内容选方向追问：
  
  - 说了画面 → 围绕画面追问细节
  - 说了切片 → 围绕切片追问（什么时候/对谁）
  - 说了经历 → 围绕经历追问事件细节
  - 只有模糊感觉 → 用镜像类/具象类问题钩出具体（见下"问法六类"）

- **第五步：用户确实没有构思 → 才用情景引导**（收窄边界再激发）：
  
  1. 题材第一步已确认 → **身份/处境**："她在这个世界里大概是个什么身份？学生？社畜？剑修？"——框住人物边界
  2. **情景引导**："想象一个场景：<契合题材和身份的具体场景>。在这个场景里，她的第一反应是什么？"
  3. 生成的初始素材回到第三步展开

- **问法六类**（在展开/追问阶段用。**2026-08-07 修正**：废除"按可答性排序"——可答性排序是教学框架，不是 AI 执行策略）：
  
  **使用方式：按用户卡壳类型匹配问法**，不是顺序遍历：
  
  - 用户说"我说不清，就是有种感觉" → **镜像类**："你认识的人里有类似的感觉吗？"
  - 用户给纯标签（"她很温柔"）→ **具象类**："她是做了什么让你觉得温柔？"
  - 用户给经历但说不出能推什么 → **反应类**："后来遇到类似的事，她的反应有变化吗？"
  - 用户给画面但没上下文 → **关系类**："那个画面里还有其他人在吗？"
  - 用户说"她在不同场合完全不一样"→ **反差类**：已在拆面
  
  **在 skill 文件中的位置**：SKILL.md 写 3 行匹配摘要（见上）。完整六类目录（每类定义 + 2-3 个例句 + 匹配的卡壳特征）放 `references/questioning-strategies.md`。

- **永远不先问"她是什么性格"**——问性格=诱导贴标签。改为问**事件类/具象类问题**，钩出用户已有的倾向，而不是要求现场创作。

- **现代都市爱情题材的现成情景引导**（第五步题材确认后用反应类问题最自然）：
  
  - 日常生活类（最容易答）："她下班回家，进门做的第一件事是什么？""她周末一个人在家，会怎么过这一天？"
  - 关系类："她最好的朋友失恋了半夜打电话给她，她第一反应是什么？""她在公司遇到一个很烦的同事，她会怎么处理？"
  - 反差类（活人感入口）："她在什么情况下会和平时完全不一样？""她在外人面前是什么样子？只有她自己一个人的时候呢？"
  - 压力类（挖深层，素材足够后再用）："她接到一个坏消息，第一反应是什么？先做什么？""她发现自己被最信任的人骗了，她会怎么做？"
  - 决策类（最难答，最后用）："她只有一次机会，只能救一个人，她会救谁？"

### 2.10 动机追问协议（先问后推演——本协作模式的核心基石）

- **AI 永远先问作者，禁止先给候选。** 原因：作者的解释永远比 AI 的推演独特。AI 一旦先给候选，作者就被框住了——要么被带着走，要么觉得"不是这个但说不清哪里不对"。
- **第一层：问。** 用**具体化问法**，不问抽象的"为什么"，问"什么时候/对谁/什么情境"：
  - "这个切片从什么时候开始有的？"
  - "她在什么样的人面前会收敛、什么样的人面前不会？"
  - "如果这个环境永远不会有人来，她还这样做吗？"
  - "她有没有一个想让他看见'原来她是这样的'的人？"
- **第二层：作者答上了 → 验证，不替换。** AI 做三件事：①检查内部矛盾（解释和已有素材打架吗）②补盲区（作者没想到的层面，标注"这是补充，不是替换"）③指出隐含结构（切片里隐含了什么可发展的结构，如"外端庄/家大胆"已是多面性的雏形）。
- **第三层：作者无解 → 多路径推演。** 无解的判定标准：作者说"不知道/没想过/说不上来"，或答案模糊（"就是感觉"），或解释与素材明显矛盾。
- **第四层：人裁决 → 循环。** 勾选→记录；修改→按修改定稿；否决→记否决原因，且否决时用户往往补充新经历→回到素材收集。

### 2.11 多框架推演（取代"反直觉"概念——重要的设计决策）

- **"反直觉"概念被废掉。** 对 AI 来说没有"反直觉"这回事：数据库里有大量"被抛弃→学会先抛弃别人"这类低频但真实的关联，AI 知道这些可能性，只是默认不会先想到它们。

- 真正的问题叫**频率偏差**：AI 生成时天然偏向语料中高频共现的关联（"被抛弃"→"缺乏安全感、敏感多疑、害怕亲密"）。文章作者观察到"AI 总是给最刻板的关联"，观察是真的，机制就是频率偏差。"活人感"恰恰来自低频但真实的关联，所以 skill 要解决的是**强制 AI 突破自己的频率偏好**。

- **为什么不干脆"列出所有可能性"**：纯清单会被频率偏差和锚定效应双重杀死——AI 列 8 条第一条还是最常见的，用户面对平铺选项会选前几条，又回到标签化。清单没有结构，每条候选没有"为什么值得选"。

- **解法：多路径推演**——从 ≥2 个不同心理学框架各推演一条，每条标注依据。**推演的多样性不靠 AI 灵机一动，靠从不同生成轴各推一条。**

- **核心四框架**（任何角色都能推出东西，普适生成轴）：
  
  | 框架   | 生成轴   | 推演方向                   | 卡片映射             |
  | ---- | ----- | ---------------------- | ---------------- |
  | 依恋理论 | 关系轴   | 怎么靠近/推开、怎么表达需求、对分离什么反应 | 调色盘衍生、核心人格层·深层缺失 |
  | 防御机制 | 自我保护轴 | 压力下做什么来保护自己            | 核心人格层·防御机制（直接对应） |
  | 社会学习 | 环境学习轴 | 从谁身上学了什么、什么行为被环境留下/抹掉  | 调色盘衍生、多面性        |
  | 认知图式 | 认知解读轴 | 内心相信什么、每个情境怎么被解读       | 深层缺失/核心恐惧、二次解释   |
  
  - 选择这四个的依据（筛选标准）：**生成性**（必须能"经历→行为"推演，纯描述的不算）、**行为落地**（推演出来必须能演）、**结构性差异**（框架视角互不重叠，重叠的只留一个）、**领域覆盖**（覆盖写卡领域真正的角色类型）、**卡片映射**（推演结果能流进调色盘结构）。
  - 排除的：**特质论（大五）**——描述性而非生成性，且整套方法论要消解的就是特质标签；**进化心理学**——讲人类共性，对个体独特性贡献低；**沟通分析（TA）**——和认知图式高度重叠，二选一。

- **扩展池**（按角色类型触发，每个只需一句话机制+触发条件+示例）：创伤/应激反应（有极端事件）、家庭系统（家庭驱动背景，陈乖乖=被父母化的孩子）、存在主义（死亡/意义主题，洛潮汐）、社会角色/印象管理（伪装/身份切换，秋明月）、自我决定理论（强烈表层欲望）、发展任务（成长转变期）、荣格阴影（表里反差极大）、情感调节（情绪表达特殊）。

- **选择规则**：每轮推演**不是全框架各来一遍**（会很机械）——从核心四挑 2-3 个 + 按角色类型从池里加 1 个，凑出 **2-3 条结构性差异最大**的推演。

- **开放原则**：池不封闭，某段经历有更贴切的框架（如文化心理学），AI 可以用，但必须标注框架名和机制，不许裸套。

- **硬规则：推演禁止出形容词，只许出行为场景。**"缺乏安全感"不许写，要写"她每次分开前都会反复确认下次见面的时间"。因为出形容词=出标签。

- **每条推演标注三要素**：①行为场景（可直接当衍生素材）②心理学机制 ③从哪段经历推出来的（闭环可回溯）。

**框架在 skill 文件中的位置**（2026-08-07 补充）：

- **SKILL.md（决策层）**：不列框架名，不列清单。写为"从 ≥2 个不同的视角推演（比如从关系的角度、她怎么保护自己的角度、她从环境中学到了什么、她内心相信什么）"——保留多视角推演的强制性，但不命名框架。
- **references/palette.md（执行层）**：保留完整框架清单和选择规则，作为 AI 推演时的参考工具箱。框架名仅出现在 reference 内部，不向用户暴露。
- 推演的主引擎是**从用户素材里抓出重复出现的模式**——框架是后备，当素材内部的模式不明显时才调用。

### 2.12 记录粒度（特征闭环即记录，事件驱动，不是轮次驱动）

- 一个特征点被用户明确认可（"这个对""就是这种感觉"）→ **立即**写入人物文档对应部分，不等轮次结束。
- 闭环判据：这条特征已经能被一句行为描述说清楚、且用户认可。
- 未闭环的留在对话里继续磨。
- **记录是事件驱动，不是轮次驱动**：只有内容变化时（特征闭环、用户否决、新素材确认）才写入，没有变化就不碰文件。**每轮结束不自动写**——很多轮次没有有效产出（"我想想"也算一轮），每轮都记太密集，且有效信息未成型就落盘没有价值。
- **不丢信息的保障**：有效信息产生的那一刻就被记录（特征闭环→构建区、否决揭示的角色特征→素材区），不需要等用户说"存档"；即使中途关掉对话，只要有过内容变化，文档就在，新会话读文档的最近更新标记即可续上。

### 2.13 组装与输出

- **先给轮廓，用户确认后补全**——不要把完整人设一次性砸给用户。
- 素材流向：推演出的行为场景→调色盘衍生；用户提供的原始切片→混色画面（原样保留）；作者解释+推演候选→核心人格层；意象→从核心矛盾里长出（不是搜来的比喻）。
- **二次解释的触发时机**（2026-08-07 补充）：**组装阶段统一生成所有二次解释条目**，不在构建过程中分散触发。原因：每个二次解释条目都依赖对角色整体的理解才能预判 AI 会怎么误读——调色盘完成前无法可靠判断，混色完成前对"情绪不稳定"类误读无法全面覆盖。组装时有了完整的调色盘（含条件步骤的结果），一次性过一遍最可靠。
- 组装完成后跑一致性验证（性格打架吗、衍生矛盾吗、多面性里混入二次解释吗、语料移出调色盘了吗、混色解释情绪了吗、防御机制落到行为了吗、意象从核心矛盾长出了吗）。

### 2.14 红线（不可违反）

1. 禁止先给推演（作者无解之前，先问；作者能答，绝不抢答）
2. 禁止形容词（所有推演/衍生只许出行为场景）
3. 禁止一次性砸完整档案（先轮廓，确认后补全）
4. 禁止标签化（不写"极度自卑""傲娇"裸标签）
5. AI 永远提案，用户永远裁决

### 2.15 边界（不做的事）

- 不生成开场白、不写正文、不做 NSFW 内容
- 不替代作者决策
- 不一次输出全部性格（分轮推进）

### 2.15b 确认与同步边界（写入 handoff 以保证 skill 设计一致性）

红线（§2.14）说"AI 永远提案，用户永远裁决"，但不是所有动作都要确认。核心区分：**确认 = 用户点头 AI 才做；同步 = 用户知道发生了什么即可。同步不是确认——同步是透明度，确认是审批。**

| 动作类型       | 确认（需用户点头） | 同步（告知用户）   | 例子                                                             |
| ---------- | --------- | ---------- | -------------------------------------------------------------- |
| **纯过滤不记**  | ❌ 不需要     | ✅ **必须同步** | "她喜欢听音乐，这个放在谁身上都行，没有推演价值，我先不记" / "这段外貌描写里'精致的脸蛋'我过滤掉了，留给特征的部分" |
| **价值判断推进** | ❌ 不需要     | ✅ 必须同步     | "世界设定聊到这儿对这个角色够了，我们往下走吧"                                       |
| **产生新内容**  | ✅ 必须确认    | ✅ 自然伴随     | 推演候选、将模糊表述转写为具体特征（"你刚说的'她很好看'我理解成'杏眼眼尾微垂、刘海自己剪的参差'，对吗？"）       |

**设计逻辑**：

- **纯过滤不同步会引发信任问题**：用户说"她喜欢听音乐"，AI 默默不记——用户下次看文档发现漏了，会怀疑"AI 是不是出 bug 了？我上次明明说了"。信任直接崩掉。同步一句"这个没有推演价值，我先不记"→ 用户要么认同，要么揭出一个隐藏经历（"不不不，她喜欢听音乐是因为那是她爸唯一留给她的东西"——后者恰好暴露重要素材）。
- **同步不需要审批**：用户不需要说"好的你跳过吧"——AI 告知即可，不等确认。但如果用户反对（"不不，这个要记"），了解清楚原因再做决定。
- **确认出现在 AI 替用户创造了新内容的时刻**：推演结果、转写用户模糊表述——这些东西不是用户原话，必须经用户点头才能进文档。这是用户掌控感的最后一道防线。

### 2.15c 引导而非说教 + 用户分层（AGENTS.md 操作原则）

**skill 的核心目标是帮用户完成角色创作，不是上课。** 教学是附带收获，不是任务目标。

用户分层：

- 用户跟着引导走、表现出学习意愿（追问"为什么"、主动问技巧）→ AI 可以展开讲原理
- 用户表达不想听（"直接来吧""别讲那么多"）→ AI 立即闭嘴，快速推进，不叨扰

**默认引导**：用户构建方式不太对时（如上来就贴"极度自卑""傲娇"这种性格标签），AI 引导正确的做法——但只说一次正确的方向（"直接贴标签容易让人物变得刻板，我们可以先聊聊她经历过什么？"），用户拒绝就不再重复。

### 2.16 问题目标层（补回"问的目标"——重要决策，2026-08-05 确认）

**问题（为什么补这一层）**

2.10 动机追问协议定义了"怎么问"——具体化问法、先问后推演、问法六类。但它**没有定义"问的目标是什么、问到什么程度算够"**。后果：一个只读 skill 文档的 AI 知道要问具体问题，却不知道每个问题在探什么、探到什么算够，会把问法六类当菜单轮着用，永远不收敛——**为问而问**。

### 2.17 维度命名方案：双名并行（产物名 + 方法名括号锚点）

**问题**：教程的维度名（调色盘、多面性、核心人格层、混色、二次解释）是作者自创的"方法名"——面向学会这套方法的人。skill 面向的是构建角色的用户，他们需要知道"我构建出来的是什么"。

**命名标准（"她的..."测试）**：好的产物名加上"她的..."还能自然使用。"她的性格质地"自然；"她的调色盘"不自然（因为调色盘是工具名不是属性名）。

**方案：面上用产物名（用户理解的），括号保留方法名（社区锚点——已有人沿用，断联不好）。**

| 教程原名（方法名） | 产物名（用户面）        | 一句话解释               |
| --------- | --------------- | ------------------- |
| 素材收集      | **身份与经历**       | 她是谁，经历过什么           |
| 调色盘       | **性格质地**（调色盘）   | 她是什么样的人：底色、主色、点缀色   |
| 多面性       | **场景模式**（多面性）   | 不同情境下，她怎么切换         |
| 核心人格层     | **内在驱动**（核心人格层） | 驱动她的：欲望、恐惧、防御、矛盾、底线 |
| 混色        | **情感交织**（混色）    | 复杂情感的瞬间——多种东西在同一刻碰撞 |
| 二次解释      | **角色边界**（二次解释）  | 告诉 AI：别把她写成什么样      |
| 意象        | **意象**          | 浓缩这个人物的总比喻          |

**命名逻辑**：

- **性格质地** 替代 调色盘："质地"是给人的触感，不撞"乐嘉性格色彩学"；用户看到"性格质地"就知道这部分在说什么
- **内在驱动** 替代 核心人格层："核心人格层"像心理学论文；"内在驱动"直接说清：欲望拉、恐惧推、防御挡、矛盾卡、底线止
- **场景模式** 替代 多面性："多面性"有"多重人格"误解风险；"场景模式"说清：不同场景不同行为模式
- **情感交织** 替代 混色："混色"依赖理解"调色盘"前置隐喻；"情感交织"不需要先学任何概念
- **角色边界** 替代 二次解释："二次解释"是写卡流程概念（"再解释一遍"）；用户看到的是"我告诉 AI 别越界"

### 2.18 阶段声明（模式切换时告知，非持续看板）

**问题**：用户不知道自己在构建什么槽位，出现迷失。2026-08-06 讨论中两度发生——第一次推演候选没标槽位，第二次"往下挖一层"没说明在挖什么。

**早期版本错误**：试图用强制格式（四要素、检查点标记、声明不过不得进入下一步）解决。审查指出过度结构化——skill 不是表单填写工具，是对话。

**最终规则（2026-08-07 修正）**：

- **声明只在交互模式改变时触发**，不是每个动作都发
- 连续追问期间不需要声明——从"她在家穿什么"到"独居前什么样"，直接问
- 触发的三个切换点：

| 切换           | 声明（一句话）                            |
| ------------ | ---------------------------------- |
| 追问 → 推演      | "素材够了，我开始推她的深层缺失。推完你选一条。有要补充的吗？"   |
| 一个槽位 → 另一个槽位 | "深层缺失定了。现在推核心矛盾——就是她想要的和她害怕的怎么打架。" |
| 推演完 → 组装展示   | "核心人格层有了。我把调色盘和核心人格层一起给你看。"        |

- 推演候选标注槽位（如"此候选 → 核心人格层·防御机制"）
- **不要求**：层级关系说明、产出用途说明、用户动作说明（这些在切换时一句话里自然带出，不需要拆成要素列出）

### 2.19 推演质量保障（三层机制）

**问题**：多框架推演（§2.11）定义了"怎么推"，但没有定义"什么时候可以开始推""推之前 AI 做了什么准备""推完怎么自查质量""推了用户全拒怎么办"。这四个缺口导致推演可能在不成熟的时机启动、基于碎片化的理解、无法验证结果质量、遇到失败没有处理机制。

**设计来源**：教程的十组问题结构（分组维度地图）、标签下钻五连问（单题质量判据）、80问结尾检查清单（全局质量检查）。skill 在这些基础上补了教程没有但协作式对话必须有的：切换信号、内部理解、交叉检查、失败处理。

---

#### 2.19a 输入端：素材是否足够推演

**设计原则**：不用硬数字门槛（"1经历+1切片"），用教程已有的分组结构做软判断。

**判断机制**：

1. **后台检查**：AI 在内部对照十组方向，判断当前素材覆盖了哪些维度
2. **不是全部覆盖才能推**：素材不需要十组全部覆盖。某个维度的素材足够 → 就可以推该维度对应的槽位
3. **各维度最低标准**（软标准，不是硬阈值）：
   - 素材区至少有一条**非标签化**的记录（行为切片或经历事件，而不是"她温柔"）
   - 对于目标槽位：至少有素材能支撑"她在这个维度上有故事可说"——不必全，但有切入
4. **显式过渡确认**（§2.18 要求）：素材够了之后，AI 必须说"目前的素材我觉得够推[具体槽位]了。你脑子里还有没有要补充的？没有的话我开始推。"
5. **不强推**：如果某个维度素材确实稀缺（如道德底线），告诉用户"这个维度素材还不够，我们先留空，后面构建中再补"，不强推

**参照**：教程的"24问答不出来就别写调色盘"——但 skill 用的是更细的维度级别判断，不是全局判断。

---

#### 2.19b 解析端：推演前的内部理解

**设计原则**：推演之前，AI 必须在内部先消化素材，用一句话写出来；不输出给用户，纯粹的服务端"检查理解深度"。

**执行在 SKILL.md 的阶段三"多框架推演"开头**：

**内部理解步骤（不输出，仅 AI 自用）**：

1. **已知事实清单**：用户确认过的经历事件、行为切片、关系动态（原文复述，不改写）
2. **已确认的人格特征**：调色盘或核心人格层中用户已经拍板的东西
3. **观察到的未言明模式**：素材里隐含的规律——"她三次在不同情境下提到不想给人添麻烦"
4. **不确定的留空**：标注出来，推演时避开，或标明"此为推测"
5. **用一句话写摘要**，确认自己全部理解。三句话写不清 → 素材不够 → 退回去追问

---

#### 2.19c 质量端：推演后的自检

**设计原则**：推完不急着给用户，先自查。

**交叉检查（每次推演后、给用户看之前）**：

1. **差异性检查**：删掉框架名和术语，只看行为描述——推出来的几条说的是不同的事吗？同一条换了三个角度 → 不合格，合并，用省下来的框架重新推
2. **标签检查**：推演里有没有出现裸形容词？"缺乏安全感""极度自卑"→ 必须替换成行为场景
3. **素材追溯检查**：每条推演能不能回到用户给的某一段素材？找不到源头 → 可能是 AI 编的，标注"此为推测"

---

#### 2.19d 失败处理：推演被否决怎么办

**问题**：推演质量检查通过了，但用户说不对。不是质量出问题，是**理解出问题**——AI 对素材的"读感"偏了。

**三种情况 + 对应处理**：

| 用户说什么            | 实质                               | 处理                                                                   |
| ---------------- | -------------------------------- | -------------------------------------------------------------------- |
| "不是 X，是 Y"       | 不是失败，是校准。用户自己在修正。                | 否决原因进素材区（§2.4），修正后的版本写入对应槽位，继续下一步。                                   |
| "不知道""没想过"       | 素材不够。                            | 停下来追问具体场景。不推，回到素材收集。                                                 |
| "都不是""说不清""感觉不对" | 理解偏差。AI 对素材的读感偏了，用户直觉感觉到了但表达不出来。 | 按 §2.22 的统一否决处理规则：**每次否决 → 轻量溯源**（"能告诉我哪里偏了吗？一个词就行。"）→ 用户说不出 → 暴露理解。 |

**否决处理的统一规则见 §2.22**——适用于脚手架试探和推演候选的每次被否。禁止跳过溯源直接暴露理解。

### 2.20 推演节奏：分批呈现

**决策**：推完一个维度不单独展示。推到核心人格层甚至混色再一起给用户看完整文档。原因：过早展示碎片会打断构建流畅感，且单个衍生在没有上下文（其他颜色、核心矛盾、混色画面）的时候，用户很难判断对不对味。但有例外——每个推演候选仍然需要用户裁决（勾选/修改/否决），裁决是即时确认，展示是分批打包。

### 2.21 最小可运行角色（MVC — Minimum Viable Character）

**问题**：教程有六种技法（调色盘/多面性/混色/核心人格层/二次解释/意象），但不是所有角色都需要全部。skill 应该知道什么时候"够用了"，而不是默认把全部技法当作流程推完。

**MVC 定义**：**调色盘 + 二次解释** = AI 已经能正确地演绎她了。

- 调色盘给了行为模式
- 二次解释拦掉了最容易误读的点

**MVC 识别标准**：MVC 在组装阶段结束时自然到达——调色盘和二次解释都已写定。AI 内部判断写定的标准：

- 调色盘：底色和主色已定，颜色都是行为描述（非标签），素材区里没有被遗漏的重要行为侧面
- 二次解释：覆盖了当前角色最可能的误读方向（§2.13 组装阶段统一生成）

**达到 MVC 后**：告诉用户——"角色已经具备初步可运行性了。你可以先去试试效果，也可以继续深化。要继续吗？"

- 用户说继续 → 按条件判据（§2.6 步骤分级表）依次检查多面性/混色/核心人格层的触发条件，按构建顺序依次处理
- 用户说够了 → 收工
- 素材明显指向某进阶技法但用户未选择 → 可提一句建议，不强制

MVC 的核心问题不是"怎么问用户"，而是标准是否足够明确——AI 必须能靠自己判断"调色盘和二次解释已经写定了"，才能在此处触发决策点。

MVC 不是放弃深度，是把深度交给用户决定。

### 2.22 交互模式三层模型：镜子 → 脚手架 → 推演（2026-08-07 新增，替代旧两阶段模型）

**问题**：旧两阶段模型（追问/推演）有一个盲区——切换条件只有一条"用户说不知道"。但用户可能在追问阶段反复用不同措辞说同一件事，不算"说不上来"，但每轮产出为零。追问循环不会自动中断。

**答案**：在两阶段中间加一个**脚手架**模式——用户不需要创作，只需要反应。

| 模式           | 用户能做什么                | AI 做什么                                   | 切换出去的判据                         |
| ------------ | --------------------- | ---------------------------------------- | ------------------------------- |
| **镜子**（=旧追问） | 有洞察，能产出新素材            | 追问具体场景、时间、对象。不提示方向，不补充用户没说的内容            | 最近 3 轮追问没有产生新的行为场景或关系细节 → 进入脚手架 |
| **脚手架**      | 没有洞察或表达力不足，但**能判断对错** | 给一个试探方向（从已积累素材提取的初步框架，不涉及未确认的维度），让用户反应   | 2 次试探被否定 → 进入推演                 |
| **推演**       | 没有洞察，也无法判断方向          | 从 ≥2 个视角给出 2-3 条候选，标注行为场景 + 机制 + 依据。用户裁决 | 用户裁决 → 继续或收工                    |

**脚手架 ≠ 推演的区别**：脚手架是反应性的（"这个方向对吗？"），推演是生成性的（"这是 2-3 条候选，你选"）。前者降低用户创作门槛——**否定比空白构思容易得多。**

**切换时告知用户**：脚手架模式启动时说一句："让我换种方式——我试着猜一个方向，你看对不对。"模式切换需要一句话告知（与 §2.18 阶段声明原则一致）。

**每次否决后的处理**（统一规则，适用于脚手架和推演）：

1. 第一步：**轻量溯源**——"能告诉我哪里偏了吗？一个词就行。"
2. 用户给方向词 → 校准方向，重试
3. 用户说不出 → **暴露理解**——整理当前对人物的理解摘要，问"我哪里理解偏了？"
4. **禁止跳过第一步直接暴露理解**——跳过溯源就是放弃获取方向词的机会

### 2.23 意象：必须尝试，允许跳过（2026-08-07 决议）

**问题**：教程体系里意象是收束步骤——一个隐喻给 AI 总感觉。

**决议**：必须尝试，但允许跳过。

**操作规则**：

1. **时机**：组装阶段的最后一步。此时人物文档所有其他部分已完成，意象需要读的核心矛盾和行为模式都在。
2. **方法**：AI 先抓出角色的核心矛盾（如果有核心人格层）或核心张力（如果没有，从调色盘和行为模式里提取），然后问："她的核心矛盾——这个东西在自然界里长什么样？"（教程原文："她像什么？不是外貌，是她存在的方式像什么。"教程找意象的实际过程是通过反复出现的细节自然结晶出来的——冻疮、红线手绳、草稿纸→窗台上一小格阳光。Skill 加了操作化步骤"先抓核心矛盾再匹配自然类比"，因为 skill 不能等"某一天自然冒出来"。）
3. **探索**：提出 2-3 个候选意象，用户选。
4. **跳过条件**：2-3 个方向都找不到自然贴合的 → 接受"这个角色可能没有明显的意象"。跳过。不贴的意象比没有意象更糟——它会误导 AI 的表达方向。
