## 〇、先看清一件事：不是两套，是三条血脉

在把 A、B 两套当成"两个竞争方案"之前，必须先知道它们有一个**共同祖先**——否则会把"继承同一处的两条分支"误判成冲突。

```
                  character-palette-collab（最早的设计讨论）
                  没有明确要求禁止读/DESIGN_HANDOFF.md（694 行）
                  没有明确要求禁止读/DESIGN_HANDOFF_REVISION.md（371 行）
                                   │
                                   ▼
                  【血脉 0】已装好的 skill：.claude/skills/char-creator/
                  SKILL.md + 8 个 references + templates/character-doc.md
                                   │
                    ┌──────────────┴──────────────┐
                    ▼                             ▼
        【A 套】books/xingge-tiaosepan/    【B 套】性格调色盘/books/char-palette/
        2026-08-09 起跑，08-13 仍在推进      2026-08-13 一次性提交（无中间历史）
        cangjie 流水线第一条支线              cangjie 流水线第二条独立支线
```

**血脉 0 是两套共同引用的东西，不是竞品：**

- A 套的 §12 承载机制（人物文档、素材区/构建区、事件驱动记录、推演价值判据）**整段继承自 handoff**，且 A 做了两轮独立审阅（批判轮 3 agent + 辩护轮 3 agent）验证后才采纳。
- A 套的 E 段决策 6（镜子→脚手架→推演→溯源→降级）、用户确认信号定义，也来自这条血脉。
- B 套的追问动作 #7 入口分流明确写着来源是"已有 char-creator 雏形的『第零步：接管道具』"。

所以：**两套决策在"底层协作模式"上本来就同源，真正的分歧集中在"这次蒸馏要产出什么形态的 skill"。**

1. **执行层是实心的**——这是 B 套最大的价值：

- 卡住了怎么办（无降级链条、无根因诊断、无升级阶梯）
- 快速路径 / 入门平替（教程 11 只被用来做验证锚点，没提取成动作）

- 用户确认信号的定义（有逐动作质量门，但没有"什么算用户认可"）
- B 段（何时不用、硬软边界、失败模式、覆盖盲区）
- 案例库（明确决策"示例文件暂缓"）
- 问题库 24/80/200 的位置（读了工作流，但没决定放哪）

## 五、读这套材料时容易踩的三个坑

1. **把"时间切片差异"当成"结论冲突"。** B 说"世界书 skill 低优先级、以后做"，A 说"worldbook-config 是 4 个之一、现在做"——这是排期不同，不是结论不同。真正的冲突要看"同一件事双方给了互斥的答案"。

2. **把"判据穷举"当成违反 A 的原则驱动。** A §1.2 否决的是"追问流程的 if-else 状态机"（什么时候问什么），B 的判定树是"文本质量判据"（这句话是不是泛化）。A 自己的 §4.3.2 质量信号表 A-G + 组合规则，形式上同样是清单。界线是**判据可以穷举，流程不可以**。

3. **忘了 B 不知道 A 的存在。** B 的 PIPELINE_STATE 里没有任何对 A 套的引用，它的每一条决策都是在"什么都没有"的前提下独立做的。所以 B 的"缺失"多数不是"否决了 A 的方案"，而是"根本没走到那一步"——这类缺失全部可以由 A 直接填补，不需要拍板。
