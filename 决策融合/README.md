## 一页纸结论

**两套决策不是竞品，是同一个 skill 的两个切面，且它们有共同祖先。**

```
        没有明确要求禁止读/DESIGN_HANDOFF.md（694 行，最早的设计讨论）
                            │
                            ▼
        【血脉 0】.claude/skills/char-creator/  ← 已经装好、能跑的 skill
                            │
              ┌─────────────┴─────────────┐
              ▼                           ▼
        【A 套】治理层完备                【B 套】执行层完备
        08-09 → 08-13，连续历史            08-13 一次性提交，独立跑完
        4 个 skill / MVC / 卡住处理        1 个 skill / 13 个追问动作
        快速路径 / 人物文档落盘             4 个诊断判定树 / 9 个 probe
              │                           │
              └─────────────┬─────────────┘
                            ▼
                 A 的 11 个 reference 是空容器
                 B 的 13 个动作三件套正是要装进去的内容
```

- **A 套答的是**：这个 skill 该长什么样、边界在哪、节奏怎么控、东西存哪。
- **B 套答的是**：每一轮具体怎么判断、怎么问、问到什么算够。
- **B 不知道 A 的存在**（B 的文档里没有任何对 A 的引用）。所以 B 的多数"缺失"不是"否决了 A"，而是"根本没走到那一步"——这类缺失可以由 A 直接填补，不需要拍板。

**碰撞结果**：14 个维度里，5 个完全互补、2 个表面冲突（有界线可化解）、**9 条真冲突需要拍板**。

其中一条必须最先定：**C1 —— 这次蒸馏的产出，是现有 char-creator 的兄弟，还是它的下一版？** A 假设并存（并为此让 description 避开最自然的触发词），B 假设替换。这条不定，A 的 description 那一整项决策都悬着。

## 融合最大的三个收益

1. **B 填满了 A 的空容器。** A 的 11 个 reference 只有文件名 + 一句话描述 + 触发条件，一条具体内容都没有。B 的 13 个追问动作三件套（内部诊断 / 外部问法 / 质量门）+ 4 个诊断判定树，正是那些容器要装的东西。

2. **A 补齐了 B 的治理真空。** B 完全没有：MVC 节奏控制、卡住了怎么办、快速路径、承载机制、确认信号、B 段边界、失败模式。这些在 A 里都是定稿状态。

3. **两套的 agent 使用经验合起来是一套完整纪律**：
   - **跨模型**（B：诊断判据用了 3 个模型家族的 5 个 agent，"三级判定"是它们不约而同提出的）
   - **不塞方案**（A §12.8：第一批 agent 带了主流程方案预设立场，产出被污染；用户纠正后重派）
   - **两轮对照**（A §12.7：单轮共识受 prompt 立场影响——"早期设计"四个字就让 3 个 agent 集体倾向推翻。批判轮 + 辩护轮才可靠）

   后续派发子任务应同时满足这三条。
