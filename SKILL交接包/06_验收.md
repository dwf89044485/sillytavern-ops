# 06 验收

> **每写完一个文件立刻跑对应的自检，不要攒到最后。**
> 自检的默认形态是**可机械判定**——一条 shell 命令（检索 / 计数 / 存在性）或一个明确的是/否问句。
> **但"可判定"不等于"必须能机械检索"**（同 `04` 〇 的元规则）：把人工判断包装成检索比诚实标注更糟，它让人以为查过了。所以本文件给每条自检**分三档，再加一个诚实标记**。

### 档位标记（写在"通过标准"里）

| 标记 | 档位 | 含义 |
|---|---|---|
| *（无标记）* | **可机械判定** | 一条命令或一个存在性是/否问句就能定通过与否。**本文件的默认档** |
| 🔍 | **半机械** | 命令能定位到"查哪几处"，但每一处命中要人工判一次。判据必须当场写清楚 |
| 🏃 | **运行时测试** | 测的是对话行为，不是静态文本。交付物是 markdown，**静态阶段只能查"规则在不在纸上"**；真跑要等 body 完成后做一次真实对话 |
| ❓ | **只能靠人看** | 无法机械判定。如实标注，**不要假装它可机械检查** |

> 分档口径是**"能不能真跑"**，不是"判据写没写清楚"——前者才是写作 AI 面对的场景。
> 三档条数统计与重跑命令见 **§十五**。

### ⚠️ "C+数字"有三套命名空间，不要串

| 命名空间 | 范围 | 定义在哪 |
|---|---|---|
| **冲突** C1–C14 | 还没拍板的设计冲突 | `05_已定决策速查.md` 待拍板表 |
| **素材** C1–C14 | 核心人格层素材的 C 段小节号 | `素材/核心人格层_原文素材.md` |
| **06** C1–C21 | 本文件 §三 核心人格层的自检编号 | 本文件 |

**本文件里每一处 C 编号都必须带限定词**（`素材 C12` / `冲突 C12` / `06 C12`）。不带限定词的裸编号（例：C12）视为格式错误。

> 检索式：``grep -on '`C[0-9]\+`' <file>`` 的命中数应等于 ``grep -on '\(素材\|冲突\|06\) \?`C[0-9]' <file>`` 的命中数。**上面这张定义表和本段的举例一律不加代码格式**，否则会污染这条检索。
