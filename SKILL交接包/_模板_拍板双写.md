# 拍板双写模板

> 每拍定一条决策，同时产出两块。**块 A 给未来的设计者，块 B 给写 skill 的 AI。**
> 两块的读者不同、需求不同，不能合并：设计者要"为什么和为什么不"，写作 AI 要"写什么、写到哪、写完怎么验"。

---

## 为什么要双写

| | 块 A 决策记录 | 块 B 施工规格 |
|---|---|---|
| 落在 | `三线碰撞/09_拍板记录.md` | `SKILL交接包/` 对应文件 |
| 读者 | 未来的设计者、接手的自己 | 写 skill 的 AI |
| 回答 | 做什么 / 怎么做 / **为什么** / 代价 / **不要怎样做** | **哪个文件的哪一段** / 写什么 / 什么形态 / 用哪份素材 / 怎么验收 |
| 保留 | 推理链、被否决方案（三条铁律） | 只保留可执行指令，**不含理由** |
| 体量 | 长，完整 | 短，条目化 |

**关键质检**：如果块 B 写不出来——写不出"这条决策落到哪个文件的哪一段"——说明这条决策**还没定到可执行的粒度**，不要收工，继续拍。

---

## 块 A 模板（进 `09_拍板记录.md`）

```markdown
## 决策 [D-NN]：<标题> ✅

**拍板日期**：
**对应冲突**：`04_冲突拍板单.md` Cxx · Lx · Dxx
**查证依据**：<专题文件 / 教程锚 / agent 报告>

### 做什么（结论）
<一句话结论>

### 怎么做（操作）
<可执行的操作，分条>

### 保留什么 / 撤回什么
<如果这条决策是在几个方案里取舍，说清哪部分留了、哪部分撤了>

### 为什么（依据）
<逐条，带出处锚。教程依据优先，其次三线设计依据，最后主流程判断>

### 代价
<放弃了什么 / 有什么风险 / 留了什么洞>

### 不要怎样做（被否决方案）
| 被否决的 | 否决原因 |

### 影响面
| 文件 | 需要的改动 | 状态 |

### 遗留待办
<这条决策没解决但暴露出来的问题>
```

## 块 B 模板（进 `SKILL交接包/`）

块 B 不是一段文字，是**对施工规格的定点修改**。每条决策按下面三步落：

### 步骤 1：写进 `05_已定决策速查.md`

一行，让写作 AI 一眼看到结论，不需要展开：

```markdown
| D-NN | <议题一句话> | **<结论一句话>** | 影响产物：<文件名列表> |
```

### 步骤 2：定点修改受影响产物的施工规格

在 `02_SKILL.md施工规格.md` 或 `03_references施工规格.md` 里，找到受影响的段/文件，按下面的条目格式增/删/改：

```markdown
| # | 必须包含 | 形态要求 | 素材 | 验收 | 来源 |
|---|---|---|---|---|---|
| n | <写什么> | <什么形态：判定树/表格/问句/条件-动作/…> | `素材/Sx.md §y` | <怎么算写对了> | D-NN |
```

**"形态要求"这一列不能省。** 三线碰撞里最常见的失败模式就是"结论对了但形态错了"——比如挖出了行为背后的原因，却写成了成因式表述而不是运行规则。

### 步骤 3：如果这条决策产生了红线，写进 `04_硬约束与红线.md`

```markdown
| # | 红线 | 硬/软 | 违反会怎样 | 来源 |
```

**硬边界**用"必须 / 不可 / 禁止"，判据必须可判定；**软边界**用"建议 / 通常"。两者显式区分——这是线 B `B_SEGMENT` 的结论。

---

## 一条决策可能不产生块 B

有的决策只影响分析文档，不影响产物（比如"确认某条内部张力怎么裁"）。这种情况在块 A 的"影响面"里注明 **"块 B：无"**，不要硬编。

但要警惕：**如果连续几条决策都"块 B：无"，说明拍板正在偏离产物**，该回头检查是不是在讨论不影响施工的东西。

---

## 素材的处理规则

块 B 的"素材"列指向 `SKILL交接包/素材/Sx.md`。如果某条决策要求的素材还没提取：

1. 在 `素材/_提取清单.md` 里登记一条：**要什么、从哪提、给哪个产物用、什么形态**
2. 施工规格里先写 `素材/Sx.md §待提取`
3. **不要在拍板阶段做提取**——提取是最后一次性做的定向工程，中途做会因为后续决策变化而返工

例外：与所有未决决策都无关的素材（追问原句、案例、题库、判据原文），可以随时提取，不会返工。
