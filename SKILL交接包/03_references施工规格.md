## 通用规格（所有 reference 都适用）

### 内部结构：四段式，顺序固定

```
1. AI 内部诊断      —— 完整判断标准（SKILL.md 里放的是摘要，这里是完整版）
2. AI 对用户的外部问法 —— 只放能直接说出口的问句，自然语言（数量以各手册本节为准）
3. 手法示范        —— 完整追问回合（摆素材→问→不合格再追一层→用户说出词→凝练命名）
4. 质量门          —— 怎么判断用户的回答"够了"，可以推进
```

**第 1 段和第 2 段必须物理分开。** 诊断是 AI 心里的判断，用户看不到；外部问法是 AI 实际说出口的话。混在一起写，执行的 AI 会把诊断词说给用户听。

> **出处锚**：段式骨架与"必须物理分开"逐字取线 C `ARCHITECTURE_DECISION.md:80-85`。

> **为什么有第 3 段（2026-08-15 裁定，原为三段式）**
> 完整追问回合天然含判断和用户台词，塞进第 2 段必然违反"问法段不能有判据"，塞进第 1 段又丢掉了它作为**可照做的动作序列**的性质。所以单列一段。
> **第 3 段是唯一允许跨越诊断/问法边界的地方**，它的内容必须标注为「形态示范」，且旁边要有一句显式警告：**只看形态，不要照搬角色专属内容。**
> 第 3 段不是每份手册都必须有——只有需要示范多轮追问节奏的手册（核心人格层、多面性、核心问法密集的那几份）才写。轻量手册可以只有 1/2/4 段。

### 各手册节头的"触发"行是规格元信息，不是产物内容

本文件每份手册节头的 `> **触发**：……` 是**写给写作者看的元信息**。它的产物形态是 `SKILL.md` body 里那一行 `<触发信号> → 读 <文件名>` 指针（见 `02` §11a），**不要把这一行原样抄进 reference 正文**——reference 正文里对应的是"进入判据"那一条。触发信号取该手册进入判据的第一条。

### 读者与语言

读者是 **AI，不是用户**。用执行语言：`✅ "追问用户哪个特质是一直在的"` / `❌ "底色是无论什么场景都隐隐存在的东西"`。

**外部问法段里的问句写成大白话**（`04` H-06）——`❌ "她的防御机制是什么？"` / `✅ "有人靠得太近的时候，她第一个动作是什么？"`。**内部诊断段照常用术语**，那是写给 AI 自己看的。

### 不要重复 body

body 已经说过的（深度轴、判停标准、硬铁律、姿态校准），reference 里不重复，只写"到了这一步具体怎么做"。

### 出处锚要不要写进产物

**不写。** 本文件与素材文件里的出处锚（`02_调色盘篇:33`、`7.md:545` 这类）是**给写作者回查用的**；产物的读者是执行的 AI，它既回查不到教程，也不需要。唯一例外：产物里**逐字引用**教程原句时，可在句末缀一个短锚，便于日后校对。行数口径按此计算——出处锚不单独占行（见 §篇幅与量级）。

### 每份都要有的四件事

1. **进入判据**——什么信号说明该进这一层
2. **不适用判据**——什么角色不需要这一层（教程对每层都给了，不要漏）
3. **外部问法**（与诊断分开）
4. **质量门**——做到什么算够，可以推进

**通用验收**：`06` `G10` —— 逐份 reference 查这四件事齐不齐，存在性可判。这四件事是**每一份的下限**；各手册节里的"必须包含"表是在此之上的加项，表里没有显式列出这四件事的，按本节补齐再写。

### 卡住模板

三套，**照抄即可用**。每套 = 一个卡住场景 + 一组 4-5 问。**用户答出空词标签时按场景选一套，整组问完再判**，不要拆开零散用。

| 模板 | 用在什么时候 | 追问组（逐字） | 锚 |
|---|---|---|---|
| **A · 标签落地（通用四问）** | 用户答出任何一个空词（"温柔""傲娇""缺爱"），且这一轮还没定到具体部件 | 它具体会做什么？／它什么时候出现？／它为什么会出现？／它会不会伤到别人？ | `24问:23-28`。⚠️ 主语用「它」不用「她」，照原文 |
| **B · 单个标签深挖（四问 + 落成判据）** | 已经锁定某一个标签要挖到底 | 她 X 的时候具体会做什么？／她 X 到过度时会伤到谁？／她为什么非要这么 X？／她什么时候不 X？ | `80问教程:36`（触发句"如果某个答案只有标签，就继续往下问一层"）+ `:44-49`。**落成判据**：追到能写成"她会记住 {{user}} 随口说过的话，假装只是顺路，却提前绕了半个城市去买"这种密度才算够（`80问教程:57`） |
| **C · 一堆标签同时来（五问）** | 用户一口气丢来多个空词（温柔／傲娇／缺爱／害怕被抛弃／想爱又不敢爱） | 她具体做什么？／她什么时候这么做？／她为什么不直接说？／她这么做会伤到谁？／她什么时候会停下？ | `80问教程:1022-1028` |

⚠️ **A 与 C 是两套不同的追问，不要合并**——C 多一条"她什么时候会停下"，且 A 的第四问是"会不会伤到别人"而不是"会伤到谁"。

### 五类场景库（卡住时给场景钩子）

用户在开放式追问上答不出来时，给一个具体场景让她答"她的第一反应是什么"。**五类按用户回答难度从易到难排：日常场景 → 关系场景 → 冲突场景 → 情绪场景 → 抉择场景。**

| 档 | 什么时候用 | 示范问句 |
|---|---|---|
| 日常场景 | 第一发子弹，用户刚卡住就用 | "她下班回家，进门做的第一件事是什么？" |
| 关系场景 | 日常没钩出东西，或缺的是关系动态 | "她最好的朋友失恋了半夜打电话给她，她第一反应是什么？" |
| 冲突场景（反差入口） | 要找点缀色 / 多面性线索时 | "她在什么情况下会和平时完全不一样？" |
| 情绪场景 | 素材已经够，要往深层挖时才用 | "她接到一个坏消息，第一反应是什么？先做什么？" |
| 抉择场景 | **最难答，最后用** | "她只有一次机会，只能救一个人，她会救谁？" |

⚠️ **待泛化**——上表示范问句出自线 A `DESIGN_HANDOFF §2.10` 的**现代都市恋爱题材**样例库，写进产物前要按用户在入口给的题材换一遍场景，**难度序不变、场景内容换**。

### 完整性检查的六组维度

这是 AI 判断"**还该问什么**"的维度索引——防止只在用户已经说过的方向上越挖越深（深度有了、广度没了）。**AI 内部对照，不外显。**

| 组 | 里面有什么 |
|---|---|
| 角色核心 | 一句话是什么 / 吸引力在哪 / 核心矛盾 |
| 性格质地 | 有哪些颜色 / 每种颜色的具体行为 |
| 来源 | 为什么长成这样 / 背景里什么事改变了她 |
| 内在驱动 | 她想要什么 / 缺什么 / 怕什么 |
| 关系 | {{user}} 对她意味着什么 / 她怎么靠近、怎么推开 |
| **AI 可执行性** | 常说什么 / 绝不会怎么说 / AI 容易把她误读成什么 |

**纪律：AI 不对用户说"你漏了 X 维度"。** 发现某一组是空的，就用自然追问把话题引过去。补白示范问法各一句——

```
缺来源：   她是从什么时候开始变成这样的？
缺关系：   她第一次觉得 {{user}} 跟别人不一样，是因为什么事？
缺内在驱动：她最不想让别人看见她的哪一面？
```

⚠️ **AI 可执行性那一组最容易被整组漏掉**——它不像其它五组那样会在用户描述里自然出现，必须 AI 主动去问。

### 案例库的内容形态规格（不等选例，现在就能定）

⚠️ **选哪几个案例**和**案例长什么样**是两件事。前者仍卡在线 B `§八` 的三个 🔴，后者六条现在定死——没有形态规格，写出来大概率是"陈乖乖是一个……的角色，她的调色盘是……"这种成品展示，而这恰好是案例库最该避免的。

| # | 必须包含 | 形态要求 | 验收 |
|---|---|---|---|
| 1 | **展示追问过程，不是方法论成品** | 对话流水，不是结论清单 | 通篇没有"她的调色盘是 X/Y/Z"这种成品罗列 |
| 2 | 每个案例保留 **2-3 个回合的原始对话片段** | 引导者一句 / 用户一句，原样 | 每案例的对话回合数在 2-3 之间，可数 |
| 3 | **逐轮标注引擎做了什么动作**（摆素材 / 追问 / 换切面 / 凝练命名 / 溯源……） | 每个回合旁一个动作标签 | 每个回合都有动作标签，无裸对话 |
| 4 | **不放反例** | 只有正向流水 | 反例归常见错误清单那一份，本文件零反例 |
| 5 | 案例的结果**对齐 body 的判停标准** | 结尾那一轮要能对上 body 写的判停判据 | 结尾能指出"这里为什么停"，且指的是 body 里那条 |
| 6 | **必须包含"用户否决"的那个瞬间** | 至少一个回合是用户说"不对/不是这样"，以及引擎接下来做了什么 | 检索"不对"／"不是这样"／"都不对"，命中 ≥1，且后面接的是换方向而不是辩解 |

⚠️ 与核心人格层第 3 段同理：案例里的角色专属内容**只看形态，不要照搬**。

### 素材流向路由图

每个构件手册各自定义了"我需要什么样的输入"，但没有一处从**素材侧**说"这条素材该往哪送"。组装时按这张表走，不要一个构件一个构件地反查。

| 素材类型 | 送到哪 | 加工规则 |
|---|---|---|
| 推演出的行为场景 | 调色盘 · 衍生 | 按衍生的四条判据过一遍再落 |
| **用户原始切片** | **混色画面** | **原样进混色画面，不加工**——这是混色手册"禁止解释"那条判据的上游保证。一旦在这里改写，下游怎么判都救不回来 |
| 作者的解释 + 推演候选 | 核心人格层 | 汇入对应部件；候选要带槽位标注 |
| 核心矛盾（或核心张力） | 意象 | 意象**从核心矛盾长出来**，不是反过来给意象找矛盾 |
| 姓名 / 年龄 / 外貌 / 世界设定这类基础事实 | 素材区 · 基础信息小节（见落盘 item 4a） | 按记录规则三条写（落盘 item 4b） |
