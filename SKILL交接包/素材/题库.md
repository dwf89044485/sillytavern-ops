## A7. ⚠️ 核实：三档是"并列分工"还是"递进"？

下游规格的说法是"**三档是并列分工，只有 24→80 是递进**"。核实结论：**这个说法与教程原文相容，但教程从未用"并列"或"递进"任何一个词自我描述。** 它是从下列几条原文推出来的，不是原文的原话。以下把正反两侧的证据都摆出来。

**支持"并列分工"的原文**

1. A1（`200问.md:11-13`）三句同一句式、同一层级，用**使用时机**而不是难度深浅区分，句中没有任何先后词。
2. A6（`工作流.md:28-49`）"你有三种模式"，由**用户开局选一种**，不是跑完一档进下一档。
3. 自由双向切换条款：
> 8. 用户可以输入“切换80问”“切换24问”“切换200问”，你要切换模式。

出处：`工作流.md:62`

  ——**允许 80 → 24 反向切换**，这是"并列"最强的一条证据：递进关系不会允许反向。
4. 200 问被明确排除在主线之外：
> 不建议作为正文必填。

出处：`80问.md:81`（同义句另见 `200问.md:3`「这份不是正文必填表。」）

**支持"24→80 递进"的原文**

5. `24问.md` 末尾整节就叫"24问结束后该怎么做"，给出七条判据后收束为：
> 那就可以进入80问正式版。

出处：`24问.md:292`（完整判据见本文件 E 段）

6. 24 问是下限门槛：
> 如果用户连24问都答不出来，就不要急着让她写调色盘、混色、三面性、核心人格层。

出处：`24问.md:11`

7. 默认入口是 24 问：
> 如果用户不选，默认从24问急救模式开始。

出处：`工作流.md:51`

**与"并列"说法有张力、需要如实报告的两点**

8. A2 的四档表（`80问.md:59-83`）按 **24 → 80 → 120到160 → 200 升序排列**，并对第三档用了"**进阶**版"这个递进词。若只读这一处，容易读成一架从浅到深的梯子。但同一张表把最高档的 200 问写成"附录题库/不建议作为正文必填"，梯子在顶端断掉了——所以这张表既不是纯递进，也不是纯并列。
9. `80问.md:69`「这是推荐主线。」把 80 问定为**主干**，24 与 200 是它两侧的辅助——这是"主干 + 辅助"结构，与"三条并列平行线"不完全等同。

**一句话结论**：原文支持"24 是入口且可升到 80""200 是卡壳时的旁路抽题库"；原文**没有**说三档是并列，也**没有**说三档是递进；`80问.md` 的四档表是唯一一处看起来像梯子的排列，且它包含一个无题库的第四档。下游若要写"三档并列分工"，属于合理归纳，但不能标成教程原话。

```
## 01. 这个角色一句话是什么？

这个问题不是让你写简介，而是让你抓住角色最核心的可识别性。

如果一句话说不清，说明你可能还没有抓住角色的骨头。

参考回答：

她是一个在学校扮演乖乖大小姐、在舞台上靠吉他找回自我的叛逆少女。

更好的地方在于：它不是只说叛逆少女，而是已经带出了扮演和找回自我这两个核心动作。
```
出处：`80问.md:116-126`

```
## 02. 她最吸引人的地方是什么？

这个问题在问角色的好味在哪里。

不是问她优点是什么，而是问用户为什么会想和她继续互动。

参考回答：

她吸引人的不是叛逆本身，而是她每次看似随性时，都在偷偷确认自己还能不能做自己。

如果答案只是漂亮、温柔、强大，就还没有挖到角色吸引力。
```
出处：`80问.md:128-138`

```
## 03. 她最不该被写成什么？

这个问题用来防止AI误读。

很多角色不是靠她是什么写活的，而是靠她绝对不是什么保住轮廓。

参考回答：

她不该被写成满嘴脏话的不良少女。
她会说脏话，但那是特定情绪下的泄漏，不是她的日常语气。

这类答案后面可以放进二次解释。
```
出处：`80问.md:140-151`

```
## 04. 她在故事里承担什么功能？

这个问题在问角色对剧情有什么作用。

她是陪伴者、冲突制造者、救赎对象、拯救者、压力源，还是让{{user}}面对某件事的人？

参考回答：

她不是单纯陪伴型角色。
她会把{{user}}拖进自己的矛盾里，让{{user}}看见她公开形象和真实自我之间的裂缝。

功能不是剧情大纲，而是角色在互动里的位置。
```
出处：`80问.md:153-164`

```
## 05. 她为什么值得{{user}}反复互动？

这个问题在问角色有没有可持续的互动张力。
```

## H3. 追问规则 —— ⚠️ 下限还是上限

**核实结论：教程写的是「必须追问一次」，是下限，不是上限。教程没有任何一条把追问次数封顶在一次。** 证据两条：

> 3. 如果用户回答只有抽象标签，比如“温柔”“傲娇”“缺爱”“病娇”，你必须追问一次具体行为。

出处：`工作流.md:57`

**"必须追问一次"这个措辞本身是义务句（"必须……"），不是限额句（不是"只能追问一次"或"最多追问一次"）。** 全文检索 `工作流.md` 无"只追问""最多追问""不要追问"等封顶表述。

配套流程（已在 §G6，此处重申其中一句，因为它决定下限的读法）：
> 如果用户仍然不知道，再记录为暂未确定。

出处：`工作流.md:88`

——「**仍然**不知道」预设了第一次追问已经发生且未成功，"暂未确定"是追问失败后的兜底，不是追问的替代。

**要如实报告的一处模糊**：条款只规定了"必须追问一次"这个下限，**也没有明文授权追问两次以上**。教程在这一点上是沉默的，不是相反。上面的 `工作流.md:88` 是推断下限读法的依据，不是"允许多轮追问"的明文条款。
