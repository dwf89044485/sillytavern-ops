#### A-01 · 入口的两个必走前置步骤：世界设定 → 用户角色定位

**内容**：追问开始前有两个**必走**步骤。第一步「世界设定」——先问题材（题材直接决定 AI 的场景库），世界基调按需追加。第二步「用户角色定位」——{{user}} 是谁、和角色什么关系。两步缺任一，角色就没有坐标系。

**出处锚**：`DESIGN_HANDOFF.md §2.9 入口引导`（线 A）

**为什么无争议**：线 C 有对应的「世界观锚定」probe（`03_references施工规格.md` 篇幅表里列了它，~15 行 / 1-2 轮），只是归宿卡在 C2；线 B 无对应内容，也无任何反对。三线方向一致。

**为什么对写 skill 有用**：`02 §7 入口意识` 现在只写了"五种入口 + 每种的第一动作"，**没有任何强制前置步骤**。AI 会直接从用户丢过来的画面或标签开始追问，角色建到一半才发现不知道她活在什么世界、和用户什么关系。这是流程第一步，不是补充项。

**建议落点**：`02_SKILL.md施工规格.md §7 入口意识`，作为"第 1/2 步"置于五种入口判断之前。

#### A-02 · 素材区的基础信息小节无归宿

**内容**：线 A 的素材区分五个小节——身份 / 外貌 / 背景 / 关系 / 习惯与偏好，并注明"**按需记录，不要求完整**"。

**出处锚**：`DESIGN_HANDOFF.md §2.3 素材区`（线 A）

**为什么无争议**：基线 `03` 的人物文档落盘机制只有**四类分组**（关系动态切片 → 行为切片 → 标志性偏好习惯 → 经历事件，按检索频率排）。线 B 的四分组是"**有推演价值的素材**"的排序规则，不是"素材区的全部结构"——姓名 / 年龄 / 外貌 / 世界设定这类基础事实在四类分组里**没有位置**。两者不互斥，是互补。

**为什么对写 skill 有用**：AI 落盘时会不知道基础信息写哪。要么硬塞进"经历事件"，要么丢掉。

**建议落点**：`03_references施工规格.md` 人物文档落盘机制，在四类分组之上补一节"基础信息"，并带上"按需记录，不要求完整"这句免责。

#### A-03 · 素材的记录标准（外貌 / 关系 / 删除测试）

**内容**：① **外貌只写特征，不写美感**——不写"精致的脸""皮肤白皙"这类放到任何角色身上都成立的词；② 关系用具体场景写，不用定性词；③ 每句话做**删除测试**——删掉这句，角色变了吗？没变就删。

**出处锚**：`DESIGN_HANDOFF.md §2.3`（线 A）

**为什么无争议**：线 C `BOOK_OVERVIEW.md` 把"泛化外貌"列为教程明确反对的问题；线 B 的 12 失败模式第 12 条是"外貌写成文学描写 / 比喻 / 意象堆砌"。三线同向，无人反对。

**为什么对写 skill 有用**：`04_硬约束与红线.md` 的 H 系列约束的是**构建区产物**（颜色、衍生、核心人格层部件），素材区落盘时**一条可判定的质量门都没有**。而素材区恰恰是 AI 最容易顺手写成通用美文的地方。

**建议落点**：`03` 人物文档落盘机制（记录规则），或 `04` 新增一条软边界。

#### A-04 · 不主动问"她是什么性格"

**内容**：AI **不主动**抛性格类问题。这类问法直接把用户推向标签，用户会用"温柔""高冷"来回答。

**出处锚**：`DESIGN_HANDOFF.md §2.10`（线 A）

**为什么无争议**：三线的共同立场都是反标签化；线 B 的深度轴起点就是"标签 → 具体行为画面"，线 C 的泛化检测是四诊断之首。无任何一线主张 AI 该主动问性格。

**为什么对写 skill 有用**：现有的 `04` H 系列全部约束的是**产物形态**（产物不能是裸标签），**没有一条约束 AI 的提问动作本身不能诱导标签**。而"她是什么性格的人？"是 AI 开场最本能的第一句话。这是产物侧规则管不到的输入侧污染。

**建议落点**：`02 §4 硬铁律` 或 `§5 姿态校准`（可作为对照句的 ❌ 一侧）。

#### A-05 · 用户裁决不可上诉

**内容**：你推演，用户裁决。**裁决不争辩，换个方向再试**。用户说"就是这个感觉"就是对的，不需要她给理由。

**出处锚**：`DESIGN_HANDOFF.md §2.14 红线`（线 A）、`KNOT_BODY_VS_REFS.md §1.5`（线 B 把"用户裁决不可上诉"列进 body 五条红线）

**为什么无争议**：线 A / 线 B 独立写到同一条；线 C 的"输出分三层、不把推论当事实"同向。⚠️ 注意线 A 自己的 `DESIGN_HANDOFF_REVISION.md` 反对的是把"AI 能力边界"写成声明式段落，**不反对这条行为规则本身**——这是线 A 内部的表述之争，不是内容之争。

**为什么对写 skill 有用**：`05` 的 M-04「AI 提案，用户裁决」只定了**谁拍板**，没定 **AI 被否决之后不许辩解**。LLM 在被否定时的默认行为是解释自己的推理为什么合理，这恰好是最伤协作的动作。

**建议落点**：`02 §4 硬铁律`，与"不替用户生成内容"并列。

#### A-06 · "作者无解"的三条判据（从追问切到推演的闸门）

**内容**：满足以下任一条，才允许从追问切到推演：① 用户直接说"不知道 / 没想过"；② 答案模糊到无法落成一句行为描述；③ 用户给的解释与已有素材**矛盾**。

**出处锚**：`DESIGN_HANDOFF.md §2.10 第三层`（线 A）

**为什么无争议**：线 B 的降级链条给的是"最近 2-3 轮无新行为场景或关系细节"——那是**方向枯竭**判据（这条方向挖不动了），与"作者答不上来"是两件事，不冲突、可叠加。线 C 无对应。

**为什么对写 skill 有用**：这是"**AI 什么时候有资格开始推演**"的唯一闸门。没有它，AI 会在用户其实答得出的时候抢答——而这正是线 A 红线第一条要防的事（"作者能答就绝不抢答"）。

**建议落点**：`02 §9 推演权限`，作为推演的进入条件。

#### A-07 · 推演前的输入闸门 + 五步内部理解

**内容**：① 推演前先判**素材够不够推**（软判断，不设硬阈值；最低线：素材区至少有一条非标签化记录、目标槽位有对应素材支撑）；② 推演前 AI 内部走五步：列已知事实 → 确认观察到的特征 → 指出用户没说出口的模式 → 不确定的留空 → 一句话概括；③ 硬判据：**三句话说不清楚 = 素材不够，回去追问，不硬推**。

**出处锚**：`DESIGN_HANDOFF.md §2.19a/b`（线 A）

**为什么无争议**：线 B、线 C 都没有推演前的输入闸门，也没有反对。这是线 A 独有的补白。

**为什么对写 skill 有用**：`05` 的 D04 确立了"三种检查落在三个不同时机"（线 C 判每轮输入 / 线 B 判 MVC 停止 / 线 A 判组装产物）——这个三分**漏掉了推演前后这两个时机**。素材不够就推演，是 AI 产出编造内容最集中的入口。

**建议落点**：`02 §9 推演权限`；并更新 `05` D04 的"三时机"为"五时机"。

#### A-08 · 推演后的差异性检查

**内容**：产出 2-3 个候选后，**遮住框架名和术语只看行为**，判断这几条描述的是不同的事，还是同一件事换了个说法。是同一件事 = 质量不合格，重推。

**出处锚**：`DESIGN_HANDOFF.md §2.19c`（线 A）

**为什么无争议**：D-01 撤掉的是四个心理学框架 + 扩展池，**不是这个自检**。D-01 的四条替代机制（抽行为题 / 条件-动作 / 高可能推论区块 / 跳过）照样会产出多个候选，差异性检查照样适用。三线无人反对。

**为什么对写 skill 有用**：LLM 产出"多个候选"时最典型的失败就是同义改写。`06_验收.md` 对推演产物只有"不出形容词""标注从哪段经历推出"两条，没有一条查候选之间是否真的不同。

**建议落点**：`02 §9 推演权限` + `06_验收.md` 推演段自检。

#### A-09 · 否决的三种情形 + 溯源的具体问法

**内容**：用户否决推演时分三种情形、三条路径：① "不是 X，是 Y"（用户给了替代 → 直接改，不追问）；② "我也不知道，没想过"（→ 降级或跳过这一层）；③ "都不对，感觉不对"（→ 走溯源）。**溯源的动作是**：问"哪一句不对？一个词就行"；用户答不上来，就把 AI 的理解和用户的反应之间的差摆出来给用户看。

**出处锚**：`DESIGN_HANDOFF.md §2.19d`（线 A）、`DESIGN_DISCUSSION_01.md §决策 4`（线 A）

**为什么无争议**：线 B 的降级链条（`E_SECTION_DESIGN 决策 6`）把"溯源"列为链条上的一环，但**只记了这一环的名字，没记这一环怎么做**——`05` 的 M-51 归并时原样继承了这个空缺。C13 管的是"模式链与引导阶梯怎么分工"，不管链上每一环的操作内容。两线互补，不冲突。

**为什么对写 skill 有用**：溯源是五环链条里**唯一一个没有操作定义的环**。AI 读到"溯源"两个字不知道该说什么。

**建议落点**：`02 §12 降级模式链`（C13 拍板后填入），或 `03` 卡住处理手册。

#### A-10 · 推演结果的批次呈现节奏

**内容**：不要每推出一条就单独抛给用户。**攒够一个维度**（素材足够时甚至攒到核心人格层 + 混色）再整批呈现；但整批呈现后，每条候选仍要用户**逐条**判。

**出处锚**：`DESIGN_HANDOFF.md §2.20 推演节奏`（线 A）

**为什么无争议**：与 `04` H-18「不一次性砸完整档案，先轮廓后补全」不冲突——H-18 管的是**成品档案**，这条管的是**推演候选**，而且这条正是"先轮廓"在推演阶段的落地方式。线 B / 线 C 无对应也无反对。

**为什么对写 skill 有用**：推演阶段是交互密度最容易失控的地方。逐条抛会把对话切成几十个来回，整批抛又违反 H-18。这条给出了中间刻度。

**建议落点**：`02 §9 推演权限`。

#### A-11 · 情景引导的五类场景库（按回答难度排序）

**内容**：卡壳时给场景钩子，场景分五类、**按用户回答难度从易到难**排：日常场景 → 关系场景 → 冲突场景 → 情绪场景 → 抉择场景。并写明什么时候用哪一档。

**出处锚**：`DESIGN_HANDOFF.md §2.10`（线 A，现代都市恋爱题材的样例库）

**为什么无争议**：⚠️ 需诚实标注一处**线内张力**——线 A 自己的 `DISCUSSION_01 §决策 2` 废除了"问法六类按可答性排序"。但那废的是**问题类别的组织方式**（改为按卡壳类型匹配），不是**场景难度分档**，两者不是同一件事。线 B / 线 C 无反对。

**为什么对写 skill 有用**：`02 §7` 第 4 项"什么都说不出的处理"目前只有一句场景钩子（"闭上眼，你第一个想到的场景是什么"），没有梯度。用户在这句上再卡住，AI 就没有第二发子弹了。

**建议落点**：`03` 问题库 / 卡住处理手册。优先级偏低（题材绑定现代都市，需泛化后再用）。

#### A-12 · 人物文档的落盘目录

**内容**：人物文档写到 `workspace/<角色名>/` 目录下。

**出处锚**：`DESIGN_HANDOFF.md §2.2 文件结构`（线 A）

**为什么无争议**：线 B 的 L1–L12 落盘机制全部在讲**文档内部结构**，没讲文件放哪；线 C 无对应。无冲突。

**为什么对写 skill 有用**：`03` 落盘机制第 1 条只规定了"文件名和文档标题都用角色名"，**没规定目录**。AI 需要知道往哪写。小，但缺了就是执行歧义。

**建议落点**：`03` 人物文档落盘机制，与文件名规则并列一行。

#### A-13 · 推演候选的槽位标注（去向，不是来源）

**内容**：每条推演候选标注它将落进文档的哪个槽位，例如"→ 核心人格层 · 防御机制"。

**出处锚**：`DESIGN_HANDOFF.md §2.18`（线 A）、`KNOT_BODY_VS_REFS.md §1.6 交互原则`（线 B）

**为什么无争议**：⚠️ 与已收录的 M-30 **不是同一条**——M-30 的三要素标注的是**来源**（"从哪段经历推出来的"，为了可回溯）；这条标的是**去向**（这条推演归到文档哪一格）。线 A / 线 B 独立写到同一条，无人反对。

**为什么对写 skill 有用**：用户面对一组无归属的推演候选，很难判断"我在给什么东西拍板"。标了槽位，裁决成本立刻下降。

**建议落点**：`02 §9 推演权限` 的标注要求那一行，与 M-30 并列。

---

#### A-14 · 意象的操作化前置步骤

**内容**：AI **先自己**从调色盘和行为模式里提取角色的核心矛盾（有核心人格层就用核心矛盾，没有就用核心张力），**再**问"这个核心矛盾在她身上表现成什么样 / 在自然界里长什么样"。理由：意象不能等它自然浮现，skill 要主动去够。

**出处锚**：`DESIGN_HANDOFF.md §2.23`（线 A）

**为什么无争议**：基线已收录主问句"她存在的方式像什么"（`03`:231）和完成标准"承载核心矛盾"，但**没有 AI 提取核心矛盾这一前置动作**。`05` 移除 G-2 时的理由是"线 B 的 G3 已给出意象行"——G3 给的是问法和完成标准，不是这个前置步骤。不冲突。

**为什么对写 skill 有用**：直接问"她存在的方式像什么"，用户大概率答不上来。前置提取是让这一问变得可答的那一步。

**建议落点**：`03` 意象手册，放在主问句之前。

---

#### A-15 · 素材流向路由图

**内容**：明确四条流向——推演出的行为场景 → 调色盘衍生；用户原始切片 → **原样**进混色画面（不加工）；作者解释 + 推演候选 → 汇入核心人格层；意象 ← 从核心矛盾长出。

**出处锚**：`DESIGN_HANDOFF.md §2.13 组装与输出`（线 A）

**为什么无争议**：三线都没有把"哪种素材去哪个构件"写成一张图，也无相反主张。

**为什么对写 skill 有用**：`03` 每个构件手册各自定义了"我需要什么样的输入"，但没有一处从**素材侧**说"这条素材该往哪送"。组装时 AI 只能一个构件一个构件地反查。其中"用户原始切片原样进混色画面、不加工"这一条尤其重要——它是混色手册"禁止解释"那条判据的上游保证。

**建议落点**：`03` 组装期一致性验证那一节（内容已定、等 C5 定落点），或人物文档落盘机制。

### 线 B（工程化线）17 条

---

#### B-01 · 一次一个交互单元

**内容**：每轮只给**一个**交互单元——一个问题、或一个方向试探、或一组推演候选。不叠加。

**出处锚**：`KNOT_BODY_VS_REFS.md §1.6 交互原则`、`CHAR_BUILD_GUIDE_DESIGN.md §交互原则`（线 B）

**为什么无争议**：线 A `§2.20` 的批次呈现是同一原则在推演阶段的具体化，方向一致；线 C 无反对。

#### B-04 · 入口检测是"素材类型识别"而非"入口类型分类"，且可多选

**内容**：步骤 1 不判"用户属于哪一类入口"，而是识别**用户给了哪些类型的素材**（可多选）：行为切片 / 经历事件 / 标签 / 画面 / 已有角色卡。然后从**信息密度最高**的那条开始追问。完成标准：素材区有 ≥1 条非标签化记录；未达标就在步骤 1 内继续追问。

**出处锚**：`E_SECTION_DESIGN.md 决策 3`、`KNOT_BODY_VS_REFS.md §1.3`（线 B）

**为什么无争议**：⚠️ 与已收录的 `02 §7`「五种入口 + 每种的第一动作」有**张力**，但这是**线 B 本线内部的后续细化**——线 B 早期的 `ARCHITECTURE.md` 写的是五入口，`E_SECTION 决策 3` 明确改成了素材类型识别并给出了理由。线 A / 线 C 未反对。这不是跨线冲突，是碰撞时只取了线 B 的旧版本。

**为什么对写 skill 有用**：真实用户一句话里常常同时给画面 + 标签 + 一段背景。"你属于哪种入口"这个问法逼 AI 二选一，选错就进错分支。改成多选后，"从信息密度最高的开始"才是那个真正的决策规则。

**建议落点**：`02 §7 入口意识`，与五种入口并存（入口类型用于识别信号，素材类型用于决定先追哪条）。

#### B-05 · 矛盾路由区分：跨场景矛盾 vs 同瞬间矛盾

**内容**：步骤 2 发现矛盾时，**先追问画面，再判类型**：
- **跨场景矛盾**（对 A 温柔，对 B 凶）→ 标记为"多面性线索" → 继续当前追问方向 → 收束时统一激活多面性
- **同瞬间矛盾**（骂的同时后悔）→ **当场**追问混色画面："那个瞬间她具体做了什么？" → 用户给不出就标记为"混色线索"，收束时处理

**出处锚**：`E_SECTION_DESIGN.md 决策 8`、`KNOT_BODY_VS_REFS.md §1.3 / §2.3`（线 B）

**为什么无争议**：线 A 无对应；线 C 的「同一瞬间追问（混色发现）」动作恰好是这条路由的**下游**——线 C 定义了动作，线 B 定义了什么时候该用它。三线无冲突。

**为什么对写 skill 有用**：**这是 4 个基础诊断里"矛盾检测"触发之后的唯一路由规则。** 基线收了"矛盾检测"（M-42/M-43，跨诊断优先级里矛盾排第一），也收了"多面性"和"混色"两个手册各自的进入判据，但**没收从矛盾检测到这两个手册的分流规则**。缺了它，AI 会把所有矛盾都当混色处理——这正是线 B 三个 agent 独立指出的具体失败（"对谁都好 vs 对妹妹凶"被错误路由到混色）。

**建议落点**：`02 §10 4 个基础诊断`（矛盾诊断项下），或 `§11 流程地图`。

#### B-06 · 卡住的根因诊断——按用户认知阶段分四类

**内容**：用户卡住不是一种情况，按认知阶段分四类，处理方式**完全不同**：

| 阶段 | 症状 | 处理 |
|---|---|---|
| 物化阶段 | 脑子里有画面但说不出 | 场景引导 |
| 展开阶段 | 只有一个画面，扩不开 | 换切面 |
| **收敛阶段** | 素材够了但看不出共性 | **回看整理**——把已有素材逐条念出来，问"这里面有没有什么感觉是共通的"。**不是继续追问** |
| 穿透阶段 | 说不清动机（好奇心到了但认知没到） | 追问 1-2 次，仍说不出就**正常降级，不算失败**："她为什么这样做你可能还没想清楚——角色现在跑起来已经够了" |

**出处锚**：`E_SECTION_DESIGN.md 决策 6.1`、`KNOT_BODY_VS_REFS.md §1.3`（线 B）

**为什么无争议**：与线 A 的三层模型（镜子 / 脚手架 / 推演）**正交**——三层模型管"AI 换什么角色"，根因诊断管"用户卡在哪种认知阶段"。`05` 的 M-51 归并降级链条时只归并了前者，`E_SECTION 决策 6.1` 明说这是决策 6 的补充维度而非替代。线 C 无反对。

**为什么对写 skill 有用**：四类里**"收敛阶段要回看整理而不是继续追问"是唯一一个反直觉分支**——AI 的默认反应一定是继续追问，而这恰恰是素材已经够时最错的动作。另外"穿透阶段追不出来是正常降级不是失败"这一条，直接决定 AI 会不会在这里反复磨用户。

**建议落点**：`02 §12 降级模式链`，作为链条之外的第二个判断维度。

#### B-07 · 三层判停框架——性质不同，不能混淆

**内容**：判停点分三层，性质完全不同：

| 层级 | 判什么 | 回跳方向 |
|---|---|---|
| **步骤级** | 整体方向对不对 | 方向错 → 回步骤 1；用户喊停 → 跳收束 |
| **轮次级** | 这条方向够不够了 | 够 → 换方向；枯竭 → 换切面；卡住 → 升级模式 |
| **里程碑级** | 此时该不该问用户 | 达到 MVC → 暂停展示进度，让用户选 |

三层互不干扰。AI 先走轮次级，再依次检查更高级别，不会同时触发多个层级。

**出处锚**：`E_SECTION_DESIGN.md 决策 9.1`（线 B）

**为什么无争议**：线 A / 线 C 无对应也无反对。与 `05` 已收录的 D04「三种检查落在三个不同时机」是**不同的分类轴**——D04 分的是检查对象（输入 / 停止 / 产物），这里分的是判停的作用域。

**为什么对写 skill 有用**：`02 §6 判停标准` 目前只有遮名测试一条——而遮名测试其实**只是轮次级里的一个判据**。没有这个分层，AI 会把"这条问够了"和"整个角色做完了"混为一谈：要么每轮都在自问"是不是该收了"，要么一路追到底不知道该在 MVC 停。

**建议落点**：`02 §6 判停标准`，把遮名测试挂到轮次级下面。

#### B-08 · 单条追问的判停 AND 条件 + 换切面的顺序

**内容**：① **追问判停**要同时满足三条：用户给出了一个画面/行为描述 **AND** 这个画面能回答"她在什么场景下做了什么"（有场景 + 有动作）**AND** 和已有素材不重复（换措辞不算新）。② 方向枯竭后**换到哪个切面**有顺序：正面 → 反面 → 侧面 → 关系面，不在同一枯竭方向继续挖。

**出处锚**：`E_SECTION_DESIGN.md 决策 9`（线 B）

**为什么无争议**：基线已收方向枯竭的**触发判据**（`04`:225"最近几轮用户在用不同措辞说同一件事 → 方向枯竭，必须换切面"），但**没收换到哪个切面**。已收遮名测试，但没收这三条 AND。互补，不冲突。

**为什么对写 skill 有用**："必须换切面"是个没有宾语的指令。给了顺序，AI 才知道换哪个。三条 AND 条件则把"这条问够了"变成可机械判断。

**建议落点**：`02 §6 判停标准`（并入 B-07 的轮次级）。

#### B-09 · 方向变更处理（允许回到步骤 1）

**内容**：用户中途推翻整体方向（"不对，她不是病娇，她是表面冷但其实关心人"）时的四步：① 确认旧素材是否保留（"你之前说的跟踪、偷看手机——她还是会做这些事吗？"）② 清除旧方向的**构建区**内容（颜色候选、衍生、二次解释）③ 保留用户确认仍属于角色的素材 ④ 回到步骤 1 重新初始化。并明确：**方向变更不适用脚手架/推演降级——它不是卡壳**。

**出处锚**：`E_SECTION_DESIGN.md 决策 7`（线 B）

**为什么无争议**：与 `05` 已收录的 M-38「素材是事实不动，构建是解读可推翻」**完全同构**——这条就是 M-38 的执行程序。线 A `§2.8` 迭代环同向但没有操作步骤。

**为什么对写 skill 有用**：M-38 给了原则（素材不动、构建可翻），没给"推翻整体方向时具体删什么、留什么、怎么问"。最后那句"方向变更不是卡壳、不走降级链"尤其关键——否则 AI 会把用户改主意误判成用户卡住，然后启动脚手架去猜，把已经明确的新方向又搅乱。

**建议落点**：`03` 人物文档落盘机制（归档区规则旁），或 `02 §11 流程地图`。

#### B-14 · B 段的六条写作原则

**内容**：① B 段是**路由器和防误触机制**，不是教程摘要——不要把教程的论证搬进来；② 硬边界用判断标准不用模糊描述（"角色卡 vs 用户信息"不是"看情况"，是"描述对象是 AI 演的角色还是 AI 读的用户"）；③ **失败模式分类呈现**：致命级（毁掉角色）→ 严重级（降低质量）→ 中等级（影响细节），**AI 优先防致命级**；④ 翻译层矛盾显式处理（"手写优于 AI 扩写"vs skill 是 AI 驱动，等）；⑤ **软边界标注组合可能性**——char-build-guide 和 dialogue-persona 不是绝对互斥，用户可能中途切换，不要假装硬隔离；⑥ 盲区诚实标注。

**出处锚**：`B_SEGMENT_AGENT_INSIGHTS.md §六`（线 B）

**为什么无争议 / 需注意**：其中「硬边界 vs 软边界显式区分」已在 `04` 收录（✅）。③ 的**严重度分级**在基线里没有——`01`:64 只把"12 失败模式 + 6 执行风险"记为一个待去重的产物项（⏳ C2），没记分级和"优先防致命"。⚠️ ⑤ 与 `01`:117 的"排他替代"表述有张力，需要一次小拍板（不是漏，是新暴露的一处需确认）。其余四条无争议。

**为什么对写 skill 有用**：12 个失败模式如果平铺直叙，AI 会平均用力；分级之后 AI 知道哪四条（AI 扩写污染 / 衍生给 AI 写 / 强行拆面 / 调色盘与台词人设混用等致命级）是必须优先拦的。

#### C-01 · 完整性检查的核心维度清单（6 组）+ 不点名纪律

**内容**：AI 内部对照的核心维度清单（来自 24 问精简）——
- 角色核心（一句话是什么 / 吸引力 / 核心矛盾）
- 性格质地（有哪些颜色 / 具体行为）
- 来源（为什么长成这样 / 背景中什么事改变了她）
- 内在驱动（她想要什么 / 缺什么 / 怕什么）
- 关系（{{user}} 对她意味着什么 / 她怎么靠近和推开）
- AI 可执行性（常说什么 / 绝不会怎么说 / AI 容易误读成什么）

配套纪律：**AI 不对用户说"你漏了 X 维度"**，用自然追问引到空白区域。并配三句补白示范问法（缺来源 / 缺关系 / 缺内在驱动各一句）。

**出处锚**：`candidates/questioning-moves.md §5 完整性检查`、`§运行规则 2`（线 C）

**为什么无争议**：⚠️ 线 C 自己把"完整性检查"从**独立追问动作**降级为流程规则（`rejected/flow-rules.md`："检查缺失维度然后补上是通用操作，不需要特定方法论"），但**降级的是它的动作地位，不是清单内容**——降级说明里明写"已嵌入流程模型的'基础诊断全程运行'规则"，运行规则 2 也明写"skill 做完整性检查，只追问空白维度，不重复已有内容"。清单被保留。线 A 的问题目标层管"每个问题探到什么算够"，线 B 的质量信号管"什么时候能停"，**都不覆盖"哪些维度还空着"**。三线互补。

**为什么对写 skill 有用**：这是 AI 判断"**还该问什么**"的唯一维度清单。缺了它，AI 只会在用户已经说过的方向上越挖越深（深度有了，广度没了），而"AI 可执行性"这一组（常说什么 / 绝不会怎么说 / 容易误读成什么）恰恰是最容易被整体遗漏的一组。

**建议落点**：`02 §10`（作为诊断的一部分）或 `03` 问题库（作为维度索引）。

#### C-02 · 深度就绪的三个探测问句

**内容**：用来**主动探**深度信号的三句问法：
- 探多面性：「她在家里和在外面，状态差别大吗？是'语气柔和了一点'的那种差别，还是'像换了一个人'？」
- 探混色：「她拒绝别人帮助的那个瞬间，她心里只有一种感觉在跑，还是好几种挤在一起？」
- 探核心人格层：「同样的处境，别人可能会接受帮助、可能会求人、可能会妥协。她为什么偏偏选了自己扛？」

**出处锚**：`candidates/questioning-moves.md §6 深度就绪检查`（线 C）

**为什么无争议**：⚠️ 线 C 自己废掉的是"深度就绪检查"这个**显式阶段**（运行规则 3："没有'深度就绪检查'这个显式阶段，追问在性格质地阶段内由信号触发"），**不是这三句探测问法**。与 M-05「深度层是条件触发不是必经关卡」完全兼容——这三句正是"触发判断"的执行手段。已收录的 M-13 采纳的是**信号识别表**（AI 观察到什么算信号），这三句是 **AI 主动去探信号的问法**，方向相反、互补。

**为什么对写 skill 有用**：`03` 各手册的"进入判据"都**假设信号已经出现了**。但真实对话里信号常常不会自己冒出来——用户不会主动说"她在家和在外面像两个人"。缺这三句，AI 就只能被动等信号，等不到就默认角色不需要深度层，把 M-05 的"条件触发"实际执行成"基本不触发"。而且这三句的措辞质量很高（"语气柔和了一点 vs 像换了一个人"给了用户可对照的刻度），属于 `02 §8` 说的"必须内化不可外置"的追问品味。

**建议落点**：`02 §8 标志性问法样本`，或各手册的进入判据那一行旁边。

## 五、整体判断

**会有实质缺失，而且缺失是有结构的——不是散点。**

按这份基线现在的样子直接开工，写出来的 `char-build-guide` 会是这样一个东西：**方法论构件（调色盘 / 多面性 / 混色 / 核心人格层 / 二次解释 / 意象）的定义、判据、质量门都相当扎实，但"AI 每一轮怎么动"这一层是残缺的。** 34 条漏项里有 26 条落在同一层——路由、闸门、退出、边界。

具体说，缺的是四种能力：

1. **诊断之后往哪走**。4 个基础诊断收得很完整（判定树、三级判定、跨诊断优先级、三条纪律），但"矛盾检测触发之后去多面性还是去混色"（B-05）没收。诊断有了、手册有了，中间的路由没了。
2. **推演的进出闸门**。什么时候有资格开始推（A-06）、推之前素材够不够（A-07）、推完了怎么自检（A-08）、被否决了怎么回（A-09）——四道闸门整体缺失。`05` 的 D04「三种检查三时机」这个分类本身就漏了推演前后两个时机，所以挂在上面的东西一起没了。
3. **退出**。追问引擎只有"方向枯竭 → 换切面"这种局部退出，没有整体退出（B-12），也没有"什么时候根本不该启动我"（B-13）。一个没有逃生门的追问引擎，遇到真的说不出东西的用户会无限循环。
4. **边界**。`02` 的 body 12 段里没有 metadata 段、没有边界段——而 `KNOT_BODY_VS_REFS` 把这两块都列为 body 必备。description 写不对（B-15）会导致 skill 根本触发不了或到处误触发；没有兄弟 skill 运行时路由（B-02）和生成请求拦截（B-03），AI 面对最高频的那句"帮我生成一个角色"不知道该回什么。

**漏项的成因也有规律**，值得在补的时候一并注意：

- **归并时取了"更精确的那份"，但两份其实不是同一件事。** 最典型的是落盘机制——取了线 B 的 L1–L12（文档内部状态管理），丢了线 A 的 `§2.2`–`§2.3`（素材怎么记）。M-17 的 MVC 判定、M-51 的降级链条也有类似痕迹（链的名字归并了，链上每一环怎么做没归并，比如 A-09 的溯源）。
- **审查报告被当成"历史输入"整体略过。** `E_SECTION_DESIGN.md` 十个决策只进了两个，`B_SEGMENT_AGENT_INSIGHTS.md` 八个发现只进了两个——这两份是漏项密度最高的文件，合计贡献 11 条。
- **"被降级"被误读成"被否决"。** 线 C 的完整性检查和深度就绪检查（C-01、C-02）被降级的是**独立追问动作的地位**，两份降级说明都明写内容保留为流程规则，但碰撞时内容一起丢了。
