## 二、互补（各说一部分，直接拼）

### M-08 ★ 三种检查落在三个不同时机（D04，最高价值）

三线的"检查"根本不是同一件事的三个版本，是**三个环节**：

| 环节 | 来源 | 内容 | 运行时机 |
|---|---|---|---|
| **输入侧诊断** | **线 C** | 4 个基础诊断（泛化 / 矛盾 / 结论 / 扁平），三级判定（触发/观察/通过）+ 灰色地带 + 正反例 + 跨诊断优先级（矛盾 > 结论 > 泛化 > 扁平）+ 单轮只处理最高的 1-2 个 | **每轮用户输入后** |
| **停止侧判据** | **线 B** | 质量信号 A–G 7 个 + 假信号黑名单（回答变长、用了术语、说"我知道了"、情绪激动都明确不算）+ 权重（E 修正精度 / F 自发延伸最高） | **判 MVC 时** |
| **产物侧校验** | **线 A** | 一致性验证（性格打架吗 / 衍生矛盾吗 / 多面性混入二次解释吗 / 语料移出调色盘了吗 / 混色解释情绪了吗 / 防御机制落到行为了吗 / 意象从核心矛盾长出来了吗） | **组装 / 收束时** |

**融合后写法**：三套并存，各挂各的时机。三线各自的"缺"正好被另外两线补上——线 A/B 没有输入侧判定树，线 C 没有停止判据也没有产物校验。

线 C 的两条设计原则一并采纳：**三条核心纪律**（只追问不指责 / 四个诊断词永远不对用户说 / 灰色地带默认走"观察"）和**可复现性目标**（"同一段用户输入，AI 10 次判断应得到 10 次一样的结果"）。

### M-09 ★ 三种追问组织落在三个不同角色（D05）

| 角色 | 来源 | 内容 |
|---|---|---|
| **方向盘** | 线 B | 追问深度轴：标签→画面→矛盾→为什么→内核。每轮对照判断"用户现在在哪一层，该往哪推" |
| **动作库** | 线 C | 13 个追问动作，其中 **11 个**含 **AI 内部诊断 / 外部问法 2-4 个 / 质量门** 三要素（2 个用户捞回动作无质量门，见 G-7） |
| **收敛判据** | 线 A + 教程 | `§2.16` 问题目标层——"每个问题在探什么、探到什么算够"。教程侧的 80 问十组目标声明是它的源头 |

**融合后写法**：深度轴放 body（每轮都用），13 动作按 C2 的结论安排文件，目标层作为质量门的上位说明。

### M-10 线 B 的 G1–G9 填补了线 A 在快速路径上的完全空白

线 A 的 D11 有 8 条但**全部是卡住处理**，没有任何降级路径 / 轻量模式设计——教程 11 这条明显的快速路径只出现在线 A 被降级的辅助材料里。线 B 的 G1–G9 是完整设计，且 G3 五步直接来自教程 11。**直接采纳，无争议。**

（G6 阶梯与线 A 三层模式的对齐关系需拍板，见 C13；G4 的双向切换需拍板。）

### M-11 线 C 的 4 个未来 skill 填补了线 B 自认的缺口

线 B 在 B 段诚实标注"测试和迭代当前无 skill 覆盖"，且机制/长期性/开场白无归属。线 C 的"角色卡设计 skill"（机制设计 / 长期性设计 / 开场白 / 用户信息）正好覆盖这一块，且给出了 skill 间依赖关系：

> 角色塑造 skill 产出角色文档 → 角色卡设计 skill 加入机制和开场白 → 世界书格式转换 skill 输出最终的世界书条目。角色验证 skill 可以独立运行。台词人设 skill 是调色盘的平替方案，独立运行。

**融合后写法**：把这条依赖链作为路线图记录。**教程直接支持拆分**——执行器四禁"不要输出完整角色卡格式，不要写开场白，不要写世界书，不要写台词人设成品"，且下游清单只有五个（调色盘/混色/三面性/核心人格层/二次解释），开场白、世界书、用户信息、长期性明文在外（`01_教程事实底册 §三`）。

（"角色验证/体检"是否纳入需拍板，见 C1。）

### M-12 线 A 的确认/同步二分 与 线 B 的 L10 在"构件"侧一致

C10 的冲突只发生在**素材过滤**这一格。在**构件**这一格三线是一致的：

- 线 A `§2.15b`："**产生新内容** → 必须确认"（推演候选、把模糊表述转写为具体特征）
- 线 B `L10`：构建区构件确认时用**自然语言投影**给用户看（不用术语格式）

**融合后写法**：AI 产生新内容（推演候选、转写、构件命名）必须经用户确认，确认形式采用线 B 的自然语言投影。
