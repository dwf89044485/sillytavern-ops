# 三线决策记录碰撞融合 — 总入口

> 本目录是一次**独立重做**的三线碰撞融合分析。上一次融合尝试失败，本目录不继承其任何结论。
> 本目录只新增文件，**不修改仓库中任何既有文件**（包括 `AGENTS.md`）。

---

## 一、任务是什么

仓库里存在**三条独立演进的 skill 设计线**，都在设计"引导用户创建角色"的 skill，但粒度、命名、架构、行为契约各不相同。任务是把三条线做**对称的碰撞融合**：

1. 哪些是**一致**的（三线说了同一件事）
2. 哪些是**互补**的（各说一部分，可直接拼）
3. 哪些是**精度升级**（同一件事，某条线说得更可执行）
4. 哪些是**可归并**（措辞不同、实质同一，需统一命名）
5. 哪些是**冲突**（互斥，必须由用户拍板）
6. 哪些是**单线独有**（另外两线完全没有覆盖）

**本目录不替用户拍板。** 冲突项只做"呈现 + 证据 + 选项 + 建议"。

## 四、方法约定

### 4.1 决策原子 schema（Phase 2 三线统一使用）

每条决策原子必须填满以下字段，**缺"出处锚"的条目不得进入碰撞矩阵**：

| 字段 | 说明 |
|---|---|
| `ID` | `A-001` / `B-001` / `C-001` |
| `议题域` | 见 §4.2 的议题域清单 |
| `结论` | 这条决策说了什么（一句话，用原文措辞，不要转写） |
| `出处锚` | `文件路径 §章节号` 或 `文件路径:行号`，**必填** |
| `依据` | 为什么这么定（教程章节 / agent 共识 / 用户拍板） |
| `代价` | 放弃了什么 / 风险 |
| `否决方案` | 本线内被否决的替代方案 + 否决原因 |
| `本线内状态` | `现行` / `已被本线取代（→ 新位置）` / `待决策` |

### 4.2 议题域清单（12 个，Phase 3 的聚合轴）

| # | 议题域 | 覆盖什么 |
|---|---|---|
| D01 | skill 边界与拆分 | 做几个 skill、各自管什么、路由关系 |
| D02 | 文件架构与 references 切分 | SKILL.md 体量、reference 按什么维度切、几个 |
| D03 | 阶段流程模型 | 有没有阶段、阶段怎么划、是否线性 |
| D04 | 诊断体系 | AI 内部怎么判断用户回答有问题 |
| D05 | 追问动作库 | 具体追问动作的定义、问法、质量门 |
| D06 | AI 推演权限 | AI 能不能替用户生成候选、边界在哪 |
| D07 | 术语暴露 | 调色盘/多面性等术语对用户可见性 |
| D08 | 人物文档排版与记录机制 | 落盘结构、记录粒度、续接机制 |
| D09 | MVC（最小可运行角色） | 定义、判据、暂停点、告知方式 |
| D10 | 意象 | 必须/可选、构建位置、呈现位置 |
| D11 | 快速路径与卡住处理 | 降级、引导阶梯、示范边界 |
| D12 | 命名与 slug | skill 名、目录名、维度命名 |

### 4.3 六档关系判定（Phase 3）

| 档位 | 判定标准 | 处理动作 |
|---|---|---|
| `一致` | 三线（或涉及的线）结论实质相同 | 直接采纳，记入 05 |
| `互补` | 各说一部分，无重叠无矛盾 | 直接拼接，记入 05 |
| `精度升级` | 同一件事，某线更可执行（有判定树/正反例/质量门） | 取精度高者，记入 05 |
| `可归并` | 措辞/命名不同，实质同一 | 统一命名后归并，记入 05 |
| `冲突` | 互斥，二者不能同时成立 | 进 04 拍板单 |
| `单线独有` | 另外两线完全没覆盖 | 判断是"被遗漏"还是"被有意舍弃"，记入 05 或 04 |

### 4.4 冲突分级（Phase 4）

| 级别 | 含义 | 例子 |
|---|---|---|
| `L0` | 命名 / 路径冲突，改个名就解决 | slug 用 `char-build-guide` 还是 `char-builder` |
| `L1` | 结构冲突，影响文件怎么切 | 11 个主题 refs vs 9 个 probe |
| `L2` | 行为契约冲突，影响 AI 在对话里能做什么 | AI 能不能出推演候选 |
| `L3` | 哲学冲突，触及"教程≠skill"这条最高约束 | 术语要不要对用户暴露 |

### 4.5 拍板单条目格式（Phase 4）

```
### 冲突 [Cxx]：<标题>   级别：Lx   议题域：Dxx

**冲突陈述**：<一句话说清两边不能同时成立在哪>

**线 A 主张**：<结论>  （锚：文件 §节）
**线 B 主张**：<结论>  （锚：文件 §节）
**线 C 主张**：<结论>  （锚：文件 §节）
（未覆盖的线写"未覆盖"）

**教程证据**：<01_教程事实底册 中的条目编号 + 教程原文锚>
**AGENTS.md 约束判定**：<这条冲突是否被"教程≠skill"或"核心目标是帮用户完成创作"直接裁定>

**选项**：
- 选项 1：<...>  代价：<...>
- 选项 2：<...>  代价：<...>
- 选项 3（若有折中）：<...>  代价：<...>

**我的建议**：<倾向哪个 + 一句话理由>（建议 ≠ 决定）
**影响面**：<拍板后要改哪些其他条目>
```

### 4.6 教程事实底册的记录规范（Phase 1）

来自 `性格调色盘/_AI_READ_THIS_FIRST.md` 与 `books/xingge-tiaosepan/design/AGENT_PROMPT_PREFAB.md`：

- **A 类 = 追问角色本身的动作** → 可融入 skill 默认行为
- **B 类 = 教柚子方法论的教学手段** → 不融入 skill 默认行为，仅在用户主动问"为什么"时简答

底册每条事实必须标注 A 类 / B 类，以及 `教程文件:行号` 锚。**冲突裁定时只有 A 类事实可作为"skill 应该怎么做"的正面依据；B 类事实只能作为"教程为什么这么讲"的背景。**

### 4.7 命名约定

"三面性"是教程历史命名，本质是**多面性**——面的数量由角色决定。本目录统一写作 **三面性（多面性）**，引用原文时保留原措辞。
